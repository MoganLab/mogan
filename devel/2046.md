## 5 What

将启动页（startup tab）从纯 C++ QWidget 实现重构为 QML + C++ Bridge 架构。

1. `QTMStartupTabWidget` 变为薄容器，内嵌 `QQuickWidget` 加载 `StartupTab.qml`
2. 新增 `StartupBridge` 作为 C++↔QML 数据/动作桥接，通过 `Q_PROPERTY` 暴露数据模型、`Q_INVOKABLE` 暴露动作
3. 删除旧 C++ 页面类 `QTMHomePage`、`QTMTemplatePage`
4. 清理 `liii.css` / `liii-night.css` 中 startup-tab 相关 CSS 规则（样式已迁移到 QML `StartupTheme.qml`）
5. 新增 `startup_bridge_test.cpp` 单元测试，覆盖构造、recentDocs CRUD、JSON 持久化、selectCategory、tr
6. 修复 `saveRecentDocs` 时间戳丢失：`makeRecentEntry` 新增 `timestamp` 字段，保存时使用条目原始时间戳
7. 修复 `selectCategory` 异步刷新时序：移除末尾的同步 `refreshCategoryTemplates()` 调用，由 `onTemplatesLoaded` 槽统一刷新

## 6 Why

1. QML 声明式 UI 比 C++ QWidget 手动布局更易维护和调样式
2. 分离数据/动作（C++）与渲染（QML），职责清晰
3. 借 HTML 原型 `ai-docs/startup/startup.html` 统一视觉规范

## 7 How

### C++ 侧
- `StartupBridge`：通过 `Q_PROPERTY` 暴露数据模型（`recentDocs`、`styleCards`、`categories`、`categoryTemplates`、`categoryLoading`），通过 `Q_INVOKABLE` 暴露动作
- `recentPathsFromScheme`：从 Scheme 获取最近文档路径
- `readRecentMeta` / `saveRecentDocs`：读写 `recent-files.json`，写入使用 temp+rename 保证原子性，条目保留原始时间戳
- `loadRecentDocs`：合并 Scheme 路径与缓存元数据，过滤不存在的文件
- `rebuildStyleCards` / `refreshCategoryTemplates`：从 `TemplateManager` 同步数据
- 非关键 `eval_scheme` 调用使用 `QTimer::singleShot` 延迟到下一事件循环，避免阻塞 UI
- `QTMStartupTabWidget::refreshTheme()`：支持运行时主题切换
- 移除 `Entry` 枚举、`set_current_entry`、`entry_changed` 信号：页面切换由 QML `StackLayout.currentIndex` 独立管理

### QML 侧
- `StartupTab.qml`：侧边栏 + StackLayout（Home / Template 页面切换）
- `StartupHomePage.qml`：Document Style 样式卡片 + Recent Documents 列表
- `StartupTemplatePage.qml`：分类标题 + 响应式模板卡片网格（Flickable 内部滚动）
- `StartupTheme.qml`：全局主题单例（pragma Singleton），颜色/尺寸/字号对齐 HTML 原型，支持 dark 模式
- `StyleCard.qml`：图标模式（新建/打开）/ 缩略图模式（推荐模板），通过 Loader 实现双模式切换
- `TemplateCard.qml`：模板缩略卡片，鼠标区域覆盖整卡包括名称和版本信息，支持右键菜单

## 8 Code Review 修复（2026-07-27）

### 8.1 修复 selectCategory 异步刷新时序（StartupBridge.cpp:420-437）

- 旧代码：调用 async `refreshTemplatesByCategory` 后立即同步 `refreshCategoryTemplates()` 并设 `categoryLoading_=false`，导致展示旧数据和 loading 闪烁
- 新代码：已初始化时走异步路径（loading=true → `refreshTemplatesByCategory` → `onTemplatesLoaded` 统一刷新），未初始化时走同步路径（直接 `refreshCategoryTemplates`）
- 同时区分了两条路径：已初始化的 `TemplateManager` 不做同步刷新，完全由 `onTemplatesLoaded` 槽处理

### 8.2 修复时间格式 12h→24h（StartupBridge.cpp:83, 91, 217, 282）

- `yyyy-MM-dd hh:mm` → `yyyy-MM-dd HH:mm`，消除正午/午夜歧义

### 8.3 saveRecentDocs 原子写入增加失败日志（StartupBridge.cpp:254-259）

- `QFile::remove` 和 `tmpFile.rename` 失败时输出 `qWarning`，避免静默丢数据
- 增加 temp file open 失败的 else 分支日志

### 8.4 修复 StartupHomePage.qml ListView margins 语义混淆（:113）

- `anchors.margins: recentItemMarginH + recentItemMarginV` → 拆分为独立的 `leftMargin`/`rightMargin`（=recentItemMarginH）和 `topMargin`/`bottomMargin`（=recentItemMarginV）

### 8.5 新增 categoryLoading 生命周期测试（startup_bridge_test.cpp）

- `test_select_category_no_loading_when_uninitialized`：验证未初始化时不 emit `categoryLoadingChanged` 信号，loading 保持 false

### 8.6 修复已缓存分类回切不显示（StartupBridge.cpp:431-445, template_manager.cpp:431）

- **根因**：`TemplateManager::refreshTemplatesByCategory` 对 `fetchedCategories_` 中已存在的分类直接 return（no-op），不触发 `templatesLoaded` 信号。导致 `onTemplatesLoaded` 永远不被调用，`refreshCategoryTemplates()` 不执行，`categoryLoading_` 保持 true。
- **修复**：`refreshTemplatesByCategory` 后追加同步 `refreshCategoryTemplates()`；若数据已就绪（`!categoryTemplates_.isEmpty()`）则同步结束 loading，未就绪则等待 `onTemplatesLoaded` 异步回调。

### 8.7 修复回切已加载分类时缩略图重新加载（StartupBridge.cpp:320-360）

- **根因**：`refreshCategoryTemplates()` 每次都 `clear()` + 重建 `QVariantList` + `emit categoryTemplatesChanged()`，QML `Repeater` 看到 model 变化后销毁所有 delegate 重创，`Image` 组件缓存失效。
- **修复**：新增 `QHash<QString, QVariantList> categoryTemplatesCache_` 按 category 缓存模板列表。`refreshCategoryTemplates()` 命中缓存时直接复用，跳过 clear/重建/signal；`onTemplatesLoaded` 异步新数据到达时先 `remove` 缓存再刷新。

### 8.8 缩略图本地缓存 — 重构到 TemplateManager（template_manager.cpp/hpp, StartupBridge.cpp/hpp）

- **根因**：QML `Image` 对 HTTP URL 默认异步加载，切换分类时 delegate 的 `source` 变化触发异步重新加载。
- **初版**：放在 `StartupBridge`，但用户指出应归属 TemplateManager 数据层。
- **终版**：缩略图缓存逻辑移入 `TemplateManager`：
  - `cachedThumbnailUrl(remoteUrl)` — public 方法，将远程 URL 转为本地 `file://` 路径；本地文件不存在时触发 `QNetworkAccessManager` 异步下载
  - `ensureThumbnailsLocal(metadata)` — 对传入的模板元数据批量转换 thumbnailUrl
  - `onThumbnailDownloaded` — 下载完成后保存文件、更新 `templates_` 中对应条目的 `thumbnailUrl`、emit `thumbnailCached`
  - `mergeMetadata()` 末尾调用 `ensureThumbnailsLocal(templates_)`
- `StartupBridge` 回归薄桥接角色：监听 `thumbnailCached` 信号，仅做缓存失效 + 刷新。

### 8.9 缩略图缓存独立为 `ThumbnailLoader`（`src/Mogan/Cache/thumbnail_loader.cpp/hpp`）

- **根因**：`QNetworkAccessManager` 下载逻辑放在 `TemplateManager` 不合适，且该功能可复用。
- **修复**：提取到 `ThumbnailLoader` 类，职责单一——传入远程 URL，返回本地 `file://` 路径，本地无文件时异步下载。
- `TemplateManager` 持有 `ThumbnailLoader*`，在 `mergeMetadata()` 末尾对每个模板调用 `thumbnailLoader_->getUrl()` 转换 `thumbnailUrl`。
- `ThumbnailLoader::ready` 信号触发时，`TemplateManager` 更新对应模板的 `thumbnailUrl` 并 emit `thumbnailCached`。
