# [2046] startup tab QML 重构

## 1 What

将启动页（startup tab）从纯 C++ QWidget 实现重构为 QML + C++ Bridge 架构：
- `QTMStartupTabWidget` 变为薄容器，内嵌 `QQuickWidget` 加载 `StartupTab.qml`
- 新增 `StartupBridge` 作为 C++↔QML 数据/动作桥接
- 删除旧 C++ 页面类 `QTMHomePage`、`QTMTemplatePage`
- 清理 `liii.css` / `liii-night.css` 中 startup-tab 相关 CSS 规则（样式已迁移到 QML `StartupTheme.qml`）
- 样式对齐 HTML 原型 `ai-docs/startup/startup.html`

## 2 Why

1. QML 声明式 UI 比 C++ QWidget 手动布局更易维护和调样式
2. 分离数据/动作（C++）与渲染（QML），职责清晰
3. 借 HTML 原型统一视觉规范

## 3 How

### C++ 侧
- `StartupBridge`：通过 `Q_PROPERTY` 暴露数据模型（`recentDocs`、`styleCards`、`categories`、
  `categoryTemplates`、`categoryLoading`），通过 `Q_INVOKABLE` 暴露动作
- `recentPathsFromScheme`：从 Scheme 获取最近文档路径
- `readRecentMeta` / `saveRecentDocs`：读写 `recent-files.json`（写入使用 temp+rename 保证原子性）
- `loadRecentDocs`：合并 Scheme 路径与缓存元数据，过滤不存在的文件
- `rebuildStyleCards` / `refreshCategoryTemplates`：从 `TemplateManager` 同步数据
- 非关键 `eval_scheme` 调用（`startup-tab-add-recent-doc`、`startup-tab-clear-recent-doc` 等）
  使用 `QTimer::singleShot` 延迟到下一事件循环，避免阻塞 UI
- `QTMStartupTabWidget::refreshTheme()`：支持运行时主题切换

### QML 侧
- `StartupTab.qml`：侧边栏 + StackLayout（Home / Template 页面切换）
- `StartupHomePage.qml`：Document Style 样式卡片 + Recent Documents 列表
- `StartupTemplatePage.qml`：分类标题 + 响应式模板卡片网格
- `StartupTheme.qml`：全局主题单例（颜色/尺寸/字号），对齐 HTML 原型
- `StyleCard.qml`：图标模式（新建/打开）/ 缩略图模式（推荐模板）
- `TemplateCard.qml`：模板缩略卡片（鼠标区域覆盖整卡包括名称和版本信息）
