# 0512: 迁移到 Velopack 打包与自动更新

## 2026/08/07 迁移到 Velopack 打包与自动更新

### What（本次改动做了什么）

把 Mogan STEM 的 Windows 发布与自动更新从"客户端下载完整 NSIS 安装包后静默执行"迁移到
Velopack：以 Velopack 作为安装/更新事务的唯一所有者，产出 `Setup.exe`/MSI 与 `releases.<channel>.json`
静态 feed + delta 增量包；应用内通过 Velopack C++ runtime 检查、后台下载、用户确认后安装并重启。
后端更新源（feed 服务）仅输出 API 设计文档，不实现。

### Why（为什么这么做）

- 常规升级路径下载整包且静默执行，更新体积大、耗时长；Velopack delta 让已装用户只下载增量。
- 文件占用、版本目录替换、重启与 delta 链选择交给 Velopack，避免自研 `MoganUpdater`/HDiffPatch/提权 worker。
- 三平台共用 Velopack 发布版本、渠道与客户端更新 API，各平台仍产出各自安装格式。

### How（怎么做的）

1. **C++ runtime 集成（Windows）**：`velopack_libc_1.2.0` vendor 到 `3rdparty/velopack/`；
   xmake 为 `stem` 引入头文件/导入库/动态库；`research.cpp` 的 `main()` 首行
   `Velopack::VelopackApp::Build().Run()`（早于 `lolly::init_tbox()` 等副作用）。
2. **tm_velopack 抽象**：保留 `tm_updater` 内部边界，新增状态机
   `idle/checking/available/downloading/ready/applying/failed` 与版本/进度/错误码/发行说明，
   以及 `downloadUpdate`/`applyUpdate`；`instance()` 在 Windows 下走 `USE_PLUGIN_VELOPACK` 分支，
   WinSparkle/Sparkle 原分支不变。
3. **Scheme/Qt 接线**：`updater.scm` 后台检查改走异步 `tm_velopack`，`init-research.scm` idle 入口保留；
   Qt/QML controller 订阅状态并暴露下载进度与"重启以更新"。
4. **打包流水线**：`tools/release/stage_velopack.lua` 组装干净 staging 并做清单校验；
   `tools/release/pack_velopack.lua` 封装 `vpk pack`（`--packId Mogan --packVersion <XMACS_VERSION>`）；
   NSIS xpack 保留为迁移期桥接。
5. **NSIS 桥接**：一次性发布签名的桥接 NSIS 包，保存 `$TEXMACS_HOME_PATH`、关闭旧版、启动 Velopack Setup；
   迁移期结束后停发 NSIS 更新。

## 2026/08/08 Velopack 扁平布局可运行性修复

### What（本次改动做了什么）

修复 Velopack 打包布局不可运行的问题：`stage_velopack.lua` 把数据收进 `TeXmacs/`
包装目录，而应用按 `$TEXMACS_PATH/progs`、`$TEXMACS_PATH/doc`、`$TEXMACS_PATH/fonts`
等**扁平**查找资源（`init_texmacs.cpp:427/453/473`）；且 Windows 分支把 `TEXMACS_PATH`
硬编码为 exe 父目录（`exedir/".."`）。两处叠加使 `MoganSTEM.exe -headless -p` 退出码 0
但**不打印** TEXMACS_PATH（scheme 因 `progs` 解析不到而无法启动到 `-p` 处理器）。

修复后：数据平铺到暂存根、辅助程序（pandoc/vc_redist）收进 `bin/`、`.pdb` 跳过，
`TEXMACS_PATH` 探测 exe 同级 `progs`（Velopack 扁平布局取 `exedir`，否则父目录）。

### Why（为什么这么做）

- Velopack `--mainExe` 必须是 packDir 根部的文件名，主 exe 与 Qt DLL、数据必须同根平铺。
- 应用内路径拼接按 `$TEXMACS_PATH/progs` 等扁平查找，`TeXmacs/` 包装目录永远解析失败。
- `find-binary` 与 pandoc 等按 `$TEXMACS_PATH/bin` 查找辅助程序，故 `bin/` 子目录必须保留。
- `TEXMACS_PATH` 不能再用 `exedir/".."`：Velopack 下 exe 位于 `current/` 根、数据与 exe 同根。

### How（怎么做的）

1. **`init_texmacs.cpp` Windows 分支**：`exists (exedir * "progs")` 为真时取 `exedir`，
   否则取 `exedir * ".."`（NSIS：exe 在 bin/，数据在父目录）。其余分支（HOME/PWD、
   末段 `resolved_texmacs_path` 检查）原样保留。
2. **`stage_velopack.lua`**：bin/ 拆分（Qt 插件目录整体拷根、MoganSTEM.exe 与 *.dll 拷根、
   *.pdb 跳过、其余辅助程序收 `bin/`）；数据条目平铺到根（不再建 `TeXmacs/` 包装目录）；
   清单校验改查 `out/progs`、`out/plugins`、`out/fonts`；顶层白名单去 `TeXmacs` 加 `bin`。
3. **`cd_research_on_windows.yml`**：第 61 行注释更新（pandoc 收进 `bin/` 而非摊平到根）。
4. `pack_velopack.lua` 不改（`--mainExe MoganSTEM.exe` 已锁定）。

### 布局矩阵（TEXMACS_PATH 探测结论）

| 布局 | exedir | `exedir/progs` 存在？ | 取 TEXMACS_PATH |
|------|--------|----------------------|-----------------|
| NSIS 安装 | `$INSTDIR\bin` | 否（bin 下无 progs） | `$INSTDIR`（父目录）✓ |
| xmake 安装树/测试 | `data/bin` | 否 | `data`（父目录）✓ |
| Velopack 安装/暂存根 | `current` | 是 | `current`（=exedir）✓ |
| 开发构建 `build/windows/x64/release` | `release` | 否 | 父目录（行为与现状一致）✓ |

### 涉及文件

- `src/System/Boot/init_texmacs.cpp`
- `tools/release/stage_velopack.lua`
- `.github/workflows/cd_research_on_windows.yml`

### 验证

- 改前基线：`./MoganSTEM.exe -headless -p` 退出 0 不打印 TEXMACS_PATH。
- 修复后：同一命令打印暂存根绝对路径且退出 0（exe+Qt DLL+scheme progs 全部解析成功）。
- `pack_velopack.lua` 产出 Setup.exe、`releases.stable.json`（channel=stable，
  packVersion=2026.3.0-rc9）、packages/。

## 2026/08/08 修复打包样式目录嵌套与校验加固

### What（本次改动做了什么）

Task 5 审查（CHANGES REQUESTED）发现 `stage_velopack.lua` 的 `os.cp` 目录合并嵌套缺陷：
Qt 插件 `bin/styles/`（`qmodernwindowsstyle.dll`）与 TeXmacs 数据 `styles/`
（`article.ts` 等 14 项）都映射到 `out/styles`，xmake `os.cp(src_dir, dst_dir)` 在 dst
已存在时把 src 整目录塞成 `dst/basename(src)`，数据被嵌套成 `out/styles/styles/`
并**已进 nupkg**（`lib/app/styles/styles/article.ts`）。当前被 `TEXMACS_STYLE_PATH`
递归 `search_sub_dirs` 容忍不崩，但违反目标扁平布局，且任何 bin 子目录与数据目录同名
都会静默嵌套。

### Why（为什么这么做）

- 目录拷贝必须内容合并语义，使 `out/styles/*.ts` 与 `qmodernwindowsstyle.dll` 同层平铺，
  与 5.1 目标布局一致；不能依赖运行期递归搜索容忍。
- `plugins/goldfish/bin/*.pdb`（2 个）靠 vpk 默认 `--exclude .*\.pdb` 剔除；stage 的清单
  目的是"构建中间产物不得进入安装树"，pdb 正是中间产物，应由 stage 自洽兜底，不依赖 vpk。
- 顶层 `COPYING/INSTALL/README/TEX_FONTS` 是合法发布物，并入白名单消除噪音 warn。

### How（怎么做的）

1. **`stage_velopack.lua` 新增 `merge_copy(src, dst)`**：目录内容合并拷贝——逐条目复制、
   文件落到 dst 根、同名子目录递归合并、过滤 `*.pdb`。bin 拆分目录分支与数据平铺目录分支
   都改用它（`os.isdir` 分流：目录 `merge_copy`，文件 `os.cp`）。
2. **forbidden 全树扫描**加 `%.pdb$`（`merge_copy` 已过滤，作为硬失败兜底）。
3. **顶层白名单 `named`**加 `COPYING/INSTALL/README/TEX_FONTS`。
4. **`pack_velopack.lua`** 注释补"同版本重打需先删 outputDir"（vpk 拒绝 channel 内已有
   ≥ 当前版本，防误覆盖）。

### 涉及文件

- `tools/release/stage_velopack.lua`
- `tools/release/pack_velopack.lua`

### 验证

- stage 退出 0、无 COPYING 等 warn、forbidden 无 pdb 失败。
- `staging/styles/article.ts` 与 `staging/styles/qmodernwindowsstyle.dll` 同层存在，
  `staging/styles/styles` 不存在，全树无 `*.pdb`。
- `./MoganSTEM.exe -headless -d -p` 打印暂存根且退出 0。
- 删 `build/velopack_release/` 后 pack 退出 0；nupkg 含 `lib/app/styles/article.ts`、
  不含 `lib/app/styles/styles/`、无 `.pdb`。
