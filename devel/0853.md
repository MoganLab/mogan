## 3 如何测试

### 3.1 确定性测试（单元测试）
```bash
xmake b stem

```

### 3.2 非确定性测试（交互验证）
1. 打开软件，进入数学环境，观察速度；尝试进入其他环境，观察**速度是否提升**；
2. 光标在各种不同环境中切换（可以使用键盘/鼠标移动光标），观察 focus/mode 图标**是否及时刷新**；
3. 点击各种环境中的各类 focus/mode 图标，观察**是否及时响应**；
4. 进入绘图模式，测试绘制功能以及绘制完图形后的移动、属性修改、拖拽控制点等**功能是否正常**，速度是否提升；
5. 进入上方主菜单（File/Edit/Insert...），观察在不同环境下**是否得到刷新**（比如数学环境下的 Focus 下拉菜单与文本模式下不同）；
6. 整体使用软件，观察是否会出现任何情景下的**菜单随功能不切换**、**菜单点击后没反应**或者**切换卡顿现象**；

## 4 What
将菜单/图标栏刷新从「纯 idle 轮询 + 全量重建」改为「事件驱动 + 分类重建」：
- 菜单/图标按钮点击后同步全量重建（after_menu_action 统一入口），消除勾选态滞后；
- 光标移动仅在焦点树身份变化时轻量刷 mode/focus 图标；绘图手势结束时同样轻量刷；
- 删除 idle 轮询，tab 栏 `*` 标记、标题、通知栏、底部工具栏等各状态变化全部改为显式事件触发；
- scheme 侧 update-menus 改为带类别参数的封装，调用点按需重建。

## 5 Why
1. **延迟**：按钮 action 执行后不设 THE_MENUS，菜单刷新完全依赖 apply_changes 的 idle 轮询分支（166ms），粗体/绘图工具勾选态有肉眼可见滞后，gr-mode「看起来没生效」即源于此。
2. **粒度粗**：轮询触发一律全量重建 8 类 chrome，光标移动这类高频操作实际只需刷 mode/focus 图标的 check 态；且每次打字停顿 166ms 后都白跑一轮全量 menu-expand，是卡顿来源。
3. **键盘路径无触发点**：菜单 action 走 protected-call → after_menu_action，但键盘快捷键执行的是 kbd-map 裸 lambda，不经此入口；删除轮询后，键盘保存（tab `*` 不消）、键盘拼写检查（底部工具栏不出）等场景必须找到各自的事件源显式触发。

## 6 How

### 掩码与 API
- C++ `update_menus(int mask)` 按位过滤 8 类：MENU_MAIN=1（顶栏）/ ICONS_MAIN=2 / ICONS_MODE=4 / ICONS_FOCUS=8 / ICONS_EXTRA=16 / TAB_PAGES=32 / NOTIFICATION=64 / SIDE_TOOLS=128，MENU_ALL=255；提升为 editor 纯虚供各处调用。副作用（set_modified/drd_update/cache_memorize/save_user_preferences）仅 MENU_ALL 执行，轻量路径只刷图标 + set_footer。
- glue 仅保留 `menu-update-mask(int)`；scheme `(update-menus . categories)` 可变参数封装，符号类别映射掩码 logior 合并，全量须显式 `'all`，空参/未知类别 = 0（无兜底）。
- 分类重建省的是各类 `menu-expand` 求值：get_menu_widget 本有两级缓存（展开结果与 menu_current 相等则跳过 widget 重建；tab 栏另用 tabpage-menu-signature 判等），内容不变时无 widget 重建。

### 触发覆盖矩阵
| 场景 | 触发路径 |
|---|---|
| 菜单/图标按钮点击 | after_menu_action（protected-call 统一收口，action 已执行完）→ MENU_ALL |
| 光标进出上下文 | apply_changes 缓存对比 focus_get() 路径，变化才刷 ICONS_MODE\|ICONS_FOCUS；同上下文移动零开销 |
| 绘图手势结束（点选/框选/拖拽/右键） | edit_mouse.cpp mouse_graphics 消费处 release/end-drag → ICONS_MODE\|ICONS_FOCUS（选中对象不改 focus path，光标检测盖不到） |
| 切 tab / 新建 / 关闭标签 | resume() → MENU_ALL（新建经 attach_view、关闭非当前标签经 suspend/resume hack 到达） |
| 拖拽排序 tab | Qt 容器 drop 时自行重排 + move_tabpage 同步数据层，无需重建 |
| 编辑置脏 / 保存清脏 / 撤销回净 | apply_changes need_save() 翻转检测、notify_save（保存统一收口）→ TAB_PAGES\|SIDE_TOOLS |
| buffer 重命名 | notify_rename_after → TAB_PAGES\|SIDE_TOOLS（侧栏文档列表与 tab 栏同显 标题+*） |
| 底部工具栏开关 | update-bottom-tools（search/spell/db/animate 收口）→ 异步 'side-tools |
| 通知栏（登录态/会员/轮播） | scheme 显式 (update-menus 'notification)、refreshScmNotificationBar → C++ update_menus(NOTIFICATION) |
| 全屏进出 | full_screen_mode → THE_MENUS → MENU_ALL |

### 关键机制与教训
- focus 身份判据 = C++ `focus_get()` 路径缓存对比，O(路径深度)；进出 `<strong|…>`/`<math|…>`/graphics 会改变，同上下文移动不变。
- **缓存自同步判重**：缓存语义 =「该类别上次重建时的状态」，update_menus 在重建覆盖了对应类别时同步（含 ICONS_MODE|ICONS_FOCUS 同步 menu_focus_path，含 TAB_PAGES 同步 menu_need_save）；不含该类别的重建（如 NOTIFICATION 单刷）不得标新，否则会造成该刷不刷。按钮点击 MENU_ALL 后紧随的 apply_changes 不再重复触发，零冗余。
- 键盘快捷键执行 kbd-map 裸 lambda，不过 protected-call——凡键盘可达的状态变化须各自找事件源。
- **update-bottom-tools 必须异步**（delayed :idle 1）：bottom tools 展开时经偏好通知器 notify-keyboard-tool 重入本函数，同步重建 side-tools 曾在 C++ widget 构建中死锁（新建文档卡死的根因）。
- notify_save / notify_rename_after 钩子须加 has_current_window 守卫：启动期加载/重命名发生在窗口创建前（曾致启动崩溃 no window attached to view）。
- MENU_MAIN 无需高频重建：Qt 子菜单为 QTMLazyMenu，弹层在 aboutToShow 时用当前环境现场展开，内容永远新鲜；重建只影响顶栏有哪些顶级菜单。点击菜单标题不执行 action，不经 after_menu_action，属预期。
- 已知行为变化：drd_update / cache_memorize / save_user_preferences 不再随打字停顿执行，仅随全量重建；若出现 drd 启发式过时症状，再挂 THE_ENVIRONMENT 处理处。
- glue-symbols.scm 为 mogan 不使用的死文件，未动。

### 已知问题
- MENU_MAIN 计划弃用：键盘进入 graphics/source/comment 上下文时顶栏条件项不刷新的缺口不修。
- 多窗口时 update_menus 只刷当前窗口 chrome（SERVER 按当前窗口路由，与 idle 时代一致），非当前窗口获得焦点时经 resume 刷新。
