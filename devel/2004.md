## 2 任务相关的代码文件

本分支的主题是：把 goldfish 内嵌的 s7 Scheme 解释器（v11.5）连同其 C++ 原生绑定落地到构建系统，并让 MoganSTEM 在新版 s7 下正常启动、通过全部 scheme 测试。改动分三块。

### 2.1 s7 解释器与 C++ 原生绑定（`TeXmacs/plugins/goldfish/src/`，随 goldfish 引入）
- `s7.c` / `s7.h` 及配套 `s7_internal.h`、`s7_continuation.{c,h}`、`s7_ctables.{c,h}`、`s7_dtoa.{c,h}`、`s7_op_names.{c,h}`、`s7_module.{c,h}` — s7 v11.5 解释器主体
- `s7_scheme_*.{c,h}`（base/char/complex/inexact/format/predicate/symbol/write）— R7RS 基础层的 C 实现
- `s7_liii_*.{c,h}`（bitwise/hash_table/list/string/vector）— liii 标准库的 s7 绑定
- `liii_*.cpp`（hashlib/http/njson/os/path/subprocess）— liii 计算密集型模块的 C++ 原生实现
- `goldfish.hpp` / `goldfish.cpp` — 解释器初始化、过程注册、REPL 与退出钩子

### 2.2 构建系统：统一 s7 源、补齐 goldfish 目标
- `xmake/goldfish.lua` — 把 goldfish 目标的 s7 源从 `3rdparty/s7/` 改指 `goldfish/src/`，补齐全部 19 个 `.c` 及 6 个 `liii_*.cpp`（此前缺失导致链接时 `glue_*` 未定义）
- `xmake/packages/s/s7/xmake.lua` + `xmake/packages/s/s7/port/xmake.lua`（新增）— 重构 s7 xrepo 包：`on_install` 将 `goldfish/src/` 的源拷进包缓存目录构建，`port/xmake.lua` 定义 `libs7` target，与 goldfish 目标编译完全相同的源集合
- 删除 `3rdparty/s7/`（18 文件）— 旧的重复 s7 源，统一到 `goldfish/src/` 后不再需要

### 2.3 TeXmacs 脚本适配新版 s7 的 API 变更
- `TeXmacs/progs/kernel/boot/boot-s7.scm` — hash-table 构造/写入改用 s7 上游命名；boot 层 `(import (scheme char))` 把 R7RS 字符过程注入全局
- `TeXmacs/progs/kernel/boot/ahash-table.scm` — `make-ahash-table`/`ahash-set!`/`ahash-remove!` 指向新的 s7 过程
- `TeXmacs/progs/kernel/texmacs/tm-define.scm`、`gui/kbd-define.scm`、`texmacs/tm-dialogue.scm` — 同步适配
- `TeXmacs/plugins/latex/progs/bibtex/{alpha,bib-utils,gbt7714-2015-author-year}.scm`、`TeXmacs/plugins/literate/progs/utils/literate/lp-build.scm` — 同步适配

## 5 What
1. 落地 goldfish 内嵌的 s7 v11.5 + liii C++ 原生绑定到构建系统。
2. 统一 s7 源：把 goldfish 目标与 s7 xrepo 包都收敛到 `goldfish/src/`，删除重复的 `3rdparty/s7/`。
3. 修复 goldfish 目标链接（补齐缺失的 `liii_*.cpp` 与 s7 全套 `.c`）。
4. 适配 TeXmacs 脚本以兼容新版 s7 的 API：hash-table 过程的 `s7-` 前缀命名、`current-second` 走 liii/SRFI-19 标准接口、R7RS `(scheme char)` 过程注入全局。
5. 验证 STEM 正常启动、`bin/test_all_scheme` 全绿。

## 6 Why
goldfish 把运行时从旧版 s7 升级到 v11.5，并把 liii 标准库的计算密集型模块下沉为 C++ 原生绑定。但 s7 源码原本在工作树里存在两份（`3rdparty/s7/` 与 `goldfish/src/`），内容已分叉；且 `xmake/goldfish.lua` 的源文件清单停留在旧布局，导致 goldfish 二进制链接时 `glue_njson`/`glue_liii_os`/`glue_liii_path` 等符号未定义。

同时，新版 s7 相对 guile / 旧版 s7 有若干 Scheme API 变更，而 TeXmacs 的历史脚本仍按旧习惯书写：
- s7 上游把 hash-table 构造/写入改名 `s7-make-hash-table` / `s7-hash-table-set!`（实现迁至 `s7_liii_hash_table.c`），不再保留无前缀的 `make-hash-table` / `hash-table-set!` 全局名。
- goldfish 删除了 `current-second` 原语，改由 `g_get-time-of-day`（经 `(scheme time)`/SRFI-19）提供。
- s7 遵循 R7RS，把 `char-numeric?`/`char-upcase` 等字符过程放在 `(scheme char)` 模块，而非 guile 那样置于全局。

这些差异使 MoganSTEM 启动时在 `boot-s7.scm` 雪崩式报 unbound，scheme 测试也无法运行。本分支在不改动 s7 上游源码的前提下，通过构建配置与消费方脚本适配，让新版 s7 在 goldfish 与 STEM 两侧都可用。

## 7 How
1. **统一 s7 源**。把 `3rdparty/s7/xmake.lua`（`libs7` target）改造为 `xmake/packages/s/s7/port/xmake.lua`，`add_files` 补全为与 goldfish 目标一致的 19 个 `.c`；s7 包的 `on_install` 把 `goldfish/src/*.c|*.h` 拷进包缓存目录构建（不污染工作树），并自行放置 `xmake.lua` 以免 xmake 自动生成默认工程把 `s7.c` 误当二进制链接。删除 `3rdparty/s7/`。
2. **修 goldfish 链接**。`xmake/goldfish.lua` 的 s7 源改指 `goldfish/src/`，新增 `liii_hashlib/http/njson/os/path/subprocess.cpp`，使 `glue_*` 符号齐备。
3. **适配 hash-table 命名**。TeXmacs 自带脚本（kernel/latex/literate）中的 `make-hash-table`/`hash-table-set!` 改为 `s7-make-hash-table`/`s7-hash-table-set!`。注意 goldfish liii/SRFI 库内部的同名调用由 `(liii hash-table)` 模块导出、自洽可用，**保持不动**。
4. **适配 `current-second`**。`tm-dialogue.scm` 改用 `(time-second (current-time))`（已 `import (liii time)`），底层即 `g_get-time-of-day`，不额外造原语。
5. **注入 R7RS 字符过程**。`boot-s7.scm` 末尾 `(import (scheme char))`，与既有 `(import (scheme base))` 同理，一次覆盖所有按 guile 全局习惯使用 `char-numeric?` 等的脚本。
6. **校验**。`xmake b goldfish` / `xmake b stem` 成功；STEM 启动 0 unbound；`bin/test_all_scheme` 全绿。
