## [7002] 协作模式下 Save as 改为 Download

### What
协作（云端）模式下，File 菜单的 "Save as / 另存为" 显示为
"Download / 下载"，功能也变为 Download：仅把当前云端文档导出一份本地副本，
**不重命名、不切换 buffer**。快捷键 `std S`（macOS Cmd+Shift+S /
Win/Linux Ctrl+Shift+S）不变。

### Why
协作 buffer 是 `tmfs://collab/<doc_id>` 的云端文档。原 Save as 走普通
`save-buffer-as` 链，叶子步骤 `save-buffer-as-save` 会 `buffer-rename` 把
当前 buffer 改名成用户选的本地文件——这会把云端协作 buffer 剥离成本地文件，
破坏协作会话。云端文档语义上应是「下载一份副本」，而非「另存并切到本地」。

### How
- 沿用本文件已有的「模块加载时捕获原始绑定」覆盖惯用法（同 `save-buffer`
  覆盖），在 `tm-collab.scm` 覆盖 `save-buffer-as`：
  - 协作分支：文件名消毒（`:`/`;` → `-`，与原函数一致）后调
    `collab-download-copy`——覆盖确认用 `url-test? "f"` + `user-confirm`
    （均为 glue/原语，跨模块可见），确认后 `collab-do-export` 用
    `(buffer-export (current-buffer) dest fm)` 写盘。`fm` 由
    `(url-format new-name)` 推导，未知后缀兜底 `texmacs`。用 `buffer-export`
    而非 `save-buffer-as`/`export-buffer-export`：前者 `buffer-rename` 切
    buffer；后者事后对源 buffer 调 `save-buffer-save` 会写回
    `tmfs://collab/...`，均有副作用。
  - 不复用 tm-files 的 `cannot-write?`：它是模块私有 `define`，跨模块不可见
    （`:use` 只导入 `tm-define`/导出符号）；且其只读对话框的"Save as"按钮会
    递归回到本覆盖。写盘失败由 `buffer-export` 返回值兜底报"Could not save"。
  - 非协作分支：`(apply %original-save-buffer-as ...)`，行为零变化。
- 菜单文案：`file-menu.scm` 两处 "Save as"（`save-menu`、`file-menu`）改为
  `((eval (if (collab-buffer? (current-buffer)) "Download" "Save as")) ...)`。
  菜单框架 `translate` 标签 → 中文 "下载"（`zh_CN.scm` 已有
  `("download" "下载")`，无需新增词典）。Export → "TM document" 不动（文案
  非_Save as_，且同样经覆盖自动获得协作模式 Download 行为）。
- 快捷键 `generic-kbd.scm` 的 `std S` 不改：它调 `save-buffer-as`，覆盖后自动分支。
- 故意不做：下载副本不进最近文件列表、不发 `DOC_SAVE_AS` 埋点（只是导出副本）。

### 涉及文件
- `TeXmacs/progs/texmacs/texmacs/tm-collab.scm`（`collab-do-export`/
  `collab-download-copy` + 覆盖 `save-buffer-as`；更新注释与 save-buffer 提示）
- `TeXmacs/progs/texmacs/menus/file-menu.scm`（两处 Save as → 动态 Download 标签）

### 如何测试
- `xmake b stem`；进协作（Collaborative 菜单建/加共享文档），确认 File 菜单
  原另存为显示为 Download/下载；点 Download 与 `std S` 均写出本地文件且当前
  buffer 仍为 `tmfs://collab/...`、协作未断；选已存在文件弹覆盖确认。
- 普通本地文档回归：菜单仍为 Save as/另存为，行为不变。
