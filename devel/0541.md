## 2026/09/22 通用等待弹窗不可取消模式与事件泵抽象

### What(本次改动做了什么)

1. **通用等待弹窗支持不可取消模式**：
   - `WaitProgressDialog.qml`：支持 `dialogCancellable` 上下文属性。为 `false` 时不展示「Cancel」按钮且屏蔽 ESC 取消操作；
   - `QTMQmlDialog.hpp` / `.cpp`：采用函数重载保留原有 `cpp_wait_dialog_open(message)` 接口（默认可取消，完全向后兼容），并新增双参数重载 `cpp_wait_dialog_open(message, cancellable)` 支持显式传递 `cancellable` 标志；关闭弹窗时同步 `delete host` 避免退出阶段延迟析构崩溃；新增 `qt_wait_dialog_shown()` 查询弹窗打开状态；
   - **Scheme 层面零改动**：Scheme 侧调用（如 OCR）均保持单参数接口不变，Glue 层（`glue_qt.lua`）和门面层（`wait-dialog.scm`）无需任何修改，完全复用单参数重载；
2. **跨平台 GUI 层事件泵与等待弹窗中性接口**：
   - `gui.hpp` 新增 `gui_wait_dialog_open`、`gui_wait_dialog_close` 与 `gui_pump_events` 接口；
   - Qt 后端实现 `gui_pump_events`（仅在弹窗打开时以 ~30ms 节流运行 `processEvents(ExcludeUserInputEvents)`，避免阻塞导致 QML 旋转动画卡死）并在 ImGui / CLI 平台提供桩实现；
   - `gui_wait_dialog_open` 在弹窗打开后立即在同调用栈泵一次首帧，避免动画延时呈现。
3. **单元测试与交互断言**：
   - 在 `tests/Plugins/Qt/qml_load_test.cpp` 中新增 `test_wait_progress_dialog_loads` 验证 QML 组件正确加载；
   - 新增 `test_wait_progress_dialog_escape_interaction` 真实弹窗交互断言：验证在不可取消模式下按 ESC 键不会触发取消回调；在可取消模式下按 ESC 键正常响应并触发 `waitCancelBridge.cancel()` 取消回调。

### Why(为什么这么做)

1. 通用等待弹窗此前写死了可取消与 Cancel 按钮，仅适用于 OCR 等异步任务。长耗时、不可中断的同步任务（如 PDF 导出等）需要一个纯等待提示状态，不能给用户误导性的取消按钮；
2. 同步任务在主线程执行时会阻塞 Qt 事件循环，导致 QML 转圈动画停滞，需要抽象非用户输入的事件泵原语 `gui_pump_events`；
3. 将通用弹窗的基础设施增强与具体业务（PDF 导出）解耦，保持基础设施层纯净与独立测试。

### How(实现细节与测试)

1. QML 层用 `property bool cancellable: typeof dialogCancellable !== "undefined" ? dialogCancellable : false` 守卫取消行为；
2. C++ 层 `cpp_wait_dialog_close` 显式同步清理 `g_wait_dialog_host`；
3. 单元测试运行：`xmake b qml_load_test && xmake r qml_load_test`。
