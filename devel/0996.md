# 0996 AI 操作栏增加释义动作

## 任务描述

在 AI 操作栏（选中文字后悬浮的翻译/润色/对话栏）中增加**释义**按钮。与
既有的 AI 对话相比，释义要发两个引用块：

1. 引文1 = 上下文（选区所在段落），可参考润色能力；
2. 引文2 = 选中的文字。

两个引用块前面各有「引用1」「引用2」的编号标签，**标签算在提示词里**；
引文2 之后追加一句「引文2是引文1的一部分，解释一下引文2的含义（含义的
范围包括字典、专业术语等）」。所有提示词文案必须走词典，不得硬编码中文。

补充约定（任务过程中确认）：

- 文案键用 `::ai` 消歧后缀，与既有 `Polish::ai` / `Chat::ai` 一致；
- 释义与翻译一样**填完输入区即自动发送**（提示词已完整，无需用户补写）；
- 上下文口径经历两轮确认：初版取「选区所在段落」（最小包含范围）；二次
  验证时确认为 **ghost 字符预算窗口**（选区前 1500 字节 + 选区 + 选区后
  500 字节，跨段落自然延伸）；
- 本分支**基于 PR #4603（0995，提示词语言首选项）**：三段提示词（引用1/
  引用2 标签、说明句）按「AI 提示词语言」首选项本地化；4603 已合并，
  已 rebase 到 main。
- **修复 1315（#4608）引入的按钮失效回归**：4608 的事件过滤器在 press
  时用 hover 异步标志 `buttonHovered` 判定是否点在按钮上，标志未置位
  时把按钮点击误吞成「栏外按下」转发给文档，导致操作栏按钮全部失效。
  本分支把判定改为按坐标同步调用 QML `overButton(x, y)` 命中检测，
  保留 4608 的修复点（栏不抢焦点、非按钮处按下照常隐藏并转发拖选）。

## Why

翻译/润色/对话都只围绕选区本身，缺少「结合上下文理解词句」的入口；释义
需要知道选区出现在什么语境里（一词多义、专业术语），因此必须把所在段落
作为引文1 一并喂给模型，并要求模型把引文2 当作引文1 的一部分来解释。

## How

### 1. 上下文提取（Scheme）

`ai-actions-bar.scm` 新增 `ai-selection-context`，采用 **ghost 字符预算窗口**
语义（二次验证后按需求方确认调整）：对正文 stree
（`tm->stree (buffer-get-body (current-buffer))`）分别按选区起点、终点路径
切分（路径先剥掉 `buffer-path` 前缀，同 `ghost-relative-path`），得到
（选区前文本 . 选区后文本）；引文1 = 选区前最多 1500 字节 + 选区本身 +
选区后最多 500 字节（预算数值同 ghost 的 prefix/suffix limit）。跨段落
自然延伸、可在段落中间截断；选区嵌在引文1 中段，「引文2是引文1的一
部分」成立。

切分与展平约定照 ghost（liii ghost-context.scm 的 `ghost-split-text-context`，
mogan2 不依赖该插件，自实现）：

- 表格 / 图片 / 公式 → `[TABLE]` / `[IMAGE]` / `[FORMULA]` 标记，切分时
  整体不透明（光标入内全归 after 的标记）；
- `with` 节点：inline 数学（`(with ("mode" "math") ...)`）整体替换成
  `[FORMULA]`，其余只取末尾 body（前面是 key/val 属性对）；
- `document` 子节点换行连接——切分时把切点两侧的文本片段当作首尾子
  节点拼回 `document` 再展平，分隔符自然落在切口两侧；
- 截断按字节计且**不切半 herk 的 `<#XXXX>` 序列**（head 退到序列起点、
  tail 从 `>` 之后开始），避免聊天输入框出现半截 `<#4E2` 字面垃圾。

返回的是 **herk 编码**（tm 内部编码）文本，C++ 侧原样插入、不再转码。

### 2. 输入体组装（C++）

`ChatController::composeAiInputBody` 增加 `context` 形参（默认空串，其余动作
不受影响），`action == "gloss"` 时按序产出 5 个节点：

```
引用1            ← translate ("reference %1::ai", "english", prompt_lang) + %1 换序号
quote-env(上下文) ← aiTextTree (context)：纯文本按行拆段，换行符不进树标签
引用2            ← 同上换序号
quote-env(选区)   ← aiQuoteBlock (sel)，与翻译/对话同一包装
说明句            ← translate (英文键, "english", prompt_lang)
```

`prompt_lang` 取 0995 的 `get_ai_language_preference ("ai:prompt language")`
（system 哨兵经 `get_locale_language()` 解析为系统语言，与翻译目标语言、
界面语言偏好相互独立）；`translate` 返回 Cork，词典缺词条时回落英文原句，
英文提示词下 `::ai` 消歧后缀自动剥掉。

从既有的 `composeAiInputBody` 里抽出 `aiQuoteBlock`（引用块包装，原先内联在
函数里）与新增 `aiTextTree`（按行拆段）两个静态辅助函数，翻译/对话共用前者。

### 3. 触发路径

- `edit_mouse.cpp`：`ai_action` 的白名单加入 `gloss`，与 translate/chat 同走
  `qt_chat_ai_send_selection (selection_get (), action)`；无选区时忽视不变。
- `qt_chat_controller.cpp`：`qt_chat_ai_send_selection` 在打开侧边栏**之前**
  `call ("ai-selection-context")` 取上下文（切到聊天输入缓冲后选区已不在文档
  上）；释义与对话同样不写进绑定文档的翻译会话；填完输入区后
  `onSendRequested` 即发。
- 按钮：`QTMAiActionsBar`（0995 由 QTMAiTranslatePopup 改名）注入
  `labelGloss = qt_translate ("Gloss::ai")`，`AiActionsBar.qml` 的静态
  model 追加 `gloss` 一项（恒可见，不受 0995 翻译显隐门控影响），图标
  `qrc:/ai-actions/gloss.svg`（新画的翻开书本线稿，风格对齐既有 24×24）。
- 命中检测（修 1315 回归）：QML 根新增 `overButton(x, y)`——遍历可见
  胶囊做 `mapFromItem` 坐标包含判定；`isOverButton` 改为同步调用它，
  移除 hover 异步态 `buttonHovered`/`checkHover`（hover 高亮本身由
  `lit` 绑定与 `syncHover` 负责，不受影响）。

### 4. 词典

`TeXmacs/plugins/lang/dic/en_US/zh_CN.scm` 新增 3 条（键保持英文，`::ai` 消歧；
英文界面 `from == to` 时 `translate` 只显示 `::` 前的部分）：

```
("gloss::ai" "释义")
("reference %1::ai" "引用%1")
("reference 2 is part of reference 1, explain the meaning of reference 2 (including dictionary and technical terms)"
  "引文2是引文1的一部分，解释一下引文2的含义（含义的范围包括字典、专业术语等）")
```

`%1` 的替换由调用方完成（与既有 `(replace (translate "Page %1") ...)` 一致）。

## 追加改动：释义会话按文档复用 + 会话 type 字段

### What

1. 同一文档的释义全部进同一个会话（此前释义与对话一样填进当前/新
   会话），行为对齐翻译：按 stem-doc-id 找未归档会话复用，未命中才
   新建；新建标题为「释义: 文件名（不带后缀）」——文件名取
   `chat-tab-source-doc-info` 返回的 url 末段去扩展名形式，前缀
   随界面语言本地化，与翻译标题的「翻译」同一取词方式。
2. 会话属性新增 `type` 字段（`translate` / `gloss`，空串为普通
   对话），区分同一文档绑定的翻译会话与释义会话；字段随 manifest
   持久化并兼容旧 manifest（缺失回退空串）。

### Why

- 释义此前每次都在当前会话里发，同一文档多次释义会散落多个会话，
  也会污染用户的普通对话；翻译已有按文档聚合的会话机制，释义应
  共享同一机制。
- 翻译与释义都绑定同一 stem-doc-id 后，仅靠 sourceDocId 无法区分
  二者（释义会复用到翻译会话里），需要类型字段各自命中。

### How

1. **会话模型（C++）**：`ChatSession` 增加 `type` 成员；
   `ChatSessionManager` 增加 `setType`，`findSessionBySourceDoc`
   增加 `type` 形参（docId + type 双条件匹配）。
2. **发送路径（C++）**：`qt_chat_ai_send_selection` 中 gloss 并入
   translate 的文档绑定分支——打开侧边栏前捕获文档身份与上下文；
   复用分支按 `(docId, action)` 查找；新建分支标题词按动作取
   `qt_translate ("Translate")` / `qt_translate ("Gloss::ai")`
   （"Gloss::ai" 即 0996 释义按钮同一消歧键，随界面语言本地化），
   并 `setType` 写入类型。对话分支不再承接 gloss。
3. **持久化（Scheme）**：`chat-persist-make-entry` 的 rest 链末端
   追加 `type`（opts4 守卫解析，缺省空串），条目新增 `"type"` 键；
   `chat-persist-load-all` 读取 `type`（缺失回退空串），恢复时经
   新增 glue `qt-chat-tab-set-session-type` 单独设置（restore 参数
   已达 glue 10 参上限，与 stemDocId 同款旁路）。
   `ChatController::updateManifest` 透传第 11 个实参 `s->type`。
