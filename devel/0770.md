# [0770] 修复 WASM 下 Cmd±= 放大/缩小等「修饰键 + 非字母键」快捷键失效

## 1 背景

线上 WASM（`research.mogan.app`）用 ImGui 前端构建（CD 命令
`--qt_frontend=no`）。在 Mac 浏览器里 `Cmd + =`（放大）、`Cmd + -`（缩小）
等快捷键无响应。

经排查，**不是 kbd `.scm` 平台加载的问题**：

- ImGui 启动时 `im_detect_browser_os()` 把宿主 OS 写入 `MOGAN_BROWSER_OS`
  （`src/Plugins/ImGui/im_gui.cpp`），`default-look-and-feel` 据此在 Mac 浏览器
  返回 `"macos"`（`TeXmacs/progs/kernel/texmacs/tm-preferences.scm`）。
- 因此 macos 的 kbd 通配符（`std`→`M-`、`cmd`→`A-` 等）正常生效，zoom 绑定
  `"std ="`/`"std -"` 正确展开为 `"M-="`/`"M--"`（`generic-kbd.scm`），且在
  macos look-and-feel 下 `like-std?` 为真、绑定处于激活状态。

## 2 根因

`src/Plugins/ImGui/im_input.cpp` 的 `im_from_key_event` 把「Ctrl/Cmd + 非字母
可打印键」**静默丢弃**了。其分支只覆盖三种情况：

1. 字母快捷键：仅 `A`–`Z`；
2. 命名键（方向键 / F 键 / space 等）：走 `im_keymap`；
3. 可打印键：仅当 `mods_text` 为 `""` 或 `"S-"` 时才让给 char 回调，**否则
   `return ""`**。

以 `Cmd + =` 为例（`=` 为 ASCII 61）：

- `mods_text = im_from_modifiers(SUPER) = "M-"`（Cmd/GLFW_MOD_SUPER → `M-`）；
- 非字母、不在 keymap、`mods_text` 为 `"M-"`（既非 `""` 也非 `"S-"`）→
  `return ""`；
- 而 `glfw_char_callback` 又因 `last_key_mods & SUPER` 提前返回。

结果 `Cmd + =` 既不产生 key 串、也不产生字符，zoom 绑定 `"M-="` 永远等不到。
`Cmd + -` 同理。对照 Qt 前端 `qt_utilities.cpp` 的 `from_key_press_event`：
`mods_text == "C-" || "M-"` 时会 `r << mods_text << key_locased`，**不会丢**。
ImGui 这套翻译漏掉了对应分支。

## 3 任务相关的代码文件

- `src/Plugins/ImGui/im_input.cpp` — 在 `im_from_key_event` 中新增「Ctrl/Cmd +
  可打印非字母键」分支，发出快捷键串，对齐 Qt 的 `from_key_press_event`。

## 4 What / Why / How

- **What**：`Cmd + =` / `Cmd + -`（以及 `Cmd/Ctrl + ` 任意非字母可打印键，如
  `Cmd + 0`、`Ctrl + -`）在 WASM（ImGui 前端）下失效。
- **Why**：`im_from_key_event` 对「Ctrl/Cmd + 非字母可打印键」返回 `""`，事件被
  丢弃，编辑器收不到对应 key 串。
- **How**：参照 Qt 的处理，在字母快捷键分支之后、最终 `return ""` 之前，补一段：

  ```cpp
  if (shortcut && im_is_printable_key (key))
    return ((mods & GLFW_MOD_SHIFT)
              ? im_from_modifiers (mods & ~GLFW_MOD_SHIFT)
              : mods_text) *
           string (locase ((char) key));
  ```

  仅限 Ctrl/Cmd（`shortcut`）：这些键的字符已被 `glfw_char_callback` 抑制，不会
  重复输入。Alt 不在此处理——Alt 走 char 回调做 Option 合字输入（如 `Alt+p` →
  `π`），若在此也产出快捷键串会与 char 回调重复。

  对 `Cmd + =`：产出 `"M-" + "=" = "M="` 的前缀形式 `M-=`，匹配 `"std =" → "M-="`。
  对 `Cmd + -`：产出 `M--`，匹配 `"std -" → "M--"`。

## 5 关于 Alt+Shift+7 / Alt+Shift+4（多行 / 单行公式）

本次**未**一并修复，原因有两点（需另行确认）：

1. 全仓库 `TeXmacs/progs/` 内**没有**把 `Alt+Shift+7` / `Alt+Shift+4`（即
   `Alt+$` / `Alt+&`）绑定到插入展示公式（`make-equation` / `make-equation*` /
   `make-eqnarray*`）的 scheme 代码——这些只在菜单和语音文件里。即便修了丢弃，
   也插不出公式，需要先确认该绑定来源（自定义 keymap？拟新增？）。
2. Alt 走 char 回调做 Option 合字输入；要让 Alt + 键产出快捷键串，需同时改
   `glfw_char_callback` 的抑制条件，会影响 Option 合字，属设计决策。

## 6 如何测试

### 6.1 编译

ImGui 前端（`im_input.cpp` 仅在非 Qt 构建里编译）：

```bash
xmake f --qt_frontend=no -p wasm        # 线上同款
xmake b stem
```

### 6.2 交互验证（Mac 浏览器）

1. `Cmd + =` → 视图放大；`Cmd + -` → 视图缩小；`Cmd + 0` → 恢复。
2. `Cmd + z` / `Cmd + Shift + z`（撤销/重做）等字母快捷键仍正常（回归）。
3. `Alt + p` 仍插入 `π`（Option 合字不受影响，回归）。
