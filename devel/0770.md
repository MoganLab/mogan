# [0770] 修复 WASM 下 Cmd±= 放大/缩小、Alt+&/Alt+$ 公式等修饰键快捷键失效

## 1 背景

线上 WASM（`research.mogan.app`）用 ImGui 前端构建（CD 命令
`--qt_frontend=no`）。Mac 浏览器里 `Cmd + =`（放大）、`Cmd + -`（缩小）、
`Alt + &`（多行公式）、`Alt + $`（单行公式）等快捷键无响应。

经排查，**不是 kbd `.scm` 平台加载的问题**：

- ImGui 启动时 `im_detect_browser_os()` 把宿主 OS 写入 `MOGAN_BROWSER_OS`
  （`src/Plugins/ImGui/im_gui.cpp`），`default-look-and-feel` 据此在 Mac 浏览器
  返回 `"macos"`（`TeXmacs/progs/kernel/texmacs/tm-preferences.scm`）。
- 因此 macos 的 kbd 通配符（`std`→`M-`、`cmd`→`A-` 等）正常生效，绑定都正确展开
  且处于激活状态（`like-std?` 为真）。

## 2 根因

都在 `src/Plugins/ImGui/im_input.cpp` 的 `im_from_key_event`，它把若干「修饰键 +
非字母键」**静默丢弃**了。其分支只覆盖三种情况：

1. 字母快捷键：仅 `A`–`Z`；
2. 命名键（方向键 / F 键 / space 等）：走 `im_keymap`；
3. 可打印键：仅当 `mods_text` 为 `""` 或 `"S-"` 时才让给 char 回调，**否则
   `return ""`**。

### 2.1 Ctrl/Cmd + 非字母键（Cmd±= zoom）

以 `Cmd + =` 为例（`=` 为 ASCII 61）：

- `mods_text = im_from_modifiers(SUPER) = "M-"`；
- 非字母、不在 keymap、`mods_text` 为 `"M-"`（既非 `""` 也非 `"S-"`）→
  `return ""`；
- 而 `glfw_char_callback` 又因 `last_key_mods & SUPER` 提前返回。

结果 `Cmd + =` 既不产生 key 串、也不产生字符，zoom 绑定 `"M-="` 永远等不到。
`Cmd + -` 同理。对照 Qt 前端 `qt_utilities.cpp` 的 `from_key_press_event`：
`mods_text == "C-" || "M-"` 时会 `r << mods_text << key_locased`，**不会丢**。

### 2.2 Alt+& / Alt+$（公式）

`text-kbd.scm:479-480` 定义 `("text $" (make-equation*))`、
`("text &" (make-eqnarray*))`。通配符 `("text" "cmd" #t)`（prefix-kbd.scm:238）
在 macos 下 `cmd`→`"A-"`（prefix-kbd.scm:155），故展开为 `"A-$"` / `"A-&"` =
Alt+$ / Alt+&。macOS 浏览器把 Alt+Shift+7 合字为 `‡`，`glfw_char_callback` 拿到
的是 `‡`（U+2021）而非 `&`，而 key 码又是未 shift 的 `7` —— ImGui 两头都拿不到
`&` 字形，于是 `‡` 被当字面字符插入。

## 3 任务相关的代码文件

- `src/Plugins/ImGui/im_input.cpp`
  - 新增「Ctrl/Cmd + 可打印非字母键」分支（修 Cmd±= zoom）。
  - 新增 `im_shift_glyph`（US 布局 shift 字形表）+「Alt+Shift + 可打印键」分支
    （修 Alt+& / Alt+$ 公式），产出 `"A-" + shift 字形`。
- `src/Plugins/ImGui/im_tm_widget.cpp` — `glfw_char_callback` 增加 Alt+Shift 抑制，
  避免浏览器合字字符（如 `‡`）与快捷键串重复分发。

## 4 What / Why / How

### 4.1 Cmd±= 放大/缩小（Ctrl/Cmd + 非字母键）

- **What**：`Cmd + =` / `Cmd + -`（及任意 Ctrl/Cmd + 非字母可打印键）失效。
- **Why**：`im_from_key_event` 对其返回 `""`，事件被丢弃。
- **How**：字母分支之后补一段（仅限 Ctrl/Cmd，其字符已被 char 回调抑制）：

  ```cpp
  if (shortcut && im_is_printable_key (key))
    return ((mods & GLFW_MOD_SHIFT) ? im_from_modifiers (mods & ~GLFW_MOD_SHIFT)
                                    : mods_text) *
           string (locase ((char) key));
  ```

  `Cmd+=` → `M-=`（匹配 `"std ="`→`M-=`），`Cmd+-` → `M--`。

### 4.2 Alt+& / Alt+$ 公式（Alt+Shift + 符号键）

- **What**：`Alt+&` 应插多行公式（`make-eqnarray*`）、`Alt+$` 应插单行公式
  （`make-equation*`），ImGui 却插入 `‡`。
- **Why**：浏览器把 Alt+Shift+7 合字为 `‡`，char 回调拿到 `‡` 而非 `&`；key 码是
  未 shift 的 `7`，也拿不到 `&` 字形。`im_from_key_event` 无 Alt 分支 → `‡` 被当
  字面字符插入。
- **How**：
  1. `im_shift_glyph`：按 US 布局把可打印键码映回 shift 字形（`'7'→'&'`、
     `'4'→'$'` …）。
  2. `im_from_key_event` 新增「Alt+Shift + 可打印键」分支，产出
     `"A-" + im_shift_glyph(key)`（对齐 Qt 的 `"A-"` 分支：drop `S-`、用字形）。
     `Alt+Shift+7` → `"A-&"`，命中 `"text &"` → `make-eqnarray*`。
  3. `glfw_char_callback` 增加：`last_key_mods` 同时含 ALT 与 SHIFT 时抑制 char
     分发，避免 `‡` 与快捷键串重复（对齐 Qt 不对 `A-S-` 做合字）。
- **局限**：
  - shift 字形表是 US 布局；其它布局下 Alt+Shift+物理键 不一定产生 `&`/`$`，但
    绑定本身也按 US 字符写，故一致。
  - **plain Alt（无 Shift）**：见 §6（后续已修复）。

### 5.2 交互验证（Mac 浏览器）

1. `Cmd + =` 放大；`Cmd + -` 缩小；`Cmd + 0` 恢复。
2. 文本模式下 `Alt + &` → 插入多行公式（eqnarray*）；`Alt + $` → 插入单行公式
   （equation*）。不再插入 `‡`。

   仍正常。

## 6 补充：plain Alt（Alt+1/2 章节、text a 等）—— 取代 §4.2「plain Alt 未处理」

§4.2 末尾原记「plain Alt 未处理 / 留作后续」，本节为后续修复（同任务 0770）。

**问题**：`("text 1" (make-section 'section))`、`("text a" (make 'abbr))` 等
plain Alt（无 Shift）绑定仍失效——`im_from_key_event` 原无 plain-Alt 分支，Alt+数字
落到 char 回调（macOS 上被 Option 合字或丢弃），从不产出 `"A-1"`/`"A-a"`。

**修复**（对齐 Qt 的 `"A-"` 分支）：

- `im_input.cpp`：新增「Alt（无 Shift）+ 字母/数字 -> `"A-" + 键`」分支；`Alt+1` →
  `"A-1"`（命中 `text 1` → 章节）、`Alt+a` → `"A-a"`（`text a` → abbr）。Alt+符号
  仍返回 `""`，走 char 回调做 Option 合字（`Alt+-` → `–` 等），与 Qt 一致。
- `im_tm_widget.hpp`：新增成员 `bool last_key_handled`。
- `im_tm_widget.cpp`：`glfw_key_callback` 据 `im_from_key_event` 返回非空置位
  `last_key_handled`；`glfw_char_callback` 在该位置位时抑制 char 分发。**取代** §4.2
  step 3 的「Alt+Shift mods 抑制」——改用标志位，使 Alt+字母/数字（已作快捷键，抑制）
  与 Alt+符号（仍需合字，不抑制）能精确区分。

**代价（与 Qt/macOS 一致）**：Alt+字母不再走 Option 合字（如 `Alt+p` 不再出 `π`）；
特殊字符用符号输入（`F5`/`F6` 等）或 Unicode `<#XXXX>`。shift 字形表仍仅 US 布局。

**注意（IME）**：WASM 中文输入法走隐藏 textarea 的 composition 事件
（`im_install_ime_listeners` → `g_ime_pending`），合成期 keydown 已在 textarea 层
`stopPropagation`、不进 GLFW 回调，故 `last_key_handled` 不影响 IME 提交文本——但
合并后需在浏览器实测 IME 仍正常。
