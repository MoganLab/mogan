# 1189 generic-kbd 按 look-and-feel 拆分为 profile 插件

## 背景

`TeXmacs/progs/generic/generic-kbd.scm`（840 行）目前混合了三类内容：

1. **通用绑定**（第 38–252 行）：所有模式共用的快捷键（方向键、structured:*、
   altcmd、symbol 等），以及 `in-hybrid?` / `in-smart-ref?` 两个 mode 块；
2. **5 个 profile 块**（第 255–770 行）：`(:profile emacs|gnome|kde|macos|windows)`
   各自的 kbd-map（emacs 两块，其余各一块）；
3. **std profile + magic-paste**（第 773–837 行）：跨平台 std 绑定和
   `kbd-apply-magic-paste-shortcut`。

`kbd-map` 的 `:profile` 守卫在**宏展开期**走 `has-look-and-feel?` 判定
（`kernel/gui/kbd-define.scm:506`），profile 不匹配时整段展开为 `(noop)`。
也就是说非 emacs 用户启动时，emacs 块不产生任何键绑定，但整个 840 行文件
仍需被读取、展开；5 个 profile 的代码耦合在一个文件里，职责不清。

另外，工作区已有一处配套改动：`(lazy-keyboard (generic generic-kbd) always?)`
从 `plugins/keyboard/progs/init-keyboard.scm` 挪到 `init-research.scm` 末尾
（generic-kbd 是核心绑定，不应依赖 keyboard 插件完成注册）。

## What

把 5 个 profile 块从 `generic-kbd.scm` 拆出，各建一个 profile 插件：

| profile | 新文件 |
|---------|--------|
| emacs | `TeXmacs/plugins/emacs/progs/init-emacs.scm` |
| gnome | `TeXmacs/plugins/gnome/progs/init-gnome.scm` |
| kde | `TeXmacs/plugins/kde/progs/init-kde.scm` |
| macos | `TeXmacs/plugins/macos/progs/init-macos.scm` |
| windows | `TeXmacs/plugins/windows/progs/init-windows.scm` |

`generic-kbd.scm` 保留：通用绑定、`in-hybrid?`/`in-smart-ref?` 块、
std profile、`kbd-apply-magic-paste-shortcut`。

## Why

- **组织**：按 look-and-feel 分文件，generic-kbd 只留真正通用的绑定，
  每个 profile 的键绑定自成一个可独立维护的单元。
- **性能**：generic-kbd.scm 从 840 行瘦到 ~390 行，缩短读取/展开时间
  （1174 实测该模块加载 25 ms）；profile 插件经 `lazy-plugin-initialize`
  （idle 10ms）懒加载，非匹配 profile 的绑定展开为 `(noop)`，不产生注册开销。

## How

- **插件自动发现，无需注册**：`plugin_list()`（`src/System/Boot/init_texmacs.cpp:291`）
  扫描 `$TEXMACS_PATH/plugins/*`，`init-research.scm:593` 对每个插件
  `lazy-plugin-initialize`，约定加载 `plugins/<name>/progs/init-<name>.scm`。
  新建 5 个目录各放一个 init 文件即可。
- **每个 init 文件不是 texmacs-module**，与 `init-buffer.scm` 一样直接在
  `*texmacs-user-module*` 顶层求值，`kbd-map` 动作里的符号（`kbd-start-line`
  等）按键时才解析，无需 `:use` 依赖声明。
- **最外层包 `(when (like-xxx?) ...)`**：插件 init 文件由 lazy-plugin 机制
  无条件加载，运行时守卫保证只有匹配 look-and-feel 的 profile 才注册绑定；
  非匹配时整段跳过，连宏展开开销都没有。内层 `(:profile xxx)` 守卫保留
  （双保险，且保持原块原样搬运）。
- **范围仅限 generic-kbd.scm**。`prefix-kbd.scm` 里的 emacs 前缀定义
  （`kbd-wildcards` 等）已有 `(when (like-emacs?) ...)` 运行时守卫，
  不在本次范围内。
- 社区版兜底：profile 插件缺失时（社区版不带这些插件目录），对应 profile
  的绑定不存在，行为等同于「该 profile 块展开为 noop」，核心 progs 无需
  改动、无需 `defined?` 守卫（键绑定注册是插件侧单向行为）。

## 验证

- 等价性：emacs look-and-feel 下启动，对比拆分前后键绑定 dump 一致
  （用户手动验证）。
- 启动日志确认 5 个插件按 lazy-plugin 机制加载（`plugin` 通道）。
- `gf fmt --changed-since=main` 格式化新增 .scm。
