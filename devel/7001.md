# [7001] 协作 buffer URL 改为 tmfs://collab/<doc_id>

## What
把协作编辑（loro CRDT 云文档）buffer 的 URL 从普通 scratch 路径
（`$HOME/Documents/LiiiSTEM/no_name/no_name_N.tmu`）改为专用
`tmfs://collab/<doc_id>`，用服务端 doc_id (UUID) 标识。

## Why
- 协作 buffer 原先复用 scratch 机制，URL 与普通未命名文档无法区分。
- 协作身份靠 Scheme 单值变量 `collab-buffer-url` 维持，单会话设计——
  第二个协作 buffer 会覆盖第一个的标识。
- 改用 `tmfs://collab/<doc_id>` 后：URL 即文档身份、可被纯 URL 谓词判定
  （顺带修掉单会话 bug）、与 chat buffer（`tmfs://chat/<sessionId>/...`）
  模式一致；tmfs buffer 自动当 scratch，契合云文档语义。

## How
- **URL 形态**：`tmfs://collab/<doc_id>`。create 时 doc_id 未知，先用占位
  URL（`tmfs://collab/pending-<ts>-<n>`，也是 collab 协议，谓词能识别），
  C++ `become_ready` 收到 `DOC <uuid>` 帧后改名成真实 doc_id URL。
- **建 buffer**：复用 `new-buffer`/`load-buffer`（保留 `with-default-view`
  既有副作用）后立即 `buffer-rename` 成 tmfs URL，不用 `buffer-set`+
  `switch-to-buffer` 替代（规避后者行为不确定性）。
- **谓词升级**：`collab-buffer?` 改为 `(url-rooted-tmfs-protocol? u "collab")`。
- **become_ready 改名**：create 模式下先更新 `session->buffer_url` 再
  `rename_buffer`，保证 `poll`/`get_editor`/`find_by_buffer` 用新 URL 匹配。
- **join 去重**：`collab-join-document` 先查 buffer-list（用 `url->unix` 串比较，
  绕过 `buffer-exists?` 经 `url->url` 对 tmfs URL 的失配），若该 doc_id 的 buffer
  已在本进程打开则 `switch-to-buffer` 跳转（同一文档在本进程唯一 buffer，与打开
  同一文件的行为一致），不新建——避免两个 buffer 抢同一 `tmfs://collab/<doc_id>` URL。
- **Save as 默认名**：`choose-file`（abbrevs.scm）原用 `buffer-get-master` 作文件
  对话框默认名，对 tmfs buffer 即 tmfs URL（→ UUID）。改为 tmfs buffer 用
  `propose-name-buffer`（= cork→UTF-8 标题 = doc_name）。
- **tab 标题刷新**：`rename_buffer`（new_buffer.cpp）原顺序是 `notify_rename_after`
  （同步触发 tab 栏重建）在 `set_title_buffer` 之前——tab 重建时标题仍是 scratch 的
  "No name [N]" 被缓存，之后 `set_title_buffer` 不再触发 tab 重建，且协作 buffer
  `need_save` 恒 false 使 `update_globals` 的 tab 刷新也不触发，导致 "No name" 残留。
  调换顺序（先 `set_title_buffer` 再 `notify_rename_after`）；并在 `become_ready` 设
  doc_name 后 `ed->notify_change(THE_MENUS)` 显式触发 tab 重建显示 doc_name。
- **tab 标题根因（set-title 前 rename）**：`create`/`join` 入口原顺序是先 `buffer-rename`
  再 `buffer-set-title`——rename 时 title 仍是 scratch 的 "No name"，`propose_title` 对 tmfs
  返回完整 tmfs URL，第一次 tab 重建 widget=URL；之后 set-title 改 doc_name 但 tab 缓存残留
  URL。调换为**先 `buffer-set-title` 再 `buffer-rename`**，rename 时 title=doc_name，
  `propose_title` 走 `keep_old` 保留 doc_name。配套：`propose_title`（new_buffer.cpp）对 tmfs
  若 `old_title` 非空/非 No name/非 tmfs URL 则保留（不再调 tmfs-title 返回 URL）；`become_ready`
  create 模式 rename 前先 `set_title_buffer(old_url, doc_name)` 兜底；`set_title_buffer` 改
  title 后同步 `update_menus(TAB_PAGES)` 刷 tab。
- **删除 cloud 标志**：URL 化后 `tmfs://collab/` 已是「是否云文档」的单一特征，
  原 `tm_buffer_rep::cloud` 布尔标志冗余（改造前 URL 是 scratch 无法区分才需要）。
  `need_save` 改用 `is_rooted_tmfs(buf->buf->name,"collab")` 据 URL 判断（与 scheme
  `collab-buffer?` 同源），删除 `cloud` 字段及其在 `get_or_create` 的置位。

## 涉及文件
- `TeXmacs/progs/texmacs/texmacs/tm-collab.scm`
- `TeXmacs/progs/kernel/boot/abbrevs.scm`（`choose-file` tmfs 默认名 → doc_name）
- `TeXmacs/progs/texmacs/texmacs/tm-files.scm`（`propose-name-buffer` tmfs → 标题）
- `src/Plugins/Collab/loro_collab.cpp`
- `src/Texmacs/Data/new_buffer.cpp`（`rename_buffer` 调换 set_title/notify 顺序；
  `propose_title` tmfs 保留 old_title；`set_title_buffer` 改 title 后 `update_menus(TAB_PAGES)`）
- `src/Edit/Modify/edit_modify.cpp`（`need_save` 改 URL 判断 + 加 include）
- `src/Texmacs/tm_buffer.hpp`（删 `cloud` 字段）
- `TeXmacs/progs/texmacs/texmacs/tests/tm-collab-test.scm`（纯逻辑：URL 构造/谓词/占位唯一）
- `TeXmacs/tests/7001_collab_url.scm`（GUI 集成：经 scheme 入口 create 验证
  buffer URL = `tmfs://collab/<doc_id>`，需 loro-server + `MOGAN_TEST_GUI=1`）
