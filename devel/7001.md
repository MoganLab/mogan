# [7001] 协作 buffer URL 改为 tmfs://collab/<doc_id>

## What
把协作编辑（loro CRDT 云文档）buffer 的 URL 从普通 scratch 路径
（`$HOME/Documents/LiiiSTEM/no_name/no_name_N.tmu`）改为专用
`tmfs://collab/<doc_id>`，用服务端 doc_id (UUID) 标识。

## Why
- 协作 buffer 原先复用 scratch 机制，URL 与普通未命名文档无法区分。
- 协作身份靠 Scheme 单值变量 `collab-buffer-url` 维持，单会话设计——
  第二个协作 buffer 会覆盖第一个的标识。
- 改用 `tmfs://collab/<doc_id>` 后：URL 即文档身份、可被纯 URL 谓词判定
  （顺带修掉单会话 bug）、与 chat buffer（`tmfs://chat/<sessionId>/...`）
  模式一致；tmfs buffer 自动当 scratch，契合云文档语义。

## How
- **URL 形态**：`tmfs://collab/<doc_id>`。create 时 doc_id 未知，先用占位
  URL（`tmfs://collab/pending-<ts>-<n>`，也是 collab 协议，谓词能识别），
  C++ `become_ready` 收到 `DOC <uuid>` 帧后改名成真实 doc_id URL。
- **建 buffer**：复用 `new-buffer`/`load-buffer`（保留 `with-default-view`
  既有副作用）后立即 `buffer-rename` 成 tmfs URL，不用 `buffer-set`+
  `switch-to-buffer` 替代（规避后者行为不确定性）。
- **谓词升级**：`collab-buffer?` 改为 `(url-rooted-tmfs-protocol? u "collab")`。
- **become_ready 改名**：create 模式下先更新 `session->buffer_url` 再
  `rename_buffer`，保证 `poll`/`get_editor`/`find_by_buffer` 用新 URL 匹配。
- **join 去重**：`collab-join-document` 先查 `(buffer-exists? tmfs-url)`，若该
  doc_id 的 buffer 已在本进程打开则 `switch-to-buffer` 跳转（同一文档在本进程
  唯一 buffer，与打开同一文件的行为一致），不新建——避免两个 buffer 抢同一
  `tmfs://collab/<doc_id>` URL。
- **删除 cloud 标志**：URL 化后 `tmfs://collab/` 已是「是否云文档」的单一特征，
  原 `tm_buffer_rep::cloud` 布尔标志冗余（改造前 URL 是 scratch 无法区分才需要）。
  `need_save` 改用 `is_rooted_tmfs(buf->buf->name,"collab")` 据 URL 判断（与 scheme
  `collab-buffer?` 同源），删除 `cloud` 字段及其在 `get_or_create` 的置位。

  buffer URL = `tmfs://collab/<doc_id>`，需 loro-server + `MOGAN_TEST_GUI=1`）

- 集成：先 `node tools/loro-server/server.js`，再
  `MOGAN_TEST_GUI=1 xmake r 7001_collab_url`
