### 3.2 非确定性测试（文档验证）
1. 点击 `插入`->`会话`，打开 Python 或 Julia 会话
2. 输入中文 “你好” 或其他一句话，字体应都为黑色，而不是第一个黑色，后几个棕色

## 4 What
在 Python 或 Julia 等插件的交互式会话中输入中文（例如“你好”）时，会出现高亮颜色不统一的异常：
- 第一个字（如“你”）显示为默认的常规颜色（黑色）
- 后续的字（如“好”）及整行其余内容全都被渲染为单行注释的颜色（棕色）

另外，本次 PR 重命名了插件路径 `TeXmacs/Plugins/julia/julia` 为 `TeXmacs/Plugins/julia/bin`，以便与 Python 插件的结构保持一致

## 5 Why
1. 在 TeXmacs/Mogan 中，非 ASCII 字符在内部采用 `tm-encoding`（如 “你” 编码为 `<#4F60>`，“好” 编码为 `<#597D>`）
2. 在语法高亮着色逻辑 `prog_language_rep::get_color` 中，扫描单行中的单行注释（inline comment）时，循环体内对扫描指针 `pos` 的自增采用的是简单的字节自增 `pos++`
3. 当扫描指针前进到 `<#4F60>` 内部第 3 个字节（即 `#`）时，由于 Python、Julia 等语言配置的单行注释开始字符是 `#`，导致其错误地触发了 `inline_comment_parser.can_parse` 并将其后续所有的字符全部渲染成了注释的颜色（棕色）

## 6 How
将单行注释扫描循环中按字节累加的 `pos++` 修改为支持 TeXmacs 字符宽度跳转的 `tm_char_forwards (s, pos)` 函数
这使得扫描指针只能在合法的 TeXmacs 字符（包括 `<...>` 标签）的边界上跳转，不会解析到 `<#4F60>` 内部的单个 `#` 字符
