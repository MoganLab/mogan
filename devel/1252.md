# 1252: 升级内置 Goldfish Scheme 到 v18.11.31

## 任务需求

将 Mogan 内置的 Goldfish Scheme 从 v18.11.29 升级到上游 v18.11.31。
参考 PR：[mogan#4393](https://github.com/MoganLab/mogan/pull/4393)（27→29 的覆盖式升级约定）。

## 现状分析

- 升级前 `GOLDFISH_VERSION` 为 `"18.11.29"`（`devel/0923.md`）。
- 内置路径：`TeXmacs/plugins/goldfish/`（`src/` + `goldfish/{scheme,liii,srfi}/`）。
- `goldfish/goldfish/`、`goldfish/texmacs/`、`tm-goldfish.scm` 为 mogan 本地文件，覆盖式升级不触碰。
- 上游 tag `v18.11.31` 相对 v18.11.29：
  - 版本号 bump 到 `18.11.31`；
  - 新增编译单元：`s7_scheme_cxr.c`、`s7_scheme_read.c`、`liii_string_cursor.cpp`（及对应头文件）；
  - JSON 继续下沉 C++，上游删除 `(guenchi json)`（`goldfish/guenchi/` 不再存在）；
  - Windows `load/read` 快路径、subprocess 管道修复、write 引擎拆分（见 goldfish v18.11.30 / v18.11.31）；
  - 上游另有 `3rdparty/curl-8.21.0`，mogan 已用自有 cpr 配方，不同步。
- `xmake/goldfish.lua` 显式枚举源文件，新增 `.c`/`.cpp` 必须登记。
- `bin/bump_goldfish` 仍拷向 `3rdparty/s7/`，与当前布局不符，未使用。

## What

1. 从 GitHub tag `v18.11.31` 源码包取出 `src/` 与 `goldfish/{scheme,liii,srfi}/`，覆盖 mogan 对应目录。
2. 删除已不存在于上游的 `goldfish/guenchi/`。
3. `xmake/goldfish.lua`：
   - `libgoldfish` 增加 `s7_scheme_cxr.c`、`s7_scheme_read.c`；
   - `goldfish` 增加 `liii_string_cursor.cpp`。
4. vendored 文件保持上游原格式，不按 `gf fmt` 重排。

## Why

与 0909/0914/0923 相同：覆盖式对齐上游 tag，避免漏带新拆分的 C/C++ 单元；不把 curl 源码树打进 mogan。

## How（本机验证）

- `xmake b goldfish-bin` 通过。
- `C:\goldfish-check\bin\goldfish.exe --version` → `Goldfish Scheme 18.11.31`（用户目录含中文时，直接跑插件目录下的 exe 会因窄路径找不到标准库，属运行路径问题，与本次升级内容无关）。
- `xmake b --jobs=1 stem` 通过，链接 `MoganSTEM.exe`。
- GUI 未跑（解释器内部升级，同 #4393）。
