# [0970] Velopack 多实例更新保护

## What

新增进程检测函数 `has_other_mogan_instances ()`（`src/Plugins/Updater/process_guard.{hpp,cpp}`），
并在更新触发的两个入口拦截，防止「实例 A 运行中、实例 B 启动或手动应用更新」时
Velopack 替换安装目录导致软件损坏：

1. **启动自动应用**（`src/Mogan/Research/research.cpp` 的 `VelopackApp::Run` 前）：
   检测到其他实例时 `SetAutoApplyOnStartup (false)`，只禁用本次自动应用，
   `Run ()` 照常执行（保留首装/卸载事件、更新后首启清理等钩子）。
2. **手动/切通道应用**（`src/Plugins/Updater/tm_velopack.cpp` 的 `applyUpdate` 入口）：
   检测到其他实例时置 `UPDATER_FAILED` + 错误信息返回 `false`，
   由 scheme 侧现有失败链路（`updater-error-code` → 阻塞确认弹窗）提示用户。

## Why

`WaitExitThenApplyUpdates` 的语义是更新器只等待**调用进程**退出（最多 60s）后即替换
安装目录。用户在实例 A 运行时双击可执行文件拉起实例 B，B 的 `VelopackApp::Run`
发现本地待应用包即拉起 Update.exe，等 B 退出后替换 `<root>/current/`，而 A 的
二进制仍锁着该目录下的文件，替换部分失败 → 安装损坏。

## How

### 1. 检测函数（`process_guard.{hpp,cpp}`）

平台 API 枚举进程 + 按「安装目录键」匹配（无状态方案，无锁文件残留/GC 问题）：

- **匹配键 `install_key`**：exe 完整路径规范化（小写、分隔符统一）后，
  - Windows：Velopack 布局 `<root>/current/<app>.exe`，取路径中 `/current/`
    之前的段（即安装根目录）；非该布局退化为完整路径本身。
  - macOS：bundle 布局 `<...>/<app>.app/Contents/MacOS/<app>`，取 `.app`
    之前（含）的 bundle 路径；非该布局退化为完整路径。
  - 不同安装位置（安装版 + 便携版）键不同，互不拦截——更新只替换自己
    安装根目录下的文件，跨安装位置的实例互不构成风险。
- **Windows 实现**：`CreateToolhelp32Snapshot (TH32CS_SNAPPROCESS)` +
  `Process32FirstW/NextW`，比较 `szExePath`（宽字符全程比较，正确处理
  中文等非 ASCII 安装路径）。
- **macOS 实现**：`proc_listallpids` + `proc_pidpath`。
- 排除自身 PID；读不到路径的进程（系统进程/无权限）跳过不误判。
- 该函数在 `lolly::init_tbox ()` 与 Qt 初始化之前被调用，只依赖系统 C API，
  不触碰 lolly 全局设施；内部用 std::string/std::vector（与 tm_velopack.cpp
  桥接层同理的例外）。

### 2. 拦截点

- `research.cpp`：`VelopackApp::Build ()` 后按检测结果调
  `SetAutoApplyOnStartup (false)` 再 `Run ()`。降级行为：本次不自动应用，
  用户关闭全部实例后下次启动正常应用（与「下次启动时应用」的既有承诺一致）。
- `tm_velopack.cpp::applyUpdate`：锁内检测，命中则
  `st = UPDATER_FAILED`、`error = "Another Mogan instance is running, close
  it before applying the update"`，返回 `false`。切通道链 poll 对 `st==6`
  已有失败弹窗（`updater-notify-failure`），无需 scheme 改动。
- `checkInBackground`/`downloadUpdate` 不拦：只写 packages 目录不替换
  current，且 Velopack 自带全局更新锁防并发下载。

### 3. 测试

`tests/Updater/process_guard_test.cpp`：

- 单实例：`has_other_mogan_instances ()` 返回 `false`；
- 拉起自身副本（子模式驻留数秒）：返回 `true`；副本退出后恢复 `false`
  （两处均带重试循环抗慢机抖动）。

### 4. 已知局限（残余风险）

- 检测是尽力而为的快照：检测与应用之间新开实例的窗口极小（apply 路径的
  检测就在 `WaitExitThenApplyUpdates` 紧前，启动路径在 `Run ()` 紧前）。
- Windows 下若另一实例以管理员运行而本实例非管理员，快照可能读不到其
  exe 路径而漏检（Toolhelp 权限限制），极罕见。
- Update.exe 重启的新实例不受影响：旧进程退出后才重启，且 Update.exe
  自身路径不是 Mogan exe，不计入。
