# [0970] Velopack 多实例更新保护

## 如何测试

单元测试（`xmake b process_guard_test && xmake r process_guard_test`，
覆盖非安装布局）见下文 How §3；安装版手动场景（单测无法构造 `/current/`
真实布局）按此流程：

**打包**。staging 源是 **install 产物**（`build/packages/stem/data`）而非
build 产物——只 `xmake b` 不 `xmake install` 会把旧 exe 打进包（2026-09-11
踩过：安装包里 grep 不到日志字符串，根因即漏 install）：

```
xmake b stem && xmake install stem       # 刷新 build/packages/stem/data
xmake l tools/release/stage_velopack.lua
xmake l tools/release/pack_velopack.lua  # vpk 拒绝重打同版本，先清 build/velopack_release
```

**安装后自检**：日志字符串编在二进制里，grep 计数应 > 0（0 = 打到了旧构建）：

```
grep -c process_guard <安装根>/current/MoganSTEM.exe                    # Windows
grep -c process_guard /Applications/MoganSTEM.app/Contents/MacOS/MoganSTEM  # macOS
```

**日志重定向**：守卫日志走进程 stderr（无缓冲，即写即现）。GUI 方式启动
（Windows 双击 / macOS `open`·Finder，经 launchd 不继承 stdio）stderr 被
丢弃——**被观测实例须从终端直接启动**：

- Windows（在安装根 `current/` 下，elvish/PowerShell/cmd 均可）：
  `MoganSTEM.exe 2> guard.log`
- macOS 直跑内层二进制（直接启动是正常运行方式，`$TEXMACS_PATH` 按
  exedir 相对解析）：`/Applications/MoganSTEM.app/Contents/MacOS/MoganSTEM 2> guard.log`

注意不要用 `xmake r` 验证：xmake 运行 GUI 子系统目标不透传标准句柄——
console 目标（process_guard_test）正常输出、GUI 目标静默丢失，极易误判为
代码未编进二进制。

**多实例场景**：干扰实例 Windows 直接再启动一份安装 exe；macOS 用
`open -n MoganSTEM.app`（`-n` 强制新实例）或再直跑一份内层二进制。被观测
实例用上述直跑 + 重定向。dev 构建直跑（无 `/current/`/`.app` 布局）键为
完整路径，与安装版互不误判，可用于验证「不同安装位置互不拦截」。

**期望输出**（键按平台走 `/current/` / `.app` 分支，路径已小写化）：

```
# Windows 安装版
process_guard: checking, install key "c:/users/<user>/appdata/local/mogan"
process_guard: no other instances                            # 单实例启动
process_guard: other instance pid=<A>, exe ".../current/moganstem.exe"
process_guard: auto-apply disabled for this session          # 启动拦截
process_guard: apply rejected, another instance is running   # apply 拦截
# macOS 安装版
process_guard: checking, install key "/applications/mogan stem.app"
```

## What

新增进程检测函数 `has_other_mogan_instances ()`（`src/Plugins/Updater/process_guard.{hpp,cpp}`），
并在更新触发的两个入口拦截，防止「实例 A 运行中、实例 B 启动或手动应用更新」时
Velopack 替换安装目录导致软件损坏：

1. **启动自动应用**（`src/Mogan/Research/research.cpp` 的 `VelopackApp::Run` 前）：
   检测到其他实例时 `SetAutoApplyOnStartup (false)`，只禁用本次自动应用，
   `Run ()` 照常执行（保留首装/卸载事件、更新后首启清理等钩子）。
2. **手动/切通道应用**（`src/Plugins/Updater/tm_velopack.cpp` 的 `applyUpdate` 入口）：
   检测到其他实例时置 `UPDATER_FAILED` + 错误信息返回 `false`，
   由 scheme 侧现有失败链路（`updater-error-code` → 阻塞确认弹窗）提示用户。

## Why

`WaitExitThenApplyUpdates` 的语义是更新器只等待**调用进程**退出（最多 60s）后即替换
安装目录。用户在实例 A 运行时双击可执行文件拉起实例 B，B 的 `VelopackApp::Run`
发现本地待应用包即拉起 Update.exe，等 B 退出后替换 `<root>/current/`，而 A 的
二进制仍锁着该目录下的文件，替换部分失败 → 安装损坏。

## How

### 1. 检测函数（`process_guard.{hpp,cpp}`）

平台 API 枚举进程 + 按「安装目录键」匹配（无状态方案，无锁文件残留/GC 问题）：

- **匹配键 `install_key`**：exe 完整路径规范化（小写、分隔符统一）后，
  - Windows：Velopack 布局 `<root>/current/<app>.exe`，取路径中 `/current/`
    之前的段（即安装根目录）；非该布局退化为完整路径本身。
  - macOS：bundle 布局 `<...>/<app>.app/Contents/MacOS/<app>`，取 `.app`
    之前（含）的 bundle 路径；非该布局退化为完整路径。
  - 不同安装位置（安装版 + 便携版）键不同，互不拦截——更新只替换自己
    安装根目录下的文件，跨安装位置的实例互不构成风险。
- **Windows 实现**：`CreateToolhelp32Snapshot (TH32CS_SNAPPROCESS)` +
  `Process32FirstW/NextW`，比较 `szExePath`（宽字符全程比较，正确处理
  中文等非 ASCII 安装路径）。
- **macOS 实现**：`proc_listallpids` + `proc_pidpath`。
- 排除自身 PID；读不到路径的进程（系统进程/无权限）跳过不误判。
- 该函数在 `lolly::init_tbox ()` 与 Qt 初始化之前被调用，只依赖系统 C API，
  不触碰 lolly 全局设施；内部用 std::string/std::vector（与 tm_velopack.cpp
  桥接层同理的例外）。

### 2. 拦截点

- `research.cpp`：`VelopackApp::Build ()` 后按检测结果调
  `SetAutoApplyOnStartup (false)` 再 `Run ()`。降级行为：本次不自动应用，
  用户关闭全部实例后下次启动正常应用（与「下次启动时应用」的既有承诺一致）。
- `tm_velopack.cpp::applyUpdate`：锁内检测，命中则
  `st = UPDATER_FAILED`、`error = "Another Mogan instance is running, close
  it before applying the update"`，返回 `false`。切通道链 poll 对 `st==6`
  已有失败弹窗（`updater-notify-failure`），无需 scheme 改动。
- `checkInBackground`/`downloadUpdate` 不拦：只写 packages 目录不替换
  current，且 Velopack 自带全局更新锁防并发下载。

### 3. 测试

`tests/Updater/process_guard_test.cpp`：

- 单实例：`has_other_mogan_instances ()` 返回 `false`；
- 拉起自身副本（子模式驻留数秒）：返回 `true`；副本退出后恢复 `false`
  （两处均带重试循环抗慢机抖动）。

### 4. 已知局限（残余风险）

- 检测是尽力而为的快照：检测与应用之间新开实例的窗口极小（apply 路径的
  检测就在 `WaitExitThenApplyUpdates` 紧前，启动路径在 `Run ()` 紧前）。
- Windows 下若另一实例以管理员运行而本实例非管理员，OpenProcess/
  QueryFullProcessImageNameW 可能读不到其完整路径；此时按存在处理
  （宁可误报推迟更新，不漏检损坏安装），日志表现为 same-name 行。
- Update.exe 重启的新实例不受影响：旧进程退出后才重启，且 Update.exe
  自身路径不是 Mogan exe，不计入。

### 5. 检测日志（stderr，2026-09-11 补充）

velopack 自身日志（`%LocalAppData%\velopack\velopack_Mogan.log`）只记录
Velopack 库自身执行的动作，不记录本进程内的守卫判定；且守卫运行于 lolly
初始化之前，无法使用项目 `cout`。故检测过程写 stderr（终端启动可见，GUI
启动不可见），统一 `process_guard:` 前缀便于 grep：

- `process_guard: checking, install key "<key>"`——检测入口，打印本进程
  的安装目录键（可直接验证 `/current/`、`.app` 键提取是否正确）；
- `process_guard: other instance pid=<pid>, exe "<path>"`——键匹配命中；
- `process_guard: same-name pid=<pid>, path unreadable, treated as other
  instance`——Windows 下同名但读不到路径的保守命中；
- `process_guard: no other instances`——遍历完毕未命中。

拦截点各补一行动作日志：`research.cpp` 打 `auto-apply disabled for this
session`，`tm_velopack.cpp` 打 `apply rejected, another instance is
running`。Windows 侧路径经 `to_utf8` 转换后输出，中文安装路径可读。
