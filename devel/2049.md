## 5 What

1. `generic-edit.scm` 中新增 `clipboard-tree-image?`：统一判断剪贴板 tree 是否为图像，覆盖两种结构：
   - 裸 `(image ...)`：`(tree-is? (tree-ref data 0) 'image)`
   - `with` 包裹的 image：`(tree-is? data 'with)` 且子节点 2 为 `'image`
   - 裸 `(image ...)`：`(tree-is? data 'image)`（直接匹配）
2. `ocr-paste`：使用 `clipboard-tree-image?` 替代原 `cond` 两个分支，并清理误导性的 `(not (null? (tree-ref data 2)))` 检查。
   - 增加 0-arg 包装器 `(tm-define (ocr-paste) (ocr-paste "image"))` 保持向后兼容
3. `paste-as-texmacs`：同样清理 `null?` 检查，保持与 `ocr-paste` 一致的判定风格。
4. `kbd-magic-paste`：
   - 在 `image*` 分支与 mode 分发之间新增 `texmacs-snippet` 前置分支
   - `texmacs-snippet` 分支内用 `clipboard-tree-image?` 判定：是 image 则 OCR；否则 `kbd-paste` 按内部格式粘贴
   - 为所有 `track-event` 调用恢复 `(defined? 'track-event)` 守卫，避免 telemetry 插件未加载时报错
5. 修正 `tree-ref` 下标偏移：所有从 `(clipboard-get "primary")` 取内容的位置，将下标 `1` 修正为 `0`。
   - `paste-widget.scm`、`math-edit.scm` 中的 `(ocr-paste)` 调用同样修正为 `(ocr-paste "image")`
6. 修正 `is-clipboard-image?` 中同样的下标偏移。

## 6 Why

### 6.1 问题现象

软件内选中内容（`Ctrl+C`）后用魔法粘贴（默认 `Ctrl+Shift+V`）：

- 普通文字：什么都不会粘贴
- 公式：被当作 LaTeX 文本重新解析，结果错乱
- 代码：被当作 code 重新解析，结果错乱
- 居中图片：不触发 OCR

### 6.2 根因

软件内 `Ctrl+C` 写入剪贴板的 mime 类型是 `application/x-texmacs-clipboard`，对应 `qt-clipboard-format` 返回 `"texmacs-snippet"`。原 `kbd-magic-paste` 没有专门分支，会落到 mode 分发：

- 数学模式：`clipboard-paste-import "latex"` → 把内部 tree 当 latex 文本解析
- 代码模式：`clipboard-paste-import "code"` → 把内部 tree 当 code 文本解析
- 文本模式：`smart-format-paste` → `paste-as-texmacs`，但普通内容没有 else 分支，静默什么都不做

同时，原 `ocr-paste` 只检查 `(tree-ref data 0)`，对 `with` 包裹的 image 直接拒绝。

### 6.3 为什么不在 smart-format-paste / paste-as-texmacs 里修

软件内复制最自然的行为就是普通粘贴。在 `kbd-magic-paste` 入口层拦截 `texmacs-snippet`，直接 `kbd-paste`，可以跳过所有 mode 分发与云端魔法粘贴校验。

### 6.4 为什么 ocr-paste 需要区分 source-format

软件内复制的 image tree 已经在 `clipboard-get "primary"` 的子树里；外部截图需要 `parse-texmacs-snippet` reparse。两种取 tree 的路径不同，所以加参数区分。

### 6.5 为什么传整个 with tree 给 ocr-to-latex-by-cursor

`ocr-to-latex-by-cursor` 内部通过扫描子节点定位 image。如果直接传 image 节点本身，子节点里没有 image，定位失败。所以传包含 image 的容器。

### 6.6 为什么恢复 track-event 守卫

`track-event` 定义在 `plugins/telemetry/progs/plugin/telemetry-track.scm`，不是全局必然存在的函数。mogan 主分支在未加载 telemetry 插件时，直接调用会报错。上游 PR #26 为简洁删掉了守卫，移植到 mogan 时需要恢复。

### 6.7 为什么 tree-ref 下标从 1 修正为 0

`(clipboard-get "primary")` 返回的 tree 结构为 `("texmacs", content, mode, lang)` 或 `("extern", s)`。在 Scheme 的 `tree-ref` 中，子节点索引是 0-based：

- `(tree-ref t 0)` = 第一个子节点 = content（或 s（extern 路径））
- `(tree-ref t 1)` = 第二个子节点 = mode（或 #f（extern 路径只有 1 个子节点））

上游 PR #26 中所有 `(tree-ref (clipboard-get "primary") 1)` 实际取到的是 mode 字符串（如 `"text"`）或 `#f`，导致 image 检测和 OCR 永远不触发。修正为下标 `0` 才能正确获取剪贴板的内容树。

## 7 How

### 7.1 新增统一图像判定 helper

```scheme
(define (clipboard-tree-image? data)
  (or (tree-is? data 'image)                                    ; 裸 image 树
      (and (tree? data) (tree-compound? data)
           (tree-is? (tree-ref data 0) 'image))                 ; snippet/document 包裹的 image
      (and (tree-is? data 'with)
           (tree-is? (tree-ref data 2) 'image))))               ; with 包裹的 image
```

### 7.2 ocr-paste 修正下标并使用 helper

```scheme
(tm-define (ocr-paste source-format)
  ...
  (with data
    (if (string=? source-format "texmacs-snippet")
        (tree-ref (clipboard-get "primary") 0)   ;; 修正：1→0，获取 content 而非 mode
        (parse-texmacs-snippet
          (tree->string (tree-ref (clipboard-get "primary") 0))))
    (when (clipboard-tree-image? data)
      (ocr-to-latex-by-cursor data))))

;; 0-arg 包装器保持向后兼容
(tm-define (ocr-paste) (ocr-paste "image"))
```

### 7.3 kbd-magic-paste 新增 texmacs-snippet 分支并恢复守卫

```scheme
(tm-define (kbd-magic-paste)
  (let ((source-format (qt-clipboard-format)))
    (cond ((string-starts? source-format "image")
           (ocr-paste "image")
           (when (defined? 'track-event)
             (track-event "OCR_RECOGNIZE" '(("mode" . "paste")))))
          ((string=? source-format "texmacs-snippet")
           (with data (tree-ref (clipboard-get "primary") 0)  ;; 修正：1→0
             (if (clipboard-tree-image? data)
                 (begin
                   (ocr-paste "texmacs-snippet")
                   (when (defined? 'track-event)
                     (track-event "OCR_RECOGNIZE" '(("mode" . "paste")))))
                 (begin
                   (kbd-paste)
                   (when (defined? 'track-event)
                     (track-event "MAGIC_PASTE" '(("mode" . "internal"))))))))
          (else
            ;; 原 mode 分发逻辑，所有 track-event 调用均保留守卫
            ...))))

## 8 补充修复：删除 account 插件残留的 ocr.scm

### What

删除 `TeXmacs/plugins/account/progs/liii/ocr.scm`。

### Why

[2048] OCR 代码迁移时把数据文件（`ocr.tex`、`ocr.md`、`md.tex`）从
`plugins/account/data/` 移到了 `plugins/ocr/data/`，但遗漏了删除
`plugins/account/progs/liii/ocr.scm`。

该文件与 `plugins/ocr/progs/liii/ocr.scm` 定义同一个模块 `(liii ocr)`。
`plugin_path("progs")` 使用文件系统 `readdir` 顺序，不保证确定性——
如果 `account/progs/` 先于 `ocr/progs/` 被搜到，加载的是 account 版本，
其中 `string-load` 引用已不存在的 `$TEXMACS_PATH/plugins/account/data/ocr.tex`，
模板文案插入失败。表现为社区版魔法粘贴触发 OCR 后，
`plugins/ocr/data/` 中设置好的文案不出现。

### How

直接 `git rm` 删除残留文件。

### 涉及文件

- `TeXmacs/plugins/account/progs/liii/ocr.scm`（删除）

## 9 补充修复：get-image 无法处理直接传入的图像树

### What

修改 `TeXmacs/plugins/ocr/progs/liii/ocr.scm` 中的 `get-image`，增加根节点为 image 的判定分支。

### Why

[2049] 修正 `tree-ref` 下标 1→0 后，`ocr-paste` 能正确获取剪贴板中的 image tree，
并传给 `ocr-to-latex-by-cursor`。但 `get-image` 的设计只扫描子节点，不检查根节点本身。
传入 `(image ...)` 时：

1. `(get-image t 0 #t)` 扫描子节点（tuple、宽度、高度等），找不到 `'image` → 返回 `#f`
2. `(get-image-extension #f)` → `(string-split #f #\.)` → 类型错误
3. `let*` 中的错误导致 `insert-latex-by-cursor` 永不执行
4. 用户看到：OCR 触发但 `ocr.tex` 中的文案不出现

上游 [0391] 修复的是 `(current-time)` 类型问题，未覆盖此场景——彼时 `ocr-paste`
的下标是 1，image 检测永远失败，`ocr-to-latex-by-cursor` 不会被调用，
`get-image` 的 bug 未被触发。

### How

在 `get-image` 开头增加 `(tree-is? t 'image)` 判定，为真时直接将 image tree
传给 `get-image-tuple`；否则走原扫描逻辑。

- `TeXmacs/plugins/ocr/progs/liii/ocr.scm`（修改 `get-image`）
```
