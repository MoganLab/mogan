# [0536] 修复软件内复制粘贴不稳定失败的问题

## 任务背景
在 Mogan 软件内进行复制粘贴时存在不稳定复现的失败情况，主要表现在 6 类典型场景：
1. 同一个文档内复制纯文本，粘贴发现没有复制成功
2. 同一个文档内复制结构（如章节、公式、表格），粘贴发现没有复制成功
3. 同一个文档内复制结构纯文本混排，粘贴发现没有复制成功
4. 文档内复制纯文本，新建一个草稿文档粘贴发现没有复制成功
5. 文档内复制结构，新建一个草稿文档粘贴发现没有复制成功
6. 文档内复制结构纯文本混排，新建一个草稿文档粘贴发现没有复制成功

在实际使用中，用户经常有连续多次按 `Ctrl+C` 的操作习惯，或在不同标签页之间频繁切换复制粘贴。

## 复现与验证
编写了自动化测试脚本 `TeXmacs/tests/python/clipboard_test.py`，使用 `D:\repositories\liii\arxiv\deepseek_v4.stem` 作为测试源：
- 严格控制变量：每次单步测试完毕后关闭并终止 MoganSTEM 进程，再启动全新的 MoganSTEM 进程。
- 测试结果：
  - 单次复制测试（1x Copy）：大部分正常，但在系统剪贴板受 Windows 监听进程锁定时也会因读取不到 PID 而偶发失败。
  - 连续复制测试（3x Copy）：**100% 稳定复现失败**，耗时从 3 秒暴增到 18 秒，剪贴板数据退化为 `(tuple "extern" "")`，后续粘贴无任何内容。

## 根本原因
1. **架构所有权判定倒挂**：
   `qt_gui_rep::get_selection` 中对主剪贴板 `key == "primary"` 的 `owns` 判定被硬编码依赖于从 Windows 剪贴板往返读取自定义 MIME 类型 `application/x-texmacs-pid`。
   一旦 Windows 剪贴板由于锁冲突、多重复制或外部监听程序未能及时返回该自定义 MIME，Mogan 便无视内存中完好保存的 `selection_t["primary"]`，强行退化为解析空的外部数据，生成 `(tuple "extern" "")`，导致粘贴静默失败。
2. **Windows OLE 剪贴板互斥锁与事件循环滞后**：
   连续复制或快速切换时，Qt 底层 `OleSetClipboard` 与 Windows 剪贴板监听服务（如 `cbdhsvc`）发生互斥锁争用，未调用 `processEvents` 导致剪贴板异步状态未能及时泵送，触发 Qt 重试循环与数据损坏。
3. **缺少 Qt 原生 `cb->ownsClipboard()` 接口判定**。
4. **缺少空剪贴板向本地内存缓存的回退安全机制**。
5. **废弃无用的 `cb->text(mode)` 产生额外的锁争用**，且缺少 `cb` 与 `md` 的非空防御。

## 修复改动
1. **`src/Plugins/Qt/qt_gui.cpp`**：
   - 在 `get_selection` 中引入 `cb->ownsClipboard()` 原生所有权判定。
   - 增加本地内存缓存安全回退网：当系统剪贴板无法提供有效数据（`buf.isEmpty()`）且本地 `selection_t` 存在对应数据时，直接信任并使用本地 AST 树，彻底根除跨标签页及连续复制下的静默丢失。
   - 在 `set_selection` 和 `get_selection` 适当时机泵送 `QCoreApplication::processEvents (QEventLoop::ExcludeUserInputEvents)`，消除异步 OLE 挂起。
   - 移除 `get_selection` 中未使用的 `originalText = cb->text(mode)`，消除冗余锁竞争。
   - 增加针对 `cb` 与 `md` 的防御性空指针校验，防止 Headless 及系统锁死时发生段错误。
