# [0538] 修复文件关闭后侧边栏仍处于打开状态的问题

## What

1. 修复文档标签页关闭时侧边栏未关闭、导致打开其他文件仍然能看到侧边栏打开的问题。
2. 当用户关闭当前正在显示的文档标签页时，侧边栏状态立即置为关闭，并清空侧边栏记忆。
3. 当关闭标签页导致当前窗口中不再有任何普通文档时，重置侧边栏状态与记忆为关闭。
4. 提供基于 `pynput` 框架的端到端自动化 UI 测试脚本（使用 `uv` 运行）。

## Why

在之前的实现中（`0184` 状态记忆引入）：
1. 侧边栏状态（`chatSidebarMode` / `chatSidebarModeMemory_`）保存在 `qt_tm_widget_rep` 中，为窗口全局状态。
2. 当文档处于侧边栏打开状态时，用户关闭该文档：
   - 多文档场景：关闭当前文档后自动切换到下一个文档，但 `chatSidebarMode` 仍为 `true`，侧边栏 dock 未关闭，导致在下一个文档中仍然看到打开的侧边栏。
   - 单文档场景：关闭当前文档后切换到首页（Startup Tab），`sync_startup_tab_mode()` 虽隐藏了 dock，但将 `chatSidebarModeMemory_` 记录为 `true`。之后用户在首页新建或打开其他文件时，`sync_startup_tab_mode()` 切回文档分支自动将侧边栏重新打开（`chatSidebarMode = true`）。
3. 用户的心理模型是侧边栏附属或服务于当前文档的编辑会话；当文件关闭后，侧边栏状态应当随之关闭，不应在后续打开其他文件时残留打开状态。

## How

1. **`qt_tm_widget_rep` (`src/Plugins/Qt/qt_tm_widget.hpp/.cpp`)**：
   - 新增 `reset_chat_sidebar()` 方法：将 `chatSidebarMode` 和 `chatSidebarModeMemory_` 均重置为 `false`，并调用 `sync_chat_sidebar_mode()` 隐藏侧边栏 dock，恢复普通界面布局与浮动按钮状态。
2. **`cpp_kill_tabpage` (`src/Plugins/Qt/QTMTabPage.cpp`)**：
   - 在关闭当前显示的文档标签页（`is_current` 为 `true` 且非特异标签页）时，调用对应窗口的 `tmw->reset_chat_sidebar()`。
   - 在 `kill_tabpage` 完成后，若窗口中不再有任何普通文档（只剩首页/Chat），同样调用 `reset_chat_sidebar()` 清理残留记忆。
3. **`kill_tabpage` (`src/Texmacs/Data/new_view.cpp`)**：
   - 在核心层 `is_current` 分支 detach 前，调用 `win->set_chat_sidebar_flag (false)`，向窗口发送 `SLOT_CHAT_SIDEBAR_VISIBILITY` 关闭侧边栏，作为通用防线。
   - 若关闭后窗口内已无普通文档，同样调用 `win->set_chat_sidebar_flag (false)` 清理记忆。
4. **测试**：
   - 编写 `TeXmacs/tests/python/0538.py` 自动化端到端测试脚本，搭配 `pynput` 模拟用户按键操作：
     - 单文件场景：创建草稿 1 -> 打开侧边栏 -> 关闭草稿 1 -> 创建草稿 2 -> 验证侧边栏处于关闭状态。
     - 多文件场景：创建草稿 1、草稿 2 -> 打开侧边栏 -> 关闭当前草稿 -> 验证切换后的草稿侧边栏处于关闭状态。
