# [1124] 把 lua glue codegen 从 on_config 迁到标准 xmake rule

## 背景

mogan 用 lua 声明文件（`src/Scheme/**/glue_*.lua`，约 20 个）+ 生成器
`src/Scheme/Glue/build_glue.lua` 生成 C++ glue cpp。

现有入口在 `xmake.lua:169-193` 的 `build_glue_on_config()`，挂在主 target 的
`on_config` 阶段，自己做 `for` 循环 + 手写 `depend.on_changed`，产物写到
`$(builddir)/glue/<name>.cpp`。诊断出的若干问题：

1. **产物未显式进 `add_files`**：`on_config` 阶段写文件，但主 target 的
   `add_files` 没列出生成的 cpp，依赖链接器兜底找符号，机制脆弱。
2. `os.mkdir` 在 `for` 循环之后（xmake.lua:191），顺序逻辑错。
3. 增量靠手写 `depend.on_changed`，`values={true}` 是无意义噪声；build_glue.lua
   若再 import 别的 lua 模块不会触发重生成；无并行。
4. 无错误处理。
5. `cprint` 用了非标准 token `${text.success}`，渲染成字面字符串。

详细诊断见 `~/git/xmake-lua-codegen/INVESTIGATION.md`，
已验证的标准 codegen rule 范本见 `~/git/xmake-lua-codegen/rules/gluegen.lua`。

## 任务相关的代码文件

- `xmake.lua`（删除 `build_glue_on_config` 函数和调用、调整 `add_files`/`add_includedirs`）
- `xmake/rules/glue.lua`（**新增**：`rule("mogan.glue")`）
- `src/Scheme/Glue/build_glue.lua`（生成器本体，**不改**，`main(glue, glue_name)` 签名复用）
- `src/Scheme/**/glue_*.lua`（声明文件，**不改名**，用 `{rule=...}` 显式绑定）

## 落地方案

### 决策

- **生成器调用**：保留 `import build_glue` 直调 `main(glue_table, glue_name)`，
  不改成 CLI 子进程。`build_glue.lua` 加 standalone 分支。
- **产物路径**：迁到 `target:autogendir()/glue/`（标准 `.gens/<target>/glue/`）。
- **声明文件不重命名**：保持 `glue_*.lua`，用
  `add_files(..., {rule="mogan.glue"})` 显式绑定
  （`set_extensions(".glue.lua")` 双扩展 xmake 不认）。
- **双模式渐进迁移**：声明文件加 `standalone = true` 标志切换独立编译单元
  模式；默认仍是文本包含（`#include "glue_xxx.cpp"`）。本任务先迁
  `glue_lolly` 作为样板，其余 glue 保持文本包含留作后续任务。

### 双模式设计

**文本包含模式（默认，现状）**：
- 产物放到 `includedirs` 暴露的目录，供源文件 `#include "glue_xxx.cpp"`
  文本包含。
- 不进 `target:objectfiles()`。
- 缺点：所有 `init_glue_*.cpp` 编译依赖整个 glue 目录，任一 glue 改动
  触发全部 `init_glue_*.cpp` 重编（增量粒度粗）。

**独立编译模式（`standalone = true`）**：
- 声明文件提供 `includes` 列表，生成器把 `#include` 前缀拼到产物顶部。
- 产物作为独立编译单元注入 `target:objectfiles()`，参与链接。
- 源文件不再 `#include "glue_xxx.cpp"`，穿插函数挪到独立 header。
- 优点：增量粒度到单文件，符合 xmake 标准 codegen 模式（参考
  `~/git/xmake-lua-codegen/rules/gluegen.lua`）。

### `xmake/rules/glue.lua`

`on_buildcmd_file` 里 `import` 声明后检查 `glue_table.standalone`：
- `true`：注入 objectfiles + compile。
- `false`：只写产物 + `set_depmtime`/`set_depcache`。
`on_load` 里统一把 `autogendir/glue` 加进 includedirs。

### `build_glue.lua`

产物拼接时若 `glue.standalone`，把 `glue.includes` 列表拼成
`#include "..."`（普通）/ `#include <...>`（以 `<` 开头）前缀。

### `glue_lolly` 样板迁移

- `glue_lolly.lua` 加 `standalone = true` 和 `includes` 列表
  （`object_l1/l2.hpp`、`s7_tm.hpp`、`analyze.hpp`、`file.hpp`、`url.hpp`、
  `tree.hpp`、`scheme.hpp`、6 个 lolly 头、`glue_l2_extra.hpp`）。
- `init_glue_l2.cpp`：删 `#include "glue_lolly.cpp"`；穿插函数
  （`blackboxP`/`treeP`/`urlP`/`url_ref`/`lolly_version`/`http_status_code`）
  挪到新 header `glue_l2_extra.hpp`，init_glue_l2.cpp 和生成的
  glue_lolly.cpp 都 include 它。
- `init_glue_l2.hpp` 加 `void initialize_glue_lolly ();` 前向声明
  （因为 glue_lolly 现在是独立编译单元，符号不再由文本包含可见）。

## 如何测试

### 1. 全量构建

```bash
xmake f -m release && xmake b stem
```

预期：
- 看到 `generating.glue src/Scheme/.../glue_basic.lua` 等进度行。
- `build/.gens/stem/<plat>/<arch>/<mode>/glue/` 下出现约 20 个 `.cpp`。
- 这些 cpp 被编译成 object 并链进 libmogan/stem。

### 2. 增量

```bash
touch src/Scheme/Glue/glue_basic.lua && xmake b stem
```
预期：只重生成 `glue_basic.cpp` 并重编，其他不动。

```bash
touch src/Scheme/Glue/build_glue.lua && xmake b stem
```
预期：所有 glue cpp 全部重生成（因为 `add_depfiles` 把 build_glue.lua 列为依赖）。

### 3. 链接符号完整性（最关键）

```bash
nm build/<plat>/<arch>/<mode>/libmogan.so 2>/dev/null | grep tmg_ | wc -l
```
预期：能看到大量 `tmg_*` 符号（`build_glue.lua` 里 `translate_name` 加的前缀）。
如果符号比改造前少，说明 object 注入失败。

### 4. 运行

```bash
xmake r stem
```
预期：TeXmacs 正常启动，scheme 函数能调（说明 glue 注册成功）。

## 链接错误修复（本分支 `da/1124/2fix`）

### 现象

`xmake b view_history_test`、`xmake build --group=tests` 报 multiple
definition：

```
new_view.cpp:(.text+0x1f10): multiple definition of `view_to_window_of_tabpage(url)';
  view_history_test.cpp:(.text+0x40): first defined here
new_window.cpp:(.text+0x26a0): multiple definition of `get_current_window()';
  view_history_test.cpp:(.text+0x20): first defined here
```

### Why

`tests/Data/view_history_test.cpp` 为了在 headless 环境测 `view_history`，
自己 mock 了 `get_current_window` 和 `view_to_window_of_tabpage` 两个全局
函数。但这俩函数在主库里也有定义
（`src/Texmacs/Data/new_window.cpp:176`、`src/Texmacs/Data/new_view.cpp:199`），
测试链接 `libmogan.a` 后两个强符号相遇，链接器拒绝。

这个 mock 从 commit `63dbfeb5d`（[201_6] 引入 `view_history`）起就一直
冲突，但只有当 `xmake b view_history_test` 被实际触发时才暴露。本分支
上下文里 #3838 的 glue 改动扩大了被链入的对象集，把这个潜在链接错误
正式带进 build。

### How

把测试里的两个 mock 函数改成 `inline`。`inline` 后编译器把符号放进
COMDAT group，链接器允许多个 TU 提供同名 inline 定义并合并，
multiple definition 错误消失。改动只在测试文件，主库代码不动，
跨平台兼容（不像 `__attribute__((weak))` 只在 GCC/Clang 上可用）。

代价：mock 不能渗透到 `libmogan.a(view_history.cpp.o)` 内部对这两个
函数的调用（那一份是非 inline 调用，编译期已绑定主库实现），所以
原 `test_get_views_for_window` 用例在运行期会失败
（headless 下真实 `view_to_window_of_tabpage` 对伪 view URL 返回
`url_none()`，窗口过滤拿不到预期结果）。这是该测试本身 mock 策略
不彻底导致的，属历史遗留。本次直接移除该用例，其余 8 个用例全部
通过；要测窗口过滤逻辑得在真实 GUI 环境跑（参考
`TeXmacs/tests/*.scm` 的 `add_target_integration_test`）。

### 涉及文件

- `tests/Data/view_history_test.cpp`：两个 mock 函数加 `inline`；
  移除 `test_get_views_for_window` 用例（slot 声明 + 实现）

### 验证

```bash
xmake b view_history_test          # 链接通过
xmake r view_history_test          # 9 passed, 0 failed
xmake build --yes --group=tests    # 整组 build ok
```
