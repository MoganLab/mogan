## 2026/09/14 实现 SemVer 2.0 规范解析与比较模块

### What（本次改动做了什么）

实现纯 Scheme 的语义化版本（Semantic Versioning 2.0.0）解析与比较模块 `(utils misc semver)` 及全套单元测试 `semver-test`：
1. **清洗与校验**：
   - `semver-clean`：去除首尾空白字符，容错剥离前导 `v` 或 `V`；
   - `semver-valid?`：校验版本字符串是否满足 SemVer 规范；
   - `semver-parse`：解析版本为 `(semver core-nums pre-list)` 结构，非法返回 `#f`。
2. **比较与谓词**：
   - `semver-compare`：按 SemVer 2.0.0 规范返回 `-1`、`0`、`1`（任一输入非法返回 `#f`）；
   - 提供 `semver>?`、`semver<?`、`semver=?`、`semver>=?`、`semver<=?` 谓词。
3. **严格遵循 SemVer 2.0.0 优先级规范**：
   - 剥离构建元数据（`+` 后的 build metadata），不影响版本优先级比较；
   - 核心段（core）按点号分割逐段数值比较；
   - 核心段相同时，无预发布段的版本优先级高于有预发布段的版本（如 `2026.3.2 > 2026.3.2-rc.1`）；
   - 预发布标识符按点号分割逐段比较：纯数字标识符按数值大小比较（防止 `rc.10` 与 `rc.2` 字典序倒挂）、纯数字低于非纯数字、非纯数字按 ASCII 字典序比较、标识符数量多者优先级高。
4. **单元测试**：
   - 新增 `TeXmacs/progs/utils/misc/semver-test.scm`，46 项断言覆盖 SemVer 2.0 规范示例链条、字典序与数值陷阱、前后空格与前缀容错等。

### Why（为什么这么做）

1. 客户端在进行版本检查、自动更新以及通道切换判断时，需要严谨规范的版本比对逻辑；若单纯使用字符串比较或旧式 path 比较，会导致诸如 `2026.3.2-rc.1` 与 `2026.3.5` 比较倒挂、`rc.10` 低于 `rc.2`、以及无法忽略构建元数据等问题；
2. 作为纯 Scheme 基础模块提供，无 C++ 或外部系统依赖，跨平台全环境秒级可用。

### How（怎么做的）

1. 在 `TeXmacs/progs/utils/misc/semver.scm` 中定义 `(texmacs-module (utils misc semver))`；
2. 内部实现字符与数字判定、构建元数据与预发布段切分、纯数字/非纯数字标识符分类；
3. 按照 SemVer 2.0.0 规范第 11 条实现完整的优先级三级比较算法；
4. 编写 `TeXmacs/progs/utils/misc/semver-test.scm` 并通过 `regtest-semver` 接入项目单元测试套件。

### 如何测试
