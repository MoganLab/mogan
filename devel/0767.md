## 5 What

1. **CRDT 反查**：维护 `rev_id_map`（TreeID→buffer 相对 path），与 `id_map` 在
   `seed_node` / `sync_walk` / `decode_id_node` 三处同写、在 `sync_id_map_from_shadow`
   / `import_and_build` 重置处同清——维护点与 `id_map` 一模一样，故始终与当前 buffer
   一致。`cursor_path_of` 经它 O(1) 解析 TreeID+偏移为 path；节点未找到返回 nil（优雅跳过）。
2. **位置编解码（只传 id，不传 path）**：上传端把光标 path 解析到其所在**节点**，
   上传该节点的 TreeID + 节点内稳定偏移——原子节点上传 `(node_id, LoroText 字符偏移)`
   （字符偏移即 CRDT 文本位置）；**复合节点上的子位置下钻到该子节点、上传 `(child_id, 0)`，
   不传 mogan 树子索引**。线上格式 `peerhex:counter:offset`（peer 为 u64 的 16 位 hex）。
   接收端 `cursor_path_of` 经 `rev_id_map` 把 id 解析回 path + 偏移。全程以 id 为主，
   保证 CRDT 级稳定。payload = 插入符+选区起止三组。
3. **捕获**：`notify_cursor_moved` / `select` 经 `collab_cursor_moved_hook`（带 applying 守卫）把「当前 buffer 的会话」标脏。
4. **传输**：`poll()` ≥50ms 节流发 `CURSOR <peer> <payload>`；**编辑上行后 `broadcast_to_server` 立即 `flush_cursor` 补发**（绕过节流），使光标更新紧随编辑、同 WS 有序到达对端——否则编辑即时到、光标被节流滞后，远程光标会短暂落在新插入文本之前（如 `Line 1|test`）。鼠标移动无并发编辑，节流即可。服务端 `broadcast` 原样转发；瞬态，断线不缓冲。
5. **接收/渲染**：`on_message` 解析后 `set_remote_cursor` 存储；`draw_post` 每次重绘经 `get_remote_cursors` 解析回当前 path，画彩色 caret + 选区高亮，颜色按 peer 哈希取调色板。

## 6 Why

0759/0768 已同步**文档内容**，但看不到其他协作者的光标/选区，无法判断别人在编辑哪里。多光标让每个客户端实时看到所有协作者的当前位置与选区，是协作编辑的基础体验。

位置表示选 **TreeID+偏移**（而非裸 path）：裸 path 是子节点索引，并发插入下会漂移；TreeID 是 CRDT 稳定身份。上传时只传 id——原子节点传 `(node_id, LoroText 字符偏移)`、复合节点传 `(child_id, 0)`，不传 mogan 树子索引，故结构位置也由 id 精确定位（`correct_cursor` 仅对失效 path 兜底夹取）。

## 7 How

- **分层**：传输层（`collab_session`）只搬运不透明的 `CURSOR <peer> <payload>` 文本帧，从不接触 `mogan_tree_id`；所有 CRDT 位置编解码集中在编辑器层（`edit_modify`/`edit_collab`）。故编辑器新增虚接口只含 `string`/`path`，无需 `#ifdef LORO_ENABLED`，非 LORO 构建下为空实现。
- **跨 aspect**：远程光标存于 `edit_modify_rep`，渲染在 `edit_interface_rep::draw_post`，沿用 `selection_get` 的虚函数跨 aspect 访问模式；`get_remote_cursors` 在 edit_modify 内即时把 TreeID 解析为当前 path 返回，渲染层只画。
- **稳定性来源**：维护与 `id_map` 完全同处的反向表 `rev_id_map`（TreeID→buffer 相对
  path）——在 `seed_node` / `sync_walk` / `decode_id_node` 三处与 `id_map` 一起写入、
  在 `sync_id_map_from_shadow` / `import_and_build` 一起重置，维护点一模一样，故始终
  与当前 buffer 一致。`cursor_path_of` 经它 O(1) 解析（再追加偏移），达成 CRDT 级稳定。

## 8 已知边界 / 后续

- 无名字标签、无 presence（加入/离开）——按本次决策只画 caret+选区。
- 结构位置已由 child_id 精确定位（不再传子索引）；仅**同一文本节点内的并发编辑**会使字符偏移（整数索引）短暂漂移——Loro 真正的 stable-position（按 op id）未在 FFI 暴露，当前整数偏移是可达上限，下个光标帧即自纠。
- `rev_id_map` 与 `id_map` 一同维护，内存约为节点数 ×2（两表）；极端超大文档可考虑惰性/按需构建以省内存。
- 仅覆盖 native（Qt）：`loro_collab_poll` 当前只在 `qt_gui.cpp` 挂钩；WASM 需另接帧循环。
