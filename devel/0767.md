## 5 What

1. **CRDT 反查**：`cursor_path_of` 在当前 buffer 树遍历匹配 TreeID，返回 path 并追加偏移；节点未找到返回 nil（优雅跳过）。
2. **位置编解码**：path 的包含节点（`path_up`）经 `get_id` 得 TreeID，末位 `last_item` 为偏移；线上格式 `peerhex:counter:offset`（peer 为 u64 的 16 位 hex，规避 lolly 无 64 位整数字符串转换）。payload = 插入符+选区起止三组。
3. **捕获**：`notify_cursor_moved` / `select` 经 `collab_cursor_moved_hook`（带 applying 守卫）把「当前 buffer 的会话」标脏。
4. **传输**：`poll()` ≥50ms 节流，发 `CURSOR <peer> <payload>` 文本帧；服务端 `broadcast` 原样转发；瞬态，断线不缓冲。
5. **接收/渲染**：`on_message` 解析后 `set_remote_cursor` 存储；`draw_post` 每次重绘经 `get_remote_cursors` 解析回当前 path，画彩色 caret + 选区高亮，颜色按 peer 哈希取调色板。

## 6 Why

0759/0768 已同步**文档内容**，但看不到其他协作者的光标/选区，无法判断别人在编辑哪里。多光标让每个客户端实时看到所有协作者的当前位置与选区，是协作编辑的基础体验。

位置表示选 **TreeID+偏移**（而非裸 path）：裸 path 是子节点索引，并发插入下会漂移；TreeID 是 CRDT 稳定身份，文本内偏移由 Loro text CRDT 保证稳定，结构边界 best-effort（`correct_cursor` 夹取）。

## 7 How

- **分层**：传输层（`collab_session`）只搬运不透明的 `CURSOR <peer> <payload>` 文本帧，从不接触 `mogan_tree_id`；所有 CRDT 位置编解码集中在编辑器层（`edit_modify`/`edit_collab`）。故编辑器新增虚接口只含 `string`/`path`，无需 `#ifdef LORO_ENABLED`，非 LORO 构建下为空实现。
- **跨 aspect**：远程光标存于 `edit_modify_rep`，渲染在 `edit_interface_rep::draw_post`，沿用 `selection_get` 的虚函数跨 aspect 访问模式；`get_remote_cursors` 在 edit_modify 内即时把 TreeID 解析为当前 path 返回，渲染层只画。
- **稳定性来源**：不维护反向映射表（增维护成本），而是在每次重绘按需 `cursor_path_of` 遍历——因 `id_map` 每次 `apply_remote` 后由 `sync_id_map_from_shadow` 刷新，结果始终反映当前 buffer；O(n)/peer/重绘，少量 peer 足够。

## 8 已知边界 / 后续

- 无名字标签、无 presence（加入/离开）——按本次决策只画 caret+选区。
- 结构边界光标（复合节点子索引）在并发结构性插入下可能漂移；文本内光标完全稳定。
- `cursor_path_of` 为 O(n) 按需遍历；文档极大且 peer 多时可改在 `sync_walk`/`seed_node`/codec 建 `hashmap<mogan_tree_id,path>` 反向表做 O(1)。
- 仅覆盖 native（Qt）：`loro_collab_poll` 当前只在 `qt_gui.cpp` 挂钩；WASM 需另接帧循环。
