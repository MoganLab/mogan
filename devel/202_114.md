## 2026年4月20日 调整 membership 提醒窗口与按钮，迁出 update/guest 通知项

### What
1. `membership-renew-soon` 的触发窗口从到期前 `0~3` 天调整为到期前 `0~7` 天。
2. 临期会员文案同步更新为 `Your membership will expire within 7 days. Renew early for more savings`。
3. `membership-renew-soon` 通知条新增 `Remind later` / `稍后提醒` 按钮。
4. 点击 `Renew Early`、`Remind later` 或关闭 `×` 都会写入 renew-soon 的 1 天静默记录；本次会话内也会隐藏该提示。
5. 行为含义：进入到期前 7 天窗口后，若用户不处理，该通知项会保持激活；若用户点击 `Remind later` 或关闭 `×`，则按 1 天静默记录控制，通常每天最多重新提醒一次。
6. `membership` 过期通知条新增 `Remind later` / `稍后提醒` 按钮，点击后写入 membership 的 7 天静默记录。
7. 当前 SCM 顶部通知条移除 `update` 和 `guest` 两类展示项；版本更新/访客相关支撑代码保留，后续迁移到新的展示位置。

## 2026年4月15日

### What
新增统一的顶部 SCM 通知条，并将会员临期续费、会员过期两类提示状态同步到这一套通知条逻辑中。

### 功能特性
1. **新增 SCM 顶部通知条通路** - 从 Scheme 菜单生成通知条内容，经 `SLOT_NOTIFICATION_BAR` 传递到 Qt 窗口显示
2. **通知项轮播框架** - 根据当前激活状态，在会员临期提示、会员过期提示之间按 5 秒轮播；当前两类会员提示通常互斥
3. **状态同步** - Qt 原生提示条与 SCM 通知条共用同一份业务状态
4. **会员提示** - 登录后后台刷新会员信息，在 7 天内到期时展示提前续费提醒，过期时展示查看会员方案入口

### 提示显示判定逻辑

SCM 顶部通知条会先收集当前所有激活项，再按数量决定是否轮播：

```text
Qt/Scheme 更新状态
    ↓
收集激活项：
  - membership-renew-soon
  - membership
    ↓
count = 激活项数量
    ↓
count <= 1  ──→ 固定显示当前项
count > 1   ──→ 每5秒按 index 轮播
```

**各提示项激活条件：**

| 提示项 | 激活条件 |
|--------|----------|
| `membership-renew-soon` | 有会员数据、不是免费用户，且 `periodLabel` 可解析为实际到期日期，并满足 `0 <= 到期日 - 今天 <= 7`，同时未处于 1 天静默期 |
| `membership` | 有会员数据、不是免费用户，且 `periodLabel` 可解析为实际到期日期，并满足 `到期日 < 今天`；若日期无法解析，则兼容回退到旧的 `productType != "Renew Early"` 逻辑，同时未处于 7 天静默期 |

**免费用户判定：**

```text
memberType == "Regular User"
periodLabel == "Non-member"
```

### UI 行为
1. **会员临期提示**
   - 使用固定帮助式文案，不展示动态剩余天数
   - 主按钮固定为 `Renew Early`
   - 额外显示 `Remind later` / `稍后提醒` 按钮
   - 点击 `Renew Early`、`Remind later` 或关闭 `×` 后静默 1 天
   - 在到期前 7 天窗口内，未静默时保持激活；用户处理后通常每天最多重新提醒一次
2. **会员过期提示**
   - 使用固定帮助式文案，不拼接 `periodLabel`
   - 主按钮固定为 `View plans`
   - 额外显示 `Remind later` / `稍后提醒` 按钮
   - 点击 `View plans`、`Remind later` 或关闭 `×` 后静默 7 天

### Why
之前顶部通知能力分散在多个 Qt 提示条里，Scheme 菜单层没有统一的通知入口。这次把会员通知条链路打通后，后续新增会员相关提示类型会更容易扩展。

### How
1. 在窗口消息系统里新增 `SLOT_NOTIFICATION_BAR`，打通 `server -> tm_frame -> tm_window -> qt_tm_widget` 的通知条传输通路
2. 新增 `QWK::NotificationBar` 作为 SCM 菜单驱动的 Qt 外壳，用来承载菜单生成的 QLabel / QPushButton 内容
3. 在 `notificationbar.scm` 中维护两类会员通知状态，并通过 `notification-bar-active-items` 和 `notification-bar-current-item` 控制显示
4. 在 `qt_tm_widget.cpp` 中将会员信息同步到 Scheme 层，同时继续兼容原有 Qt 提示条
5. 会员临期与过期提示分别使用独立静默 key，并优先基于 `periodLabel` 的实际日期计算；当日期格式无法解析时，再回退到旧的 `productType` 逻辑
