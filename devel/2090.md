# [2090] 设置文档背景图片的功能有问题

## 任务相关的代码文件
- src/Graphics/Renderer/brush.cpp
- src/Graphics/Renderer/renderer.cpp
- TeXmacs/progs/generic/pattern-selector.scm
- TeXmacs/progs/kernel/gui/menu-define.scm

## 2026/08/04 修复三个导致背景图片功能失效的 bug

### What
1. brush.cpp: `make_brush` 校验过严（`N(p)!=4` 改为 `N(p)<3`），误拒合法的
   3 子节点 pattern，导致所有背景图片不渲染；同时修正 `p[3]` 作为颜色名
   读取时的类型守卫。
2. renderer.cpp: `clear_pattern` 高度空值检查索引错误（`pattern[1]` 改为
   `pattern[2]`），修正用户指定高度被忽略的问题。
3. Windows 路径序列化损坏：`pattern-selector.scm` 的 `url->unix` 在 Windows
   上对盘符路径丢失冒号，改用 `url->system` 保留完整路径；`menu-define.scm`
   的 `tm-pattern` 统一用 `liii-path` 的 `path-as-posix` 将反斜杠转正斜杠，
   避免偏好持久化时序列化/反序列化不对称导致 Ok 按钮卡死和路径损坏。

### Why
背景图片功能在以下场景失效：带背景 pattern 的文档无法渲染背景、用户指定
的背景高度被忽略、Windows 下设置/保存背景路径时 Ok 按钮卡死。

### How
- `make_brush` 放宽 pattern 子节点数量校验，并对颜色名读取做类型守卫。
- `clear_pattern` 修正高度字段的空值检查索引。
- 路径统一走 `url->system` + `path-as-posix`，保证 Windows 盘符保留且
  序列化链路中不出现反斜杠。

## 如何测试

### 文档测试（推荐）
打开 `TeXmacs/tests/tmu/2090.tmu`，应看到：
- 第一段文本带 neutral 图案背景（`neutral-pattern.png`）
- 第二段文本带纸纹图案背景（`paper-ridged-bright.png`）
- 背景图案正常渲染（修复前 3 节点 pattern 会被 `make_brush` 拒绝，完全不显示）

### 手动测试
1. 新建文档，菜单 Document → Colors → Background → Pattern，选择内置
   neutral 图案，确认整页背景渲染。
2. 菜单 Document → Colors → Background → Picture，选择任意图片文件
   （如 PNG），确认：
   - 预览中图片可见（修复前 Windows 下预览不可见）
   - 背景生效
3. 保存文档后重新打开，背景保持。
4. Windows 下：偏好设置中 "my pictures" 的路径应为正斜杠
   （如 `C:/Users/...`，而非 `C:\Users\...`），Ok 按钮不再卡死。
