# [1109] 将 lolly 作为 xmake 子模块接入顶层构建

## 1 相关文档
- [dddd.md](dddd.md) - 任务文档模板

## 2 任务相关的代码文件
- `xmake.lua` — 顶层构建配置
- `xmake/vars.lua` — 全局构建变量
- `xmake/tests.lua` — C++ 测试目标生成函数
- `moebius/xmake.lua` — moebius 子模块构建配置
- `lolly/xmake.lua` — lolly 子模块构建配置
- `xmake/packages/l/lolly/xmake.lua` — 待删除的本地 lolly package 定义

## 3 如何测试

### 3.1 确定性测试（单元测试）

lolly 子模块的测试目标默认不生成，需要在配置时显式开启：

```bash
xmake config --yes --enable_tests=true
```

构建 lolly 子模块：

```bash
xmake build liblolly
```

构建并运行 lolly 单元测试：

```bash
xmake build lolly_tests
xmake test "lolly_tests/*"
```

也可以直接运行测试二进制：

```bash
xmake run lolly_tests
```

顶层构建并运行全部测试（包括 lolly 测试）：

```bash
xmake config --yes -vD --enable_tests=true
xmake build liblolly
xmake build libmogan
xmake build stem
xmake test
```

> 注：`lolly_tests` 已临时排除依赖外部网络的 `lolly/io/http_test`，其余用例应全部通过。

仅运行 lolly 测试时，不需要构建 `libmogan` 和 `stem`。

### 3.2 非确定性测试（文档验证）

1. 确认 `xmake show --targets` 中 `liblolly`、`lolly_tests`、`lolly_bench_base` 等 target 无重名冲突。
2. 确认 `libmogan` 和 `stem` 能正常编译，说明 lolly 头文件路径已通过 `{public = true}` 正确传递。

## 4 如何提交

提交前执行以下最少步骤：

```bash
xmake config --yes -vD --enable_tests=true
xmake build liblolly
xmake build libmogan
xmake build stem
xmake test
```

## 5 What

将 lolly 从 `3rdparty/lolly/` 的 vendored 源码 + 本地 xmake package 模式，重构为顶层 xmake 子模块，与 moebius 保持一致。

1. 使用 `git mv` 将 `3rdparty/lolly` 移动到顶层 `lolly/`。
2. 修改 `lolly/xmake.lua`，使其既能独立构建，也能作为子模块被顶层包含；将内部 target 重命名为 `lolly_` 前缀避免冲突。
3. 顶层 `xmake.lua` 使用 `includes("lolly")` 引入子模块，并将 `add_packages("lolly")` 改为 `add_deps("liblolly")`。
4. `moebius/xmake.lua` 同样将 `add_packages("lolly")` 改为 `add_deps("liblolly")`，并删除 `add_requires("lolly")`。
5. `xmake/tests.lua` 中测试目标已通过 `libmogan` 继承 `liblolly`，删除冗余的 `add_packages("lolly")`。
6. 删除本地 package 定义 `xmake/packages/l/lolly/xmake.lua`。
7. 统一 `LOLLY_VERSION`：由 `xmake/vars.lua` 维护，与 `lolly/xmake.lua` 保持一致。
8. 临时禁用 `lolly/io/http_test`，避免该用例依赖外部网络导致测试失败。

## 6 Why

- lolly 是 Mogan 自研 C++ 基础设施，不是真正的第三方依赖；放在 `3rdparty/` 并通过本地 package 包装，增加了构建复杂度。
- 参考 moebius 子模块化经验，将 lolly 提升为顶层子模块可以降低耦合、统一构建机制，并保留独立开发/测试能力。
- 移除本地 package 后，lolly 的版本、依赖和 target 名称由子模块自身管理，顶层只需 `includes("lolly")` 和 `add_deps("liblolly")`。

## 7 How

- 在 `lolly/xmake.lua` 中使用 `os.scriptdir()` 定位 lolly 根目录，确保独立构建和子模块包含两种模式下路径都正确。
- `liblolly` 使用 `add_includedirs(lolly_includedirs, {public = true})`，让依赖方无需再显式声明 lolly 头文件路径。
- 顶层 `xmake.lua` 删除 `add_requires("lolly")` 和 `LOLLY_VERSION` 重复定义；`libmogan` 与 `stem` 直接依赖 `liblolly`。
- `moebius/xmake.lua` 删除对 `lolly` package 的 require，改为直接依赖 `liblolly` target。
- `xmake/tests.lua` 中 C++ 测试已通过 `libmogan` 间接依赖 `liblolly`，移除 `add_packages("lolly")` 避免重复。
