# [0774] 远端操作节流：每 1.5s 统一应用一次

## 1 背景（Why）

协作（Loro CRDT）稳态下，对端每推送一个操作（一条 WebSocket 二进制帧 = body/meta
内容更新，或 `CURSOR` 文本帧 = 远程光标），`collab_session::on_message`（[loro_collab.cpp](src/Plugins/Collab/loro_collab.cpp)）
就**立即**调用 `editor::apply_remote` / `set_remote_cursor`，前者触发整篇
`typeset_invalidate_all` + 全量 retypeset。对端快速敲字时，每个按键都驱动一次重排版，
性能吃不消。

目标：把 `ready` 稳态下收到的远端消息（body 内容、meta、远程光标）**攒起来，每 1.5s
统一应用一次**，把高频重排版降到 ≤1 次/1.5s。初始同步（JOIN 首帧）与协议控制帧保持
立即处理，连接建立与文档加载不受影响。

## 2 方案（How）

**节流放在 `collab_session` 传输层，不碰 editor / loro_shadow。** 两次 flush 之间编辑器
树完全不动，避免「立即应用 mods、只延迟排版」会导致的 box 树 (ttt) 与源树在 1.5s 窗口
内不一致、期间穿插本地编辑操作在不一致状态上的风险。flush 时原样调用现有
`apply_remote` / `set_remote_cursor`。

- **仍立即处理**（不缓冲）：
  - `await_frame` 初始同步：首条二进制帧 → `apply_remote` + `become_ready()`。
  - 控制文本帧 `DOC ` / `ERR ` / `SYNC-END`（驱动状态机）。
  - `await_frame` 期间的 `CURSOR`（沿用原行为）。
- **缓冲 + 节流**（仅 `ready` 状态）：二进制内容帧 + `CURSOR` 文本帧都进待应用队列。
- **节流语义**：首条消息到达记 `first_inbound_at = now`；`poll()` 每帧检查
  `now - first_inbound_at >= interval` 则 flush。flush 后清空并重新 arm → 连续输入下约每
  interval flush 一次，单条消息最迟 interval 内落地。
- **flush 回放**：内容帧按到达顺序（Loro update 有序，必须保序）；`CURSOR` 按序回放
  （`set_remote_cursor` 按 peer 覆盖，自然 last-wins）。
- **editor 为 nil**（无视图）跳过 flush、保留待应用消息，下帧重试；`disconnect()` 先
  force-flush（避免丢失未落地的远端编辑），再拆连接。
- **间隔可调**：`MOGAN_LORO_REMOTE_INTERVAL_MS` 环境变量，默认 1500；设 0 即立即
  （恢复旧行为，便于对比/测试）。

## 3 涉及文件

- `src/Plugins/Collab/loro_collab_ws.hpp`
  - `collab_session` 类 private 区：新增 `pending_inbound_data`、
    `pending_inbound_binary`、`first_inbound_at` 成员；声明 `apply_inbound`、
    `buffer_inbound`、`flush_inbound`。
- `src/Plugins/Collab/loro_collab.cpp`
  - 新增 file-scope `remote_flush_interval_ms()`（读 `MOGAN_LORO_REMOTE_INTERVAL_MS`，
    回落 1500）。
  - 抽取 `apply_inbound`（原 `on_message` ready/await 分支内联逻辑：binary→`apply_remote`，
    `CURSOR `→解析 peer/payload→`set_remote_cursor`）。
  - 新增 `buffer_inbound`、`flush_inbound(bool force)`。
  - 重写 `on_message`：控制帧立即；`ready` 缓冲内容+光标；`await_frame` 立即+`become_ready`。
  - `poll()` 末尾 `flush_inbound()`；`disconnect()` 开头 `flush_inbound(true)`。

`src/Edit/Modify/edit_collab.cpp`、`moebius/.../loro_shadow*` **零改动**（flush 复用现有入口）。

## 4 验证

- 现有协作 GUI 测试不受影响（关键回归点）：`0759_collab.scm`、`0772_collab_meta.scm` 都是
  「A 编辑→断开→B 新会话 JOIN」模式，B 经 `await_frame` 初始同步拿快照（保持立即），不触发
  ready 节流。
  ```bash
  node tools/loro-server/server.js
  MOGAN_TEST_GUI=1 xmake r 0759
  MOGAN_TEST_GUI=1 xmake r 0772_collab_meta
  ```
- 手动：两个客户端连同一文档，A 持续敲字 → B 内容/远程光标约每 1.5s 更新一次且最终一致；
  `MOGAN_LORO_REMOTE_INTERVAL_MS=0` 恢复每键即时。
