# [0753] 修复 ImGui 空格双插与 macOS 中文输入法

## 1 相关文档

- 本任务面向 ImGui 前端（macOS 桌面 / WASM），输入路径与 Qt 前端的
  `QTMWidget::inputMethodEvent` 对齐参考。

## 2 任务相关的代码文件

- `src/Plugins/ImGui/im_tm_widget.cpp` — 空格双插修复；接入 macOS IME 桥接
  （队列放宽、key 回调抑制、install 调用、pre-edit/commit 入队访问器）。
- `src/Plugins/ImGui/im_ime_macos.hpp` — 新增，macOS IME 桥接 API 声明，非
  macOS 提供 inline 空桩。
- `src/Plugins/ImGui/im_ime_macos.mm` — 新增，交换 `GLFWContentView` 的
  `NSTextInputClient` 捕获预编辑/提交。
- `xmake/targets/libmogan.lua` — macOS 下编译 `src/Plugins/ImGui/**.mm`。

## 3 如何测试

### 3.1 确定性测试（单元测试）

```bash
xmake b stem
```

### 3.2 非确定性测试（交互验证）

1. 文本模式按空格 → 只插入一个空格；数学模式按空格 → 仍触发 `kbd-space`
   语义（终止宏输入等）。
2. 拼音输入法：输入 `ni` 应看到行内预编辑随键入更新；`nihao` + 空格 → 插入
   `你好`（无前导空格）。
3. IME 提交或取消后，退格 / 回车 / 空格等键立即恢复正常。
4. 定位问题时用 debug 构建：`xmake f -m debug && xmake b stem && xmake r stem`，
   终端打印 `im_ime install / setMarkedText / insertText` 日志（`#ifdef LIII_DEBUG`）。

## 4 What / Why

### 4.1 空格双插

ImGui（GLFW）中按一次空格插入两个空格。GLFW 对同一次物理空格按键同时触发 key
回调（`GLFW_KEY_SPACE` 在 keymap 中映射为 `"space"` → `kbd-space` → 插入空格）
与 char 回调（codepoint 32 → 插入 `" "`）。字母不受影响：`im_from_key_event` 对
可打印字母返回 `""`、让给 char 回调，且合成/普通情形不重复；但空格在 keymap 里，
两条路径都生效。Qt 无此问题（`keyPressEvent` 单事件同时携带 key 与 text）。

### 4.2 macOS 中文输入法

- **pre-edit 不显示**：官方 GLFW 3.4 无 marked-text 回调，且 `NSTextInputClient`
  协议没有 marked text 的 getter，无法直接读取预编辑文本。
- **提交用的空格插在内容前**（如 ` 你好`）：`GLFWContentView keyDown:` 在
  `interpretKeyEvents:` 之前触发 key 回调，空格在 keymap 中被先分发插入，随后 IME
  提交的文本才经 char 回调到达。

## 5 How

### 5.1 空格双插

char 回调把控制字符跳过条件由 `codepoint < 32` 改为 `codepoint <= 32`，让空格
（codepoint 32）只走 key 回调（`"space"` → `kbd-space`）。`<= 32` 精确覆盖控制字符
（0–31）+ 空格（32）；keymap 中唯一既可打印又触发 char 回调的就是空格。与 Qt 行为
一致，且保留数学模式下 `kbd-space` 的特殊语义。

### 5.2 macOS IME 桥接

- 新增 `im_ime_macos.mm`：`im_macos_install_ime` 幂等地用
  `method_setImplementation` 交换 `GLFWContentView` 的
  `setMarkedText:selectedRange:replacementRange:` / `unmarkText` /
  `insertText:replacementRange:`（`nm libglfw3.a` 已确认三者定义在该类上）。
- 预编辑/提交经 `im_macos_enqueue_preedit/commit` 投入与 WASM 桥接共用的
  `g_ime_pending` 队列，由 `im_main_loop` 顶部排空（`"pre-edit:<utf8>"` 重建为
  `key_press` 所需的 `"pre-edit:<pos>:<cork>"`）。故把队列与排空块从
  `__EMSCRIPTEN__` 放宽到 `__EMSCRIPTEN__ || OS_MACOS`（剪贴板粘贴段仍为 EMSCRIPTEN）。
- IME 提交也走队列（而非 char 回调），保证「清预编辑 + 提交」同批按序排空，避免
  char 回调立即触发造成提交先于预编辑清除的残影；普通按键仍走 char 回调。
- `glfw_key_callback` 在合成期用 `im_macos_ime_composing()`（自维护标志，提交时
  可靠清除，不依赖可能卡住的 `hasMarkedText`）抑制字面键分发。
- `setMarkedText`/`insertText` 的参数可能是 `NSString` 或 `NSAttributedString`
  （后者不响应 `UTF8String`），用 `mogan_utf8()` 经 `isKindOfClass:` 判别提取。
- 构建：`libmogan.lua` 的 ImGui 分支下 macOS 增加 `**.mm` glob（AppKit 已链接，
  `GLFW_EXPOSE_NATIVE_COCOA` 在 .mm 内定义）。
