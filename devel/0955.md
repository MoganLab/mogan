# 0955 Qt 读取模型清单 + 完整模型菜单 + 会话级切换 + 默认模型修正

## What

1. 新增 `ChatModelInfo` 值类型与 `ChatModelStore`：从
   `$TEXMACS_HOME_PATH/plugins/llm/data/liii_llm_menu.json`
   （优先）或 `$TEXMACS_PATH/plugins/llm/data/liii_llm_menu.json`
   （兜底）加载模型清单，支持新格式（顶层 `models` 数组）并兼容旧格式
   （顶层键即条目）；解析失败或文件缺失时回退内置兜底清单
   （`Kimi-VLM` 单条目）。
2. 落地正式模型清单 `TeXmacs/plugins/llm/data/liii_llm_menu.json`
   （kimi-k3 + deepseek-v4-pro + deepseek-v4-flash 三条目，正式字段值）。
3. 把 M2 落地的 Model 占位菜单升级为完整模型选择菜单：logo + 名称 +
   描述徽标 + 选中项背景加深；选择写回 `ChatSession.model` 并落 manifest。
4. 修正默认模型语义（G7）：新会话（含复用空白会话）固定为清单
   `default`，不再继承最近激活会话的模型。

## Why

- M2 的 Model 按钮只有只读占位菜单，用户无法切换模型；模型清单此前只
  存在于 goldfish 插件侧（Scheme），Qt 菜单没有数据来源。
- 旧实现 `ChatController::currentModel_` 使新会话继承"最近激活会话"的
  模型：用户在 A 会话切到模型 X 后新建会话，新会话静默绑定 X，与
  「新会话固定为清单默认模型」的预期不符；且 `createView` 末尾还会用
  恢复会话的模型反向覆盖 `currentModel_`，语义混乱。
- 发送路径（`chat-tab-send` 4 参数）本任务不改（PR-M5 的事）；菜单/
  切换只写 `ChatSession.model` 与 manifest，不触碰协议参数。

## How

1. **`qt_chat_model.hpp/.cpp`（新增）**
   - `ChatModelInfo`：key（= 真实模型 id，manifest/协议共用）、name、
     icon、description、dscColor、allowThinking/allowSearch、baseUrl、
     defaultSystem。
   - `chat_model_parse_list (jsonText, outModels, outDefaultKey)`：
     `QJsonDocument` 解析。顶层含 `models`（数组）按新格式：条目键取
     `model` 字段，缺省 `name`=key、`icon`/`description`/`base_url`/
     `default_system`=`""`、`dsc_color`=`"orange"`、布尔字段缺省 true，
     `enable` 为 false/0 的条目过滤；顶层 `default` 缺失或不在清单内取
     第一个条目。顶层无 `models` 按旧格式：顶层键即 key（`name` 字段
     补显示名，名为 `default` 的条目取其 `model` 字段作默认键），其余
     按缺省补齐。解析失败（非法 JSON / `models` 非数组 / 过滤后清空）
     返回 false 且 out 不变。
   - `ChatModelStore`：构造即按 HOME 优先、PATH 兜底加载（`url_system` +
     `exists` + `load_string`），任一环节失败回退内置兜底清单
     `{"Kimi-VLM", name="K3", icon="kimi"}`。
2. **`qt_chat_tab_widget.hpp/.cpp`**：新增 `chat_model_menu_populate`，
   为 `QMenu` 填充 `QWidgetAction` 自定义行：`[logo][name][徽标]`。
   行为 QToolButton 子类（`ToolButtonTextBesideIcon` 渲染 logo+名称，
   徽标为鼠标透明子控件挂在右侧，其宽度计入行 `sizeHint` 以免压住
   文本）；交互沿用项目内 QTMMenuButton 的
   成熟配方（QTBUG-10427 / TeXmacs #37719）：`released()` 手动
   `trigger()` 所在 action + 鼠标事件显式转发父级让菜单自行关闭。
   logo 用 `:llm-chat/models/<icon>.svg`，空或 `isNull()` 画占位圆点；
   徽标为圆角小标签（`dsc_color` 红/橙两种预设），`description` 空不
   创建；选中行（== 当前会话 model）以 objectName + qss 背景加深，
   配色沿用既有选中色（浅色 `#e8eefc` / 深色 `#1a3a5a`）。菜单每次
   打开重建。
3. **`qt_chat_controller.hpp/.cpp`**
   - 持有 `ChatModelStore modelStore_`（构造于 `createView` 之前）。
   - G7 修正：删除 `currentModel_` 成员与 `createView` 末尾的覆盖
     逻辑；`ensureNewConversation` 两处 `setModel` 改用
     `modelStore_.defaultKey ()`。
   - 新增 `onModelSelected (sessionId, key)`：key 不在清单内忽略；
     `setModel` + `updateManifest`；不触碰 thinking/search（PR-M4）。
   - `activateSession` 入口校验：会话 model 不在清单内时内存视为
     `defaultKey ()`（不回写 manifest）——manifest 旧值（如
     `Kimi-VLM`）恢复即回退默认，不崩不回写。
   - `onModelMenuRequested` 替换占位实现：构建完整菜单，项点击转
     `onModelSelected`。选择结果从 `QMenu::triggered` 信号捕获而非
     `exec()` 返回值——QWidgetAction 内控件手动 trigger 时 Qt 不写
     exec 的 `syncAction`（返回 null），只有 Qt 自身的鼠标处理路径
     才写。
4. **`TeXmacs/plugins/llm/data/liii_llm_menu.json`（新增）**：
   正式清单（与 liii 侧 PR-L2 同一契约）：kimi-k3（K3，
   `base_url=/api/v1/ai/siliconflow/chat`，允许搜索）、deepseek-v4-pro
   （V4-Pro）/ deepseek-v4-flash（V4-Flash）（`base_url=/api/v1/ai/
   deepseek/chat`，禁止搜索），`default_system` 沿用现网 Kimi-VLM 条目
   全文，徽标均"订阅优先"/orange，`default` = kimi-k3。
