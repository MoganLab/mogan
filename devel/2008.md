# [2008] 基于 macOS 平台修复 C++ 测试

## 如何测试

```bash
# 单个测试
xmake b <test_target>
xmake r <test_target>

# 全部 C++ 测试
./bin/test_all
```

## What

修复在 macOS 平台上批量运行 C++ 测试（`bin/test_all`，即 `xmake run --group=tests`）时出现的失败与耗时问题，让全量套件在 macOS 上能够稳定跑完。

1. `qt_chat_tab_widget` 析构期间，`titleEdit` 的信号回调重入访问正在销毁的 `items_`，导致 use-after-free（崩溃）
2. `qt_tab_page_test::closeButtonAppearOnHover` 在 macOS 上 hover 检测失败（关闭按钮弹不出来）
3. `table_performance_test` 中存在大量断言为 `QVERIFY(time>=0)` 的无意义性能测试，耗时过长，拖慢全量套件

## Why

这些问题在单跑某个测试时往往不出现或可接受，但在 `bin/test_all` 批量串行跑 100+ 个测试时会集中暴露，导致 macOS 上套件无法稳定通过：

- **析构重入崩溃**：`ChatSidebar` 析构时，Qt 在 `~QWidget` 阶段会派发 `CloseEvent`，焦点离开 `titleEdit` 触发 `editingFinished` / `returnPressed`，重入到 `endEditTitle`。此时 `items_` 已进入销毁流程，再访问会触发 use-after-free，在批量测试末尾崩溃。
- **macOS hover 检测**：macOS（Cocoa）的 `QTest::mouseMove` 不会向未 grab 鼠标的 widget 派发 `mouseMoveEvent`，`QTRY_VERIFY` 一直等不到关闭按钮可见，用例超时失败。
- **无效性能测试**：`QVERIFY(time>=0)` 永远成立，这些用例只跑了一遍 typeset 然后丢弃数据，无法捕获任何回归，却在 CI 里浪费时间，拖慢 `bin/test_all`。

## How

### 1. 析构期间禁止信号重入（`qt_chat_tab_widget.cpp` / `.hpp`）

为 `ChatSidebar` 新增 `~ChatSidebar()` 析构函数和 `destroying_` 标志位：

- 析构函数里先置 `destroying_=true`，再断开每个 `titleEdit` 与 `this` 的信号连接，阻止后续 `editingFinished` / `returnPressed` 回调重入。
- `endEditTitle` 入口处增加 `if (destroying_) return;` 兜底：即使有信号在置标志前已入队，重入时也直接返回，避免访问正在销毁的 `items_`。

### 2. macOS 上合成 MouseMove 触发 hover（`qt_tab_page_test.cpp`）

`closeButtonAppearOnHover` 原本用 `QTest::mouseMove(&tab, closeCenter)` 让鼠标移入关闭按钮区域。macOS（Cocoa）上该 API 不会向未 grab 鼠标的 widget 派发 `mouseMoveEvent`，hover 检测逻辑拿不到事件。

改为手动合成 `QMouseEvent(MouseMove, ...)`，并用 `QApplication::sendEvent(&tab, ...)` 直接投递给 tab，等价于 Windows 上鼠标移入关闭按钮区域，触发其 hover 检测逻辑，`QTRY_VERIFY` 即可观察到关闭按钮可见。

### 3. 精简 `table_performance_test` 以提高效率

`table_performance_test` 在 macOS 上耗时过长，且多数用例断言为 `QVERIFY(time>=0)`（恒成立），无法捕获回归：

- 删除最耗时的 `test_50x50_text_table`（50x50 矩阵排版）。
- `test_handle_decorations_performance` 的规模档从 `{20, 30, 40, 50}` 缩减为 `{20, 30}`，减少无效的放大规模运算。

精简后用例仍保留对真实回归的覆盖（装饰性能、单元格换行、长内容无行重复），但显著缩短了运行时间，提高 `bin/test_all` 整体效率。
