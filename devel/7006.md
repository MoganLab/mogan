## [7006] 最近协作文档显示

### What
协作文档与本地文档**共用同一份 Recent 列表**（`recent-files.json`），按最近打开
时间交错排序，提供「最近用过、一键回到」的入口（区别于 Join 子菜单的「浏览服务端
全量文档」）：

- **File → Recent**：云文档与本地文档同列，菜单标签用文档 title。
- **startup tab**：云文档与本地文档同列，云条目名后追加「云端」小标签。
- 点云条目 = 按 `doc_id` 重新 `join`（非 `load` 文件）；「Clear」同时清两类。
- 附带补全 C++ `become_ready` 的 buffer 改名，使 CREATE 文档落到稳定的
  `tmfs://collab/<doc_id>` URL（Recent 重开能复用已有 buffer）。

### Why
- 云文档缺「最近用过」入口；Join 子菜单是服务端全量浏览，不适合快速重开。
- 用统一存储而非独立列表：三个消费端（File→Recent、Go→Recent、startup tab）读
  同一份 `recent-buffer`，借其既有 `last_open` 时间戳 + LRU 天然按时间交错，复用
  既有的清理/持久化，无需重复实现。
- 副作用（可接受）：统一存储无 server 维度，切到别的服务端时旧云条目仍在，点它会
  JOIN 失败（服务端回 ERR），可手动从列表移除。

### How

**become_ready 改名**（`src/Plugins/Collab/loro_collab.cpp`）
CREATE 文档建 buffer 时用占位 URL `tmfs://collab/pending-<ts>-<n>`，需在 C++ 收到
服务端 DOC 帧、得到真实 `doc_id` 后改名。`become_ready` 里补全
`rename_buffer(old_url, new_url)` + 更新 `session->buffer_url`（`old==new` 跳过），
保证改名后 `poll`/`get_editor`/`find_by_buffer` 用新 URL 匹配；也使
`collab-join-document` 的去重（按 URL 匹配 `buffer-list`）能 switch 到已有 buffer。

**存储 API**（`tm-dialogue.scm`）
- `recent-files-learn (file-path name)`：命中则 touch（`last_open`/`open_count`），
  否则 `recent-files-add` 新增并跑 LRU。`recent-buffer-json` 委托它（本地 name 仍由
  `url-tail` 推导）。
- `recent-files-get-name (file-path)`：按 path 反查 name（云 URL 的 `url-tail` 是
  UUID 非标题，菜单渲染标题用）。
- `recent-files-save`：立即把 `recent-files.json` 落盘。`recent-files-learn` 只更
  内存态、默认 `on-exit` 才 flush；C++ 启动页**直接读该文件**取 name，云文档记录
  后若不立即落盘，同会话内 name 会回退为 UUID。join/create 频次低，每次写一次小
  JSON 可接受，且提升崩溃后的最近列表持久性。

**放行云 URL**（`base.scm`）：`buffer-in-recent-menu?` 加 `tmfs://collab/`，否则
`recent-file-list` 的过滤会把云条目全滤掉。

**记录**（`tm-collab.scm`）
- `collab-real-doc-id?`：非空且非 `pending-` 占位，记录前剔除占位。
- `collab-record-recent (doc-id name)`：`recent-files-learn` 写
  `tmfs://collab/<doc_id>` + name，再 `recent-files-save` 落盘。
- 钩子：`collab-join-document` 末尾同步记；两处 CREATE
  （`collab-new-document-named`/`collab-new-document-from-file-named`）用
  `collab-schedule-record-on-create`——doc_id 由 C++ `become_ready` 收 DOC 帧异步
  回填，`delayed (:pause 1500)` 后读当前活跃会话的 `loro-collab-doc-id`/`-doc-name`
  记（不捕获 buffer 身份：改名后 `current-buffer` 是新 URL，与占位 URL 不再 `==`；
  读会话字段无歧义）。

**显示与分派**
- `file-menu.scm` `short-menu-name`：最前加 collab 分支
  `(or (recent-files-get-name …) (collab-url->doc-id u))`。
- `file-menu.scm` `file-list-menu`：云→`collab-join-document`（**带 title**，否则
  名字缺省 → buffer 标题退化为 UUID），本地按 `win?` 走 `load-document`/`load-buffer`；
  缺失清理（`recent-files-remove-by-path`）加 `(not (collab-buffer? name))` 门控——
  云 URL 非磁盘路径，`url-exists?` 必假，不可据此误删。
- `startup-tab-file.scm` `startup-tab-open-recent (path)`：C++ 点击入口，云→join
  （同样带 title）、本地→`load-document`。

**startup tab C++**（`QTMHomePage.{hpp,cpp}`）
- `RecentDoc` 加 `bool isCloud`；文件内 `isCollabPath(p)` = `startsWith("tmfs://collab/")`。
- `loadRecentDocs`：exists 过滤 `QFile::exists(path) || isCollabPath(path)` 放行云；
  建 `RecentDoc` 时设 `isCloud`，name 仍走 JSON `name` 字段（云文档名已落盘）。
- `renderRecentDocs`：云条目名后追加「云端」`QLabel`（objectName
  `startup-tab-cloud-badge`，内联样式兜底，可被主题 CSS 覆盖）。
- `onRecentDocClicked`：云 path 走 `(startup-tab-open-recent …)`，**不**查本地
  exists、**不**调 `addRecentDoc`（其 name 推导对云 URL 退化为 UUID；重加由 join
  的记录钩子带正确 name 完成）。

  `file-list-menu` 分派 + 跳过误删）

`startup-tab-open-recent`）。

### 如何测试
**纯逻辑单测**（headless，秒级，无需服务端/GUI）：
```bash
xmake b stem && xmake r tm-collab-test
```
用例全过（含 `collab-url->doc-id` 互逆、`collab-real-doc-id?` 占位判定）。

**统一存储 + GUI**（需 `--loro=y` + 服务端）：
```bash
node tools/loro-server/server.js &
xmake f --loro=y --yes && xmake b stem
MOGAN_TEST_GUI=1 xmake r 7001      # 既有 buffer-URL 集成测试不回归
```

**端到端手测**：
1. Collaborative → Set server address 配好 → New shared document（起名「周报」，
   等 ≥2s 会话就绪）→ Leave。
2. 开 File → Recent：该云文档与本地文档同列、按时间交错，标签为「周报」（非 UUID）。
3. 点该云条目 → 重新 join，buffer 标题为「周报」（**不是 UUID**——分派须带 title）。
4. 经 Join shared document 子菜单加入的文档也进 Recent。
5. startup tab：云文档与本地文档同列，云条目名后显示「云端」小标签；点击重新 join；
   右键 remove/clear 生效。
6. 关闭重开 Mogan → 云条目持久（`recent-files.json`，因 `recent-files-save` 即时落盘）。
7. Clear menu（File→Recent）/ Clear list（startup tab）→ 云条目一并清除。
8. 回归：本地文档 Recent 打开/清理行为不变；切到另一服务端 → 旧云条目仍在，点击
   JOIN 失败（预期），可手动移除。
