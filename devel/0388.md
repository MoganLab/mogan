## 5 What

将 OAuth 登录回调返回的 HTML 由「静态成功提示页」改为「极简跳转页」，让浏览器在收到 loopback callback 后立即跳转到官网成长激励计划页面。

具体改动在 `src/Plugins/Qt/QTMOAuth.cpp` 构造函数中（原 97-107 行 → 新 97-113 行）：

1. 移除原 callback HTML 中的文案 `<h2>亲爱的三鲤用户，恭喜登录成功！您可以关闭此页面并返回应用。</h2>` 与 3 秒后 `window.close()` 的脚本。
2. 移除原有的 `<style>` 块（不再需要背景色与字体样式，因为页面瞬间即被跳走）。
3. 通过 `call("account-oauth2-config", "growth-url")` 从 Scheme 配置中读取目标跳转 URL。
4. 用 `c_string` + `QString::fromUtf8` 完成类型转换，与同文件 `getAuthorizationUrl()`、`getAccessTokenUrl()` 等函数保持一致的写法。
5. 生成的新 HTML 中包含：
   - `<script>window.location.replace(...)</script>`：立即跳转，且不留浏览器历史（用户不能"返回"到这个一次性 callback 页）。
   - `<noscript><meta http-equiv="refresh" content="0;url=..."></noscript>`：当 JS 被禁用时兜底用 meta refresh 跳转。

## 6 Why

**业务背景**：官网新增了"成长激励计划"页面（`/personal-center/growth`），作为 OAuth 登录成功后的统一落地页。该页面通过 URL 参数 `?from=oauth` 区分入口来源，对 OAuth 登录用户显示显著的"登录成功"提示横幅。

**原本的问题**：旧的 callback HTML 仅显示一句"恭喜登录成功"静态文案，并尝试 3 秒后 `window.close()`。但 `window.close()` 对非脚本打开的标签页在主流浏览器（Chrome/Firefox/Edge）中无效，用户最终看到一个**啥都做不了**的空白页。这既浪费了用户注意力，也错过了引导用户进入官网业务流程的机会。

**改造后的好处**：
- 用户登录后立即被引导到官网业务页面（成长激励计划），提升官网曝光与用户参与度。
- 复用 `account-oauth2-config` 配置机制，目标 URL 跟随 `stem-profile` 自动在 production/staging/local 之间切换，便于本地与测试环境联调。
- 使用 `location.replace` 而非 `location.href`，避免 callback 临时页污染浏览器历史。

## 7 How

### 实现要点

**1. 为什么不用真正的 HTTP 302 重定向？**

`QOAuthHttpServerReplyHandler`（来自 QtNetworkAuth）的公开 API 只暴露了 `setCallbackText(QString)`，用于设置响应 body；**没有公开接口**设置响应头（如 `Location`）或状态码（如 302）。源码层面，它内部硬编码返回 200 状态码。

如果一定要发真正的 302，需要 fork 或继承 `QOAuthHttpServerReplyHandler` 重写私有的 `handleRequest`。考虑到当前需求只是"让浏览器跳到指定 URL"，HTML + JS 跳转在功能上完全等价（浏览器解析后立即跳转，对用户而言瞬间完成），因此选择了不增加复杂度的方案。

**2. 为什么用 `location.replace` 而不是 `location.href`？**

`replace()` 不会在会话历史中留下当前页（callback 临时页）。这意味着用户在跳转后的官网页面按"返回"按钮，**不会**回到 loopback callback URL（那个 URL 早已失效，回调码已被消费），体验更干净。

**3. 为什么需要 `<noscript>` 兜底？**

虽然现代浏览器默认开启 JS，但企业环境、隐私模式或安全策略严格的用户可能禁用 JS。`<meta http-equiv="refresh" content="0;url=...">` 是 HTML 原生的跳转机制，不依赖 JS，作为兜底成本极低（多一行 HTML）。

**4. 类型转换踩过的坑**

最初写的是：
```cpp
QString::fromStdString(as_string(call("account-oauth2-config", "growth-url")))
```
编译报错：`cannot convert 'string' to 'const std::string&'`。

原因：mogan 项目中 `as_string()` 返回的是项目自定义的 `string` 类型（Scheme 层封装），并非 `std::string`，因此不能直接传给 `QString::fromStdString`。

正确做法参考同文件第 440-442 行 `getAuthorizationUrl()` 的写法：用 `c_string` 包装，再以 `(const char*)` 或 `(char*)` 取出 C 字符串：
```cpp
c_string growthUrlC(as_string(call("account-oauth2-config", "growth-url")));
QString redirectUrl = QString::fromUtf8((const char*)growthUrlC);
```

使用 `fromUtf8` 而非 `fromLatin1` 是为了更安全的默认（虽然当前 URL 是纯 ASCII，但保持与 Scheme 字符串编码一致的习惯更稳妥）。

**5. 配置侧的联动改动（不在本任务范围）**

`TeXmacs/plugins/account/progs/liii/account.scm` 中的 `account-oauth2-config` 需要新增 `growth-url` 配置项，C++ 端才能 `call` 出来。例如生产版：
```scheme
((== key "growth-url") (string-append base-url "/personal-center/growth?from=oauth"))
```
本地版：
```scheme
((== key "growth-url") "http://127.0.0.1:3000/personal-center/growth?from=oauth")
```

该 Scheme 改动属于 `account.scm` 文件，不在本次"对 QTMOAuth.cpp 的修改"范围内，但 C++ 代码依赖此项配置存在才能正常工作。
