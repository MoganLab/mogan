# [1092] 修复 Windows 上 autosave 插件无法触发本地备份

任务编号：1092。PR #3734 合入后，Linux/macOS 上 autosave 插件能正常生成 `$TEXMACS_HOME_PATH/system/backup/<doc-id>/<yyyymmdd>_<hhmmss>.tmu`，但 Windows 上不产生任何备份文件。根因是内嵌的 goldfish `(liii path)` 在 Windows 上只识别 `\`，对 `(port-filename)` 返回的正斜杠路径解析错误，导致 `tm-autosave.scm` 顶部扩展 `*load-path*` 失败、`(import (liii autosave))` 找不到模块，插件进程握手前即崩溃。

## 5 What
1. 在内嵌的 `TeXmacs/plugins/goldfish/goldfish/liii/path.scm` 中修两处函数：
   - `parse-windows-path`：进入 split 前先把 `/` 替换为 `\`，使带正斜杠的 Windows 绝对路径（如 `C:/Users/.../foo.scm`）能正确切分为 parts
   - `path-parent`：string 输入分支同样在 Windows 上做 `/` → `\` 归一化，否则即便上层用 `path->string` 直通字符串也只识别单种分隔符
2. 保持 `tm-autosave.scm` 原状：原 PR 已经写好 `(path-parent (port-filename))` 的 fallback 链路，只是被 goldfish path 模块的 bug 卡住；上游 path 修复后这一行立即恢复可用，**不需要** 在 `tm-autosave.scm` 内部加 `argv`/`getcwd` 等额外回退

## 6 Why
PR #3734（commit 39a7d4239）把 `(liii autosave)` 模块拆出后，`tm-autosave.scm` 顶部需要把脚本所在目录加入 `*load-path*`，否则 `import (liii autosave)` 找不到模块。Linux/macOS 上之所以能跑，是侥幸——goldfish 默认 `*load-path*`、`cwd`、port-filename 在那些平台恰好凑出了正确目录。Windows 上不行：

- goldfish 主进程以**绝对路径**启动脚本（`init-autosave.scm` 中 `url->system entry`），子进程 cwd 与脚本位置无关，所以不能用 `(getcwd)`
- s7 的 `(port-filename)` 在脚本被 `s7_load` 时**确实**返回脚本路径，但在 Windows 上是带正斜杠的绝对路径（如 `C:/Users/.../tm-autosave.scm`）
- goldfish 的 `(liii path)` 在 Windows 上只按 `(os-sep)`（`\`）切分，遇到正斜杠路径会一刀不切，`path-parent` 把整串当作单一 part，剥到只剩 `C:`，`*load-path*` 加了个错误目录，于是 `liii/autosave.scm` 找不到，插件进程在握手前就崩了
- 主进程的 `silent-feed* "autosave" ...` 投递到一个已死的子进程，表现就是「Windows 上没触发自动备份」

修 goldfish 的 path 模块是更彻底的修法——`(port-filename)` 是 s7 内置、行为正确，问题在 path 解析层。`parse-path-string` 在非 drive-letter 路径上已经做了 `/` → `\` 归一化（line 87），`parse-windows-path` 漏了，`path-parent` 漏了。补齐即可。

## 7 How
- `parse-windows-path`：参照同文件 `parse-path-string` 的写法，先把 `s` 中所有 `/` 替换为 `\`，得到 `normalized`，后续判断与 split 都基于 `normalized`。这样既支持 `C:\Users\...` 也支持 `C:/Users/...`
- `path-parent`：在 string 分支入口（`(path->string p)` 之后）加一层 `(let ((s (if (os-windows?) (string-replace s "/" "\\") s)))` shadow 外层 `s`，后续 s-trimmed 与 loop 都基于规范化后的 s。`string-replace` 已经在同文件 `parse-path-string` 中使用，签名是 `(string-replace str old new)`，从 `(liii string)` 导入
- 不修改 `tm-autosave.scm`：原代码 `(path->string (path-parent (port-filename)))` 修复后即可正常工作。如果在 `tm-autosave.scm` 内加 `argv`/`getcwd` 回退，是绕过 root cause 的局部 workaround，每个新插件入口都要重写一遍，且掩盖 goldfish 的 bug 让其它插件也踩同样的坑
