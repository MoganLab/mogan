# [0739] 修复 WASM (ImGui) 剪切板无法与系统剪切板交互

## What?

WASM（ImGui）前端无法与系统剪切板交互：

- 在应用内复制/剪切后，粘贴到**外部应用**（浏览器其它页面、系统文本框）拿不到内容；
- 在**外部应用**复制的文本，在 Mogan 里粘贴不出来。

而 Qt 前端一切正常。本任务修复 ImGui 后端的剪切板后端（`set_selection` /
`get_selection` / `clear_selection`），使其在 WASM 下真正桥接到浏览器（系统）
剪切板。改动**仅限 ImGui 后端**，不触碰共享编辑器代码，Qt 前端行为不变。

## Why?

### 编辑器经由 `"primary"` 键访问系统剪切板

全局搜索可知，复制/剪切/粘贴走的是 `kbd-copy` / `kbd-cut` / `kbd-paste`
（`generic-edit.scm:1216-1226`），它们都调用 `(clipboard-* "primary")`，最终到
`selection_copy/cut/paste("primary")` → `::set_selection` / `::get_selection`
（`edit_select.cpp:646 / 680`）。Qt 的 `set_selection`（`qt_gui.cpp:430`）正是把
`key == "primary"` 写入 `QClipboard::Clipboard`（真正的系统剪切板）。

旧 ImGui 实现却是在 `cb == "clipboard"` 时才镜像系统剪切板（`im_gui.cpp` 旧代码），
而编辑器实际用的是 **`"primary"`**——所以即便后续桥接正确，旧代码也永远触发不到，
复制根本写不到系统剪切板。

### 根因一：emscripten 的 GLFW 移植版根本没实现剪切板

ImGui 后端用的是 GLFW 的 `glfwSetClipboardString` / `glfwGetClipboardString`。
但在 emscripten 的 GLFW 移植版（`contrib.glfw3`，位于 xmake 的 emscripten 包目录
`cache/ports/contrib.glfw3/src/cpp/glfw3.cpp:1260-1261`）里，它们是**空操作**：

```cpp
GLFWAPI void glfwSetClipboardString(GLFWwindow* window, const char* string) { logNotImplemented("glfwSetClipboardString"); }
GLFWAPI const char* glfwGetClipboardString(GLFWwindow* window) { logNotImplemented("glfwGetClipboardString"); return nullptr; }
```

`glfwSetClipboardString` 什么都不写，`glfwGetClipboardString` 恒返回 `nullptr`。
ImGui 自身的 `imgui_impl_glfw` 后端（`imgui_impl_glfw.cpp:695-696`）也只是转调这两个
空操作。所以「写不进、读不到」是必然的——必须绕开 GLFW，直接用浏览器剪切板 API。

> 桌面 GLFW（macOS/Linux/Windows）的这两个函数是**真实可用**的，无需此修复；
> 本任务的浏览器桥接仅对 `__EMSCRIPTEN__` 生效，桌面端仍走 `glfwSet/GetClipboardString`。

### 根因二：Web 粘贴是异步的，而 `get_selection` 在 keydown 期同步执行

即便接上 `navigator.clipboard`，粘贴仍有时序问题。浏览器里：

1. `keydown`（Ctrl/Cmd+V）→ GLFW 转发 → 编辑器 → `get_selection("primary")`（**同步**，
   在 keydown 的调用栈里）；
2. keydown 默认动作之后才派发 `paste` 事件（`event.clipboardData` 在这里才有值）。

即 `get_selection` 跑在 `paste` 事件**之前**。`navigator.clipboard.readText()` 又是
异步 Promise，无法在同步的 `get_selection` 里拿到当前内容。若放任 GLFW 走自己的
Ctrl+V 路径，`get_selection` 只会拿到**上一次**缓冲的旧文本（首次粘贴更是空的）。

### 复用既有的「隐藏 textarea + JS 监听 → C++ 队列 → 主循环 drain」模式

IME 实现（`im_tm_widget.cpp:67-177`）已经为同类问题搭好了脚手架：一个隐藏的真实
`<textarea id="mogan-ime-input">`（IME 编辑宿主，且常驻焦点），其 DOM 事件经
`ccall(EMSCRIPTEN_KEEPALIVE C 函数)` 入队，在 `im_main_loop` 顶部 drain。剪切板
完全复用这一模式：textarea 常驻焦点 ⇒ 浏览器会在它上面派发 `copy`/`cut`/`paste`
事件，`paste` 事件的 `clipboardData` 是**同步可读**的（无需权限、跨浏览器通用）。

## 涉及的主要代码位置及实现方式

实现思路：

- **复制/剪切**：`set_selection("primary",…)` 把选区转成 verbatim 纯文本，调
  `navigator.clipboard.writeText`（在用户手势内，键盘和菜单复制都覆盖）；结构化
  texmacs tree 仍存内部 store，供应用内粘贴保留格式。
- **粘贴**：在隐藏 textarea 的 keydown 上对粘贴手势（Ctrl/Cmd+V、Shift+Insert）做
  `stopPropagation`（拦住 GLFW 的旧同步路径，**不** `preventDefault`，好让默认动作
  仍派发 `paste` 事件）；`paste` 事件把 `clipboardData` 经 `mogan_clipboard_deliver_paste`
  入队；`im_main_loop` drain 时 `call("clipboard-paste","primary")` 重放——此时
  `get_selection` 已能返回最新文本，单次粘贴、不与 GLFW 路径重复。
- **所有权判定**：把 paste 事件文本与上次写出的 `im_last_clip_text` 比较——相等则
  返回结构化 tree（应用内粘贴保留公式/格式），否则作为外部纯文本（`tuple("extern", …)`）。

| 位置 | 文件 | 说明 |
| --- | --- | --- |
| 系统文本读取 | `src/Plugins/ImGui/im_gui.cpp`（`im_system_clip_text`，:650） | WASM 返回 `g_clipboard_foreign`（paste 事件刷新）；桌面返回 `glfwGetClipboardString` |
| 选区纯文本 | `src/Plugins/ImGui/im_gui.cpp`（`im_selection_verbatim`，:643） | 取选区 envelope 的 content，`tree_to_generic(content,"verbatim-snippet")`，供写入系统剪切板（外部应用可读） |
| 写剪切板（WASM） | `src/Plugins/ImGui/im_gui.cpp`（`im_clipboard_write` EM_JS，:611） | `navigator.clipboard.writeText`，吞掉 reject |
| paste 入队 | `src/Plugins/ImGui/im_gui.cpp`（`mogan_clipboard_deliver_paste`，:625） | `EMSCRIPTEN_KEEPALIVE`：`g_clipboard_foreign=utf8; g_clipboard_paste_pending=true` |
| drain 钩子 | `src/Plugins/ImGui/im_gui.cpp`（`im_clipboard_consume_paste`，:632） | 消费一次 pending，返回是否需重放粘贴 |
| set/get/clear | `src/Plugins/ImGui/im_gui.cpp`（`set_selection`:662 / `get_selection`:690 / `clear_selection`:724） | 仅 `"primary"` 桥接系统剪切板；其余键只服务内部 store |
| JS 监听 | `src/Plugins/ImGui/im_tm_widget.cpp`（`im_install_ime_listeners`，:157 起） | textarea keydown 拦截粘贴键 + `window` 的 `paste` 事件 → `ccall('mogan_clipboard_deliver_paste',…)` |
| 主循环 drain | `src/Plugins/ImGui/im_tm_widget.cpp`（`im_main_loop`，:555） | `if (im_clipboard_consume_paste()) call("clipboard-paste","primary");` |
| 头文件声明 | `src/Plugins/ImGui/im_tm_widget.hpp` | `__EMSCRIPTEN__` 守卫下声明 `im_clipboard_consume_paste()` |

`get_selection` 的所有权逻辑：

```cpp
bool own;
#ifdef __EMSCRIPTEN__
// 浏览器文本只能从 paste 事件得知；缓冲为空（尚未捕获）时假定我们仍拥有。
own= is_empty (cur) || cur == im_last_clip_text;
#else
own= !is_empty (im_last_clip_text) && cur == im_last_clip_text;
#endif
```

- 应用内复制后清空 `g_clipboard_foreign` ⇒ `own` 为真 ⇒ 应用内粘贴返回结构化 tree；
- 键盘粘贴时 `paste` 事件把**当前**剪贴板文本写入 `g_clipboard_foreign`，与
  `im_last_clip_text` 比较即准确区分「自己 vs 外部」。

桌面端（非 WASM）`im_system_clip_text` 直接 `glfwGetClipboardString`（同步、真实），
所以所有权判定始终准确，无需 paste 事件/drain。

## 如何测试

```
xmake f -p wasm -m debug --qt_frontend=no --pdfhummus=no
xmake b stem          # 产物 build/.../stem.* (+ stem.data)
xmake r stem          # 经 bin/wasm_server.py 起本地 http 服务，浏览器打开
```

1. **应用内 → 应用内（保留格式）**：在文档里选一段含公式/格式的文本，Ctrl/Cmd+C 复制，
   再 Ctrl/Cmd+V 粘贴——应原样保留公式与格式（走结构化 tree 路径）。
2. **应用内 → 外部**：在 Mogan 里复制文本，粘贴到浏览器地址栏/记事本/其它页面——
   应得到可读纯文本（verbatim）。(目前没有适配 copy to 和 magic paste)
3. **外部 → 应用内**：在外部应用复制一段文本，在 Mogan 里 Ctrl/Cmd+V——应插入该文本。
   如果文本为 tmu，则应带格式插入。

## 备注

- **键盘粘贴（Ctrl/Cmd+V、Shift+Insert）每次都是新鲜的**：`paste` 事件在重放前捕获
  当前 `clipboardData`，故外部复制后无需任何前置操作即可正确粘贴。
- **已知局限——菜单「粘贴」**：菜单点击不经过键盘，不触发 `paste` 事件，故
  `get_selection` 只能返回上一次（键盘粘贴/应用内复制时）缓冲的 `g_clipboard_foreign`。
  若「外部复制后直接点菜单粘贴」（中间没有键盘粘贴），会取到旧内容。键盘粘贴不受影响。
  如需修复，可在 `window` 的 `focus`/`visibilitychange` 上 best-effort 调
  `navigator.clipboard.readText` 刷新缓冲——但部分浏览器会弹权限提示或静默拒绝，
  故当前未启用。
- **验证范围**：沙箱内仅能编译验证非 `__EMSCRIPTEN__` 路径（`xmake b libmogan`，
  macOS）及对所改文件做 clang `-fsyntax-only` 复核（我的代码零错误）；emscripten 代码
  沿用同仓已验证的 `EM_JS`+`EMSCRIPTEN_KEEPALIVE`+`ccall` 模式（与 IME 实现一致），
  浏览器内的实际行为需按上面的「如何测试」在本地实测。
- 本次仅修复 ImGui 后端剪切板桥接；未改共享编辑器代码（`edit_select.cpp` 的
  `selection_copy/paste/cut`、`gui.hpp` 的 `set_selection`/`get_selection` 接口）。
