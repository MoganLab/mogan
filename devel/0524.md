# [0524] OAuth 回调链路改造（一）：redirect_uri 提取

## 背景

登录 OAuth 采用授权码 + PKCE 流程（`QTMOAuth`），回调通道为本地回环 HTTP：

- `redirect_uri = http://127.0.0.1:{port}/callback`，在 `login()`（授权请求）和
  `handleAuthorizationCode()`（令牌交换）两处各自硬编码拼接；
- OAuth 2.0 规范要求两处的 redirect_uri **必须完全一致**，双份硬编码改一漏一
  即登录故障；
- 多实例靠固定端口列表（`account.scm` 的 `port-list`）分区：每个实例探测占用
  第一个空闲端口，端口耗尽时 `m_port` 撞车、`isListening()` 为 false，
  `login()` 静默无反应；
- 未发送 `state` 参数，无 CSRF 防护。

后续计划把回调通道切换为 `liiistem://` 自定义协议（授权后浏览器原生弹窗确认、
拉起软件），届时 redirect_uri 将整体变更，先消除双份硬编码。

## 改动

- `src/Plugins/Qt/QTMOAuth.hpp` — 私有方法区新增 `QString getRedirectUri ()`
- `src/Plugins/Qt/QTMOAuth.cpp` — 新增实现（由 `m_port` 构造回环回调地址）；
  `login()` 与 `handleAuthorizationCode()` 两处改调 `getRedirectUri ()`

纯提取，行为零变化。后续切换自定义协议只需改 `getRedirectUri ()` 一处。

## 验证

纯重构无行为变化：`xmake b stem` 编译通过后，走一遍网页登录，确认授权与换
token 正常（两处 redirect_uri 现由同一函数生成，一致性由构造保证）。

## 后续（OAuth 链路分步改造计划）

1. `login()` 发送 `state`（含 nonce），回调校验，补 CSRF 防护；
2. 端口改 OS 分配（`listen(127.0.0.1, 0)` + `serverPort()`，RFC 8252 推荐做法），
   删除 `port-list` 配置与探测循环，消除多实例端口撞车；
3. 回调服务器改为 `login()` 时才启动、收到回调或超时后关闭；
4. `isListening()` 失败时显式报错（日志 + 信号），不再静默；
5. 切换 `liiistem://callback`：`research.cpp` 截获协议参数并按 `state` 内的
   instanceId 经 `QLocalServer("LiiiSTEM-<instanceId>")` 转发至发起登录的实例
   （多实例路由不依赖"主实例"概念，不强制单实例），配合
   `AllowSetForegroundWindow` 完成前台激活；
6. provider 后台白名单：`liiistem://callback`，并允许回环地址任意端口
   （RFC 8252 §7.3）。

## 关联

- 安装器仓库（tauri-installer）已完成协议注册：安装后写
  `HKCU\Software\Classes\liiistem`（`URL Protocol` 空标记、
  `ApplicationName = "Liii STEM"`、`DefaultIcon`、
  `shell\open\command = "...\current\LiiiSTEM.exe" "%1"`），浏览器弹窗显示
  应用名由 `ApplicationName` 提供；
- scheme 定名 `liiistem`：已核查本机 HKCR/HKCU/HKLM（含 WOW6432Node）无冲突，
  官网前端无需提供任何按钮——授权后的 302 重定向本身触发浏览器协议确认弹窗，
  授权页的点击手势即满足浏览器对外部协议跳转的用户激活要求。
