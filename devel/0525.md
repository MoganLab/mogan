# [0525] OAuth 回调链路改造（二）：回调端口改系统动态分配

## 背景

承接 [0524] 的 redirect_uri 提取。回调服务器沿用固定端口列表分区
（`account.scm` 的 `port-list`，11 个端口），存在三个问题：

- **多实例上限**：第 12 个实例无端口可用，`m_port` 撞车回退到首端口，
  `isListening()` 为 false，`login()` 静默无反应，用户无任何反馈；
- **TOCTOU 竞态**：先用临时 `QTcpServer` 探测再关闭、随后 `m_reply` 重新绑定，
  两步之间端口可能被抢占；
- **常驻监听**：不登录也在构造时监听端口，暴露面大于必要。

RFC 8252 §7.3 的推荐做法：环回重定向由系统分配临时端口（`listen` 端口传 0），
授权服务器对环回地址必须接受任意端口。

## 改动

- `src/Plugins/Qt/QTMOAuth.cpp`
  - 构造函数删除端口列表读取/解析/探测整块（约 46 行），回调服务器改监听
    端口 0，实际端口由系统分配，绑定一步完成（无竞态窗口）；
  - `getRedirectUri ()` 改为 `return m_reply->callback ()`——redirect_uri 由
    回调服务器自报实际监听地址，构造上不可能与监听不一致；未监听时返回空串，
    由 `login ()` 开头的 `isListening ()` 守卫兜住；
  - 删除 `qtcpserver.h` include。
- `src/Plugins/Qt/QTMOAuth.hpp` — 删除 `int m_port;` 成员。
- `TeXmacs/plugins/account/progs/account/liii.scm` — 删除 `port-list` 配置项
  （含注释掉的本地配置副本）。

多实例效果：每个实例独立获得系统分配的临时端口（49152-65535 区间），
互不冲突，无数量上限。

## 配套（liii-server，另仓库）

后端授权校验必须同步放行，否则动态端口被"端口号必须在允许范围内"拒绝：

- `agent-server` 模块 `DirectUserAuthenticationConverter`：删除 11 端口白名单，
  环回地址接受任意端口（仅要求显式指定）；同时补上缺失的 scheme 校验
  （原先 `ftp://127.0.0.1:6029/callback` 亦可通过，现要求 loopback 必须 http）；
- 对应单测更新：缺端口 / https 为反例，临时高位端口为正例。

兼容性：后端先行部署无窗口期——旧版客户端的固定端口 redirect_uri 在新规则下
照常通过。前端（cn.liiistem）`OAuth2Login.vue` 为纯透传，零改动。

## 验证

本地分段验证（前端 127.0.0.1:3000，Vite 代理 `/api/v1/oauth2` → 后端 127.0.0.1:8082）：

- 授权页地址栏确认 `redirect_uri=http://127.0.0.1:<临时高位端口>/callback`，
  后端（新校验器）放行并签发授权码；
- 浏览器 302 回环回调，应用成功收到 code（`handleAuthorizationCode` 被触发）；
- 排障记录：应用直连 token 端点报 `Connection refused`，根因是本地配置块
  写的 8081 而后端实际监听 8082（`liii.scm` 本地注释块中仍为 8081，本地联调
  时需按实际端口调整）；
- 待办：配置修正后完整走通一次登录 + 双实例并发登录回归。
