# 0987 首选项转换页新增 AI 子标签页

## 需求

编辑 → 首选项 → 转换 标签页下新增 AI 子标签页（与 Html / LaTeX / BibTeX /
Verbatim / Pdf / Image 同级，排在最后），内含设置：

1. **AI 操作栏**开关（默认开启）：控制 0986 实现的选中文字后悬浮操作栏
   （🦞 翻译 / 润色 / 对话）是否出现；
2. **翻译目标语言**下拉（默认「按界面语言」）：AI 翻译拼提示词时读取
   （上游 0986 第二步已接入 AI 翻译，本 PR 把其中硬编码的「中文」改为读
   该偏好）。

## 测试方法

1. `xmake b stem` 构建通过；
2. `xmake r preferences-widgets-test`（Scheme 纯逻辑测试：子 tab 数量/顺序、
   AI 字段 kind、combo 首项 interface、options/optionsTr 等长、set-field
   往返落库与恢复）；
3. 手动 GUI 验证：首选项 → 转换出现 AI 子 tab；开关默认开启；选中文字
   出现操作栏 → 关闭开关后选中不再出现（≤100ms 缓存窗口）；翻译目标语言
   默认显示「界面语言」，可选语言列表，改动仅存 preferences.json、不影响
   现有行为。**社区版构建**（xmake 默认 `is_community=true`）下操作栏整体
   不弹（无 AI Chat 接收方），企业版构建下上述开关行为不变。

## 实现记录

### What

- 首选项 Convert 主 tab 新增第 7 个子 tab「AI」（`preferences-qml-meta`
  数据驱动，QML Preferences.qml 无功能改动，仅同步头注释）。
- 子 tab 含两个字段：toggle `ai:actions bar`（默认 on）与 combo
  `ai:translate target language`（默认 internal 键 `interface`，显示
  「User interface language」）。
- `should_show_translate_popup`（0986 操作栏的显示判定入口）增加两道门控：
  偏好非 "on" 即不弹；社区版（`is_community_stem()`）整体不弹。

### Why

- 首选项 QML facade 完全由 scheme 侧 meta 树驱动（bridge 通用解析 subTabs），
  新增子 tab 只需 scheme 侧组装，避免碰 QML/bridge。
- 翻译目标语言按任务要求暂不生效：本 PR 只落偏好存储与 UI，供后续
  一键翻译第二步 PR 读取。
- 操作栏开关需要真正生效：0986 的显示判定集中在
  `edit_interface_rep::should_show_translate_popup`（已有 100ms 结果缓存，
  scheme 调用开销可控），在此处加一道 `get_preference` 门控即可全局拦截
  弹出；关闭后已显示的操作栏在下一次选区/滚动/鼠标更新（≤100ms）隐藏。
- 社区版没有 AI Chat 基础设施（`SLOT_CHAT_SIDEBAR_VISIBILITY` 被忽略、
  侧边栏/标签页均未创建，`qt_chat_ai_send_selection` 因 `ctrl->view_`
  为空而静默返回），操作栏的翻译/润色/对话全是死按钮（表现为「点翻译没
  反应」）。与幽灵文本/聊天入口的社区版隐藏惯例一致，社区版下操作栏
  整体不弹。

### How

- `pref-keys.scm`：新增 `(pref-convert-ai-actions-bar)` → `"ai:actions bar"`、
  `(pref-convert-ai-translate-target)` → `"ai:translate target language"`
  （单一可信源惯例）。
- `tm-server.scm`：`define-preferences` 注册默认值 `"on"` / `"interface"`
  （未设置时 scheme `get-preference` 返回注册默认，首选项面板才能正确显示
  默认开启/界面语言）。
- `preferences-widgets.scm`：
  - `define-preference-names "ai:translate target language"` 登记
    `interface ↔ User interface language`，并 for 循环把 supported-languages
    各语言登记进 encode/decode 表（与 General 的 language 字段同法）；
  - 新增 `preferences-qml-convert-ai-fields`（toggle + combo，combo 静态
    options 留空 `'()` 避开模块加载期求值）；
  - `preferences-qml-meta` 的 convert 子 tab 列表尾部追加 `("ai" …)`。
- `preferences-tools.scm`：`resolve-options` 新增 AI 目标语言分支——options
  动态取 `("interface" . supported-languages)`、optionsTr 取
  `("User interface language" . (map upcase-first supported-languages))`，
  options/optionsTr 等长同序。
- `edit_mouse.cpp`：`should_show_translate_popup` 在 100ms 缓存之后、其它
  判定之前检查 `get_preference ("ai:actions bar", "on") != "on"` 即返回
  false；紧随其后 `is_community_stem ()` 为真（社区版）也返回 false。
  新增 include `preferences.hpp` 与 `tm_sys_utils.hpp`（key 字面值与
  pref-keys.scm 保持一致，同 conservative_fromtex.cpp 等 C++ 直读惯例）。
- 词典 `zh_CN.scm`：`("ai action bar" "AI 操作栏")`、
  `("translation target language" "翻译目标语言")`（按字母序插入；
  「User interface language」已有词条；AI 子 tab 标签 "AI" 无需词条，
  同 Html/Pdf 标签显示原样）。
- 测试 `preferences-widgets-test.scm`：子 tab 数量 6→7 并钉入 "ai" 顺序；
  新增 `test-ai-subtab-fields`（结构 + options 契约 + set-field 往返）；
  `test-key-consistency` 钉两个新 key。
- `qt_chat_controller.cpp`（rebase 到含 0986 第二步的上游后）：
  `composeAiInputBody` 的翻译提示词不再硬编码「中文」——读
  `ai:translate target language` 偏好，`interface`（默认）回退到界面语言
  `language` 偏好，语言名经 C++ `translate`（dictionary.cpp，输出 Cork）转成
  界面语言显示后拼入提示词；新增 include `preferences.hpp` / `analyze.hpp`
  （upcase_first）/ `dictionary.hpp`。测试 `qt_chat_controller_test.cpp`
  同步更新并新增两例（显式目标语言、interface 跟随界面语言；测试环境经
  `set_user_preference` 直写 C++ 偏好层，无 scheme boot、无词典，
  translate 原样返回）。

- `preferences-widgets-test.scm`：`test-meta-field-counts` 的 other 字段数

# 0987（续）AI 对话输入框固定档位伸缩

## 需求

AI 对话输入框（不限定 Chat 标签页还是 dock 侧边栏，两者共用
`ChatConversationPanel`）：按照输入框内容数量，输入框固定变化为现有的
2 倍、3 倍；删除已有的输入框大小变化机制（逐行渐变伸缩）。

## 测试方法

1. `xmake b qt_chat_tab_widget_test && xmake r qt_chat_tab_widget_test`
   （新增 `input_height_step_lines` 三档边界测试：1~3 行 → 3 行、
   4~6 行 → 6 行、7 行起 → 9 行封顶）；
2. `xmake b stem` 构建通过；
3. 手动 GUI 验证（企业版构建）：输入框输入 1~3 行内容高度不变；
   第 4 行出现时整个输入框一次跳为现有高度 2 倍；第 7 行出现时跳为
   3 倍并封顶，后续行在输入区内滚动；删除内容降回 3/6 行以内时
   逐档缩回；Chat 标签页与 AI 侧边栏行为一致。

## 实现记录

### What

- 删除旧的逐行渐变机制：`adjust_input_height` 按
  `clamp(行数, 3, 10)` 每增删一行变高/变矮一行的逻辑、`kInputMaxLines`
  常量、回车预扩一行逻辑中的逐行计算，以及无人连接的死信号
  `inputHeightChanged`。
- 新增固定档位机制 `input_height_step_lines(docLines)`：档位只有
  基准（3 行，即现有大小）的 1/2/3 倍三档——行数 ≤3 维持现有大小，
  4~6 行取 2 倍，≥7 行取 3 倍封顶（超出部分输入区内滚动）。
- `adjust_input_height` 与回车预扩档均改为调用该函数；Chat 标签页与
  侧边栏共用同一面板控件，一处修改两种场景同时生效。

### Why

- 逐行渐变导致输入框频繁小幅跳动，观感不稳；固定 2/3 倍档位使
  高度变化次数最少且可预期。
- `inputHeightChanged` 信号自引入起无任何连接方，属旧机制遗留死代码，
  一并删除。
- 回车预扩档（TeXmacs 处理按键前先放大 viewport，避免
  `cursor_visible()` 触发上滚）保留其防闪烁意图，仅把档位计算换成
  新机制，保证单一可信源。

### How

- `qt_chat_tab_widget.cpp`：
  - 删 `kInputMaxLines` 常量；
  - 新增静态 `ChatConversationPanel::input_height_step_lines`，输入
    行数映射为 3/6/9 可视行；
  - `adjust_input_height` 改为按档位设置 frame 高度（升档与缩档对称，
    高度不变则不动）；
  - `eventFilter` 回车分支预估 `行数 + 1` 取档位，仅升档不缩档，
    `setUpdatesEnabled(false)` + 0 延时恢复的防闪烁时序不变。
- `qt_chat_tab_widget.hpp`：声明 `input_height_step_lines`（Doxygen
  说明三档语义）；删除死信号 `inputHeightChanged`；同步
  `adjust_input_height` / `schedule_input_height_adjust` 的注释。
- 触发链路不变：KeyRelease/InputMethod/Drop/FocusIn 事件与 scheme 侧
  粘贴/表格变化经 `qt-chat-notify-input-height` 均仍走
  `schedule_input_height_adjust`（0 延时合并），仅末端计算换为档位。
- 测试 `qt_chat_tab_widget_test.cpp`：新增
  `test_input_height_step_lines_within_default/_double/_triple_capped`
  三例钉住档位边界。

### 二轮修订：块级内容（引用块等）不触发放大

- **What**：`count_input_lines` 改为只统计用户敲入的文本段——顶层
  原子串与行内包装（CONCAT/WITH）各计 1 行；引用块（quote-env）、
  表格、图片等块级内容计 0 行。删除 `find_table_node` /
  `count_table_rows`（旧行为递归探入 quote-env 统计内嵌表格行数，
  选区含表格的 AI 引用会误触发放大；[0332] 的表格行数驱动高度
  自适应随之被固定档位机制取代）。
- **Why**：AI 对话/翻译把选区包成 quote-env 注入输入框，引用内容是
  整块搬运而非用户敲入，不应推动 2/3 倍档位；表格、图片等同类块级
  注入内容同理。采用白名单式识别（只认文本段），未知块级标记一律
  不触发，避免逐个枚举遗漏。
- **How**：新增文件内静态 `is_input_text_paragraph` 判定顶层子节点
  是否计入行数；`count_input_lines` 仅累加文本段，空文档/非 DOCUMENT
  短路保持不变。测试新增六例：引用块不计行、引用块内表格行数不
  泄漏、顶层表格不计行、WITH 段计行、混合场景只按文本段计数、
  长引用块 + 提示词端到端维持基准档。
- **验证状态**：本轮改动后本机 `build/.packages` 包缓存丢失（磁盘
  清理误伤），单元测试未能完成运行；待环境恢复后补跑
  `xmake b qt_chat_tab_widget_test && xmake r qt_chat_tab_widget_test`。

### 三轮修订：外观块（插入 → 外观块 → 引用）行内标记形态

- **What**：二轮修订只挡住了块级形态的引用（`(quote-env (document …))`）。
  实测（headless `make 'quote-env` 诊断）发现 chat 输入区是 generic
  样式链，用户经 插入 → 外观块 → 引用 得到的是**行内标记形态**：
  `(concat (quote-env) "文字")`——标记是段落 CONCAT 里的空复合节点，
  该段此前被当作普通文本计行。本轮把「携带外观块行内标记的段落」
  也排除出计数。
- **Why**：外观块家族标记（prominent-menu：quote-env、quotation、
  verse、indent、jump-in、padded-center、padded-left-aligned、
  padded-right-aligned、compact、compressed、amplified、padded、
  overlined、underlined、bothlined、framed、ornamented）在 generic
  样式下全部退化为同款行内标记，均属特殊格式，不应触发放大；
  行内公式/样式（CONCAT 内 WITH）是正常输入内容，不得误伤。
- **How**：新增 `is_prominent_mark_label`（外观块家族标签清单，对应
  text-menu.scm 的 prominent-menu）与 `has_prominent_mark`（递归检测
  段内标记，标签经 `as_string (L (t))` 取得）；`is_input_text_paragraph`
  对 CONCAT/WITH 段落加一道「不含外观块标记」判定。实测三种引用形态
  （行内标记段、多段选区退化出的顶层空 `(quote-env)`、AI 引用的
  `(quote-env (document …))`）现均不计行。测试新增四例：实测形态
  计数、家族标记排除、行内公式不误伤、端到端档位。
- **验证**：`xmake b qt_chat_tab_widget_test && xmake r` 126 例全过；
  `xmake b stem`（企业版 `--is_community=n`）构建通过。期间本机构建
  环境曾出现 `build/.packages` 包缓存被清、`~/.xmake` 下 4 个空的
  qt 6.9.1 包目录误导解析、`libmogan.a` 归档损坏（8 字节空档）等
  问题，均已排查修复（重装 liii-tbox、删除空壳目录、重新归档）。
  手动 GUI 验证仍待用户执行。

### 四轮修订：需求更正——特殊格式内容照常计入、照常触发放大

- **需求更正**：用户明确「引用块这些也要放大」——特殊格式（引用块、
  表格等）的内容**同样属于输入框内容数量**，达到 4/7 行就要跳 2/3
  倍档。此前真正的问题是旧计数把 quote-env 整块只计 1 行，引用再长
  也不放大。二、三轮按「排除」方向实现，与本轮语义相反，**已被
  本轮取代**（上文二、三两节仅作过程记录，最终以本节为准）。
- **What**：`count_input_lines` 改为递归计入全部内容：
  - 原子串、行内包装（CONCAT/WITH）各计 1 行；
  - 引用块等块级包装（quote-env 宽形态、列表等）按其**内部文档**
    递归计行；
  - 表格族恢复按行数计（0332 行为回归，`find_table_node` /
    `count_table_rows` 恢复使用）；
  - 插入 → 外观块 → 引用 在 generic 样式下的行内标记形态
    `(concat (quote-env) "文字")` 的段落照常计 1 行，其后续普通段
    逐段计入。
- **Why**：固定档位的判定依据是「输入框内容数量」，不区分内容是
  用户敲入还是引用/粘贴注入；只有把块级包装的内部内容递归计入，
  引用长文时输入框才会按 2/3 倍放大。
- **How**：新增 `count_input_lines_rec`（行内 1 行、DOCUMENT 累加、
  块级转 `count_block_lines`）与 `count_block_lines`（取首个 DOCUMENT
  子节点递归，无则按表格族行数，再无则 1 行）；删除二、三轮的
  `is_prominent_mark_label` / `has_prominent_mark` /
  `is_input_text_paragraph` 排除机制。测试 12 例改写为计入语义
  （引用内容计行、引用内表格计行、顶层表格计行、列表递归、混合
  场景、行内标记段计行、端到端引用触发 3 倍档等）。
- **验证**：`xmake r qt_chat_tab_widget_test` **127 例全过**；
  `xmake b stem`（企业版）构建通过。

### 五轮修订：档位扩为基准的 1~5 倍

- **What**：用户反馈 3 倍封顶仍太小，档位改为基准（3 行）的
  **1/2/3/4/5 倍**：1~3 行维持现有大小，4~6 行 2 倍，7~9 行 3 倍，

### 追加修订（2026-09-16）：操作栏「润色」接入既有润色功能（等同 Tab）

#### What

AI 操作栏「润色」按钮从「仅关闭操作栏」改为触发既有的 AI Suggestion 自动
润色（0872 的 diff-text），与选中文本后按 Tab 快捷键完全同一入口：选区送
`diff-cloud-polish`，模型返回后以 `version-both` 差异节点原位替换选区，
Enter 接受 / Escape 拒绝逐处审阅。

#### Why

- Tab 的润色入口是 `diff-text.scm` 的 `kbd-tab`（`:require (diff-enable?
  && selection-active?)` → `trigger-diff-text`），按钮直接转调
  `trigger-diff-text` 即天然等同：函数内部自带 `(when (diff-enable?) ...)`
  门控（`diff-cloud-polish` 由企业版 AI 插件定义，社区版未定义时 no-op），
  C++ 侧无需重复判社区版。
- 与翻译/对话不同，润色不开侧边栏、无焦点/视图切换，scheme 侧同步读当前
  选区即可（无「先捕获再切换」约束）；操作栏 popup 是画布子 widget，点击
  按钮不清选区（0986 第二步翻译链路已实证点击时选区仍在）。
- 润色差异节点替换选区后选区变化，操作栏 dismissed 缓存随之失效复位，
  新选区上操作栏照常弹出，无需额外处理。

#### How

- `edit_interface_rep::ai_action`（`edit_mouse.cpp`）：选区判空提为外层
  `if (selection_active_any ())`（三个动作共用，语义不变），内层新增
  `action == "polish"` 分支 `call ("trigger-diff-text")`（scheme.hpp 已
  include，同文件 `call ("in-math?")` 同法）；非 Qt 构建维持
  `(void) action;`。`(generic diff-text)` 模块随 generic-kbd.scm 常规加载，
  文档打开编辑时符号必已定义。
- `QTMAiTranslatePopup.cpp` 构造处「润色后续接入」注释同步更新。
- 无新增自动化测试：改动为单行桥接调用，`trigger-diff-text` 依赖企业版
  AI 插件（模型异步响应），无纯逻辑可断言（同 1248「GUI 键盘交互不新增
  单元测试」惯例）；以构建 + 既有回归测试 + 手动 GUI 验证覆盖。
