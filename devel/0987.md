# 0987 首选项转换页新增 AI 子标签页

## 需求

编辑 → 首选项 → 转换 标签页下新增 AI 子标签页（与 Html / LaTeX / BibTeX /
Verbatim / Pdf / Image 同级，排在最后），内含设置：

1. **AI 操作栏**开关（默认开启）：控制 0986 实现的选中文字后悬浮操作栏
   （🦞 翻译 / 润色 / 对话）是否出现；
2. **翻译目标语言**下拉（默认「按界面语言」）：AI 翻译拼提示词时读取
   （上游 0986 第二步已接入 AI 翻译，本 PR 把其中硬编码的「中文」改为读
   该偏好）。

## 测试方法

1. `xmake b stem` 构建通过；
2. `xmake r preferences-widgets-test`（Scheme 纯逻辑测试：子 tab 数量/顺序、
   AI 字段 kind、combo 首项 interface、options/optionsTr 等长、set-field
   往返落库与恢复）；
3. 手动 GUI 验证：首选项 → 转换出现 AI 子 tab；开关默认开启；选中文字
   出现操作栏 → 关闭开关后选中不再出现（≤100ms 缓存窗口）；翻译目标语言
   默认显示「界面语言」，可选语言列表，改动仅存 preferences.json、不影响
   现有行为。**社区版构建**（xmake 默认 `is_community=true`）下操作栏整体
   不弹（无 AI Chat 接收方），企业版构建下上述开关行为不变。

## 实现记录

### What

- 首选项 Convert 主 tab 新增第 7 个子 tab「AI」（`preferences-qml-meta`
  数据驱动，QML Preferences.qml 无功能改动，仅同步头注释）。
- 子 tab 含两个字段：toggle `ai:actions bar`（默认 on）与 combo
  `ai:translate target language`（默认 internal 键 `interface`，显示
  「User interface language」）。
- `should_show_translate_popup`（0986 操作栏的显示判定入口）增加两道门控：
  偏好非 "on" 即不弹；社区版（`is_community_stem()`）整体不弹。

### Why

- 首选项 QML facade 完全由 scheme 侧 meta 树驱动（bridge 通用解析 subTabs），
  新增子 tab 只需 scheme 侧组装，避免碰 QML/bridge。
- 翻译目标语言按任务要求暂不生效：本 PR 只落偏好存储与 UI，供后续
  一键翻译第二步 PR 读取。
- 操作栏开关需要真正生效：0986 的显示判定集中在
  `edit_interface_rep::should_show_translate_popup`（已有 100ms 结果缓存，
  scheme 调用开销可控），在此处加一道 `get_preference` 门控即可全局拦截
  弹出；关闭后已显示的操作栏在下一次选区/滚动/鼠标更新（≤100ms）隐藏。
- 社区版没有 AI Chat 基础设施（`SLOT_CHAT_SIDEBAR_VISIBILITY` 被忽略、
  侧边栏/标签页均未创建，`qt_chat_ai_send_selection` 因 `ctrl->view_`
  为空而静默返回），操作栏的翻译/润色/对话全是死按钮（表现为「点翻译没
  反应」）。与幽灵文本/聊天入口的社区版隐藏惯例一致，社区版下操作栏
  整体不弹。

### How

- `pref-keys.scm`：新增 `(pref-convert-ai-actions-bar)` → `"ai:actions bar"`、
  `(pref-convert-ai-translate-target)` → `"ai:translate target language"`
  （单一可信源惯例）。
- `tm-server.scm`：`define-preferences` 注册默认值 `"on"` / `"interface"`
  （未设置时 scheme `get-preference` 返回注册默认，首选项面板才能正确显示
  默认开启/界面语言）。
- `preferences-widgets.scm`：
  - `define-preference-names "ai:translate target language"` 登记
    `interface ↔ User interface language`，并 for 循环把 supported-languages
    各语言登记进 encode/decode 表（与 General 的 language 字段同法）；
  - 新增 `preferences-qml-convert-ai-fields`（toggle + combo，combo 静态
    options 留空 `'()` 避开模块加载期求值）；
  - `preferences-qml-meta` 的 convert 子 tab 列表尾部追加 `("ai" …)`。
- `preferences-tools.scm`：`resolve-options` 新增 AI 目标语言分支——options
  动态取 `("interface" . supported-languages)`、optionsTr 取
  `("User interface language" . (map upcase-first supported-languages))`，
  options/optionsTr 等长同序。
- `edit_mouse.cpp`：`should_show_translate_popup` 在 100ms 缓存之后、其它
  判定之前检查 `get_preference ("ai:actions bar", "on") != "on"` 即返回
  false；紧随其后 `is_community_stem ()` 为真（社区版）也返回 false。
  新增 include `preferences.hpp` 与 `tm_sys_utils.hpp`（key 字面值与
  pref-keys.scm 保持一致，同 conservative_fromtex.cpp 等 C++ 直读惯例）。
- 词典 `zh_CN.scm`：`("ai action bar" "AI 操作栏")`、
  `("translation target language" "翻译目标语言")`（按字母序插入；
  「User interface language」已有词条；AI 子 tab 标签 "AI" 无需词条，
  同 Html/Pdf 标签显示原样）。
- 测试 `preferences-widgets-test.scm`：子 tab 数量 6→7 并钉入 "ai" 顺序；
  新增 `test-ai-subtab-fields`（结构 + options 契约 + set-field 往返）；
  `test-key-consistency` 钉两个新 key。
- `qt_chat_controller.cpp`（rebase 到含 0986 第二步的上游后）：
  `composeAiInputBody` 的翻译提示词不再硬编码「中文」——读
  `ai:translate target language` 偏好，`interface`（默认）回退到界面语言
  `language` 偏好，语言名经 C++ `translate`（dictionary.cpp，输出 Cork）转成
  界面语言显示后拼入提示词；新增 include `preferences.hpp` / `analyze.hpp`
  （upcase_first）/ `dictionary.hpp`。测试 `qt_chat_controller_test.cpp`
  同步更新并新增两例（显式目标语言、interface 跟随界面语言；测试环境经
  `set_user_preference` 直写 C++ 偏好层，无 scheme boot、无词典，
  translate 原样返回）。

- `preferences-widgets-test.scm`：`test-meta-field-counts` 的 other 字段数
  期望改为按 `(community-stem?)` 区分——非社区版多 1 个 Ghost text 实验选项
  （上游 #4413 起社区版隐藏；上游原期望只在社区版构建下成立，企业版构建
  跑该测试会差 1）。

### 构建版本说明

`xmake f -c` 会把 `is_community` 重置为默认 `true`（社区版）。社区版下
幽灵文本选项（其他 → 实验性功能）与 AI Chat 基础设施均被上游隐藏/禁用，
AI 操作栏即使弹出也是死按钮。验证幽灵文本、AI 翻译等功能须用企业版：
`xmake f --is_community=n --yes && xmake b stem && xmake install --yes stem`。

### 追加修订（2026-09-16）：操作栏「润色」接入既有润色功能（等同 Tab）

#### What

AI 操作栏「润色」按钮从「仅关闭操作栏」改为触发既有的 AI Suggestion 自动
润色（0872 的 diff-text），与选中文本后按 Tab 快捷键完全同一入口：选区送
`diff-cloud-polish`，模型返回后以 `version-both` 差异节点原位替换选区，
Enter 接受 / Escape 拒绝逐处审阅。

#### Why

- Tab 的润色入口是 `diff-text.scm` 的 `kbd-tab`（`:require (diff-enable?
  && selection-active?)` → `trigger-diff-text`），按钮直接转调
  `trigger-diff-text` 即天然等同：函数内部自带 `(when (diff-enable?) ...)`
  门控（`diff-cloud-polish` 由企业版 AI 插件定义，社区版未定义时 no-op），
  C++ 侧无需重复判社区版。
- 与翻译/对话不同，润色不开侧边栏、无焦点/视图切换，scheme 侧同步读当前
  选区即可（无「先捕获再切换」约束）；操作栏 popup 是画布子 widget，点击
  按钮不清选区（0986 第二步翻译链路已实证点击时选区仍在）。
- 润色差异节点替换选区后选区变化，操作栏 dismissed 缓存随之失效复位，
  新选区上操作栏照常弹出，无需额外处理。

#### How

- `edit_interface_rep::ai_action`（`edit_mouse.cpp`）：选区判空提为外层
  `if (selection_active_any ())`（三个动作共用，语义不变），内层新增
  `action == "polish"` 分支 `call ("trigger-diff-text")`（scheme.hpp 已
  include，同文件 `call ("in-math?")` 同法）；非 Qt 构建维持
  `(void) action;`。`(generic diff-text)` 模块随 generic-kbd.scm 常规加载，
  文档打开编辑时符号必已定义。
- `QTMAiTranslatePopup.cpp` 构造处「润色后续接入」注释同步更新。
- 无新增自动化测试：改动为单行桥接调用，`trigger-diff-text` 依赖企业版
  AI 插件（模型异步响应），无纯逻辑可断言（同 1248「GUI 键盘交互不新增
  单元测试」惯例）；以构建 + 既有回归测试 + 手动 GUI 验证覆盖。
