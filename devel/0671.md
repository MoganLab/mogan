
### 3.2 非确定性测试（启动 R7RS 会话）
直接运行 R7RS 会话入口，验证 `goldfish-welcome` 不再因 `string-upcase` 未绑定而崩溃：
```bash
./TeXmacs/plugins/goldfish/bin/goldfish \
  ./TeXmacs/plugins/goldfish/goldfish/tm-goldfish.scm -m r7rs
```
预期输出（开头两行）：
```
prompt#R7RS] 
verbatim:Goldfish Scheme 18.11.11 Community Edition by LiiiLabs
implemented on S7 Scheme (11.5, 22-Sep-2025)
```
不应再出现 `;unbound variable string-upcase`。

## 5 What
1. 修复 R7RS 会话启动时崩溃的问题：在 `TeXmacs/plugins/goldfish/goldfish/goldfish/repl.scm` 的 `(goldfish repl)` 库导入列表中增加 `(scheme char)`。
2. 仅改动一行 import，其余逻辑保持不变。

## 6 Why
`[2004]` 将 goldfish 从 17.11.55 升级至 18.11.11 时，s7 实现从 `3rdparty/s7` 迁移到 `TeXmacs/plugins/goldfish/src`，同时 `string-upcase` 的提供方式发生变化：
- 旧版 s7 在 C 层通过 `s7_define_typed_function` 把 `string-upcase` 注册为全局原语，任何 Scheme 代码无需 import 即可调用。
- 新版 goldfish 18.11.11 不再保留这个全局 C 原语，而是把 `string-upcase` 实现为 R7RS 库 `(scheme char)` 的导出过程（见 `TeXmacs/plugins/goldfish/goldfish/scheme/char.scm` 第 5868 行）。

`repl.scm` 中的 `goldfish-welcome` 在 R7RS 模式下会执行 `(string-upcase mode)`，以把 `r7rs` 渲染为大写提示符 `R7RS]`。由于 `(goldfish repl)` 原本只导入 `(texmacs protocol) (liii list) (liii string) (liii sys) (liii base)`，其中 `(liii string)` 并不导出 `string-upcase`，因此升级后该符号在库环境中未绑定，启动即报错。

## 7 How
在 `(goldfish repl)` 的 `import` 中追加 `(scheme char)`，使其获得 R7RS 标准的 `string-upcase` / `string-downcase` / `string-foldcase` 等字符/字符串大小写过程。这是 goldfish 18.11.11 提供的标准库，无需改动 C 层或 goldfish 上游源码。
