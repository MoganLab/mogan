# [0772] 协作同步整个文档（不只是 body）

## 1 背景（Why）

协作（Loro CRDT）此前只同步文档的 `<body>` 子树：文档加载时 `detach_data`
（`src/Data/Document/new_data.cpp`）把 `style`/`initial`/`project`/`final`/
`references`/`auxiliary`/`attachments` 全部剥离进 `buf->data`，只有 `body` 进编辑树
`buf->rp`；而 CRDT 入口 `ensure_loro_seeded`/`mirror_loro`/`apply_remote` 都以
`the_buffer()`（= body）为根。结果是协作者看不到彼此的样式、页面设置等。

目标：把用户创作的整篇文档纳入 CRDT 同步——`body` + `style` + `initial` + `project`
+ `final` + `attachments`。**排除** `references`/`auxiliary`（排版器对 body+style 求得
的派生数据，各端本地生成，同步会在并发排版时产生无意义冲突）与 `TeXmacs` 版本号。

## 2 方案（How）

**单 LoroDoc + 单 LoroTree + 多 root**：
- `body` 保持 `roots[0]`，现有字符级/结构级镜像路径**零改动**（最高频路径，零回归）。
- 5 个 meta section（style/initial/final/project/attachments）各作为该 LoroTree 的一个
  独立 root，其 meta 写 `__section__` 标签区分。LoroTree 原生支持多 root。
- `export`/`import`/`subscribe_local_update`/`advance_export_vv` 都是 doc 级——一条
  update 流天然携带全部 section，**服务端 + 会话层 + scheme 零改动**。
- 关键约束：FFI 的 `subscribe_local_update` 订阅以 `doc as usize` 为键，多 shadow 共享
  同一 doc 会让后注册者覆盖前者订阅 → 广播丢段。故采用 **单 shadow + meta 侧栏 map**。
- meta 用 **coarse 镜像**（删旧 root + 重建），section 粒度 Loro LWW 合并；metadata 改动
  稀疏，不需要字符级 CRDT。

### 数据流

- 本地 body 编辑：`edit_announce→edit_done→mirror_loro→mirror_mod`（不变）。
- 本地 meta 编辑：setter → `mirror_meta_if_active(section)` →
  `shadow.mirror_meta_replace`（删旧 root+重建+commit）→ `local_update_cb`（doc 级）
  → 广播。
- 远端 update：`apply_remote` → `remote_diff_mods`（内部 import 整 doc，含 meta root）
  → body apply（不变）+ `apply_remote_meta`（回写 `buf->data`）→ notify。
- JOIN：import A 的 snapshot → 同上；`ensure_loro_seeded` 末尾补 seed 本端缺失的 meta。

### 关键正确性点

- **`apply_remote` 改动是纯追加**：`remote_diff_mods` 已在内部 import 整 doc，meta root
  一并就位，body 路径不动，末尾追加 `apply_remote_meta`，`loro_applying_remote=false`
  后移到 meta 回写之后。
- **initial 同步剔除显示专用变量**（`PAGE_SCREEN_WIDTH/HEIGHT`、`ZOOM_FACTOR`、
  `full-screen-mode`），与 `attach_data` 一致；回写时保留本端显示变量、文档变量取远端。
- **比较用 hashmap 等值**（顺序无关），因 `make_collection` 遍历 hashmap 顺序不确定。
- **回环防护**：`loro_applying_remote` 守卫贯穿 `apply_remote_meta`，所有 setter 钩子
  首行检查该标志。
- **三个新方法实现在 `edit_main_rep`**：它同时继承 `edit_modify_rep`（持 `loro_doc`）与
  `edit_typeset_rep`（持 style/init getter/setter），二者是兄弟 mixin，故方法须落在
  汇聚子类。

## 5 已知限制 / 后续

- metadata 是 **section 粒度 LWW**（非字段/字符级）：两端同时改同一 section，按 Loro
  LWW 取胜者。对样式/页面等稀疏改动可接受；如需字段级合并（如 initial 的不同环境变量
  并发共存），后续可把 initial 映射成 LoroMap。
- `project` 在会话开始时 seed；会话中途改 project 不会实时镜像（project 极少中途改）。
- `references`/`auxiliary` 不同步（派生数据）。
