# 216_22 PDF 预览控件悬停按钮修复

## 如何测试
1. 编译：`xmake b stem`
2. 打开启动页 `Template` 页面，点击任意模板卡片打开预览弹窗。
3. 确认首次打开时，鼠标悬停在预览区域上，左右翻页按钮和页码指示器正常显示。
4. 关闭弹窗后再次打开同一模板（走缓存路径），确认悬停按钮依然正常显示。
5. 测试翻页功能是否正常，按钮在单页 PDF 时是否隐藏。

## 2026/04/20 实现说明

### What
本次修复 PDF 预览控件（`QTPdfPreviewWidget`）悬停按钮在缓存命中时不显示的问题：
- **缓存命中时按钮不显示**：第二次打开同一模板时，缓存命中导致 `pageCount_` 为 0，按钮被隐藏。
- **鼠标跟踪优化**：修复鼠标从预览容器移到按钮时按钮闪烁/隐藏的问题。

#### 修改文件

**src/Plugins/Qt/qt_pdf_preview_widget.cpp** (修改)
- 缓存命中处理（`loadFromUrl`, `loadFromFile`）：
  - 缓存命中时临时设置 `pageCount_ = 2` 以显示按钮。
  - 继续发起网络/文件请求获取 PDF 数据以确定真实页数。
  - 检查鼠标位置，如果在预览区域上则立即显示按钮。
- 事件过滤器优化：
  - 为所有相关控件（按钮、页码指示器、预览标签）安装事件过滤器。
  - 启用鼠标跟踪以接收 `HoverMove` 事件。
  - 使用 `underMouse()` 替代依赖 `Enter/Leave` 事件，避免子控件间切换时按钮闪烁。
- 代码优化：
  - 提取 `mouseInWidgetHierarchy()` 成员函数，避免 lambda 重复创建。
  - 提取 `goToPage()` 公共方法，消除 `goToPreviousPage`/`goToNextPage` 重复代码。
  - 移除 `updatePageControls` 重复调用。
  - 网络错误时清理 `pdfData_` 避免残留。
  - 移除未使用的 `QHBoxLayout` 头文件。

**src/Plugins/Qt/qt_pdf_preview_widget.hpp** (修改)
- 新增 `mouseInWidgetHierarchy()` 方法声明。
- 新增 `goToPage(int page)` 槽函数声明。

### Why
1. **缓存命中时按钮不显示**：原代码在缓存命中时直接返回，未设置 `pageCount_`，导致 `setControlsVisible` 中判断 `pageCount_ > 1` 失败。
2. **按钮闪烁问题**：原事件过滤器只监控 `previewContainer_`，当鼠标从容器移到按钮时，容器的 `Leave` 事件会隐藏按钮，而按钮因被隐藏接收不到 `Enter` 事件。
3. **widget 创建时鼠标已在区域上**：Qt 不会为新创建的 widget 发送 `Enter` 事件，需要主动检查 `underMouse()`。

### How
1. **缓存命中处理**：
   - 缓存命中时立即显示缓存图片，临时设置 `pageCount_ = 2` 让按钮显示。
   - 不提前返回，继续获取 PDF 数据以更新真实页数。
2. **事件过滤器优化**：
   - 为所有相关控件安装事件过滤器，统一处理悬停事件。
   - 使用 `QTimer::singleShot(50, ...)` 延迟检查 `underMouse()`，避免子控件间切换时误判。
3. **性能优化**：
   - `mouseInWidgetHierarchy` 改为成员函数，避免每次事件触发都创建 lambda。
   - `goToPage` 提取公共逻辑，减少重复代码。
