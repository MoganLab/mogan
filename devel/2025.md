### 3.2 非确定性测试（文档验证）

前置：使用**商业版**（非 community）构建，社区版登录按钮行为本身已与本任务一致，无法区分。

1. **未登录态启动**：冷启动后观察标题栏左侧登录按钮——按钮宽度应为 60px（与系统按钮等宽），仅显示图标，无任何文字，鼠标悬停 tooltip 显示「用户中心」；
2. **未登录 → 已登录切换**：完成登录，等待用户信息返回，观察按钮——尺寸、外观、文字均无变化（仍然 60px、仅图标）；

4. **半屏 / 最大化切换**：把窗口在半屏 ↔ 最大化之间反复拖动，登录按钮尺寸始终保持 60px，不出现文字，不闪烁；

## 5 What

1. **删除 `updateLoginButtonState` 函数**：原本根据登录态动态切换按钮文字（「未登录」/空）、tooltip、宽度（120px/60px）与 QSS 状态属性（`not-logged-in`/`logged-in`），现在统一为已登录样式，函数不再需要。
2. **删除全部 4 处调用点**：构造函数初始调用、`QTMOAuth::loginStateChanged` 信号回调、account 初始化同步调用、`updateDialogContent` 中的状态同步调用——全部移除。
3. **构造函数统一设置**：把原本只在 `is_community_stem()` 分支执行的 `setText/ToolTip/AccessibleName` 三行提取到 `if` 之前，社区版与商业版共用，构造时一次性完成按钮外观配置。
4. **CSS 状态选择器清理**：删除 `[login-state="not-logged-in"]` 与 `[login-state="logged-in"]` 两条规则，颜色值合并到无状态的 `#login-button` 选择器，避免维护永远只会取一个值的状态分支。
5. **`updateHalfScreenUi_onResize` 改回 `updateVipButtonVisibility_onResize`**：上一任务（2024）为了让 resize 同时刷新 VIP 按钮和 login 按钮而改成通用名，本任务删除了 login 按钮的运行期更新需求，函数只剩一处调用，名字恢复贴切。
6. **清理未使用的 `<QFontMetrics>` include**：原函数用 `QFontMetrics` 计算文字宽度，删除后无人引用。
7. **VIP 预留宽度回归**：`QTMTabPage.cpp` 中 VIP 预留宽度从 110 调回 90（本任务范围内的微调，注释同步改为「邀请按钮」）。

## 6 Why

旧登录按钮设计在未登录态显示「未登录」文字并扩宽到 ~120px，已登录态收回到 60px 只显示图标。这套动态宽度逻辑带来三个问题：

1. **运行期频繁重排**：登录、登出、网络状态变化都会触发按钮宽度切换，连带 `parentWidget()->layout()->activate()` 反复重排标题栏，半屏下与 VIP 按钮显隐叠加时容易引起标签页布局抖动。
2. **维护成本高**：状态分支由 C++（`setProperty`）、QSS（`[login-state="..."]` 选择器）、字体度量计算（`QFontMetrics` elidedText）三层协同维护，任何一处改了都要担心另外两处是否同步，但实际产品诉求只有「让用户认得这是登录入口」。
3. **状态语义混乱**：`updateLoginButtonState(isLoggedIn, displayName)` 的参数和真实登录态耦合，但 2024 任务为了半屏压缩又需要在函数内部把 `isLoggedIn` 改写为 `true`，参数变成了「实际登录态」与「期望渲染态」的混合体，阅读困难。

产品诉求上，登录按钮始终承担「点击进入用户中心 / 登录入口」的功能，文字标签并非必要信息（图标 + tooltip 足够），统一为已登录样式后上述三个问题一并消除：构造时一次性配置，运行期零更新；C++ 不再写状态属性，QSS 不再有状态分支；调用方不再需要传登录态参数。

## 7 How

整体策略：**做减法**，让登录按钮的渲染完全由构造函数决定，运行期不可变。

### 7.1 构造函数统一外观

把社区版分支里的 3 行外观设置提到 `if (is_community_stem ())` 之前，社区版和商业版共用：

```cpp
// 永远按已登录样式渲染：只图标、固定 60px 宽（构造时 setFixedSize 已设定）
loginButton->setText (QString ());
loginButton->setToolTip (qt_translate ("User Center"));
loginButton->setAccessibleName (qt_translate ("User Center"));

if (is_community_stem ()) {
  // 社区版：点击跳转官网
}
else {
  // 商业版：弹出登录对话框
}
```

按钮的尺寸（`setFixedSize (buttonWidth=60, buttonHeight=42)`）、图标（`setIconNormal`）、object name 在两个分支之前就已设置好，这 3 行只是补齐「文字内容」和「无障碍/tooltip」文案。

### 7.2 删除 `updateLoginButtonState` 与所有调用

调用点共 4 处，全部直接删除（不需要替换为别的调用）：

| 调用点 | 处理方式 |
|---|---|
| 商业版构造函数初始 `updateLoginButtonState (false)` | 替换为 7.1 的 3 行内联设置 |
| `QTMOAuth::loginStateChanged` 信号回调内 | 直接删除，回调只保留 SCM 通知 / 网络检查副作用 |
| account 初始化同步调用 | 直接删除，只保留 `if (account->isLoggedIn ()) refreshMembershipInfoInBackground ();` |
| `updateDialogContent` 末尾 | 直接删除，函数其它逻辑（弹窗字段更新、VIP 按钮刷新）不受影响 |

函数定义本身（约 60 行，含 `QFontMetrics` 文字宽度计算、`applyWidth` lambda、`QTimer::singleShot` 延迟应用宽度等）整段删除。

### 7.3 CSS 去状态化

原 CSS：

```css
#login-button { qproperty-iconNormal: ...; }

#login-button[login-state="not-logged-in"] { color: #0078d4; }  /* 蓝色强调 */
#login-button[login-state="logged-in"]     { color: #2c2c2c; }  /* 常规色 */
```

C++ 不再调 `setProperty("login-state", ...)` 后，两条状态选择器都不会命中，按钮颜色会丢失。直接合并为：

```css
#login-button {
  qproperty-iconNormal: ...;
  color: #2c2c2c;
}
```

夜间主题同理（`#ffffff`）。这样 CSS 也不再维护永远只取一个值的状态分支。

### 7.4 重命名回 `updateVipButtonVisibility_onResize`

2024 任务为了让 resize 同时刷新 VIP 按钮和 login 按钮，把函数改成 `updateHalfScreenUi_onResize`。本任务删除了 login 按钮的运行期更新，回调里只剩 `updateVipButtonVisibility` 一个调用，函数名恢复为 `updateVipButtonVisibility_onResize` 更贴切。

### 7.5 VIP 预留宽度微调

`arrangeTabPages` 里 VIP 按钮预留宽度由 110 调回 90。原 110 是 2024 任务为了给 VIP 按钮和系统按钮之间留间距加上的，本任务范围内验证发现 90 已足够（VIP 按钮自身 90px 宽度刚好覆盖），多预留的 20px 在半屏下会浪费标签页可用空间。
