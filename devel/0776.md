# [0776] 协作编辑：输入法 pre-edit 不同步

## 背景（Why）

输入法（IME）预编辑文本以 `<pre-edit|s>` 节点经标准编辑路径插入（`edit_keyboard.cpp`
的 `insert_tree`），提交时再由 `mark_cancel` 回撤。二者都走
`edit_announce → edit_done → mirror_loro`，导致对端看到预编辑节点随输入反复出现/消失。
预编辑期间光标也落在未同步的临时节点内，其位置对对端无意义。

## 实现（How）

以既有的「是否处于 pre-edit」权威状态 `pre_edit_mark != 0` 为判据（置位于
`edit_keyboard.cpp:328`，提交回撤**之后**才清零于 `:288`），在协作上行的两个出口加门：

- `editor.hpp`：新增虚函数 `is_pre_editing()`，默认 `return false`（其余 mixin 自动继承）。
- `edit_interface.hpp`：override 为 `return pre_edit_mark != 0`。
- `edit_collab.cpp`：
  - `mirror_loro` 首部 `if (is_pre_editing()) return;` —— 跳过预编辑节点的插入与
    `mark_cancel` 回撤（回撤发生时 `pre_edit_mark` 仍未清零，故一并覆盖）。
  - `collab_cursor_payload` 首部 `if (is_pre_editing()) return "";` —— 预编辑期间不上行光标。

提交的正式文本在 `pre_edit_mark` 清零后才插入，仍正常同步；光标也恢复正常上行。
ImGui 的并行预编辑路径复用同一 `key_press`，一并覆盖。

## 涉及文件

- `src/Edit/editor.hpp`
- `src/Edit/Interface/edit_interface.hpp`
- `src/Edit/Modify/edit_collab.cpp`

## 如何测试

手动（GUI）：
1. 两端进入同一协作会话。
2. A 端用输入法输入中文（预编辑串仅 A 本地可见）。
3. 预期：B 端**看不到** `<pre-edit>` 节点闪烁、也看不到 A 光标在预编辑期间跳动；
   A 提交后 B 端出现最终提交的文本。

```
xmake b stem        # 确认 loro option 开启
gf fmt --changed-since=main   # 提交前
```
