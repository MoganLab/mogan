# 1193 规范化插件模块命名

## 任务 8：插件 binary 定义模块命名空间规范化

### What

4 个插件的 binary 定义模块从共享命名空间 `(binary ...)` 改为插件专属 `(<plugin> <plugin>-binary)`：

| 插件 | 旧模块名 | 新模块名 | 文件位置变更 |
|------|---------|---------|------------|
| gnuplot | `(binary gnuplot)` | `(gnuplot gnuplot-binary)` | `progs/binary/` → `progs/gnuplot/gnuplot-binary.scm` |
| maxima | `(binary maxima)` | `(maxima maxima-binary)` | `progs/binary/` → `progs/maxima/maxima-binary.scm` |
| julia | `(binary julia)` | `(julia julia-binary)` | 从共享 binary 插件移至 `progs/julia/julia-binary.scm` |
| python | `(binary python3)` | `(python python-binary)` | 从共享 binary 插件移至 `progs/python/python-binary.scm` |

同时将 tikz 插件内的 pdflatex 定义 `(binary pdflatex)` 移至共享 binary 插件
（pdflatex 是通用工具，非 tikz 专属）。

### Why

插件内模块命名规范：必须以插件名开头。`(binary gnuplot)` 等占据 binary 命名空间，
违反规范。改为 `(<plugin> <plugin>-binary)` 后与 language 模块 `(<plugin> <plugin>-lang)`
和 format 模块 `(<plugin> <plugin>-format)` 命名模式一致。

### How

- 模块声明从 `(texmacs-module (binary <name>) ...)` 改为 `(<plugin> <plugin>-binary)`
- 文件从 `progs/binary/<name>.scm` 迁移到 `progs/<plugin>/<plugin>-binary.scm`
- 各 init 文件中 `use-modules` 引用同步更新

### 涉及文件

- `TeXmacs/plugins/gnuplot/progs/gnuplot/gnuplot-binary.scm`（改名+重命名）
- `TeXmacs/plugins/gnuplot/progs/init-gnuplot.scm`
- `TeXmacs/plugins/maxima/progs/maxima/maxima-binary.scm`（改名+重命名）
- `TeXmacs/plugins/maxima/progs/init-maxima.scm`
- `TeXmacs/plugins/julia/progs/julia/julia-binary.scm`（从 binary 插件移入）
- `TeXmacs/plugins/julia/progs/init-julia.scm`
- `TeXmacs/plugins/python/progs/python/python-binary.scm`（从 binary 插件移入）
- `TeXmacs/plugins/python/progs/init-python.scm`
- `TeXmacs/plugins/binary/progs/binary/pdflatex.scm`（从 tikz 插件移入）

### 如何测试

`xmake b stem` 构建通过即可（binary 查找逻辑不变，仅模块名变更）。

## 任务 4：语言插件模块命名空间规范化

### What

19 个语言插件的模块一级命名空间从共享的 `code` 改为插件专属命名：

| 插件 | 旧模块名 | 新模块名 |
|------|---------|---------|
| bash | `(code bash-edit\|bash-lang\|bash-mode)` | `(bash bash-edit\|bash-lang\|bash-mode)` |
| json | `(code json-lang)` | `(json json-lang)` |
| csv | `(code csv-lang)` | `(csv csv-lang)` |
| java | `(code java-edit\|java-lang)` | `(java java-edit\|java-lang)` |
| javascript | `(code javascript-lang)` | `(javascript javascript-lang)` |
| lua | `(code lua-edit\|lua-lang\|lua-mode)` | `(lua lua-edit\|lua-lang\|lua-mode)` |
| r | `(code r-edit\|r-lang\|r-mode)` | `(r r-edit\|r-lang\|r-mode)` |
| r7rs | `(code r7rs-edit\|r7rs-lang\|r7rs-keyword\|srfi-keyword)` | `(r7rs r7rs-edit\|r7rs-lang\|r7rs-keyword\|srfi-keyword)` |
| scala | `(code scala-edit\|scala-lang\|scala-mode)` | `(scala scala-edit\|scala-lang\|scala-mode)` |
| sql | `(code sql-edit\|sql-lang\|sql-mode)` | `(sql sql-edit\|sql-lang\|sql-mode)` |
| gnuplot | `(code gnuplot-lang)` | `(gnuplot gnuplot-lang)` |
| fish | `(code fish-edit\|fish-lang\|fish-mode)` | `(fish fish-edit\|fish-lang\|fish-mode)` |
| goldfish | `(code goldfish-edit\|goldfish-lang\|goldfish-ast-lang\|liii-keyword)` | `(goldfish goldfish-edit\|goldfish-lang\|goldfish-ast-lang\|liii-keyword)` |
| julia | `(code julia-lang)` | `(julia julia-lang)` |
| moonbit | `(code moonbit-edit\|moonbit-lang\|moonbit-mode)` | `(moonbit moonbit-edit\|moonbit-lang\|moonbit-mode)` |
| tikz | `(code tikz-edit\|tikz-lang\|tikz-mode)` | `(tikz tikz-edit\|tikz-lang\|tikz-mode)` |
| matlab | `(code matlab-edit\|matlab-lang\|matlab-mode)` | `(matlab matlab-edit\|matlab-lang\|matlab-mode)` |
| python | `(code python-edit\|python-lang)` | `(python python-edit\|python-lang)` |
| cpp | `(code cpp-edit\|cpp-lang)` | `(cpp cpp-edit\|cpp-lang)` |

### Why

插件模块的一级命名空间从共享的 `code` 改为插件专属名（`bash`、`python` 等），
缩小 `use-modules` 查找模块时的搜索范围。例如 `(bash bash-edit)` 只需在 load
path 上查找 `bash/bash-edit.scm`，只有 bash 插件有该目录，而非 `(code bash-edit)`
需要在每个插件的 `progs/code/` 子目录下逐一查找。随着插件数量增长，收益递增。

### How

- 每个插件的模块文件从 `progs/code/` 迁移到 `progs/<name>/`
- `texmacs-module` 声明及模块间 `:use` 同步改一级名
- 对应的 `packages/code/<name>.ts`（或 `.stem`）的 `<use-module>` 更新
- goldfish 额外修复对 r7rs 已改名模块的跨插件引用
- C++ 侧直接使用 `<name> <name>-lang` 命名空间：
  - `prog_language_rep` 构造器直接 `(use-modules (<name> <name>-lang))`
  - `prog_lang_exists` 移除 `progs/code/` 旧路径，仅保留 `progs/<name>/<name>-lang.scm` 新路径
  - `prog-kbd.scm` 中 cpp 引用同步更新

### 涉及文件

共 47 个模块文件 rename + edit，18 个 `.ts`/`.stem` 编辑，外加 `init-tikz.scm`、
`python.stem` 的引用更新，以及 `src/System/Language/prog_language.cpp` 的 C++ 改动。

### 如何测试

点击 **帮助 → 插件**，在插件列表中逐一打开各语言插件的文档页面，确认文档能正常加载
且语法高亮、缩进等功能无异常。涉及的插件：bash、json、csv、java、javascript、lua、
r、r7rs、scala、sql、gnuplot、fish、goldfish、julia、moonbit、tikz、matlab、python、
cpp。

## 任务 10：image_xmgrace 插件合并到 image 插件

## 任务 16：latex 插件子模块命名空间规范化

### What

latex 插件中 35 个子模块从共享命名空间改为插件专属 `latex` 命名空间。

原模块使用三种共享命名空间：
- `(bibtex ...)` — 14 个 bibtex 子模块
- `(convert latex ...)` — 17 个 LaTeX 转换子模块
- `(convert bibtex ...)` — 3 个 BibTeX 转换子模块

另有 `(latex-kbd)` 独立模块，一并规范化。

规范方式：所有原命名组件以 `-` 连接，统一以 `latex` 为一级命名空间。例如：
- `(bibtex plain)` → `(latex bibtex-plain)`
- `(convert latex tmtex)` → `(latex convert-latex-tmtex)`

### Why

插件内模块命名规范：一级命名空间必须以插件名开头。`(bibtex ...)`、`(convert ...)`、
`(latex-kbd)` 等占据 bibtex/convert 命名空间或使用不符合两级模块名规范的名称，
违反规范。统一为 `(latex ...)` 两级命名模式与 R7RS 的 `define-library` 规范一致。

### How

- 35 个文件 `texmacs-module` 声明及模块间 `:use` 同步更新

## 任务 17：use-module 路由优化

### What

`list->module` 不再扫描 `$GUILE_LOAD_PATH`（50+ 个路径），改为按最外层模块名路由，
固定路径定位：

- **内置模块**：仅查 `$TEXMACS_PATH/progs/`（1 次）
- **插件模块**：先查 `$TEXMACS_HOME_PATH/plugins/<first-ns>/progs/`，
  再查 `$TEXMACS_PATH/plugins/<first-ns>/progs/`（最多 2 次）

同时移除 `url-materialize` 调用（对单路径 URL 无实质作用，纯开销），
`url-exists?` 确认存在后直接返回 URL。

math 插件改名为 math-kbd，消除内置命名空间 `math` 与插件目录名重叠，
init 文件中移除不必要的 `(texmacs-module (math))` 声明。

### Why

插件命名空间规范化后，模块名本身携带定位信息：`(latex bibtex-format)` 的第一级
`latex` 就是插件名，文件必在 `plugins/latex/progs/latex/bibtex-format.scm`。
不再需要遍历 50+ 个 load path 去扫描。

### How

- `boot-s7.scm` 的 `list->module`：用 `url-unix` 构造固定路径，`url-exists?` 确认存在后返回
- `TeXmacs/plugins/math/` → `TeXmacs/plugins/math-kbd/`，init 文件移除模块声明
