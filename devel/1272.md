# 1272 深色模式下新建 AI 对话自动带上 dark 样式包

## What

深色模式（`gui theme` = liii-night）下新建 AI 对话并发送首条消息后，
消息区画布是白色（generic 样式），与深色 UI 割裂；点击历史会话恢复
的消息区同样发白。

## Why

- `chat-tab-add-default-style-packages!`（chat-style.scm）只追加
  number-europe / 语言包 / 插件包，从不追加 dark。首条消息发送时
  `ensureMessageWidget` 先创建嵌入消息编辑器，`chat-tab-session-send`
  随后在 focus-ok 分支调用该函数，最终消息 buffer 样式仍是 generic。
- `ensureMessageWidget` / 输入框构造把嵌入样式硬编码为
  `(style (tuple "generic"))`，而 `texmacs_input_widget` 对已存在
  buffer 会 `set_buffer_tree` 整体覆盖：即使 scheme 侧先加了 dark，
  恢复会话路径（`loadSessionContent` → `ensureMessageWidget`）也会把
  样式重置回 generic，故恢复的会话同样发白。

## How

- scheme 侧（chat-style.scm）：`chat-tab-add-default-style-packages!`
  在 liii-night 时把 dark 一并追加进 packs，一次 `set-style-list`
  生效。新建对话输入区、首发消息区、`chat-tab-init-session!`、
  `chat-persist-load-session-content` 四处调用点统一覆盖。
- C++ 侧（qt_chat_tab_widget.cpp）：新增 `chat_embedded_style ()`，
  深色主题下嵌入样式带 dark 包，输入框与消息编辑器两处构造点换用，
  避免 `set_buffer_tree` 覆盖时丢掉 dark（与 new_buffer.cpp 的
  `use_dark_style_package_for_gui_theme` 判定一致：liii-night/dark）。

## 测试

- `TeXmacs/tests/python/1272.py`（pynput + RapidOCR 全链路 GUI 自动化）：
  启动应用 → 打开 Chat 标签 → 开启新对话 → 点输入框输入文本并回车发送
  → OCR 确认标题回显 → 测量消息画布中央区域平均亮度（修复前 ~254，
  修复后 ~64，dark.ts canvas-color #202020）。修复前实测 FAIL、修复后
  PASS。OCR 缺失时退化为固定相对坐标点击（亮度判定不依赖 OCR）。
- `TeXmacs/tests/1184.scm`（`xmake r 1184`）：等价性基准
  `ref-add-default-style-packages!` 同步 dark 分支，并顺手把其插件包
  检测从旧 `$TEXMACS_STYLE_PATH/*.ts` 布局改为与实现一致的
  `plugins/<名>/packages/session/<名>.stem`（该失配在干净 main 上已使
  1184 处于失败状态）。修复后 1 correct, 0 failed。
- 手动验证恢复路径：点击历史会话，消息区画布深色、文字浅色可读。
