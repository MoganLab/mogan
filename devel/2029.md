# [2029] 段落格式 QML 迁移

「格式 → 段落」(`open-paragraph-format`) 从 tm-widget 迁移到 QML。参考 [2028 字体选择器](2028.md)。

## 0 阶段一：HTML 设计稿（当前）

先在 `ai-docs/qml/qml-dialog.html` 里把段落格式对话框的样式与布局定下来，再写 QML。

### What
- 在现有 QML 组件模拟器的侧边栏新增 `ParagraphFormat.qml` 导航项。
- 新增 `#panel-paragraph`：复用 `form-shell` + `tabs-box` + `option-list`/`option-row` 已有样式，
  分「基础 / 高级」两个 tab，覆盖 `paragraph-parameters` 全部 19 个可配置项。
- 复用 FontSelector 已有 tab 切换 JS 模式，作用域限定在 `#panel-paragraph`（`data-ptab`），
  并把 FontSelector 的 `.tab` 选择器收敛到 `#panel-font` 作用域，避免两组 tab 互相干扰。
- 底部按钮：重置 / 确定 / 取消。确定收集所有 `data-par` 字段，日志输出
  `make-multi-line-with(values)`。

### Why
- 段落格式**需要 live 重绘**：现有 tm-widget 的 `change` 每次下拉改动就立即
  `make-multi-line-with` 写回文档、实时重排段落。QML 版必须保留这一体验——
  用 `run_modal_qml_dialog`(setModal+show) 非阻塞模态（主窗口照常 paint），
  每次 selector-set live 写回；OK 落定，Cancel/重置走快照撤销。
  即与 FontSelector 同一套模态引擎与撤销机制（见 README 的 live 写回/Cancel 章节与
  selector-set/selector-get-changes/initial-snapshot/revert-to-snapshot 通用 facade）。
- exec 的嵌套事件循环不重绘被遮的主窗口，会改了文档树但画面不更新——不能用于本对话框。
- 用 HTML 先定样式，是为了在 QML 实现前就确定布局/控件密度/分组，减少 QML 来回返工。

### How（设计稿要点）
- **可输入下拉 combo**（自建浮层，不用原生 datalist）：每个字段各自独立带 `editable`
  开关，保证组件可变性。交互：**点一下**弹下拉浮层选；**双击**（仅 `editable=on`）进入可编辑
  输入态（Enter/失焦落定、Esc 撤销）。默认：枚举类（对齐/断行/CJK/栏数/边距字距调整）
  `editable=off`（只能下拉选），数值尺寸类（fn/tab/fns）`editable=on`——对应 scheme 末尾
  空串槽位 + `cons-new`。
  - 为何不用 `<input list>`+datalist：Firefox 对 input[list] 悬停时显示的原生箭头无法用 CSS
    隐藏（双箭头），故自建「只读输入框 + 常驻 ▾ 箭头按钮 + 浮层选项列表」，箭头常驻、可控。
  - 取值列表从 `data-options`（JSON）读，与 `format-widgets.scm` 的 `enum` 取值一一对应。
- combo 宽度对齐到能容下「3 个预设按钮 + 间距」（184px）；行间距预设按钮组同宽居中。
- 基础 tab：对齐 `par-mode`、左/右边距 `par-left`/`par-right`、首行缩进 `par-first`、
  行间距 `par-sep`（+ 1.5x/2.0x 预设按钮）、段落间距 `par-par-sep`、栏数 `par-columns`、
  栏间距 `par-columns-sep`。
- 高级 tab：断行 `par-hyphen`、额外行间距 `par-line-sep`、最小行间距 `par-ver-sep`、
  水平折叠 `par-hor-sep`、空间伸展性 `par-flexibility`、CJK 字间距 `par-spacing`、
  字符间拉伸/压缩 `par-kerning-stretch`/`par-kerning-reduce`、字符扩展/收缩
  `par-expansion`/`par-contraction`、边距字距调整开关 `par-kerning-margin`。
- 每个 combo 的取值列表与现有 `format-widgets.scm` 中 `enum` 的取值集合一一对应。
- 控件交互语义按 live 模式：每次下拉/输入改动 → `selector-set` 实时写回文档；确定=落定关闭，
  取消/重置=快照撤销。HTML 设计稿只呈现布局/取值，交互日志见各按钮 `data-log`。

### 涉及文件
- `ai-docs/qml/qml-dialog.html` — 新增 ParagraphFormat panel + 导航 + JS（仅本阶段）

## 1 阶段二：QML 实现（已完成）

### What
- 扩展 `EnumCombo.qml` 加 `editable` 属性 + 双击切编辑态（TextInput 覆盖）：
  默认仍是点一下弹 DialogShell 共享浮层选；`editable=true` 时双击进入可编辑输入
  （Enter/失焦落定发 changed，Esc 撤销）。`EnumComboList` 透传 `editable` 字段。
- 新建 `ParagraphFormat.qml`（DialogShell + TabBar 基础/高级 + EnumCombo 竖列 +
  行间距预设按钮行 + DialogButtons 重置/确定/取消）。布局以 HTML 设计稿为准。
- 新建 scheme facade `TeXmacs/progs/generic/paragraph-format-widgets.scm`：独立 specs
  注册表（paragraph-specs-registry/snapshot，**不复用**字体的 selector-table——后者
  硬编码字体字段）、register/meta(basic/advanced)/set(live 写回 make-multi-line-with)
  /revert-to-snapshot(快照撤销)/commit/cancel/restore/ui-labels。
- 新建 C++ bridge `src/Plugins/Qt/ParagraphFormatBridge.{hpp,cpp}`：无状态透传 specsKey。
- `QTMQmlDialog.{hpp,cpp}`：新增 `cpp_paragraph_format_dialog`（run_modal_qml_dialog
  非阻塞模态 + MOGAN_TEST_PARAGRAPH_FORMAT 钩子）。
- `glue_qt.lua`：注册 `cpp-paragraph-format-dialog`。
- `moganqml.qrc`：注册 `ParagraphFormat.qml`。
- `format-widgets.scm`：`open-paragraph-format-window` 改走 QML（register-specs +
  cpp-paragraph-format-dialog），并 `:use (generic paragraph-format-widgets)`。
- `TeXmacs/tests/2029.scm`：GUI 数据契约集成测试（meta 形状 / live 写回 / cancel / ok 钩子）。

### Why
- **不复用字体 selector-table**：字体的 selector-set/get/get-changes 硬编码 `:family`
  /`:style`/`:size`、`pref-font*` 与字体专属 refresh-now；段落字段是 `par-*`，写回用
  make-multi-line-with。强行复用会污染字体状态且字段对不上，故独立 specs 注册表。
- **meta 用纯 list/cons 不用 quasiquote**：mogan scheme 的 quasiquote 在 `map` lambda
  内嵌套 `unquote`/`,` 混用时报 "unquote occurred outside quasiquote"（见 ui-labels/meta
  初版崩溃）；改纯 `(list (cons 'k v) ...)` 避之，C++ 侧 assoc 遍历不变。
- **editable 在 EnumCombo 而非新组件**：复用 DialogShell 共享浮层（限高翻转/遮罩透传），
  一处扩展全局可用；双击编辑态覆盖 TextInput，点一下仍走浮层。

### How（运行/测试）
```bash
xmake b stem
xmake r 2029                       # headless 数据契约
MOGAN_TEST_GUI=1 xmake r 2029      # 真实 GUI 手动验证：点选/双击编辑/预设/Cancel 回滚
```
- 模态引擎：`run_modal_qml_dialog`(setModal+show) 非阻塞，主窗口 live 重排段落。
- 生命期：host 堆分配 + WA_DeleteOnClose，bridge 不挂 parent，靠 destroyed→deleteLater。
- Cancel/重置：快照写回（一次 make-multi-line-with 写所有差异，避免多次嵌套 with 吞选区）。

## 2 阶段三：文档段落格式迁移 + 死代码清理（已完成）

「文档 → 段落」(`open-document-paragraph-format`)与「格式 → 段落」共用同一套 QML 对话框
与 bridge，区别仅在数据通路：文档级读写 init 环境，不是段落 with。

### What
- `paragraph-format-widgets.scm`：facade 按 scope 分流读写通路。`register-specs` 接收
  `(scope getter setter)`——`'paragraph` 走 `get-env`/`make-multi-line-with`，`'document`
  走 `get-init`/`init-multi`。新增 `paragraph-scope` 表存 scope，`paragraph-fields-for`
  按 scope 过滤字段（文档级基础 tab 去掉 par-left/par-right），`paragraph-all-var-names`
  供文档级 init-default。
- **reset 与 cancel 语义区分**：`paragraph-format-revert`（重置按钮）文档级走 `init-default`
  恢复默认、段落级走快照写回；`paragraph-format-cancel` 两级都快照写回（回到打开时）。
  快照写回抽成 `paragraph-format-restore-snapshot`，setter 按 scope 选通路。
- `document-widgets.scm`：`open-document-paragraph-format-window` 改走 QML（register-specs
  带 `'document` scope + cpp-paragraph-format-dialog）。
- **死代码清理**：`format-widgets.scm` 删除迁移后无引用的 tm-widget 代码——`get-env-table`、
  `get-init-table`、`ahash-table-changes`、`differences-list`、`change`、
  `paragraph-formatter-basic`、`paragraph-formatter-advanced`、`paragraph-formatter`。
  保留 `paragraph-parameters`（仍被 format-tools.scm 的 side-tool 用）。
- `TeXmacs/tests/2029.scm`：补文档级 set/reset/cancel 断言（读 get-init，稳定），共 33 check。

### Why
- **scope 分流而非复用读写函数**：get-env/make-multi-line-with 对 init 环境无效，文档级
  强行用段落通路会写错位置（段落 with 而非文档 initial）。
- **reset ≠ cancel**：原 tm-widget 文档级 Reset 按钮就是 `init-default`（恢复默认），与
  Cancel（回到打开时）语义不同，迁移须保留这一区分。
- **不依赖 `paragraph-parameters`**：它是 format-widgets 的跨模块变量，在
  paragraph-format-widgets 编译期 unbound；facade 用本地 `paragraph-all-var-names` 自包含。

### How（运行/测试）
```bash
xmake b stem
MOGAN_TEST_GUI=1 xmake r 2029      # 33 check：段落级 + 文档级全链
# 文档级手动验证：文档 → 段落，改对齐/重置恢复默认/Cancel 回滚
```
