# [2029] 段落格式 QML 迁移

「格式 → 段落」(`open-paragraph-format`) 与「文档 → 段落」(`open-document-paragraph-format`)
从 tm-widget 迁移到 QML，共用同一套对话框与 bridge，区别仅在数据通路（段落 with / 文档
initial）。参考 [2028 字体选择器](2028.md)。

## 3 如何测试

### 3.1 确定性测试（集成测试）
```bash
xmake b stem
xmake r 2029                       # headless：数据契约冒烟（事件循环未跑，仅加载/注册）
MOGAN_TEST_GUI=1 xmake r 2029      # 真实 GUI：跑全部断言（段落级 + 文档级全链）
```
`2029.scm` 覆盖：basic/advanced meta 形状、ui-labels、specsKey 句柄往返 + 复用、
段落级 live 写回 / 快照撤销、文档级 live 写回 / 重置(init-default) / 取消(快照) /
cancel 不固化冗余 init、cpp-paragraph-format-dialog 的 ok/cancel 钩子。

断言方式按 scope 分：
- 段落级用 `buffer->tree` + `stree-with-ref` 提取 with 值（make-multi-line-with 末尾
  tree-select 挪焦点，`get-env` 读数不稳，故抓 buffer 树不依赖 current-buffer）。
- 文档级用 `get-init`（init 不依赖光标位置，读数稳定）。

### 3.2 非确定性测试（手动 GUI 验证）
```bash
MOGAN_TEST_GUI=1 xmake r 2029      # 真实 GUI：点选/双击编辑/预设按钮/Esc/Cancel 回滚
```
QML 真实交互（点选下拉、双击键入自定义值、点行间距预设、Esc 撤销编辑）无法在 scheme

- 格式 → 段落：改对齐/边距/行间距 → 主窗口 live 重排；Cancel 回滚；重置回打开时。
- 文档 → 段落：改对齐 → 文档 initial 更新；重置恢复默认；Cancel 回滚；基础 tab 无边距项。

## 5 What

「格式 → 段落」与「文档 → 段落」共用一套 QML 对话框 + bridge + scheme facade 完成
迁移，并清理迁移后的 tm-widget 死代码。完成后又修复 review 发现的三个缺陷。

1. **HTML 设计稿**：在 `ai-docs/qml/qml-dialog.html` 新增 `#panel-paragraph`，复用
   `form-shell` + `tabs-box` + `option-list`，分基础/高级两 tab 覆盖全部 19 个 `par-*`
   参数；自建可输入下拉 combo（点一下弹浮层选、双击进编辑态），取值与原 `enum` 一一对应。
2. **QML 实现**：扩展 `EnumCombo.qml` 加 `editable` + 双击编辑态；新建 `ParagraphFormat.qml`
   （DialogShell + TabBar + EnumCombo 竖列 + 行间距预设 + DialogButtons）。
3. **scheme facade**：新建 `paragraph-format-widgets.scm`，独立 specs 注册表（**不复用**
   字体 selector-table），register/meta/set(live 写回)/revert/cancel/commit/ui-labels。
4. **C++ bridge + glue**：`ParagraphFormatBridge` 无状态透传 specsKey；`QTMQmlDialog` 加
   `cpp_paragraph_format_dialog`（非阻塞模态 + 测试钩子）；`glue_qt.lua`/qrc 注册。
5. **scope 分流**：facade 按 `(scope getter setter)` 分流——`'paragraph` 走
   `get-env`/`make-multi-line-with`，`'document` 走 `get-init`/`init-multi`；文档级基础 tab
   隐藏 `par-left`/`par-right`，重置走 `init-default`（恢复默认，非快照回滚）。
6. **死代码清理**：`format-widgets.scm` 删除迁移后无引用的 tm-widget 代码
   （`get-env-table`/`get-init-table`/`ahash-table-changes`/`differences-list`/`change`/
   `paragraph-formatter-*`），保留 `paragraph-parameters`（仍被 side-tool 用）。
7. **review 缺陷修复**：
   - 缺陷1：文档级重置后 QML `resetValues()` 重读 meta 重建 values（原用打开时缓存，
     文档级 init-default 后显示与真相源背离）。
   - 缺陷2：specsKey 自由链表回收（`paragraph-specs-free` + `alloc-key` helper），
     cleanup 回收的 key 供 register 复用，避免单调递增。
   - 缺陷3：文档级 cancel 不固化冗余 init——新增 `paragraph-snapshot-has` 记录打开时
     各字段 `init-has?`，restore-snapshot 对「打开时无显式 init」的字段写 `:default`，
     经 `init-multi` 的 `:default` 分支走 `init-default` 移除 init。

## 6 Why

- **live 重绘必须保留**：原 tm-widget 每次 `change` 立即 `make-multi-line-with` 写回、
  实时重排段落。QML 版用 `run_modal_qml_dialog`(setModal+show) 非阻塞模态——主窗口照常
  paint，每次 `selector-set` live 写回。exec 的嵌套事件循环不重绘被遮的主窗口，会改了
  文档树但画面不更新，不能用于本对话框。
- **显示真相源在 QML values，不在 scheme**：scheme 不维护运行期当前值，避开写回相对读取
  的延迟导致的显示滞后（参考 FormDialog）。唯一例外是「重置」——scheme 侧改变真相源后，
  values 必须跟着重读（缺陷1）。
- **不复用字体 selector-table**：字体的 selector-set/get/get-changes 硬编码 `:family`
  /`:style`/`:size` 与字体专属 refresh-now；段落字段是 `par-*`、写回用 make-multi-line-with。
  强行复用会污染字体状态且字段对不上，故独立 specs 注册表。
- **scope 分流而非复用读写函数**：get-env/make-multi-line-with 对 init 环境无效，文档级
  强行用段落通路会写错位置（段落 with 而非文档 initial）。
- **reset ≠ cancel**：原 tm-widget 文档级 Reset 是 `init-default`（恢复默认），与 Cancel
  （回到打开时）语义不同，迁移须保留这一区分。
- **cancel 应回到 init 状态而非仅值**（缺陷3）：`get-init` 对「无显式 init」字段返回全局
  默认字符串，cancel 若直接写回会把默认值固化成冗余显式 init（文档树冗余、后续改全局默认
  不跟随）。精确语义是回到打开时的 init **状态**（有/无显式 init），故另记 `init-has?`。
- **meta 用纯 list/cons 不用 quasiquote**：mogan scheme 的 quasiquote 在 `map` lambda
  内嵌套 unquote 混用时报 "unquote occurred outside quasiquote"；改纯 `(list (cons 'k v) ...)`
  避之，C++ 侧 assoc 遍历不变。

## 7 How

- **模态引擎**：`run_modal_qml_dialog`(setModal + show) 非阻塞模态，主窗口 live 重排段落。
  生命期：host 堆分配 + `WA_DeleteOnClose`，bridge 不挂 parent，靠 `destroyed`→`deleteLater`
  自清。
- **Cancel/重置**：快照写回——一次 `make-multi-line-with`/`init-multi` 写所有差异（扁平
  `(var val ...)`），避免段落级多次嵌套 with 吞选区。重置按 scope：段落级快照写回（回到
  打开时）、文档级 `init-default`（恢复默认）。
- **editable 在 EnumCombo 而非新组件**：复用 DialogShell 共享浮层（限高翻转/遮罩透传），
  一处扩展全局可用；双击编辑态覆盖 TextInput，点一下仍走浮层。
- **alloc-key 用 helper 而非内联 set!**：specsKey 分配若在 `(with key <init> ...)` 的初始
  化表达式里 `set! key` 会 unbound——初始化时绑定尚未建立；用 `paragraph-format-alloc-key`
  返回值承载分配（更新自由链表/计数器的副作用）彻底绕开。
- **文档级 cancel 的 `:default` 技巧**：`init-multi` 本身已处理 `(== (cadr l) :default)` →
  走 `init-default`，故对「打开时无显式 init」的字段在快照写回时填 `:default`，即可移除
  init 而非固化默认值，无需在 facade 里另写 init-default 调用路径。
