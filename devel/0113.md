### 验证步骤
1. 打开 Mogan STEM，新建一个空白文档。
2. 插入一个无框表格（如 2x2，边框类型设为无框）。
3. 在无框表格的某个单元格中，再次插入一个子表格（可以是带框或无框）。
4. 确认**"显示表格单元格"**偏好设置已开启（编辑 -> 首选项 -> 其他 -> 显示表格单元格）。
5. 观察子表格与父表格单元格边界处，确认**编辑时的辅助线条（灰色细框）没有出现重叠或错位**。
6. 对比修复前：子表格边框与父表格单元格细线在同一位置绘制，导致线条加粗或视觉重叠。
7. 测试不同边框类型的组合（父无框+子有框、父无框+子无框等），确认边界显示一致。
8. 测试包含合并单元格的无框表格中嵌套子表格，确认无额外线条问题。

## What
修复无框表格中嵌套子表格时，编辑辅助线条（`env_rects`）出现重叠的问题：
- 根因：`compute_env_rects()` 在遍历父表格单元格时，对包含子表格（`subtable`）的单元格仍绘制了完整的单元格边框。而子表格内部的 `TABLE` 也会独立绘制自己的 `env_rects`，两者在同一坐标范围重叠，导致视觉上线条加粗。
- 修复：在 `src/Edit/Interface/edit_interface.cpp` 的表格单元格循环中，生成 `env_rects` 前检查单元格内容。若单元格直接或间接包含 `SUBTABLE`（包括 `<cell|<subtable|…>>` 和 `<cell|<document|<subtable|…>>>` 两种形式），则跳过该单元格的 `env_rects` 绘制，仅保留相邻单元格的 `correct_adjacent` 对齐逻辑。
- 仅影响编辑时的视觉辅助线，不影响实际排版或打印输出。

## Why
当光标位于子表格内部时，编辑界面会分别为父表格和子表格绘制 `env_rects`。父表格包含子表格的单元格（如 (1,1)）其坐标范围恰好被子表格完全覆盖，导致父单元格边框和子表格边框在同一位置重复绘制，出现线条重叠/加粗。

## How
在 `compute_env_rects()` 处理每个单元格的最后阶段（将 `selp - selm` 加入 `rl` 之前），增加以下判断：
```cpp
tree cell_tree = st[i][j];
if (is_func (cell_tree, CELL)) {
  if (N (cell_tree) > 0) {
    tree cell_content = cell_tree[0];
    if (is_func (cell_content, SUBTABLE) ||
        (is_func (cell_content, DOCUMENT) && N (cell_content) > 0 &&
         is_func (cell_content[0], SUBTABLE))) {
      continue;
    }
  }
}
```
- 此判断位于 `correct_adjacent` 之后，因此相邻单元格仍能借用当前单元格的 selection 进行边界对齐，只是最终不输出该单元格的边框矩形。
- 保留了 `cell_cache` 的完整数据，避免破坏相邻单元格的对齐逻辑。
