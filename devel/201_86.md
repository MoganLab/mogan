# 201_86 修复替换功能在a->axa可能发生的卡死问题

## 如何测试
1. 打开mogan，输入：
   ```
    aaaaaaaaaaaaaa

    a

    aaaaa
    aa

    a

    aa

    a

   ```
2. 选中一个a，打开替换窗口，替换为 `axa`，执行“替换全部”。
3. 预期：
   - 不会卡死/无响应；
   - 每个原始 `a` 仅替换一次（如 `aaa -> axaaxaaxa`，`aa -> axaaxa`）。

## 2026/03/03 修复 replace-all 在注入型替换场景下的游标推进
### What
- 修改 `TeXmacs/progs/generic/search-widgets.scm` 中 `replace-next`：
  - 在单次替换后，立即将搜索参考点更新到替换后光标 `mid-p`；
  - 重新搜索后，要求新命中位置满足：
    - `path-less? old-p new-p`
    - `path-less-eq? mid-p new-p`
  - 若条件不满足，则以 `mid-p` 为参考点强制执行一次 `search-next-match #t`。

### Why
- 旧逻辑在 `a -> axa`、`墨 -> 墨1墨` 这类“替换文本包含原搜索词”的场景中，会重新命中新插入文本，可能导致 replace-all 长时间循环甚至卡死。
- 仅做“严格大于 mid-p”会误伤相邻命中，出现漏替换（例如 `aa` 的第二个 `a` 被跳过）。

### How
- 通过 `set-search-reference mid-p` 固定下一轮搜索起点，避免回卷到已替换区间。
- 使用 `path-less-eq? mid-p new-p`（而非 `path-less?`）允许紧邻命中继续被替换，修复 `aa` 场景。
- 保留兜底分支，在异常路径下仍强制向前推进，避免停滞。
