# [0815] 调整图片前后`delete`/`backspace`键删除逻辑

- `TeXmacs/progs/generic/generic-edit.scm`
  - `kbd-remove` 拦截分支
  - `just-after-image?`、`just-before-image?` 判定函数


## 3 如何测试

### 3.1 确定性测试（单元测试）
```bash
xmake b stem
xmake r stem
```

### 3.2 非确定性测试（文档验证）
1. 打开 `TeXmacs/tests/tmu/0815.tmu`，进入大图片的内部环境；
2. 光标放在图片后一位置，按 `backspace` 键，图片应被整体删除；按下 `delete` 键后，应该退出环境而不是删除图片；
3. 光标放在图片前一位置，按 `delete` 键，图片应被整体删除；按下 `backspace` 键后，应该删除图片前面的空行，而不删除整个图片；
4. 以上操作按下 `ctrl+z` 键时应该可以撤回操作；

## 4 What
- 重写 `kbd-remove` 的图片删除判定：用 `just-after-image?`/`just-before-image?` 替换原 `at-image-start?`
- 按删除方向（`forwards?`）分离触发条件：`backspace` 只在图片后触发，`delete` 只在图片前触发，二者各自整体删图

## 5 Why
- `[201_31]` 引入的 `at-image-start?` 用 `cAr p <= 1` 判定，无法区分图片前与图片后（光标在 image 原子节点上只有 offset 0 / 1 两个停留位，两个位置都满足 `<= 1`），导致在图片前按退格会误删整图而非删换行
- 原逻辑不区分 `backspace`/`delete` 方向

## 6 How
- `just-after-image?`：`cDr p == image 路径 && cAr p >= 1`（图片后）
- `just-before-image?`：`cDr p == image 路径 && cAr p == 0`（图片前）
- `kbd-remove` 的 `:require` 改为 `(if forwards? (just-before-image?) (just-after-image?))`，方向与位置匹配时才 `tree-cut` 删图，否则回退到 `remove-text`
