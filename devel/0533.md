# [0533] OAuth 回调链路改造（五）：liiistem:// 深链接入 macOS

承接 [0532]（Windows 侧深链）。[0532] 的「后续」里写着 macOS 要做
`CFBundleURLTypes` + `QFileOpenEvent`，本次就是这条。深链的职责不变：**只做纯唤起**，
授权码仍由环回回调收下（见 [0524]/[0525]/[0526]/[0529]）。

## 背景：macOS 与前一个平台不是一回事

| | Windows（[0532] 已实现） | macOS（本次） |
|---|---|---|
| 协议注册 | 运行期写 `HKCU\Software\Classes\liiistem`，可探测/自愈 | 只能打包期声明 `CFBundleURLTypes`，无运行期接口 |
| 浏览器点链接 | 按注册表那行命令行**新起一个进程**，URL 在 argv 里 | LaunchServices 投给**已运行**实例；没有才先拉起 App |
| 实例路由 | 新进程用 `QLocalSocket` 转发给发起实例 | 不需要转发，OS 自己路由 |
| 前台激活 | 需 `AllowSetForegroundWindow` 交接前台权 | 由 LS 完成激活 |
| 无人可投时 | 转发进程丢弃 URL 后静默退出 | **App 被 LS 拉起**，之后才收到 URL 事件 |

最后一行是本任务的全部难点，见下。

## 实测：被拉起时，URL 什么时候到？

`QFileOpenEvent` 是异步投递的，而「被拉起的进程要立刻退出、不留界面」要求尽早知道。
打探针实测（release 构建、真 plist、`open "liiistem://wake?instance=probe"`、
App 未运行）：

```
+0ms    App 进程启动
+0ms    冲窗口系统事件队列（QWindowSystemInterface::flushWindowSystemEvents）→ 空
+28ms   提前调用 [NSApp finishLaunching] 后再冲一次 → 仍为空
+141ms  init_texmacs 完成             已有 1 个可见窗口
+341ms  事件循环开始                  已有 2 个可见窗口
+447ms  FILEOPEN 到达（gui-helper）   已有 2 个可见窗口
```

结论：

1. `kAEGetURL` 不在窗口系统事件队列里，**提前冲队列冲不到**；
2. 提前走完 `finishLaunching` 也没用——排除「Qt 注册 Apple Event handler 太晚」，
   事件迟到是 LaunchServices 侧行为（它等 App 启动完成才投递）；
3. **事件最早只能在 +447ms 被我们看到，而那时界面已经在了**。

对照实测（App 运行中）：`FILEOPEN` 立即到达、同一个 pid，**没有新进程**。

所以 macOS 的「被拉起就退出」只能做到「界面已出现约 0.3~0.45 秒后退出」，这是
平台下限，不是能调好的时序（另两个换法——推迟窗口显示 ~500ms、放弃 scheme 改由
页面打本机端口——分别要拿全局启动变慢和官网改动去换，已评估后放弃）。

## 改动

### 1. 判定：instance 是 macOS 上的唯一判据

`oauth_deeplink::is_wake_for(url, instance_id)`：`is_wake` 通过且 URL 里的
`instance` 等于本进程登记的标识。本进程标识由 `QTMOAuth` 构造时经
`set_local_instance_id()` 登记（与 Windows 的 `startUrlRouter()` 同一处）。

`handle_open_url(QUrl)` 按它分流：

| 情况 | 处理 |
|---|---|
| 指向本实例 | `bring_to_front()` |
| 不指向，且本进程刚起来（事件循环开始不足 5 秒） | 本进程就是被这条深链拉起的 → 记日志后退出 |
| 不指向，但本进程已跑了一阵 | 别人的唤醒投到了我这儿（多开/有人直接开链接）→ 只记日志，**不置前也不退出** |

第三行是实测后补的：最初写成「不匹配就退出」，验证时发现那意味着**任何一条外来
`liiistem://` URL 都能杀掉用户手里正在编辑的 App**（连同未保存的工作）。判据用
「事件循环开始了多久」（`mark_loop_started()`，在 `qt_gui.cpp` 的 `app->exec()`
前调用）区分「刚被拉起」与「用户正在用」：被拉起的进程，URL 在事件循环开始后约
0.1 秒到达，5 秒是给慢机器留的余量。

退出走 `get_server()->quit()`（关管道 + scheme 退出钩子 + `exit(0)`），与
`qt_startup_quit_requested` 同一条路径。

### 2. 接收：两个接入点

- `QTMGuiHelper::eventFilter` 的 `FileOpen` 分支最前面加一句 `handle_open_url`。
  原来的代码只看 `openEvent->file()`，自定义 scheme 这里是空串，落进旧分支会被
  **静默吞掉**（还会置 `new_window_flag`）。
- `QTMApplication::event()` 覆写兜住 GUI 起来之前到达的事件（那时 `QTMGuiHelper`
  的过滤器还没装上）。两个接入点互斥：过滤器装上后先接住并返回 true，走不到 app。

### 3. 注册：打包期声明，只在商业版

`packages/macos/Info.plist.in` 加占位符 `@URL_SCHEME_DECL@`，两处渲染各按
`is_community` 决定是否展开 `CFBundleURLTypes`：

- `tools/release/stage_velopack.lua`——**macOS 实际发布走的就是这一条**（CD 里
  `xmake install stem` 不跑 stem_packager，真 plist 由本脚本生成）。该脚本经
  `xmake l` 运行，config 不会自动加载（实测 `config.get` 返回 nil），须显式
  `config.load()`；
- `xmake/targets/stem_packager.lua`——遗留 DMG 流程（`packages/macos/package.scm`）
  用。不改它的后果不是「少了声明」而是**占位符原样留在 plist 里**，bundle 直接失效。

社区版不声明的理由与 Windows 侧「只有商业版写注册表」相同：两版
`CFBundleIdentifier` 都是 `app.mogan`，社区版先注册就占住 LaunchServices 的
scheme 归属，而 macOS 没有运行期夺回的手段。

运行期没有对应物：`ensure_registered()` 在 macOS 仍是空实现。

## 验证

已完成的（本机 macOS 26.5 / arm64 / releasedbg，商业版配置）：

- **单元测试**：`xmake b oauth_deeplink_test && xmake r oauth_deeplink_test` → 6 passed；
- **打包**：`VPK_STAGING_SRC=build/macosx/arm64/releasedbg/MoganSTEM.app xmake l tools/release/stage_velopack.lua` 跑通，暂存 .app 的 plist 含 `CFBundleURLTypes` 且 `plutil -lint` 通过；社区版分支（占位符渲染为空）同样 `plutil -lint` 通过；
- **App 未运行 + 点唤醒链接**：进程被拉起后自行退出，无残留；临时探针文件证明它走完了 startup（即不是启动期崩溃）；
- **App 运行中 + 指向本实例的唤醒**：前台应用由「终端」变为「墨干」，进程存活；
- **App 运行中 + 别人的唤醒**：日志 `OAuth deep link: not for this instance (want someoneelse, have WF3umGVA9iWRIJXh), ignored`，进程存活、不置前。

待真机/发版链路确认：

- **真实登录全链路**（浏览器授权 → 回调 → 成长页发 URL → 窗口置前）：需官网成长页
  按 `instance` 参数发 `liiistem://wake?instance=<值>`，与 Windows 侧同一个外部依赖；
- **发布包**：本地只能构造 releasedbg 的 .app 验证（dev 构建的 plist 是
  `qt.widgetapp` 占位符），正式 plist 由 release+`stage_velopack` 产出，已在上面用
  暂存流程验过。

## 已知限制（本次不处理）

- **被拉起时界面会闪现约 0.3~0.45 秒**：macOS 上限，见「实测」一节。用户点链接时
  App 早已不在（关掉或崩溃），登录作废，看到的是一次「弹出又消失」。
- **多实例（`open -n`）下唤醒可能丢失**：LS 把 URL 投给哪个实例不由我们决定，
  投错了那个实例只会记日志（不置前、不退出）。macOS 上多开不是受支持用法。
- **dev 构建测不了深链**：`build/macosx/<arch>/<mode>/MoganSTEM.app` 的 plist 来自
  `qt.deploy`（`org.example.*`、无 `CFBundleURLTypes`）。手工验证要 release 构建
  走 `stem_packager`，或手工把声明补进 dev bundle 的 plist 后
  `codesign --force --deep --sign -` + `lsregister -f`。
- **社区版不声明 scheme**：与商业版共用 bundle id，二者不能在同一台机器上共存
  谈论归属问题。
