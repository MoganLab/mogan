# 0993 同一文档共享一个翻译会话

## 需求

1. 同一个文档只共享一个翻译对话：AI 操作栏点「翻译」时，若该文档已有
   翻译会话则复用（激活并继续发送选区），否则新建；文档到会话的映射
   依靠文档的 `stem-doc-id`；
2. AI 操作栏按钮文案去掉英文「AI」前缀（英文界面原显示
   "Ai translate / Ai polish / Ai chat"）；
3. 翻译会话标题固定为「翻译: 文件名」，其中「翻译」必须走词典本地化
   （不得硬编码中文），文件名取来源文档 url 末段、不含扩展名；
4. 翻译会话专用于翻译：AI 操作栏「对话」动作不得写入翻译会话
   （修复：先翻译再对话时，对话落进了翻译会话）。

## 测试方法

1. `xmake b stem` 构建通过；
2. `xmake b qt_chat_session_test && xmake r qt_chat_session_test`：
   `setSourceDocId` / `findSessionBySourceDoc`（空 docId 不匹配、
   跳过归档、最近活跃优先）；
3. `xmake b stem && xmake r chat-list-test`：manifest 条目新增
   `stemDocId` 字段的写入/读取/兼容回退（缺省为空字符串）；
4. 手动 GUI 验证：
   - 中文界面操作栏显示「翻译/润色/对话」，英文界面显示
     "Translate / Polish / Chat"（均无 AI 字样）；
   - 文档 A 选区点翻译 → 新建会话，标题「翻译: A 的文件名」；再次
     选区点翻译 → 复用同一会话追加发送，不产生新会话；
   - 切换到文档 B 点翻译 → 新建另一个翻译会话；
   - 先翻译再点对话 → 对话写入普通（空白/新建）会话，不进翻译会话；
   - 重启应用后翻译会话恢复，再点翻译仍复用同一会话；
   - 归档/删除某文档的翻译会话后再次翻译 → 重新新建。

## What

- 翻译会话与来源文档绑定：`ChatSession` 新增 `sourceDocId`（来源文档
  的 `stem-doc-id`，空串表示未绑定），随 manifest 的 `stemDocId`
  字段持久化，重启后映射依然有效；
- AI 操作栏翻译动作：先按当前文档的 `stem-doc-id` 查找未归档的翻译
  会话（最近活跃优先），命中则激活并继续发送；未命中才新建会话，
  标题直接置为「翻译: 文件名」；
- AI 操作栏对话动作：当前激活会话是绑定了文档的翻译会话时，先切到
  空白会话（复用或新建）再填入选区引用，不把对话写进翻译会话；
- 操作栏按钮文案键改为 `Translate` / `Polish::ai` / `Chat::ai`
  （`::` 消歧，英文界面只显示 `::` 前部分），中文词典去掉
  `ai translate` 等旧键，新增 `chat::ai` / `polish::ai` 词条
  （`translate` →「翻译」复用既有词条）；
- 移除仅为旧翻译标题服务的 `titlePrefix` 机制（标题不再从内容生成，
  创建时即确定）。

## Why

- 旧实现每次翻译都新建会话，同一文档多次翻译会在侧边栏堆积多个
  翻译会话；按文档共享一个翻译会话更符合「围绕这篇文档持续翻译」
  的使用心智；
- 操作栏按钮带英文「AI」前缀在英文界面冗余（栏本身已有龙虾标识
  表明 AI 语义）；
- 标题用「翻译: 文件名」比「翻译: 内容摘要」更直白地标明会话归属；
  「翻译」经词典 `translate` 键本地化，随界面语言切换。

## How

- `stem-doc-id` 读取：scheme 侧新增 `chat-tab-source-doc-info`，一次调用
  返回 `(stem-doc-id . 文件名)` pair——doc-id 先读 init-env（会话内
  绑定），再读文档 initial collection（文件内持久化），与 autosave 插件
  同一两跳逻辑；文件名取 `url-tail` 末段去掉扩展名（`url->system` 转
  系统编码）；C++ 在打开侧边栏（焦点/视图切换）之前调用（模块经一次性
  守卫加载），保证 `current-buffer` 仍是来源文档；
- 映射查找：`ChatSessionManager::findSessionBySourceDoc` 按
  `timeIndex_` 降序返回第一个 `sourceDocId` 匹配且未归档的会话；
  归档/已删除的不复用（重新新建）；来源文档无 `stem-doc-id`（未保存
  的新文档）时退化为每次新建；
- 复用路径：`activateSession`（按需建面板、加载内容）后写入引用选区
  的输入体并走 `onSendRequested` 管线；会话生成中则只激活不覆盖输入；
- 对话路径：填入前用 `findSessionByPanel` 反查激活会话，若其
  `sourceDocId` 非空（翻译会话）则先 `ensureNewConversation` 切换
  （复用空白会话或新建），再对新的激活面板填输入；
- 标题：新建翻译会话时 `setTitle` 为「Translate 词典值 + ": " +
  文件名」，因标题非空，`onSendRequested` 不再从内容生成标题；
  面板标题标签同步从「生成标题」分支中移出，标题非空即同步；
- 持久化：`chat-persist-make-entry` rest 参数尾部追加 `stem-doc-id`
  （缺省 ""），manifest 条目写 `stemDocId` 字段；加载侧缺省回退 ""
  兼容旧 manifest。glue 单函数参数上限为 10（`TMSCM_ARG10` 为止），
  `qt-chat-tab-restore-session` 已满 10 参，故恢复时 `stemDocId` 经
  新增 glue `qt-chat-tab-set-source-doc-id` 单独设置；
- 修复顺手暴露的隐患：`qt_chat_tab_restore_session` 原未初始化
  `ChatSession.registered`（POD 缺省初始化，值不确定），恢复的历史
  会话首次发送时 `registerSession` 行为依赖脏值；现显式置 `true`
  （恢复的会话本就在 manifest 与侧边栏中）。
