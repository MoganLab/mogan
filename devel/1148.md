## 5 What

把 telemetry 相关实现从启动期 eager 加载的 `TeXmacs/progs/telemetry/`
迁移到 telemetry 插件（懒加载），加快软件启动速度。

1. 在 `TeXmacs/plugins/telemetry/progs/plugin/` 下新增入口模块
   `(plugin telemetry)`（仅 `:use` 实现模块）和三个实现模块
   `telemetry-utils` / `telemetry-track` / `init-telemetry`（直接迁自
       `TeXmacs/progs/telemetry/`）
2. `TeXmacs/plugins/telemetry/progs/init-telemetry.scm` 在原有
   `plugin-configure` 后追加 `(use-modules (plugin telemetry))` 与
   `(init-telemetry)`，把原 init-research.scm 中的初始化下沉到插件
3. `TeXmacs/progs/init-research.scm` 移除 telemetry 三个 use-modules
   与 `(init-telemetry)` 调用；同时在顶部注入 rootlet 的 pending 队列
   （`telemetry-pending-events`、`telemetry-track-or-enqueue`、
   `telemetry-drain-pending!`），让插件加载前的 C++ 上报不丢失
4. `TeXmacs/progs/generic/generic-edit.scm` 的 `track-event` 调用点
   用 `(when (defined? 'track-event) ...)` 兜底（窗口期内未上报可接受）
5. `src/Mogan/Telemetry/telemetry.hpp` C++ 调用点改为
   `(telemetry-track-or-enqueue ...)`：插件加载前入队，加载后通过
   `init-telemetry` 内的 `telemetry-drain-pending!` 一次性补 track
6. `(plugin init-telemetry)` 在 `init-telemetry` 函数体开头先调用
   `telemetry-drain-pending!`，消费启动期入队的事件（OPEN/LOGIN 等）
7. 删除 `TeXmacs/progs/telemetry/` 整目录

## 6 Why

`init-research.scm` 全程同步执行（OPEN 埋点前），其中 eager 加载的
`telemetry-utils` / `telemetry-track` / `init-telemetry` 三个模块带
`(liii njson)` / `(liii uuid)` / `(srfi srfi-19)` 等较重导入，
拖慢启动。插件 init 文件由 `lazy-plugin-initialize` 在事件循环启动
~3s 后才加载，不在启动关键路径上；迁入后这部分代码与 liii 库的
求值成本从启动路径移除。

## 7 How

1. **加载时机**：`init-research.scm:564`
   `(for-each lazy-plugin-initialize (plugin-list))` 为所有插件登记
   `(delayed (:pause 3000) (plugin-initialize name))`；`plugin-initialize`
   `(load ...)` 插件的 `init-<name>.scm`。因此 `init-telemetry.scm`
   在 ~3s 时执行，其中 `(use-modules (plugin telemetry))` 同步加载
   入口与实现模块，再 `(init-telemetry)` 启动周期 flush。
2. **符号可见性**：`tm-define` 经 `(varlet (rootlet) ...)` 把符号定义到
   全局 rootlet，`define-public` 则只绑定到当前模块。所以跨模块的入口
   函数必须用 `tm-define`，否则 eager 端 `(defined? 'xxx)` 兜底失效。
   本次将 `init-telemetry`、`track-event` 由 `define-public` 改为
   `tm-define`；`telemetry-home-path` 提升为 `define-public` 供 2013
   测试访问。其余 `define-public` 函数在 `(plugin telemetry)` 内部
   互相调用，无需改 `tm-define`。
3. **入口/实现拆分**：`(plugin telemetry)` 作为被 `use-modules` 直接
   加载的入口模块不能含 `(import ...)`（S7 R7RS import 会破坏 texmacs
   module 环境，同 `autosave.scm`/`llm/chat-loader.scm` 头注）。
   但 telemetry-track / telemetry-utils / init-telemetry 各自作为
   `:use` 依赖被入口加载时，每个都已是独立 texmacs-module，内部
   `(import ...)` 安全。入口仅声明 `(:use (plugin telemetry-utils)
   (plugin telemetry-track) (plugin init-telemetry))`。
4. **pending 队列（核心）**：C++ 启动期就会触发 OPEN/LOGIN 等关键事件，
   但 telemetry 插件 ~3s 后才加载。为避免事件丢失，在 init-research.scm
   顶部（启动期同步执行）用 `(let ((rl (rootlet))) ...)` 注入三个符号
   到 rootlet：
   - `telemetry-pending-events`：事件队列，初始 `'()`
   - `telemetry-track-or-enqueue`：`(if (defined? 'track-event) (track-event
     ...) (varlet rl 'telemetry-pending-events (cons ...)))`，加载后直接
     track，加载前入队
   - `telemetry-drain-pending!`：消费队列，`(for-each track-event
     (reverse pending))` 后清空
   C++ 改为调 `telemetry-track-or-enqueue`（不再 delayed），保持同步
   语义；`(plugin init-telemetry)` 的 `init-telemetry` 函数体开头先
   `(telemetry-drain-pending!)` 把积压事件补齐 track。
5. **rootlet 引用捕获**：lambda 注入到 rootlet 后，从 C++ 通过
   `eval_scheme` 调用时 closure 仍在；但 lambda 内访问 `(rootlet)`
   可能在某些环境下不被求值，因此外层 `(let ((rl (rootlet))) ...)`
   先把 rootlet 引用捕获到 `rl`，lambda 内用 `rl` 而不是 `(rootlet)`。
6. **rootlet 符号访问语法**：`telemetry-pending-events` 是 rootlet 上
   的变量，**不能写成 `(telemetry-pending-events)`**（那是函数调用，
   会报 `attempt to apply nil`）。lambda 内通过 closure 链查找 rootlet
   上的变量要用裸符号 `telemetry-pending-events`。
7. **scheme 调用点兜底**：`generic-edit.scm` 中 `(track-event ...)`
   用于 OCR / MAGIC_PASTE 行为埋点，丢失一次埋点可接受；用
   `(when (defined? 'track-event) (track-event ...))` 跳过窗口期内
   的调用。
8. **必定触发的初始化**：`init-telemetry` 自身负责
   `telemetry-clean-orphans`、`on-exit` 的 CLOSE 上报与周期 flush；
   这些都不在启动关键路径上，下沉到插件 init 无功能损失。

## 8 验证记录

  启动期 `[telemetry] enqueue: LOGIN/OPEN` → ~3s 时
  `[telemetry] drain: 2 pending events` → `[telemetry] track: LOGIN/OPEN`
  补 track → `[telemetry] init: enabled` 无报错

- `(regtest 2013)`：9 correct, 0 failed
- 关键事件 0 丢失：OPEN/LOGIN/HEART_BEAT 等启动期上报全部经 pending
  队列补 track，符合预期
