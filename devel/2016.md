## 2 任务相关的代码文件
- `TeXmacs/plugins/goldfish/src/goldfish.hpp` - 版本号 `18.11.13` → `18.11.15`，声明并注册新 glue 函数
- `TeXmacs/plugins/goldfish/src/liii_base64.cpp` - 新增，C++ 实现 `g_bytevector-base64-encode` / `g_bytevector-base64-decode`
- `TeXmacs/plugins/goldfish/src/scheme_base.cpp` - 新增，C++ 实现 `g_string->utf8`
- `TeXmacs/plugins/goldfish/goldfish/liii/base64.scm` - 删除纯 Scheme 实现，改为调用 C++ glue
- `TeXmacs/plugins/goldfish/goldfish/scheme/base.scm` - 同上，`string->utf8` 改为薄包装
- `xmake/goldfish.lua` - 把新增的两个 `.cpp` 加入 goldfish binary target 的 `add_files` 列表

### 3.1 确定性测试（单元测试）
本仓未随附 goldfish 自身的 Scheme 测试套件，通过两个构建目标 + 功能往返验证：

```bash
# 1. goldfish REPL binary target（依赖新增 .cpp，验证链接）
xmake b goldfish

# 2. Mogan 主程序（经 src/**.cpp glob 自动纳入新 .cpp）
xmake b stem

# 3. 功能往返（base64 编解码 + string->utf8 字符切片）
TeXmacs/plugins/goldfish/bin/goldfish eval \
  '(import (liii base64))
   (display (utf8->string (bytevector-base64-encode (string->utf8 "hello 金鱼")))) (newline)
```


## 4 如何提交


## 5 What
1. 把 Goldfish 版本号从 `18.11.13` 升到 `18.11.15`。
2. `bytevector-base64-encode`、`bytevector-base64-decode`、`string->utf8` 三个函数的纯 Scheme 实现被移除，改为在 C++ 层（`liii_base64.cpp` / `scheme_base.cpp`）以 `g_*` glue 函数实现，Scheme 侧仅保留薄包装。
3. `goldfish.hpp` 中声明并在 `glue_for_community_edition` 里调用 `glue_liii_base64` / `glue_scheme_base` 完成注册。
4. 修正 `xmake/goldfish.lua`：把 `liii_base64.cpp` 与 `scheme_base.cpp` 加入 goldfish binary target 的源文件列表（缺这一步会链接失败）。

## 6 Why
这三个函数是热点路径（base64 编解码、UTF-8 转换），C++ 实现比纯 Scheme 解释执行更快；同时把它们从解释执行的 Scheme 代码下沉到编译期 native 代码，是 goldfish 18.11.15 上游的一次性能与可维护性改进。版本升级把这一改动同步进 Mogan 内置的 goldfish 源码。

## 7 How
调用方侧**无需改动**：这三个函数的公开 Scheme 名字与签名完全不变（`string->utf8` 仍支持 `(start end)` 可选参数，base64 仍按 `bytevector` 进出），`base64.scm` / `scheme/base.scm` 内部把实现体替换成对 `g_*` C 函数的调用，外部所有引用点（`string-cursor.scm`、`unicode.scm`、`uri-record.scm`、`char.scm`、`guenchi/json.scm` 等）透明继续工作。

唯一需要处理的是构建配置：
- Mogan 的 `stem` 目标经 `xmake.lua` 第 729 行 `src/**.cpp` glob 自动纳入两个新 `.cpp`，无需改动。
- goldfish **binary target**（`xmake/goldfish.lua`）显式枚举源文件，原列表漏掉了新 `.cpp`，导致 `init_goldfish_scheme → glue_for_community_edition` 引用的 `glue_liii_base64` / `glue_scheme_base` 符号未定义，链接报错：

  ```
  Undefined symbols for architecture arm64:
    "goldfish::glue_liii_base64(s7_scheme*)", referenced from:
        goldfish::glue_for_community_edition(s7_scheme*) in goldfish.cpp.o
    "goldfish::glue_scheme_base(s7_scheme*)", referenced from:
        goldfish::glue_for_community_edition(s7_scheme*) in goldfish.cpp.o
  ```

  在该 target 的 `.cpp` `add_files` 列表里补上 `liii_base64.cpp` 与 `scheme_base.cpp` 即可，重新构建 `goldfish` 与 `stem` 均通过，功能往返验证正确。
