# 0986 一键 AI 翻译

## 需求

选中文字后，选区下方出现 AI 操作栏（翻译/润色/对话）；点击「翻译」把选中
文字以「引用」外观块（插入 → 外观块 → 引用）引用进 AI 侧边栏（自动打开）
输入框，下方追加提示词「请翻译上述文字为中文」并自动发送；「对话」同样以
引用块引用选中文字但不放提示词、不自动发送；润色后续接入。

分两步实现，每步一个 PR：

1. **第一步**：选中文字后，选区下方出现 AI 操作栏（仅 UI，不含点击动作）。
2. **第二步**：点击「翻译/对话」按钮引用选区到 AI 侧边栏并按动作发送。

## 测试方法

第一步：

1. `xmake b stem` 构建通过；
2. `xmake b qml_load_test && xmake r qml_load_test`（QML 操作栏加载与
   hover 用例）；
3. 手动 GUI 验证：打开文档，鼠标选中一段文字，选中文字的下一行出现一行
   「龙虾图标 + 翻译 / 润色 / 对话」操作栏（按钮带图标）；
   滚动文档按钮跟随选区；点击选区外/取消选区后按钮消失；点击按钮后按钮消失；
   Shift+方向键键盘选区也能触发；聊天输入框等 tmfs 页面内选中不出现按钮；
   **重启应用后重复上述悬浮验证**（第二次启动悬浮点亮也正常）。

第二步：

1. `xmake b stem` 构建通过；
2. `xmake b qt_chat_controller_test && xmake r qt_chat_controller_test`
   （`composeAiInputBody` 纯逻辑用例：单段/多段选区包引用块、翻译追加 cork
   编码提示词、对话不追加）；
3. `xmake b qml_load_test && xmake r qml_load_test`（操作栏回归）；
4. `xmake r chat-list-test` 冒烟：boot 加载改动后的 llm 模块无错误；
5. 手动 GUI 验证：选中文字点「翻译」→ 侧边栏打开、输入框为选区内容 +
   末行提示词、自动发送并出回复；点「对话」→ 输入框仅选区内容、焦点在
   输入框且长引用时光标行可见（不被挡住）、不自动发送；侧边栏已打开时
   再选中文字触发各动作 → 内容进入当前会话。

## 实现记录

### 第一步：选区下方 AI 操作栏（当前分支）

#### What

选中文字后，在选中文字的下一行出现一行 AI 操作栏：最左侧为 🦞（OpenClaw）
标识，随后是「翻译」「润色」「对话」三个带图标的按钮；滚动时按钮跟随选区，
选区取消/移出视口时按钮隐藏；点击按钮暂时仅关闭按钮（翻译/润色/对话流程在
后续接入）。

#### Why

复用现有悬浮 popup 体系（`QTMBasePopup`/`QTMTextPopup` 家族）：选区变化通知、
逻辑坐标到画布像素换算、视口裁剪、滚动同步都已就绪。文本工具栏由编译选项
`text_toolbar`（默认关闭）控制，而 AI 翻译按钮是独立默认开启的功能，因此
新增一个并行 popup，不复用 `USE_TEXT_TOOLBAR` 宏。

#### How

- 新增 `QTMAiTranslatePopup`（继承 `QTMBasePopup`）：内嵌 `QQuickWidget`
  加载 `src/Plugins/Qt/qml/AiActionsBar.qml`（非模态、不走 DialogShell），
  QML 渲染圆角胶囊操作栏——🦞 标识（`Text` emoji，仓库无 OpenClaw Logo
  资源）+ 翻译/润色/对话三个带 SVG 图标的按钮（图标在
  `TeXmacs/misc/images/ai-actions/` 并注册进 `images.qrc`，hover 胶囊高亮、
  配色走 `Theme` 单例）。按钮文案由 C++ 经 context property 注入（
  `qt_translate` 走词典，translate 只折叠首字符）；点击经 QML 根信号
  `triggered(action)` 回传 C++ 槽 `onActionTriggered`（字符串式 connect，
  类上加 Q_OBJECT，libmogan 的 qt.static 规则自动 moc）。宿主窗口透明
  （`WA_TranslucentBackground` 经顶层 backing store 合成即可，**勿设
  `WA_NativeWindow`**：macOS 上原生子窗口收不到无按键 mouseMoved，按钮纯
  悬浮不点亮、按住拖动/点击才反应）、基类 widget 阴影对 QQuickWidget
  离屏渲染不生效故关闭，阴影由 QML 偏移圆角矩形模拟。重写
  `getCachedPosition` 定位（见下方位规则）。
  hover：QQuickWidget 把无按键 move 转发离屏窗口后 Quick 侧本就合成 hover
  （纯悬浮链路本身是通的，之前失效是原生子窗口挡住了 move 投递）。
  `showPopup` 显示后按当前光标位置向离屏 scene 发一次 HoverMove
  （`syncHover`）：光标在栏外时即为清空，纠正上次会话残留的 hover 态；
  MouseArea 高亮条件 `containsMouse && !pressed` 从机制上杜绝拖动中
  多按钮同亮。
  基类 `QTMBasePopup` 新增 `blank_top_offset()` 助手，消除「视口高于画布表面
  时顶部居中留白补偿」在基类两处与本类一处的复制。
  按钮字号与内边距跟随选区内**最小文字渲染高度**
  （`edit_interface_rep::get_selection_min_height` 取未加厚选区矩形的最小
  高度，经缩放因子换算成像素），整体尺寸由布局自适应；取不到高度时退回
  mini 控件字号。按钮点击后调用 `edit_interface_rep::dismiss_translate_popup`
  ——本次选区内不再弹出（选区变化时缓存失效自动复位）；Esc 同样 dismiss。
- 位置规则：始终显示在选中文字的**下一行**——与「选区最末矩形」
  （`get_selection_last_rect`：屏幕最下方、同行最右的选区矩形，即最后一个
  选中文字所在行）左缘对齐、位于其下方；下方放不下时退到选区上方，最终
  裁剪到视口内。
- `qt_simple_widget_rep`：新增 `translatePopup` 成员及
  `ensure/show/hide/scroll_translate_popup_by/is_point_in_translate_popup`，
  与 text popup 同构。
- `edit_interface_rep`：新增 `should_show_translate_popup`（100ms 缓存；
  排除 `tmfs://` 内嵌页面（聊天输入框等）、数学/代码/verbatim 上下文，
  要求选区非空）与 `update/show/hide/dismiss/invalidate_translate_popup_cache`，
  复用 `get_text_selection_rect()` 取选区矩形。
- 触发点与 text popup 并行挂接：`apply_changes`（THE_SELECTION）、
  `notify_change`（缓存失效）、键盘处理后、鼠标移动处理、视口滚动
  （`QTMWidget::scrollContentsBy`）；点击选区外且不在按钮上时隐藏。
- 词典新增 `("ai translate" "翻译")`、`("ai polish" "润色")`、
  `("ai chat" "对话")`。
- 单元测试：`editor_rep` 基类新增两个带默认实现的虚函数
  `get_selection_min_height` / `selection_last_rect_array`（仿
  `is_pre_editing` 模式，`edit_interface_rep` override），经 `glue_editor.lua`
  暴露为 `(selection-min-height)` / `(selection-last-rect)`；曾配集成测试
  `TeXmacs/tests/0986.scm` 钉其语义，但 headless 下选区几何断言依赖异步
  排版、无法稳定同步执行（还触发过游标路径崩溃），已移除，几何语义改由
  手动 GUI 验证覆盖；
  `tests/Plugins/Qt/qml_load_test.cpp` 新增 `test_ai_actions_bar_loads`
  （注入按钮文案占位，断言 `qrc:/qml/AiActionsBar.qml` 加载为 Ready）与
  `test_ai_actions_bar_hover`（直接发无按键 move，断言 containsMouse
  点亮/熄灭/重新点亮——纯悬浮链路的回归用例）。

### 追加修订（2026-09-14 下午）

#### What

1. 龙虾标识由 🦞 emoji 改为 SVG 线稿图标（与三个操作按钮同风格，
   `TeXmacs/misc/images/ai-actions/lobster.svg`，注册进 `images.qrc`）；
2. 操作栏尺寸不再跟随选区字体，改为按屏幕 DPI（`DpiUtils::scaleFactor`，
   与 QML 弹窗 dpScale 同源）缩放：`autoSize` 以 12px 基准字号按 DPI 注入
   `fontPixelSize`，整体尺寸随 QML 内边距/图标比例自适应；
3. 修复「第二次启动软件后悬浮不点亮」：hover 改由 **qApp 级 move 流**
   驱动——popup 显示期间（`showEvent`/`hideEvent` 管理挂载/卸载）在
   `QCoreApplication` 上安装 `eventFilter`，截获 `QEvent::MouseMove` 并按
   当前光标位置持续向离屏 scene 发 HoverMove（复用 `syncHover`）；栏内
   移动或刚离开时才同步，栏外远处的 move 不触发 Quick 场景命中测试。

#### Why

1. emoji 在部分平台/字体下渲染异常（缺字、基线不齐、单色），SVG 与既有
   图标体系一致且渲染确定；
2. 悬浮操作栏是 UI 控件而非文档内容，尺寸跟随文档字体（选区最小文字高度）
   语义错位——小字号文档里按钮过小难以点击；按分辨率/DPI 缩放才符合控件
   常规行为，且与基类 `QTMBasePopup::autoSize`、QML 弹窗的缩放基准统一；
3. 无按键 move 的 hover 依赖「macOS → 顶层窗口 → 半透明子 widget →
   QQuickWidget → 离屏窗口」逐级投递，该链路在部分会话下会整体失效
   （首次启动正常、后续悬浮不点亮，但点击因 grab 语义仍可用）。挂单个
   widget 的过滤器只能看到投递给该 widget 自己的事件（子 widget 路由
   不经过父级过滤器），覆盖不了失效场景；qApp 级过滤器能看到投递给
   任意对象的原始 move 流，不受路由成败影响——据此直接同步 hover，
   从机制上绕开失效环节。

#### How

- `AiActionsBar.qml`：emoji `Text` 换成 `Image`
  （`qrc:/ai-actions/lobster.svg`，`sourceSize` 随 `iconPx`）。
- `QTMAiTranslatePopup::autoSize`：`fontPixelSize = max(10,
  DpiUtils::scaled(12))`；删除 `setTextHeight`/`sel_text_height` 及
  `show_translate_popup` 链路上的 `sel_h` 参数。字号与会话内 DPI 绑定，
  鼠标移动高频重入时字号未变即跳过 QML 写入与布局重算。
- `QTMAiTranslatePopup::eventFilter`（override `QObject::eventFilter`）：
  `MouseMove && isVisible()` 时按 `hover_inside` 三态（进入/栏内/刚离开）
  决定是否 `syncHover()`；`showEvent` 挂载、`hideEvent` 卸载 qApp 过滤器，
  隐藏期间零开销。
- 顺带收敛：`get_selection_geometry(rectangle&, SI&)` 与
  `get_selection_min_height`/`selection_last_rect_array` glue（消费者
  仅剩已删除的集成测试）一并移除，收敛为 `get_selection_last_rect()`；
  且优先复用 `apply_changes` 维护的已绘制 `selection_rects`，仅缓存为空时
  才 `search_selection` 重走 `find_check_selection`——与 text toolbar 同
  模式，规避 box 树重建瞬态期的越界访问（16:27 崩溃报告实证过该路径：
  `find_check_selection ← search_selection ← get_selection_geometry`）。
  注意锚点随之从文字矩形变为**绘制选区矩形**（含 3 像素加厚），定位与
  屏幕所见一致。
- `editor.hpp` 两个带默认实现的虚函数、`glue_editor.lua` 两条 glue
  （`selection-min-height`/`selection-last-rect`）随之下线。

### 第二步：AI 翻译 / AI 对话接入（当前分支）

#### What

1. 操作栏「翻译」：把当前选区（无选区则忽视）包成「引用」外观块
   （`(quote-env (document ...))`，同 插入 → 外观块 → 引用）引用进 AI 侧边栏
   （自动打开）输入框，末行追加固定提示词「请翻译上述文字为中文」，
   **自动发送**；
2. 操作栏「对话」：同样以引用块引用选区，但不放提示词、**不自动发送**，
   引用块下留空段使光标落在引用块的下一行，聚焦输入框并滚动输入区到
   光标（`revealInputCursor`：同步滚一次 + 250ms/700ms 延时补拍——首次
   打开侧边栏时同步聚焦先于 dock 显示事件处理、会被晚到的焦点分配覆盖，
   250ms 拍挽回聚焦并补滚动，700ms 拍只补滚动覆盖慢排版），等用户补写
   后手动发送；
3. 移除「打开侧边栏自动预填选区」旧机制（1243 引入）及其 scheme 函数与测试。

#### Why

- 「引用的语法」沿用旧预填机制的数据通路：选区以 tree（C++ `selection_get`）
  传入，经 `chat-tab-set-input-body!` 写入
  `tmfs://chat/<sid>/input`，富文本（数学/加粗等）原样保留；
- 发送必须走 C++：模型/参数/状态由 ChatController 管理，直接复用发送按钮的
  `onSendRequested` 管线（标题生成、消息区创建、manifest 持久化全部一致）；
- 打开侧边栏会切换焦点与活动视图，选区必须在切换**前**捕获（旧机制注释已证），
  操作栏路径由 C++ 在点击时先取 `owner` 编辑器的选区再调发送函数；
- 侧边栏动作的目标是**当前活动会话**（侧边栏首次打开时自动新建会话），不做
  强制新建——用户会话中途引用选区进当前上下文更自然。

#### How

- `qt_chat_controller`：新增自由函数 `qt_chat_ai_send_selection (tree sel,
  string action)`——侧边栏未打开时 `call("show-chat-sidebar", #t)` 同步打开
  （已打开则跳过，避免 sync 重复 dock 重排）→ 取活动面板（面板存在即保证
  llm 模块已加载：会话创建路径 eval 过 use-modules，chat-loader 亦在启动
  idle 阶段整体加载）→ `chat-tab-set-input-body!` 写入组合后的输入体 →
  translate 走 `onSendRequested` 自动发送、chat 走 `revealInputCursor`
  （聚焦输入框并把输入区滚动到光标处；动作分支显式判 translate/chat，
  未知动作不追加尾段不发送）；
  组合逻辑抽为静态方法 `ChatController::composeAiInputBody`
  （选区包成 `(quote-env (document ...))` 引用块；翻译在其后追加
  `utf8_to_cork` 的提示词——树内字符串约定 cork，不能放 UTF-8 原始字节；
  对话追加空段，`go-end` 使光标落在引用块下一行；quote-env 宏由 generic
  样式链的 std-markup 包提供，聊天输入/消息区（generic 基样式）可直接渲染）；
- 操作栏：`QTMAiTranslatePopup::onActionTriggered` 对 translate/chat 在
  dismiss 前先取 `ed->selection_get()` 调发送函数（polish 暂仅关闭）；
- 旧机制移除：`qt_tm_widget.cpp::sync_chat_sidebar_mode` 删去选区捕获与
  `chat-tab-prefill-session-input!` 调用；`chat-protocol.scm` 删
  `chat-tab-prefillable-source?` / `chat-tab-prefill-session-input!` /
  `chat-tab-prefill-from-selection!`，`chat-tree-ops.scm` 删
  `chat-tab-should-prefill?` / `chat-tab-prefill-input!`；
  随之删除 `TeXmacs/tests/1243.scm` 与 `TeXmacs/tests/python/1243.py`
  （被测对象已不存在）。

### 追加修订（2026-09-15，基于 main；第二步已合并）

#### What

1. AI 操作栏水平位置由「与锚行左缘对齐」改为「居中于锚行」；
2. 出现位置按选择方向决定：从上往下选择显示在最后选中文字（选区底行）
   的下一行（原行为），从下往上选择显示在最后选中文字（选区顶行）的
   上一行；首选侧放不下时退到另一侧，最终裁剪到视口内；
3. cmd+j / ctrl+j（`std j`）改为：未选中文字时开关 AI 侧边栏（原语义），
   有选中文字时直接触发操作栏的「对话」动作（引用选区进当前会话输入区，
   不自动发送，与点击「对话」按钮一致）。

#### Why

1. 左缘对齐在长选区/窄末行下视觉偏置，居中更贴合悬浮工具栏惯例；
2. 操作栏应贴着「最后选中」的一端出现——从下往上选时最后选中的文字在
   选区顶部，固定显示在选区下方会把栏甩到远离落笔处；
3. cmd+j 作为 AI 入口，选中文字时用户意图是「对选中内容发起对话」而非
   开侧边栏，直接路由到操作栏「对话」可免除先找按钮一步。

#### How

- 方向判定 `edit_interface_rep::selection_made_upward`：选区按文档序规范
  化存储（start ≤ end），方向信息只在光标上——拖拽与 shift+方向键选择
  结束时光标 `tp` 停在「最后选中」的一端（mouse_drag 的 p2 与 tp 同源同
  参，严格相等），故 `path_less_eq (tp, selection_get_start ())` 为真即
  从下往上选择；选区为空时 start 为空路径，判定自然回落到向下。
- 方向与锚行在同一时刻确定并**随调用链一路传入 popup 缓存**：
  `update_translate_popup` 算一次方向 → `get_selection_last_rect (upward)`
  取锚行（向下取屏幕最下方、同行最右；向上取屏幕最上方、同行最左）→
  `show_translate_popup (selr, upward, ...)` → `qt_simple_widget` 调
  `popup->setUpward (upward)` 存入缓存。`getCachedPosition` 只读缓存字段，
  不在定位时回查编辑器活态——避免选区变化后「位置按新方向、锚行是旧的」
  的失配，也省掉每 tick 的 dynamic_cast 与重复计算。
- `QTMAiTranslatePopup::getCachedPosition`：x 为锚行水平中心减栏宽一半；
  纵向以方向无关的 `first/backup` 两候选取首选侧，放不下退另一侧，最终
  `clampToViewport` 收敛。坐标换算（逻辑→像素 + 留白补偿）与视口裁剪
  提取为基类 `QTMBasePopup::selectionEdgePixels` / `clampToViewport`，
  基类与派生定位共用（原先两处复制，会随维护漂移）。
- 操作栏动作统一入口 `edit_interface_rep::ai_action (action)`：第二步（已
  合并进 main）在 `onActionTriggered` 槽内的取选区 +
  `qt_chat_ai_send_selection` + dismiss 流程移入此方法（含「选区须在打开
  侧边栏前捕获」约束），QML 按钮 `triggered(action)` 槽改为一行转调。
- 快捷键：cmd/ctrl+j 的真实派发点是 `QTMWidget::keyPressEvent` 里 [0247]
  引入的 C++ 拦截（在 scheme 键位表之前 `return`）——拦截改为：有选区
  （编辑器 `selection_active_any`）先走 `ai_action ("chat")`，无选区保持
  原 dock 开关逻辑不变。曾同步新增 scheme 侧 `ai-chat-shortcut` +
  `("std j")` 改绑 + glue `ai-action` + `editor.hpp` 虚函数，但 Qt 是
  唯一编辑器前端、该键在 Qt 上被 C++ 拦截，四层均为不可达死代码，
  简化审查后整链移除（`ai_action` 保留为纯 C++ 方法）。
  `selection-active-any?` 对纯点击后的退化选区
  （`simple_range (p, p)` 判空）为假，天然区分「未选中」。cmd+j 的对话
  动作只看选区、不看操作栏可见性（同按钮白名单 translate/chat），
  数学/代码/verbatim 等操作栏不弹出的上下文里也可用 cmd+j 把选区引用进
  对话。
