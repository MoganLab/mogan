# 1226: 移除休眠的手写识别功能（含 poly_line）

## 任务

移除 TeXmacs 遗留、在 Mogan 中从未可用的手写字形学习/识别功能，连同其唯一
消费者 `moebius/Kernel/Types/poly_line` 模块一并删除。

## 背景

排查发现该功能处于「功能死、代码活」的休眠状态：

- `glyph-widget` 的手写区依赖 `ink_widget`，而 Mogan 的 Qt/CLI/ImGui 三个
  后端的 `ink_widget` 均为 `NOT_IMPLEMENTED` 存根——画不了任何东西，
  `last-glyph` 永远为空，Learn/Recognize 按钮全部空转。
- `learn-glyphs`（唯一打开入口）没有任何菜单/快捷键绑定，只能 scheme 会话
  手动调用，而调出来的 widget 本身不可用。
- `poly_line` 模块（`access`/`vertices`/`invariants`/`hull` 等）在整个仓库
  中除 Handwriting 自身外没有任何生产代码消费者（绘图区域手绘笔走的是
  `src/Graphics/Types` 的 calligraphy，与 moebius `poly_line` 无关）。

此前曾在分支 `da/1226/handwrite` 上对该识别管线做过性能优化（识别 ~7×），
因功能本身休眠、优化无受益方，该分支弃用，本分支改为整体移除。

## What

删除的文件：

- `moebius/Graphics/Handwriting/`（`handwriting.hpp`、`learn_handwriting.cpp`、
  `recognize_handwriting.cpp`）——识别实现与 `register_glyph`/`recognize_glyph`
  的函数体
- `moebius/Kernel/Types/poly_line.{hpp,cpp}` —— 折线几何模块
- `moebius/tests/Graphics/Handwriting/handwriting_test.cpp`
- `moebius/tests/Kernel/Types/poly_line_test.cpp`
- `moebius/bench/Graphics/Handwriting/handwriting_bench.cpp`
- `moebius/bench/Kernel/Types/poly_line_bench.cpp`
- `TeXmacs/progs/utils/handwriting/handwriting.scm` —— glyph-widget、
  learn-glyphs 与 glyphs.scm 持久化

修改的文件：

- `moebius/xmake.lua`：移除 `Graphics/Handwriting` 的源文件 glob 与
  includedirs 两条
- `src/Scheme/Glue/glue_basic.lua`：移除 `glyph-register`/`glyph-recognize`
  两个 glue 绑定
- `src/Scheme/L5/glue_l5_extra.hpp`：移除对应两个 C++ 声明
- `TeXmacs/progs/init-research.scm`：移除 `(use-modules (utils handwriting handwriting))`
- `TeXmacs/progs/prog/glue-symbols.scm`：移除符号表中的两个名字

保留（不属于本功能）：`ink_widget` 的 scheme widget 语法（`menu-define.scm`
等处的 `(ink ...)` 构造）及各后端的 `ink_widget` 存根——它们属于通用 widget
基础设施，`menu-test.scm` 等仍在引用。

## Why

- 休眠代码持续产生维护成本：glue 绑定、构建脚本、scheme 模块加载都要带着它。
- 若未来要实现真正的手写识别（含 `ink_widget`），git 历史里随时可以找回；
  届时以可用 UI 为前提重新设计，比维护一个从未可用的遗留管线更划算。

## 验证

- `xmake b stem` 编译通过（glue 重新生成无悬空符号）
- `xmake b moebius_tests && xmake test moebius_tests` 全绿
