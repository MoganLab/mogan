### 3.2 非确定性测试（手工验证）
1. 将偏好 `stem-preview` 设置为 `on`，登录或刷新登录状态。
2. 检查 OAuth 换 token、刷新 token、用户信息和魔法粘贴检查请求均携带：
   `liii_user_preview=preview; liii_agent_preview=preview; liii_admin_preview=preview`。
3. 把 `stem-preview` 设为非 `on`，确认以上请求没有 `Cookie` 头。
4. 在 production 与 staging profile 下重复步骤 1-3，确认 Cookie 只随预览开关变化，
   不改变原有站点选择。

## 5 What
为 Mogan 的预览模式提供统一的 Cookie 策略，并将其接入公共的账户相关请求。

1. 当 `stem-preview` 为 `on` 时，生成三类预览 Cookie；其他值返回空字符串。
2. OAuth 授权码换 token、刷新 token 和用户信息请求在 Cookie 非空时附加 `Cookie` 头。
3. 魔法粘贴检查请求仅在 URL 属于当前 Stem 站点时附加 Cookie。
4. 通过 `account-oauth2-config` 向 Qt 层暴露当前 Cookie 字符串。

## 6 Why
预览实例依赖 Cookie 做蓝绿路由。客户端只对部分请求携带 Cookie 时，登录状态、
会员信息和实际功能请求可能落到不同实例，造成令牌、额度或功能行为不一致。

`stem-preview` 只决定当前 profile 是否访问候选实例；`stem-profile` 仍然独立决定
production 或 staging 站点，避免把环境选择和蓝绿路由混为同一个偏好。

## 7 How
账户模块集中定义：

```
stem-preview = on
  -> stem-preview-cookie-header
  -> account-oauth2-config("preview-cookie-header")
  -> Qt OAuth / user-info 请求
```

Scheme 的魔法粘贴调用 `stem-preview-request-headers`，该函数同时检查 Cookie 是否非空
以及请求 URL 是否以 `current-stem-site` 开头。Qt 代码从账户配置读取同一字符串；
为空时不设置 `Cookie` 头，因此关闭预览模式保持既有网络行为。
