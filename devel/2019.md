## 5 What

为 `archiver.hpp` / `archiver.cpp` 补全 doxygen 风格中文注释，重点讲清
`depth`、`last_save`、`last_autosave` 三个深度字段的作用与区别。

1. `archiver.hpp`：
   - 文件头 `DESCRIPTION` 译为中文；
   - 顶部全局函数（`global_clear_history` 等）加 `@name` 分组与注释；
   - `archiver_rep` 类文档 + 全部成员变量行内注释；
   - `protected` 内部子例程（`apply`/`split`/`make_future`/`expose`/`normalize`/`corrected_depth`）注释；
   - `public` 各方法分组注释（构造清理、修改累积、Undo/Redo、分组标记、保存状态）；
   - 外层句柄 `archiver` 与 `archive_announce` 加 doxygen 注释。
2. `archiver.cpp`：
   - `clear`、`confirm`、`retract`、`simplify`、`redo_one` 中对 `depth`/`last_*`
     增减与失效点加行内说明；
   - `corrected_depth` 及 `require_/notify_/conform_save/autosave` 六个接口加 doxygen 注释。

## 6 Why

archiver 是 undo/redo 与「文档是否需要保存」判定的核心，但其历史树结构
（archive/current、多分支、跨作者）较复杂，原文件仅有零星英文注释，
 newcomers 难以快速理解。尤其是三个深度字段语义接近、却各自承担不同角色，
 缺乏说明时极易误用。补全中文注释以降低维护门槛、统一文档语言。

## 7 How

### 7.1 archiver 的整体设计

历史以一棵 **patch 树**承载（patch 类型见 `moebius/Data/History/patch.hpp`）：

- `PATCH_MODIFICATION`：单次文档修改；
- `PATCH_COMPOUND`：若干 patch 的串行序列（`make_compound`，连续修改）；
- `PATCH_BRANCH`：若干 patch 的并行分支（`make_branches`，同一时刻的多个未来）；
- `PATCH_AUTHOR`：作者标记包裹（协作场景）；
- `PATCH_BIRTH`：分组 marker（mark_start/mark_end 用）。

两个状态字段：

- `archive`：**已确认**的历史树。约定第 0 个分支是 undo 部分（可撤销历史），
  其余分支是 redo 部分（可重做的不同未来）。
  `make_history(undo, redo)` 即 `make_branches([undo, ...redo分支])`。
- `current`：**尚未确认**的修改序列（compound），由 `add()` 实时累积。

核心流程：

- 编辑 → tree 观察者调 `archive_announce` → `add()` 累积进 `current`
  → 事务结束 `global_confirm()` → `confirm()` 把 `current` 作为新 undo 节点
  `patch(current, archive)` 压入 `archive`。
- undo：把最近一个 undo 条目搬回 `current`，`depth--`。
- redo：从 redo 分支取出压成新 undo 节点，`depth++`；redo 多次产生分叉。
- 跨作者协作时，`expose`/`normalize` 会重排历史树，把被他人修改遮蔽的
  本作者条目重新暴露到 undo 链顶。

### 7.2 三个深度的作用与区别

| 字段 | 含义 | 更新方 |
|------|------|--------|
| `depth` | 当前 archive 深度（已确认的历史条目数），即「当前状态在历史链中的位置」 | confirm `++`；retract/undo `--`；redo `++`；simplify `--` |
| `last_save` | 最近一次**手动保存**时的深度，`conform_save()` 的基准 | `notify_save()` 用 `corrected_depth()` 写；`require_save()` 置 -1；保存点不可达时置 -1 |
| `last_autosave` | 最近一次**自动保存**时的深度，`conform_autosave()` 的基准 | `notify_autosave()` 用裸 `depth` 写；`require_autosave()` 置 -1；保存点不可达时置 -1 |

关键不变式：**历史一旦被重排，相关 `last_*` 即置 -1**。触发点包括：

- `normalize` / `expose`：跨作者重排历史树（`last_save = last_autosave = -1`）；
- `redo_one` 切到非第 0 分支：原主分支上的保存点被压入未选分支，不可达；
- `simplify` 合并恰好吞掉自动保存点（`depth == last_autosave + 1`）。

置 -1 后 `conform_*()` 返回 false，提示文档已变化、需重新保存。

save 与 autosave 的细微差别：

- `notify_save()` 用 `corrected_depth()`（扣除分组 marker 的虚假 +1 偏移，精确）；
  `notify_autosave()` 直接用裸 `depth`（粗粒度）。
- 初始值：构造时二者均为 0（新空文档视为已保存）；
  `clear()` 重置后二者置 -1（清空后无保存点对齐，需重新保存）。
