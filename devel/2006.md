# [2006] 基于 Windows 平台修复 C++ 测试

## 如何测试

```bash
# 单个测试
xmake b <test_target>
xmake r <test_target>

# 全部 C++ 测试
./bin/test_all
```

## What

修复在 Windows 平台（MSVC 2022 / Qt 6.8.3）上批量运行 C++ 测试时出现的多处失败与卡死问题，让 `bin/test_all`（即 `xmake run --group=tests`）能够稳定跑完。

1. `smart_font_test::test_resolve_chinese_puncts` / `test_resolve_200B` 因机器未安装 `Noto CJK SC` 失败
2. 批量跑时 GUI 窗口弹出卡住整个测试套件，并触发下一个测试进程 `0xC000013A`（`STATUS_DLL_INIT_FAILED`）
3. `template_utils_test::test_generate_without_documents_dir` 在 Windows 上 `QDir::removeRecursively()` 失败
4. `qt_pdf_reader_widget_test::test_linkClickAfterQScrollerPress` 失败（drag 判定用全局坐标导致误判）
5. `table_performance_test` 中存在大量断言为 `QVERIFY(time>=0)` 的无意义性能测试，耗时过长
6. `CLAUDE.md` 新增 Qt 窗口测试规范

## Why

这些问题在单跑某个测试时往往不出现，但在 `bin/test_all` 批量串行跑 100+ 个测试时会集中爆发，导致 CI 不可靠、开发者每次跑全量测试都要手动干预。

- **窗口泄漏**：`show()` 了顶层 widget 的测试，断言失败时 `new` 出来的 widget 不会被 `delete`，窗口持续显示。串行场景下，残留窗口 + 未处理的事件让进程退出时 Qt 卡住，下一个测试 exe 启动遇到 `0xC000013A`。
- **字体依赖**：测试硬编码 `Noto CJK SC`，而 Windows 默认只有 `SimSun`。
- **文件锁时序**：Windows 上 `QFile::close()` 后文件句柄释放有延迟，紧接的 `removeRecursively` 会偶发失败。
- **drag 判定**：用 `globalPosition()` 判定拖拽，测试手动构造的事件该值为 `(0,0)`，与 `QTest::mousePress` 真实计算的全局坐标差距巨大，误判为 drag。
- **无效性能测试**：`QVERIFY(time>=0)` 永远成立，这些用例只跑了一遍 typeset 然后丢弃数据，无法捕获任何回归，却在 CI 里浪费时间。

## How

### 1. CJK 字体平台适配（`smart_font_test.cpp`）

用 `#ifdef OS_WIN` 区分：Windows 上 CJK 字体名用 `SimSun`，其它平台用 `Noto CJK SC`。`OS_WIN` 是 lolly/xmake.lua 里定义的项目级 Windows 宏（包含 MinGW）。

### 2. 统一的 Qt 窗口清理工具（`tests/Base/base.hpp` / `base.cpp`）

新增共享函数 `cleanup_qt_top_level_widgets()`：隐藏所有可见的顶层窗口并处理事件队列。

```cpp
void cleanup_qt_top_level_widgets () {
  if (qApp == nullptr) return;
  const QWidgetList tops= qApp->topLevelWidgets ();
  for (QWidget* w : tops) {
    if (w->isVisible ()) w->hide ();
  }
  qApp->processEvents ();
}
```

三个会 `show()` 顶层窗口的测试各加一个一行 `cleanup()` 槽调用它：
- `qt_pdf_reader_widget_test`（37 处 `show()`）
- `qt_chat_tab_widget_test`
- `qt_tab_page_test`

`cleanup()` 会在每条用例结束后执行，即使中途断言失败也会兜底隐藏窗口。

### 3. Windows 文件删除时序（`template_utils_test.cpp`）

`test_generate_without_documents_dir` 原本删的是 `Documents` 根目录，但被测函数实际检查的是 `Documents/LiiiSTEM/library` 子目录。改成：
- 只删被测函数真正依赖的 `LiiiSTEM/library` 子目录
- 加 5 次重试 + `QTest::qSleep(50)`，应对 Windows 句柄释放延迟
- 用 `QVERIFY2` 带上下文信息

### 4. drag 判定改用 viewport-local 坐标（`qt_pdf_reader_widget.cpp`）

#### 背景

`PDFReaderWidget::eventFilter` 的 browse（hand）工具分支按下列规则区分"点击"和"拖拽"：

- `MouseButtonPress`：记录起始位置 `browseDragStartPos_`，置 `browseDragging_=true`、`browseDragActive_=false`
- `MouseMove`：算当前位置到起始位置的 manhattan 距离 `delta`，超过 `QApplication::startDragDistance()` 就置 `browseDragActive_=true`
- `MouseButtonRelease`：仅当 `!browseDragActive_ && overLink_` 时触发 `handleLinkClick`——即"没拖动 + 在链接上"才算点击链接

也就是说，`browseDragActive_` 一旦被误置为 true，release 时就不会触发 link click。

#### Bug

原实现把起始位置和当前位置都用 `mouseEvent->globalPosition().toPoint()`（全局屏幕坐标）：

```cpp
// press 分支（旧）
browseDragStartPos_= mouseEvent->globalPosition ().toPoint ();
// move 分支（旧）
int delta= (mouseEvent->globalPosition ().toPoint () - browseDragStartPos_)
              .manhattanLength ();
```

在单元测试里这会误判 drag：

- 测试先手动构造一个 `QMouseEvent(MouseMove, QPoint(50,50), ...)` 来 hover，这个构造函数不传 globalPosition，默认值为 `QPointF()`，即 `(0,0)`
- 紧接着 `QTest::mousePress` 注入的 press 事件，其 globalPosition 由 Qt 按窗口几何真实计算（例如 `(800, 400)`）
- 于是 move 分支里 `(800,400) - (0,0)` 的 manhattan 距离远大于 `startDragDistance()`，`browseDragActive_` 被置为 true
- release 时 `!browseDragActive_` 为 false，link click 不触发——`test_linkClickAfterQScrollerPress` 失败

```cpp
// 测试里的 hover（globalPosition 默认 (0,0)）
QMouseEvent moveEvent (QEvent::MouseMove, QPoint (50, 50), Qt::NoButton,
                       Qt::NoButton, Qt::NoModifier);
QApplication::sendEvent (vp, &moveEvent);
// press（globalPosition 由 Qt 真实计算，是个大坐标）
QTest::mousePress (vp, Qt::LeftButton, Qt::NoModifier, QPoint (50, 50));
```

#### 修复

改用 viewport-local 坐标 `viewportPos`（在 eventFilter 前段由 `me->pos()` 赋值，press 和 move 都走同一段公共代码）：

```cpp
// press 分支（新）
browseDragStartPos_= viewportPos;
// move 分支（新）
int delta= (viewportPos - browseDragStartPos_).manhattanLength ();
```

viewport-local 坐标是相对 scrollArea viewport 的，hover 和 press 都在同一个 `(50,50)` 上，`delta=0`，不会误判为 drag，release 时 link click 正常触发。

#### 生产鲁棒性收益

这不是只为了让测试通过的改动——globalPosition 在真实使用中本就不可靠：

- **多屏/DPI 不一致**：窗口跨屏时全局坐标可能跳变
- **窗口被拖动**：用户按住 hand 工具拖动 PDF 内容时，如果同时移动了主窗口，全局坐标差会被污染，可能误判 drag 状态
- **Wacom/触屏输入**：部分输入设备的 globalPosition 语义不一致

拖拽本质是"相对位移"，用 viewport-local 坐标判定更符合直觉，也消除了上述场景的潜在 bug。

#### 影响范围

只改了 `eventFilter` 的 browse 分支（press 记录、move 比较），`browseDragStartPos_` 的类型仍是 `QPoint`（头文件无需改动）。`rectSelectMode_` 分支用的是独立的一组状态变量（`rectSelectDragging_` 等），不受影响。

### 5. 精简 `table_performance_test`

删除 14 个断言为 `QVERIFY(time>=0)` 的无意义性能测试（1x1、100x100、multiple、eqnarray 全系列等），以及随之变成死代码的辅助函数（`create_eqnarray_tree`、`measure_median_table_creation_time`、`measure_two_calls_us`、`create_expanding_decoration_tree`）。保留 3 个有真实断言的用例（`test_handle_decorations_performance`、`test_cell_hyphen_wrapping`、`test_cell_long_content_no_row_duplication`）。剩下的规模档从 100x100 缩到 50x50，并删除最耗时的 `test_50x50_matrix_table`。

### 6. CLAUDE.md 新增 Qt 窗口测试规范

在「C++ 单元测试」节下新增「Qt 窗口测试」子节，说明：`show()` 顶层 widget 的测试必须在 `cleanup()` 调用 `cleanup_qt_top_level_widgets()`，并解释泄漏窗口导致套件卡死和 `0xC000013A` 的根因。
