# [1241] 连按 ￥$ 进入单行公式

## 1 相关文档
- [1199.md](1199.md) - utf8-kbd-map 支持 ￥、等非 ASCII 键
- [1233.md](1233.md) - 连按 $ $ 进入单行公式

## 2 任务相关的代码文件
- `TeXmacs/progs/generic/generic-kbd.scm` - 新增 `￥ $` 组合规则

## 3 What

在 `utf8-kbd-map` 的 `￥` 规则基础上新增一条组合键:

- `￥ $` 进入单行公式(equation*)

## 4 Why

中文输入法下连按两个 `￥` 无法进入单行公式。根因:`￥` 只有单键规则
`("￥" (make 'math))`,第一个 `￥` **立即**进入数学模式;数学模式下
`QTMWidget::inputMethodQuery` 对 `ImEnabled` 返回 false
(`!in-math-or-hybrid?`,光标刷新时 `im->update(Qt::ImEnabled)` 通知平台),
输入法随即被禁用,第二个按键只能产生 ASCII `$`,永远凑不出 `￥￥` 序列。

`$` 之所以能工作(1233):注册了 `$ $` 之后,第一个 `$` 进入 kbd 待定前缀
状态,不立即切模式,输入法保持启用,第二个 `$` 正常到达并合成规则。

## 5 How

快捷键的执行模型(`edit_interface_rep::try_shortcut`,src/Edit/Interface/edit_keyboard.cpp)
是「立即执行 + mark_cancel 回滚」:第一个 `￥` 立即执行 `(make 'math)`;
第二个键到达时若组合键命中,先 mark_cancel 回滚第一次的效果,再执行
组合键命令。因此第二个键的键名至关重要:数学模式下 ImEnabled 为 false,
第二个键是 ASCII `$`,组合序列是 `￥ $` 而非 `￥ ￥`。

在 `TeXmacs/progs/generic/generic-kbd.scm` 的 `utf8-kbd-map` 中追加:

```scheme
;; 第一个 ￥ 立即进数学模式并禁用输入法,第二个键是 ASCII $
("￥ $" (make 'equation*))
```

只注册 `￥ $` 即可:输入法被禁用后第二个键必然是 ASCII `$`;
若平台禁用不及时,第二个 `￥` 仍按单键规则处理(进入/切换数学
模式),不破坏原行为。

## 6 如何测试

本任务改动依赖真实输入法的 ImEnabled 状态切换,headless 无法复现,
没有编写自动化测试(`TeXmacs/tests/1241.scm` 不存在),验证方式为
构建后手动测试:

```bash
xmake b stem && xmake r stem   # 启动 GUI
```

### 6.1 手动验证(中文输入法,全角 ￥)

1. 文本模式连按两个 `￥`(即实际序列 `￥ $`),预期进入单行公式
   equation*,而非行内 math
2. 文本模式单按一个 `￥` 后停顿(等待组合窗口过期),预期进入行内
   公式 math(原行为不变)
3. `￥` 后接 Tab(`￥ var`),预期插入字面 `￥`(原行为不变)
4. 数学模式下按 `￥`,预期退回文本模式(原行为不变)
5. 回归:英文输入法下 `$ $` / `$ $ var` 保持 1233 的行为;`、` /
   `、 var` 行为不变

### 6.2 快速冒烟(可选)

改完后用 GUI 集成测试随便跑一个现有用例确认 kbd 文件无语法错误、
启动不崩即可,例如:

```bash
xmake b stem && MOGAN_TEST_GUI=1 xmake r 2044
```
