# [0302] LLM 侧边栏实现

## 如何测试
1. 启动 Mogan
2. 点击 `工具 -> Chat sidebar`，确认右侧出现 `Chat` 侧边栏
3. 使用快捷键 `extra c`，确认可以关闭侧边栏
4. 再次使用快捷键 `extra c`，确认可以重新打开侧边栏
5. 确认消息区不可直接输入，但可以选中其中内容
6. 确认输入区可以正常输入
7. 确认侧边栏包含标题栏、消息区、输入区和禁用状态的 `Send` 按钮
8. 多次关闭并重新打开侧边栏，确认不会因为没有 active view 而在启动阶段崩溃
9. 点击顶部 `Close` 按钮，确认侧边栏关闭后可用 `extra c` 重新打开
10. 调整界面缩放比例，确认侧边栏中的标题、边距和按钮尺寸随 `DpiUtils` 缩放
11. 当侧边栏里出现 `tool-permission` 时，确认 `yes / no` 可点击，并能触发对应回调
12. 点击 `yes / no` 后，确认 `tool-permission` 面板会自动关闭，重新触发后可再次出现
13. 确认 input 区下方与 Send 平行展示 `model`、`permission` 和 `thinking` 控件

## 2026/05/11 输入区下方新增发送选项

### What
在聊天侧边栏 input 区下方增加与 Send 按钮同排的三个控件：`model` 下拉框、`permission` 下拉框和 `thinking` 单选框。

### Why
这些是后续聊天请求发送参数的 UI 占位，需要先把布局和交互外观定下来，再逐步接入实际逻辑。

### How
底部发送区域改成一排平行控件；`model` 仅提供 `auto`，`permission` 提供 `default` 和 `full access`，`thinking` 目前只做 UI 展示，不绑定任何行为。

## 2026/05/11 统一 chat sidebar 关闭状态

### What
把聊天侧边栏顶部按钮从 `Refresh` 改为 `Close`，并让它和菜单项、快捷键 `extra c` 共享同一套关闭入口。

### Why
侧边栏关闭必须保持单一状态源，避免按钮关闭后又被快捷键或菜单误判成“还开着”而发生二次关闭或状态错乱。

### How
顶部按钮直接调用 `close-chat-sidebar`，侧边栏隐藏时同步收起 `tool-permission` 面板并重置其状态。这样菜单、快捷键和标题栏按钮都走同一个关闭路径。

## 2026/05/11 tool-permission 改成可点击 UI

### What
把聊天侧边栏 demo 里的 `tool-permission` 从纯文本提示改成带 `yes / no` 按钮的交互控件。

### Why
`tool-permission` 需要像正常 UI 一样能触发回调，后续才能把 approve / reject 接到真实 agent 控制流，而不是只展示一段静态说明。

### How
在侧边栏里增加一个独立的 permission 面板；`tool-permission` 仍保留在数据层，但消息流只显示文本提示，`yes / no` 放在原生按钮区里并通过 Scheme 回调记录选择。

普通消息流仍保持文档渲染，不把按钮混进一般文本内容里，避免把交互控件塞进文档树。

## 2026/05/11 关闭聊天内嵌 widget 首行缩进

### What
仅针对聊天侧边栏中的 message/input 两个内嵌 TeXmacs widget，关闭初始文档的首行缩进。

### Why
聊天侧边栏中的内容更接近即时消息和结构化事件流，不应继承主编辑区文档样式中的段落首行缩进。该设置必须限定在聊天侧边栏创建路径中，不能影响其他 custom embedded widget。

### How
在聊天侧边栏懒加载 message/input widget 时，将传入的初始文档包上一层局部 `with`：

`par-first = 0fn`

这样只影响 `tmfs://aux/chat-sidebar-body` 和 `tmfs://aux/chat-sidebar-input` 两个聊天 buffer，不改变通用 custom widget 的默认初始化逻辑。

## 2026/05/11 扩展 echo demo 的 item 类型展示

### What
扩展聊天侧边栏当前的 echo demo，使 agent 回复不再只返回普通文本，而是一次性展示当前数据层支持的全部 item 类型：`thinking`、`text`、`tool-call`、`tool-permission` 和 `file-diff`。

### Why
当前阶段仍不接入真实 LLM，但需要先验证消息数据结构和渲染层是否能覆盖后续 agent 回复中会出现的主要语义片段。把 echo demo 扩展为完整 item 展示，可以在 UI 中直接观察各类型的基础呈现效果。

### How
在 `chat-widgets.scm` 中把原来的 agent 文本回复替换为一个 demo agent block，依次追加 thinking、text、tool-call、tool-permission 和 file-diff item。

`file-diff` 的 payload 改为结构化 diff lines：删除行渲染为红色并带 `- ` 前缀，新增行渲染为绿色并带 `+ ` 前缀。渲染层不再使用 `verbatim` 展示 tool-call 和 file-diff 文本，避免 UI 中暴露 `<verbatim|...>` 形式的内部结构。

## 2026/05/09 关闭消息区的光标可见性链

### What
调整 `texmacs_custom_message_widget` 对应 editor 的 cursor 可见性逻辑，让消息区在鼠标点击或拖选后不再参与光标矩形的可见性计算、失效区域标记和闪烁动画。

### Why
实际验证发现，消息区中“字符中间出现一条光标状空白”的现象并不只是绘制阶段还在尝试显示光标，而是消息区虽然已经不画 cursor，本身仍然沿普通编辑区的 `make_cursor_visible / cursor_visible / copy_always` 链路维护 cursor 矩形。这样点击后会先为 cursor 位置挖出一块局部重绘区域，再因为消息区不画 cursor 而留下空白。

### How
在 `edit_interface.cpp` 中按 `buf->message_widget` 分流：

- `make_cursor_visible` 直接返回
- `cursor_visible` 直接返回
- old/new cursor 矩形的 `invalidate` 与 `copy_always` 更新整体跳过
- `animate` 中不再为消息区驱动 cursor blink invalidation

这样消息区不仅不显示插入光标，也完全退出 cursor 的可见性和擦除链，只保留文本与选区自己的重绘路径。

## 2026/05/09 接入聊天侧边栏最小 echo 闭环

### What
把聊天数据层和渲染层真正接入侧边栏的 message/input buffer，并实现一个最小的 `echo` 闭环：用户点击 `Send` 后，消息区先显示用户输入，再显示一条 `echo: ...` 的 agent 回复。

### Why
前一阶段只有 `chat-model` 和 `chat-render` 两层，还没有真正驱动侧边栏中的 message 区。接入真实 agent 之前，需要先验证从 input buffer 读取、更新 session、刷新 message buffer 到 UI 展示这一整条控制链是否成立。

### How
在 Qt 侧为聊天消息区和输入区固定命名两个嵌入 buffer：

- `tmfs://aux/chat-sidebar-body`
- `tmfs://aux/chat-sidebar-input`

同时把 `Send` 和 `Refresh` 按钮接到 Scheme 命令。Scheme 侧在 `chat-widgets.scm` 中新增最小控制器：

- 维护一个全局 `chat-session`
- 从输入 buffer 读取纯文本
- 追加一个 `user` block
- 紧接着追加一个 `agent` block，内容为 `echo: <input>`
- 清空输入区并刷新 message buffer

另外新增 `chat-widgets-test.scm`，覆盖最小 echo 闭环：写入输入区、触发 `chat-sidebar-send`、检查消息区文档树，以及确认输入区已被清空。

### Why
聊天数据层已经稳定，但它还只是状态机和持久化结构，尚不能直接驱动 message 区显示。接真实 echo 或刷新逻辑之前，先把“模型到文档”的转换独立出来并测透，可以把视图层的语义固定下来，避免后面把渲染和状态更新混在一起。

同时新增 `chat-render-test.scm`，覆盖空会话、普通文本、`thinking + text`、`tool-call`、`tool-permission` 以及多 block 顺序渲染。

## 2026/05/09 新增聊天数据层及测试

### What
新增纯 `Scheme` 的聊天数据层模块和对应测试，先把 `session / block / item` 三层结构以及核心状态机固定下来。

### Why
当前阶段的目标不是接 UI 或真实 agent，而是先把聊天记录的分块语义、item 合并规则、seal 时机和 JSON 导出结构锁定下来。先有测试，再有实现，后续接 echo 和真实对话时才不会把状态机做散。

### How
新增 `chat-model.scm`，使用两层 `flexvector` 分别承载 `blocks` 和 `items`，并提供会话创建、打开 block、追加 item、seal block 和导出 JSON 的最小 API。

### 数据结构

数据层按 `session -> block -> item` 三层组织：

- `session` 表示一次完整聊天会话，保存 `id`、`json-path`、`created-at`、`updated-at`、`dirty?`、`blocks` 和当前开放 block 的 id
- `block` 表示一段连续消息区块，保存 `id`、`actor`、`started-at`、`ended-at`、`close-reason`、`status` 和 `items`
- `item` 表示 block 内的最小语义片段，保存 `id`、`type`、`content`、`payload`、`created-at`、`updated-at` 和 `status`

其中 `blocks` 和每个 block 内部的 `items` 都使用 `flexvector` 承载，适合会话运行时频繁追加。渲染、导出或序列化时再转换为稳定顺序结构，避免 UI 或 JSON 层直接依赖可变容器。

`block` 的边界由用户提交、agent 回复完成、用户停止回复等动作驱动。一个 block seal 后不再允许继续追加 item，后续内容必须进入新的 block。

`item` 用 `type` 区分语义：

- `thinking` 表示思考过程
- `text` 表示普通文本回复
- `tool-call` 表示工具调用通知
- `tool-permission` 表示工具调用权限请求
- `file-diff` 表示文件 diff 信息

同一 block 内连续的同类型、可合并 item 可以合并内容；当 item 类型变化，或 payload/status 不适合合并时，会创建新的 item。这样既能支持 agent 连续流式输出文本，也能在工具调用、权限请求、diff 等结构化事件出现时切出独立片段。

同时新增 `chat-model-test.scm`，覆盖以下约束：

- 新建会话初始状态
- 任意时刻最多只有一个开放 block
- 同类型可合并 item 的追加规则
- 类型切换时拆分 item
- seal 后禁止继续追加
- 失败路径不污染现有状态
- `tool-call` payload 保真
- JSON 导出中的关键字段和顺序

## 2026/05/09 修正消息区选中时的局部缺字问题

### What
修正 `texmacs_custom_message_widget` 在鼠标按下并拖动选择时，按下点附近偶发字符局部消失的问题。
将 `texmacs_custom_message_widget` 的文本重绘入口从 `eb->find_box_path (tp, tp_found)` 改为根路径重绘，不再沿当前编辑光标 `tp` 的盒子路径进入消息区内容。

### Why
实际验证表明，消息区拖动选择时出现的“从选中起点开始、直到空格前的字符局部消失”并不是 cursor 闪烁或脏区擦除造成的，而是消息区仍然沿普通编辑区的 `tp` 路径参与重绘。对只读消息区来说，这条编辑态重绘路径本身没有意义，反而会把局部文本盒子带进错误的重绘顺序。

### How
在 `edit_repaint.cpp` 的 `draw_text` 中按 `buf->message_widget` 分流：

普通编辑区和输入区继续使用 `eb->find_box_path (tp, tp_found)`；消息区则直接从根路径调用 `eb->redraw`。这样只改变消息区的文本重绘入口，不影响其他 editor 的光标、选择和局部重绘逻辑。

## 2026/05/09 屏蔽聊天消息区的 Ctrl+滚轮缩放

### What
为聊天侧边栏消息区增加与输入区一致的事件过滤，只屏蔽 `Ctrl+滚轮` 触发的缩放，不影响普通滚轮和文本选择。

## 2026/05/09 新增 custom message widget

### What
新增 `texmacs_custom_message_widget`，并把聊天侧边栏消息区切换到这个新 widget。

### Why
消息区需要保留嵌入式 editor/view 的选择语义，但不应继续表现成普通编辑区。与其在 Qt 宿主层拦事件，不如在底层 editor 链路里给消息区一个独立身份，再按这个身份关闭光标和键盘编辑入口。

### How
在 `tm_buffer_rep` 上新增 `message_widget` 标志，并在 `texmacs_custom_message_widget` 的创建流程里把对应 buffer 标记为消息区。随后在 `edit_interface_rep::handle_keypress`、`handle_keyboard_focus` 和 `draw_cursor` 中按这个标志分流：

消息区不再处理键盘输入，不再启动光标闪烁，也不再绘制插入光标；普通 input widget 完全不受影响。

## 2026/05/09 屏蔽聊天输入区的 Ctrl+滚轮缩放

### What
为聊天侧边栏输入区增加事件过滤，只屏蔽 `Ctrl+滚轮` 触发的缩放，不影响普通滚轮和其他快捷键。

### Why
聊天输入区已经单独设置了固定缩放比，再允许 `Ctrl+滚轮` 继续改缩放，会让这块区域的显示比例偏离预期。这里需要的是局部禁止缩放，而不是完全禁用输入区快捷键。

### How
在 `ChatSidebarWidget` 中为输入区实际挂载的 Qt widget 及其子 widget 安装事件过滤器。检测到输入区内的 `QWheelEvent` 且带有 `Qt::ControlModifier` 时，直接 `accept` 并返回，阻止事件继续传给内部 `QTMWidget::wheelEvent` 的全局缩放逻辑。

## 2026/05/09 为 texmacs-custom-input-widget 增加自定义缩放比

### What
将 `texmacs_custom_input_widget` 的接口从三个参数改为四个参数，新增 `double zoom`，由调用方显式传入输入区域的缩放比。

### Why
聊天输入区原先仍然复用了固定的嵌入文档缩放初始化逻辑，无法像消息区那样单独控制显示比例。把缩放比提升为 custom input 的接口参数后，聊天输入区可以独立调整缩放，而不会影响现有 `texmacs_input_widget` 的默认行为。

### How
在 `tm_window.hpp`、`tm_window.cpp` 和 `glue_widget.lua` 中同步把 `texmacs_custom_input_widget` 改为接收 `zoom` 参数，并新增 `enrich_custom_embedded_document`，专门为 custom input 生成带指定 `ZOOM_FACTOR` 的嵌入文档。

聊天侧边栏当前调用先固定传入 `2.0`，其余 buffer 创建、被动 view 绑定、scrollable 设置和关闭命令包装逻辑保持不变。

## 2026/05/09 将聊天侧边栏切换到 custom widget

### What
将聊天侧边栏中消息区和输入区的构造调用，从 `texmacs_output_widget` 和 `texmacs_input_widget` 切换为 `texmacs_custom_output_widget` 和 `texmacs_custom_input_widget`。

### Why
前面已经补出了两条与现有接口等价的 custom widget。聊天侧边栏改用这两条新接口后，后续对聊天场景做缩放、只读或初始化定制时，就不会影响现有通用嵌入式 widget 的行为。

### How
在 `qt_tm_widget.cpp` 的 chat sidebar 懒加载逻辑里，仅替换两个 widget 构造函数调用，其余显示、挂载和显隐逻辑保持不变。这样当前行为和原实现一致，但聊天侧边栏已经完全切到新的 custom 分支上。

## 2026/05/09 新增与 texmacs-output-widget 等价的自定义输出 widget

### What
新增 `texmacs_custom_output_widget`，并通过 Scheme 暴露为 `widget-texmacs-custom-output`。当前实现与现有 `texmacs_output_widget` 完全一致，只是提供一条新的平行接口。

### Why
后续如果要为聊天消息区定制只读展示、缩放或渲染行为，直接修改现有 `texmacs_output_widget` 会影响其他嵌入式输出场景。先拆出一条等价接口，可以让后续定制只落在聊天相关分支上。

### How
在 `tm_window.hpp` 中新增 `texmacs_custom_output_widget` 声明，并在 `tm_button.cpp` 中直接复制 `texmacs_output_widget` 的实现，包括嵌入文档增强、环境初始化、惰性排版、背景色处理以及最终的 `box_widget_rep` 包装。

在 `glue_widget.lua` 中新增 `widget-texmacs-custom-output` 的 glue 定义，并在 `glue-symbols.scm` 中补齐对应符号，使 Scheme 层可以像调用现有 `widget-texmacs-output` 一样调用这条新接口。

## 2026/05/09 新增与 texmacs-input-widget 等价的自定义输入 widget

### What
新增 `texmacs_custom_input_widget`，并通过 Scheme 暴露为 `widget-texmacs-custom-input`。当前实现与现有 `texmacs_input_widget` 完全一致，只是提供一条新的平行接口。

### Why
后续如果要为聊天侧边栏定制缩放、只读或初始化行为，直接继续复用 `texmacs_input_widget` 会把通用嵌入式输入控件和聊天场景耦合在一起。先复制出一条等价接口，可以在不影响现有调用方的前提下逐步做定制。

### How
在 `tm_window.hpp` 和 `tm_window.cpp` 中新增 `texmacs_custom_input_widget`，实现直接复制 `texmacs_input_widget` 的构造流程，包括嵌入文档增强、buffer 创建、被动 view 绑定、scrollable 设置和关闭命令包装。

在 `glue_widget.lua` 中新增 `widget-texmacs-custom-input` 的 glue 定义，并在 `glue-symbols.scm` 中补齐对应符号，使 Scheme 层可以像调用现有 `widget-texmacs-input` 一样调用这条新接口。

## 2026/05/09 将消息区改为 output，输入区改为 input

### What
将聊天侧边栏中的两个静态占位区域替换为真正的 TeXmacs 嵌入式 widget。其中消息区改为 `texmacs_custom_output_widget`，输入区改为 `texmacs_custom_input_widget`。

### Why
静态骨架只能验证 dock 布局，无法验证聊天侧边栏承载 TeXmacs 组件时的实际行为。消息区需要天然只读但可选择，输入区需要保持可输入，因此两者不应继续共用静态占位实现。

### How
在 `ChatSidebarWidget` 中去掉原来的消息区和输入区占位 `QLabel`，改为保存两个 `qt_widget` 句柄，并新增 `setMessageWidget`、`setInputWidget` 和 `hasEmbeddedBuffers`，用于把外部传入的 TeXmacs widget 装入两个容器区域。

在 `qt_tm_widget.cpp` 中，保持侧边栏骨架初始化逻辑不变，但把消息区和输入区的真正创建延迟到第一次显示 chat sidebar 时执行。这样可以避开主窗口构造早期没有 active view 的问题。创建时，消息区使用 `texmacs_custom_output_widget (tree (DOCUMENT, ""), chat_style, 2.0)`，输入区使用 `texmacs_custom_input_widget (tree (DOCUMENT, ""), chat_style, url_none (), 2.0)`。

## 2026/05/09 添加聊天侧边栏静态骨架

### What
新增一个独立的聊天侧边栏静态骨架，通过 `工具 -> Chat sidebar` 和快捷键 `extra c` 控制显隐。侧边栏使用新的 `ChatSidebarWidget` 作为 Qt 宿主，当前只包含标题栏、消息区、输入区和禁用状态的发送按钮，不接入任何 LLM 或消息业务逻辑。

### Why
第一步需要先验证侧边栏作为独立 dock 的可行性，包括显隐控制、布局结构和高缩放场景下的显示效果。在这一阶段不引入实际对话逻辑，可以避免 UI 骨架和业务代码耦合在一起。

### How
在 Qt 层新增 `ChatSidebarWidget`，使用 `QDockWidget + QSplitter + DpiUtils` 组织静态布局；在主窗口中挂载新的 chat dock，并增加 `SLOT_CHAT_SIDEBAR_VISIBILITY` 用于控制显隐。

在 Scheme 层新增 `chat-widgets.scm`，提供 `open-chat-sidebar`、`close-chat-sidebar` 和 `toggle-chat-sidebar` 三个最小命令；再分别在 `tools-menu.scm` 和 `generic-kbd.scm` 中增加菜单入口和快捷键入口。
