# [0735] 修复 WASM (ImGui) footer 不更新：画布失效区重绘后未清空

## What?

WASM ImGui 前端的底部状态栏（footer）不更新：mode/字号/页码/光标位置等始终为
空或停留在初始值，而 Qt 前端正常。直接表象是 `update_menus`（scheme:
`update-menus`）在启动后几乎不再被调用，导致 `set_footer()` 不执行，
`SLOT_LEFT/MIDDLE/RIGHT_FOOTER` 从不发送到窗口 widget。

本任务修复 ImGui 画布（`im_simple_widget_rep`）在重绘后不清空失效区
（`is_dirty` / `invalid_regions`）的问题，使 `update_menus` 的空闲触发路径恢复
工作。改动**仅限 ImGui 后端**，不触碰共享编辑器代码，Qt 前端行为不变。

## Why?

### footer 内容的唯一来源

全局搜索可知，`set_footer()` 只在一处被调用：`update_menus()` 内
（`edit_interface.cpp:857`）。`set_footer()` 再经编辑器的
`set_left/middle/right_footer()` → `tm_window` → `::set_left_footer(wid)` →
`send<string>(wid, SLOT_LEFT_FOOTER)` 写入窗口 widget。**没有其它路径写 footer。**
因此「footer 是否更新」⟺「`update_menus()` 是否跑到第 857 行」。

而菜单栏 `menu_main` 有两个调用点：`update_menus()` 内（`edit_interface.cpp:830`）
**和** `resume()` 内（`edit_interface.cpp:117`）。`resume()` 会刷新菜单/图标栏/
工具栏，但**不调用 `set_footer()`**；且 `attach_view → resume()`
（`new_view.cpp:585`）在 WASM 启动时一定会执行。所以即便 `update_menus()` 一次都
不跑，菜单也能由 `resume()` 单独显示——这正是「菜单正常、footer 异常」同时出现
的原因，它恰恰证明了 `update_menus()` 没有跑到末尾。

### `update_menus` 的触发机制

`update_menus()` 在 `apply_changes()` 里有两个入口（`edit_interface.cpp:894`）：

- 入口 B（`env_change & THE_MENUS`，行 1237）：`THE_MENUS` 只在退出全屏时
  `notify_change`（`edit_interface.cpp:1294`），基本不触发。
- 入口 A（空闲路径，行 926）：需 `idle_time(INTERRUPTED_EVENT) >= 1000/6`（约 167ms）。
  `idle_time()`（`edit_interface.cpp:806`）定义为
  `env_change==0 && got_focus && !query_invalid(this) && !check_event()` 时返回
  `texmacs_time() - last_change`，否则返回 0。

即 `update_menus()` 要跑起来，编辑器必须连续空闲 ≥167ms。

### 根因：ImGui 画布失效区重绘后从不清空

ImGui 的 `im_simple_widget_rep` 用 `is_dirty` / `invalid_regions` 记录「需要重绘」，
`SLOT_INVALID` 查询返回 `is_invalid()`（`im_simple_widget.cpp:211`、`130`）：

```cpp
bool is_invalid () { return is_dirty || !is_nil (invalid_regions); }
```

但全仓搜索 `is_dirty =` / `invalid_regions =`，它们只会在
`invalidate_rect`/`invalidate_all`（`im_simple_widget.cpp:119/124/126`）里被置 `true` 或
累加，**重绘后从不被清回 `false` / nil**。对比 Qt：
`qt_simple_widget_rep::repaint_invalid_regions`（`qt_simple_widget.cpp:496-507`）在重绘
时逐块消费 `invalid_regions`（`invalid_regions = invalid_regions->next`），重绘后清空。

因此 ImGui 下 `is_invalid()` 一旦被置脏就**永远为 `true`**，导致完整因果链：

1. `query_invalid(main_widget)` 恒为 `true`；
2. `im_main_loop` 的渲染门 `if (texture_dirty || query_invalid(main_widget)) render_editor();`
   **每帧都触发**；
3. `render_editor` → `handle_repaint` → `edit_repaint.cpp:513`
   `if (last_change - last_update > 0) last_change = texmacs_time();` → **每帧把
   `last_change` 刷成当前时间**（debug 实测约 31ms 一次，即帧率）；
4. `idle_time() = texmacs_time() - last_change` 恒为 **0**（debug 已证实
   `idle_time(INTERRUPTED_EVENT): 0`）；
5. 空闲路径入口 A 永不满足 → `update_menus()` 启动后几乎不再运行 →
   `set_footer()` 不执行 → footer 不更新；
6. 菜单由 `resume()` 独立刷新，故表面正常。

> 附带收益：这也是一个性能 bug——修之前 ImGui 每帧都对整篇文档做一次
> `handle_repaint` + 纹理上传（`im_tm_widget.cpp:266`）。修好后渲染变为事件驱动，
> 仅在真正失效（编辑/滚动/光标闪烁）时重绘。

## 涉及的主要代码位置及实现方式

实现方式：仿照 Qt，在画布整块重绘后清空失效区，使 `is_invalid()` 在空闲时回到
`false`，让 `idle_time` 能涨过 167ms。改动只在 ImGui 后端。

| 位置 | 文件 | 说明 |
| --- | --- | --- |
| 新增清空方法 | `src/Plugins/ImGui/im_simple_widget.hpp` | 在失效区方法组里加 public 声明 `void clear_invalid ();` |
| 清空实现 | `src/Plugins/ImGui/im_simple_widget.cpp` | 新增 `im_simple_widget_rep::clear_invalid ()`，置 `is_dirty = false; invalid_regions = rectangles ();` |
| 重绘后调用 | `src/Plugins/ImGui/im_tm_widget.cpp`（`render_editor()`） | 在 `ed->handle_repaint (ren, x1, y2, x2, y1);` 之后、`tm_delete (ren);` 之前加 `ed->clear_invalid ();` |

`render_editor()` 每次重绘的是整张画布（`x1,y2,x2,y1` 取整张 picture 边界，
`im_tm_widget.cpp:247-259`），故一次性清空全部 `invalid_regions` 与 Qt 逐块消费的
语义等价、且正确。清空逻辑放在 `render_editor` 而非共享的
`edit_interface_rep::handle_repaint`（`edit_repaint.cpp`），是为了不影响 Qt。

修复后的帧循环：
- 编辑/滚动/光标闪烁 → `invalidate` → `is_invalid` 为 `true` → 触发 `render_editor`
  → `handle_repaint`（含光标）重绘 → `clear_invalid` 消费失效区；
- 空闲时 `is_invalid` 为 `false`，不再每帧重绘，`idle_time` 涨过 167ms →
  `update_menus()` → `set_footer()` 正常运行，footer 随之更新。

## 如何测试
```
xmake f -m debug --qt_frontend=no --pdfhummus=no
```
1. 构建 ImGui 前端（桌面）：`xmake b stem`，运行 `xmake r stem`
   - 确认底部状态栏随编辑实时变化：移动光标时右侧位置/快捷键更新、
     切换 text/math 模式时左侧 mode/字号更新、翻页时中间页码 `当前/总数` 更新。
   - 确认 footer 不再恒为空或停留在初始值。
   - 确认光标仍能正常闪烁（`animate → invalidate → render → clear_invalid`
     每个闪烁周期触发一次重绘）。
2. （可选）在 `edit_interface.cpp:921` 附近保留 `LIII_DEBUG` 打印，确认
   `idle_time(INTERRUPTED_EVENT)` 在空闲时能涨到 ≥167，且 `update_menus` 被调用。
3. 构建 Qt 前端：`xmake f --qt_frontend=y && xmake b stem`，确认 Qt 行为与改动前
   完全一致（本次未改任何 Qt 或共享编辑器代码）。
4. 代码风格：提交前执行 `gf fmt --changed-since=main` 格式化所改
   `.cpp`/`.hpp`。

## 备注

- 本次仅修复「画布失效区重绘后未清空」这一根因，未改动 `update_menus` 的触发逻辑、
  也未改 footer 的内容计算（`edit_footer.cpp`）与三栏渲染（`im_tm_widget.cpp` 状态栏）。
- `edit_repaint.cpp:513` 在每次重绘时刷新 `last_change` 是共享逻辑（Qt 同样依赖它），
  不应改动；正确的修法是让 ImGui 像 Qt 一样「按需重绘」，从而避免空闲期被无谓重绘
  反复刷新 `last_change`。
- footer 三栏（`SLOT_LEFT/MIDDLE/RIGHT_FOOTER`）的接收与渲染（`im_tm_widget.cpp`
  的 `send` 处理与即时模式状态栏）已验证正确，无需调整。
