# 1174 keyboard 快捷键模块加载性能观测

## What

1. 给 `init-keyboard.scm` 中 `lazy-keyboard` 注册的 19 个快捷键模块
   （`math/math-sem-edit.scm` 无 `kbd-map`，除外）各加两条
   `debug-message`（`keyboard` 通道），仿照 mogan 仓库
   `plugins/keyboard/progs/keyboard/emoji.scm` 的风格：

   - 模块加载开始时（`texmacs-module` 之后）：
     `(<模块名>): registering kbd-map ...`
   - 模块加载完成时（文件末尾）：`(<模块名>): kbd-map registered`

2. 插件加载日志（`tm-plugins.scm` 的 `plugin-initialize`）改为同样
   风格：通道由 `debug-std` 改为 `plugin`，消息为
   `(<插件名>): loading plugin ...` / `(<插件名>): plugin loaded`，
   时间戳之差即单个插件的加载耗时。

## Why

`init-keyboard.scm` 末尾的 `(lazy-keyboard-force #t)` 在 init 阶段就
同步 `module-provide` 全部模块，`lazy-keyboard` 的延迟（`delayed
(:idle 250)`）与 mode 门控均被旁路，懒加载名存实亡。启动时这批模块
到底花多少时间、哪个是大头，之前没有数据。在模块内部埋点（而不是在
`init-keyboard.scm` 的 `lazy-keyboard` 调用处）才能量到每个模块真实
的加载耗时。

## How

- 用 Python 脚本统一插入：按括号平衡定位 `texmacs-module` 表单结束行，
  其后插入 registering 消息；文件末尾追加 registered 消息。
- **`text/text-kbd.scm` 是 latin-1 编码**（含 4 个 `0xff` 字节，即
  `ß`），该文件用 latin-1 读写，处理前后 `0xff` 计数不变（4 → 4），
  文件长度差恰为两行新增。其余 18 个文件均为 UTF-8。
- **`(generic search-kbd)` 的特殊性**：注册时无 mode 参数，
  `lazy-keyboard-do` 的 `for-each` 空转，从不进入
  `lazy-keyboard-waiting`（故 force 时 `waiting=19` 而非 20），只能靠
  `delayed (:idle 250)` 延迟加载，不在本次 force 日志里。

## 性能数据（2026-08-06 实测，启动日志时间戳）

`lazy-keyboard-force` 全程 **~675ms**（36.859 → 37.534），各模块
`registering` → `registered` 耗时：

| 模块 | 耗时 |
|------|------|
| **math math-kbd** | **382ms（占 57%）** |
| text text-kbd | 37ms |
| generic generic-kbd | 25ms |
| table table-kbd | 14ms |
| source source-kbd | 9ms |
| keyboard text-kbd-utf8 | 8ms |
| graphics graphics-kbd | 8ms |
| texmacs keyboard prefix-kbd | 7ms |
| prog prog-kbd | 4ms |
| 其余 10 个 | 0–3ms |

- 模块本体合计 ~510ms；模块间空隙（`module-provide` 定位文件 +
  `:use` 依赖加载）合计 ~160ms。
- **结论**：`math-kbd.scm`（3041 行）一家占 382ms，是唯一值得优化
  的目标（拆分文件或对其恢复真正的懒加载）；其余 18 个模块合计不到
  300ms，直接加载没有问题。

## 子任务：清理 math:symbol:limits 快捷键前缀（2026-08-06）

### What

删除 `math:symbol:limits` 前缀（按键序列 `S-F5 L`）及其下 14 条绑定
（`math-kbd.scm` 中 `math:symbol:limits I/O ...` 一系列），以及
`prefix-kbd.scm` 中对应的前缀定义和 kbd-tooltip 条目。

### Why

该前缀下绑定过于复杂（`I`/`O` × 1–4 重 × `var` 组合共 14 条），
且提供的带上下限大算符（`intlim`/`ointlim` 系列）已有更直接的入口：

- `math:symbol I var var`（`S-F5 I var var`）→ `intlim`
- `math:symbol I !`（`S-F5 I !`）→ `intlim` 等 `!` 后缀系列

前缀本身也被嵌套在 `math:symbol`（`S-F5`）之下，实际按键序列是
`S-F5 L ...`，层级深、难记忆，属于罕见用法，不值得占用前缀资源。

### How

- `math-kbd.scm`：删除 14 条 `math:symbol:limits ...` 绑定。
- `prefix-kbd.scm`：删除 `("math:symbol:limits" "math:symbol L" #t)`
  及 tooltip 条目 `("math:symbol:limits" "" "Insert ...")`。
- `math:symbol:circled`（`S-F5 @`）及其他 `math:symbol` 子绑定不受影响。

### 涉及文件

- `TeXmacs/progs/math/math-kbd.scm`
- `TeXmacs/progs/texmacs/keyboard/prefix-kbd.scm`

## 子任务：清理 math:greek / math:bold:greek 快捷键前缀（2026-08-06）

### What

删除 `math:greek` 前缀（`S-F7`）下全部 75 条绑定（4 条 `make-rprime`
杂项符号 + 71 条希腊字母），以及派生前缀 `math:bold:greek`
（`math:bold math:greek`）下全部 66 条粗体希腊字母绑定，共 141 条；
同步删除 `prefix-kbd.scm` 中两个前缀定义和两个 kbd-tooltip 条目。

### Why

希腊字母已有更直接的入口，无需占用 `S-F7` 前缀：

- 普通希腊字母：数学模式下 `a var` → `<alpha>`、`b var` → `<beta>`
  （`in-math-not-hybrid?` 模式的 var 循环绑定）
- 粗体希腊字母：`math:bold a var` → `<b-alpha>`（`math:bold` 前缀下
  的 var 绑定）

`math:greek` 绑定存在大量与 var 循环重复的别名（如 `math:greek c` 与
`math:greek s var` 同为 `<varsigma>`），属于 TeXmacs 遗留的冗余入口。
与 `math:symbol:limits` 同理：层级深、与主入口重复，不值得保留。

### How

- `math-kbd.scm`：删除三段——`math:greek '/"/+/*`（4 条
  `make-rprime`）、`math:greek a` 至 `math:greek F`（71 条）、
  `math:bold:greek a` 至 `math:bold:greek F`（66 条），连同段前空行。
- `prefix-kbd.scm`：删除 `("math:greek" "S-F7" #t)`、
  `("math:bold:greek" "math:bold math:greek" #t)` 及两个 tooltip
  条目。
- 全库确认无残留：`math:greek` / `math:bold:greek` 仅这两个文件
  引用；文档（`TeXmacs/doc`）与语言包未提及 `S-F7`。
  `gui-keyboard.scm` 的 `F7/S-F7` 是虚拟键盘按键渲染、`tmdoc-kbd.scm`
  的 `("S-F7" (make 'scm))` 是 tmdoc 模式独立绑定，均不受影响。

### 涉及文件

- `TeXmacs/progs/math/math-kbd.scm`
- `TeXmacs/progs/texmacs/keyboard/prefix-kbd.scm`

## 子任务：清理 math:bold:up / math:bold:cal 快捷键前缀（2026-08-07）

### What

删除组合前缀 `math:bold:up`（`F6 F5`）和 `math:bold:cal`（`F6 F7`）
及其全部绑定：`math:bold:up` 下 90 条有效绑定（52 条拉丁字母 + 38 条
粗体直立希腊字母 var 绑定，另有 27 条早已注释的大写希腊字母一并删除），
`math:bold:cal` 下 52 条拉丁字母绑定；同步删除 `prefix-kbd.scm` 中两个
前缀定义和两个 kbd-tooltip 条目。

### Why

组合前缀需要连按两个功能键再输入字符（如 `F6 F5 a`），层级过深、
难以记忆和发现。粗体直立字符已有更直接的替代入口：字母双写 + var
循环（如 `A A var var var var var var` → `<b-up-A>`、
`a a var var var var` → `<b-up-a>`）。

注意：`<b-cal-*>`（粗体花体）在 `math:bold:cal` 之外没有其他键盘
入口（var 循环只覆盖 bbb/cal/cal*/frak/b/up/b-up 七种字形），删除后
该组字符仅能通过菜单或 `\b-cal-x` 命令输入；因前缀本身过于复杂，
仍按任务要求一并移除。

### How

- `math-kbd.scm`：删除两段——`math:bold:up a` 至注释段
  `;; ("math:bold:up Z var" ...)`（含段前空行）、`math:bold:cal a` 至
  `math:bold:cal Z`（含段前空行）。
- `prefix-kbd.scm`：删除 `("math:bold:up" "math:bold math:up" #t)`、
  `("math:bold:cal" "math:bold math:cal" #t)` 及两个 tooltip 条目。
- 全库确认无残留：`math:bold:up` / `math:bold:cal` 仅这两个文件引用；
  文档（`TeXmacs/doc`）、语言包、测试目录均未提及。

### 涉及文件

- `TeXmacs/progs/math/math-kbd.scm`
- `TeXmacs/progs/texmacs/keyboard/prefix-kbd.scm`
