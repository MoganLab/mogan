# [1271] 导出PDF弹窗内联目的地路径 + Browse

## 如何测试

1. `xmake b stem && xmake r stem` 启动 Mogan，`文件 -> 导出为PDF...`：
   - 预期：弹窗内直接显示默认目的地完整路径（缺省目录 + 建议文件名，
     右侧「浏览」按钮），不再点确认后再弹文件选择框
   - 预期：路径不长时原样展示；路径过长时中间省略（开头目录与结尾文件名
     保留，形如 `/home/da/…/demo.pdf`）
2. 点「浏览」弹原生保存对话框（过滤 PDF），选中的完整路径回填弹窗，
   确认后导出到该路径
3. 勾选「将源文档作为附件嵌入PDF」后导出：目的地不变（不再随勾选联动
   `xxx.tmu.pdf` 命名），PDF 内嵌入源文档附件
4. 中文路径实测：打开位于中文目录（如 `~/文档/演示/`）或中文名的 tmu 导出，
   或 Browse 选中含中文的路径——预期正常落盘，文件名不乱码
5. `xmake r export-pdf-default-dir-test`：9 组用例全过（新增 3 组
   `export-pdf-ensure-suffix` 后缀兜底用例）
6. `xmake b qml_load_test && xmake r qml_load_test`：
   `test_export_pdf_loads` 过（含 path 字段透传断言）、
   `test_export_pdf_path_utf8_roundtrip` 过（中文路径往返保真）；
   `test_version_dialog_focuses_on_open` 失败为环境固有，与本任务无关，
   干净树同样失败

## 2026/09/05

### 中文路径导出失败修复（同名日第三次提交）

#### What/Why

路径含中文时导出失败。根因在返回链：QML 提交的值经 `from_qstring` 转回
scheme，而 `from_qstring = utf8_to_cork (from_qstring_utf8 (s))` 强制过
cork——cork 是 8 位编码，表达不了 CJK，中文被转成 `<#6D4B#>` 形态的逃逸串，
落盘路径无效。正向（scheme→QML）的 `to_qstring` 靠 `looks_utf8` 启发式恰好
走对分支（`looks_universal` 只认 `<#...>` 逃逸），显示无恙，故故障只出现在
导出环节。

#### How

- `src/Plugins/Qt/QTMQmlDialog.cpp`：`cpp_export_pdf_dialog` 三处按数据契约
  显式走 UTF-8，不调 `looks_utf8` 启发式——path 字段值经 `utf8_to_qstring`
  注入 QML；"ok" 测试钩子与真实返回链的 value 一律 `from_qstring_utf8`
  （本弹窗 value 只有布尔与路径，均为 ASCII/UTF-8）。
- `tests/Plugins/Qt/qml_load_test.cpp`：新增
  `test_export_pdf_path_utf8_roundtrip`——经 "ok" 钩子喂入
  `/tmp/导出/演示.pdf` 断言往返保真。已在旧代码上验证该用例失败（cork
  逃逸）、修复后通过，非空洞用例。

### GUI 验证反馈修复（同名日第二次提交）

#### What/Why/How

1. **导出报 `unbound variable fname`**：mogan 的 `with` 是单绑定宏
   `(with var val . body)`（`abbrevs.scm:96`），扁平写多绑定
   `(with embed #f fname "" ...)` 展开成 `(let ((embed #f)) fname "" ...)`，
   `fname` 被当 body 表达式求值。改用 `let*` 双绑定（同文件
   `attach-doc-to-exported-pdf` 惯例），并留注释说明。
2. **路径展示偏短**：label 固定占 35% 宽（≈144px）挤占路径区；改为 label 取
   文案自然宽度（「导出到」≈45px），余宽全给路径展示（`Row` 内 Text 自然宽 +
   Rectangle 减 `destLabel.implicitWidth`）。
3. **选完目录意外触发导出**：Browse 弹的原生保存对话框里按 Enter 确认后，
   焦点切回弹窗瞬间按键泄漏进 DialogShell 的 `Keys.onReturnPressed →
   onActivate → submit`。去掉 ExportPdf 的 `onActivate`（PrintToFile 同款——
   该弹窗本就无 Enter 确认链路），确认只认「导出」按钮。

### 导出PDF弹窗显示默认完整路径，Browse 自定义目的地

#### What

「导出为PDF」QML 弹窗（1267）原先只收集「是否嵌入源文档」，点确认后才弹
`choose-file` 选目录。改为：弹窗内直接显示默认目的地（完整路径，含文件名），
右侧「浏览」按钮弹原生保存对话框自定义；路径过长时中间省略展示。确认后按
返回的路径直接导出，不再二次弹框。

#### Why

两步弹框（选项确认 → 文件选择）割裂且多一次点击；目的地默认值（1270 的
目录策略 + 建议文件名）本就完全确定，直接展示出来所见即所得，想改再点
「浏览」。

#### How

- `TeXmacs/progs/texmacs/texmacs/tm-print.scm`：`export-as-pdf` 表单追加
  `(path ...)` 字段，初值为 `export-pdf-default-dir` + `propose-export-pdf-name`
  拼出的完整路径（经 `url->system` 转系统串）；确认时从返回 kv 里取
  `"path"`，`export-pdf-ensure-suffix` 兜底 `.pdf` 后缀后，按 embed 分发给
  `wrapped-print-to-pdf-embeded-with-tmu` / `wrapped-print-to-file`，
  `choose-file` 移除。新增纯函数 `export-pdf-ensure-suffix`（Browse 允许选
  任意文件名，对齐旧 choose-file 按类型补后缀语义）。
  注意：目的地不再随「嵌入源文档」勾选联动 `xxx.tmu.pdf` 命名——勾选只影响
  是否嵌入附件；要换名经「浏览」。
- `src/Plugins/Qt/qml/ExportPdf.qml`：path 型字段单列渲染——label +
  只读路径展示 + `MiniButton`「Browse」。展示用 `Text` 的
  `ElideMiddle`：过长时中间省略（保住开头目录与结尾文件名），不长则原样
  展示；Repeater 只渲染非 path 字段（toggle）。Browse 点按经 context
  property `browseBridge.browse(current)` 取新路径回填 values。
- `src/Plugins/Qt/PrintToFileBridge.hpp/.cpp`：构造函数加 `filter` 参数
  （缺省保持打印到文件的 ps/pdf 过滤），「导出为PDF」传 `PDF (*.pdf)` 复用
  本桥弹原生保存对话框。
- `src/Plugins/Qt/QTMQmlDialog.cpp/.hpp`：`cpp_export_pdf_dialog` 注入
  `browseBridge`（PrintToFileBridge，PDF 过滤）与 `browseLabel`
  （qt_translate "Browse"），exec 后 delete。
- `TeXmacs/plugins/lang/dic/en_US/zh_CN.scm`：新增 `("Export to" "导出到")`、
  `("Browse" "浏览")`。
- `TeXmacs/progs/texmacs/texmacs/tests/export-pdf-default-dir-test.scm`：
  追加 `export-pdf-ensure-suffix` 三组用例（无后缀补 .pdf、已带 .pdf 原样、
  其他后缀追加）。
- `tests/Plugins/Qt/qml_load_test.cpp`：`test_export_pdf_loads` 注入 path
  字段与 browseBridge 桩，断言 QML 侧 `pathKey`/`pathValue` 透传初值。
