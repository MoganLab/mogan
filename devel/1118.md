## 5 What

将整个颜色子系统（基础颜色 API、`true_color` 浮点类型、6 张命名颜色表）从 `src/Graphics/Colors/` 整体迁入 `moebius/moebius/data/`，使其成为 moebius 提供的领域数据能力：

1. 在 `moebius/moebius/data/colors.hpp` 中以命名空间 `moebius::data` 重新声明全部公共 API（`rgb_color` / `get_rgb_color` / `xpm_color` / `cmyk_color` / `named_color` / `get_hex_color` / `blend_colors` / `reverse` / 各 `*_color` 查表内联函数 / 全局颜色 extern 声明 / `initialize_colors` 等）
2. 将 `colors.cpp`、`true_color.{hpp,cpp}`、6 张命名色表头文件整体迁入 `moebius/moebius/data/`
3. 更新 `moebius/xmake.lua`，把新源文件与头文件加入 `libmoebius` target 的 `add_files` / `add_headerfiles`
4. 删除 `src/Graphics/Colors/` 下全部 10 个文件
5. 更新 18 处调用方的 `#include "colors.hpp"` 为 `#include <moebius/data/colors.hpp>`，并在调用处加 `using moebius::data::*` 或显式限定（优先 `using` 集中在各 cpp 顶部，最小化调用点改动）
6. 在 `moebius/tests/moebius/data/colors_test.cpp` 中以 doctest 框架固化行为，覆盖：
   - RGB 往返：`get_rgb_color(rgb_color(r,g,b,a))` 四分量无损
   - 命名颜色解析：`named_color("red")` / `"Blue"`（大小写）/ `"#aabbcc"`（hex）/ 未知名称回退
   - 各色表查表：`dvips_color` / `x11_color` / `svg_color` / `html_color` / `tm_color` / `xc_color` 各取若干代表色验证
   - `blend_colors` / `reverse` 的关键性质
   - hex 描述往返：`get_hex_color` 与 `named_color("#...")` 一致

## 6 Why

颜色子系统是 Graphics/Typeset/Fonts/Plugins 共用的基础领域数据，但其当前位于 `src/Graphics/Colors/` 导致三个问题：

1. **font 模块拆分的拦路虎**：1119（font 独立为依赖 lolly+moebius 的子模块）要求 font 代码只向下游依赖 `libmoebius`/`liblolly`。但 `src/Graphics/Fonts/{font,recolored_font,superposed_font}.cpp` 共 3 个文件 `#include "colors.hpp"`，把 font 反向拽回了应用层的 `src/Graphics/Colors/`。本任务把这 3 处（连同其余 15 处）反向依赖一次性清除。
2. **职责错位**：颜色是纯数据域（无 GUI、无 Qt、无 Scheme 回调），与 moebius 已有的 `data/page_type`（1117 刚迁入）、`data/scheme`、`Kernel/Types` 同属"领域基础数据"。其底层类型 `color` 本就定义在 `lolly/Kernel/Abstractions/basic.hpp`，下沉后与类型定义同处 lolly/moebius 体系，依赖方向自然纠正。
3. **重复耦合点**：当前 `src/Graphics/Pictures/raster.hpp`、`raster_picture.hpp`、`src/Graphics/Bitmap_fonts/glyph_effected.cpp` 经 `true_color` 也被拽回 `src/Graphics/Colors/`，下沉后 Pictures/Bitmap_fonts 同样升级为"使用 moebius 公共 API"。

下沉后，颜色与 1117 的 `page_type` 在 moebius/data 内并列，font（1119）、Pictures、Bitmap_fonts、Renderer、Typeset 等下游统一从 `#include <moebius/data/colors.hpp>` 取用。

## 7 How

### 7.1 实现要点

- **`colors` 进命名空间、`true_color` 保留全局作用域**：`colors.{hpp,cpp}` 的全部公共符号移入 `namespace moebius::data`（与 page_type 先例一致）。但 `true_color` 类及其大量内联自由函数（`operator+`/`min`/`max`/`source_over`/...）依赖参数依赖查找（ADL），若移入命名空间，调用方（effect/picture/raster 等）的所有运算符重载解析会大面积出错。因此 `true_color.{hpp,cpp}` 仅做物理位置迁移，**保持全局作用域**，调用方零改动（只换 include 路径）。
- **`reverse_colors` 命名对齐**：原 `colors.hpp` 声明 `extern bool reverse_color`（单数），但 `colors.cpp` 定义 `bool reverse_colors`（复数），两者本就是不同符号——`reverse_color` 是悬空声明，`reverse_colors` 是实际使用的未声明全局变量。迁移时统一为 `reverse_colors`（对齐 cpp 实现），顺手清掉这个历史不一致。`renderer.hpp` 的 `extern bool reverse_colors;` 与 `void reverse(int&,int&,int&);` 旧前向声明一并删除（改由 colors.hpp 提供唯一声明）。
- **`colorhash` 改 `inline` 修 ODR**：原 `static colorhash tm_ch, dvips_ch, ...` 置于头文件，导致每个翻译单元（TU）各持一份独立副本——colors.cpp 的 TU 填充了表，其它 TU 的表恒空。原 mogan 单库下没人测所以未暴露。迁移后 moebius 测试 TU 调用 `x11_color("red")` 会读到空表。改为 `inline colorhash`（C++17 inline 变量，所有 TU 共享一份），既修复真实 ODR bug，也让色表查表有意义。moebius 已设 `c++17`，可用。
- **补 `reverse(int&,int&,int&)` 与 `get_rgb_color(array)` 声明**：`colors.cpp` 实现了 `void reverse(int&,int&,int&)`（qt_utilities/qt_picture 等按引用反转 RGB 用）与 `array<int> get_rgb_color(color)` 重载，但原 `colors.hpp` 未声明——靠 cpp 定义的全局符号链接进来。迁移后补上声明，避免调用方解析到悬空符号。
- **全局兼容 using 集中在 `gui.hpp`**：主项目大量文件通过 `gui.hpp` 间接 include colors.hpp，历史上靠 colors 符号全局可见直接调用 `red`/`black`/`named_color`/`reverse` 等。迁移后在 `gui.hpp` 的 `#include <moebius/data/colors.hpp>` 之后集中加 36 条 `using moebius::data::*;`，把这些符号重新导出到全局——所有通过 gui.hpp 传递的旧代码零改动。`true_color` 本就全局，无需此处理。少数不经过 gui.hpp 的文件（`edit_mouse.cpp`/`edit_repaint.cpp`/`triangulated.cpp` 等）单独加 `#include <moebius/data/colors.hpp>` + `using namespace moebius::data;`。
- **静态初始化**：`initialize_colors` 与各色表的 lazy 填充（`init_colors` 守卫）语义不变；主项目启动时仍调用 `initialize_colors()`，只是函数地址落在 libmoebius。
- **回退/大小写语义**：`locase_all` 用于色名归一化、未知名称回退到 `black` 的行为，用单元测试固化。

### 7.2 迁移步骤（实际执行）

1. 在 moebius 侧新建 `colors.{hpp,cpp}`、`true_color.{hpp,cpp}`、5 张色表头（`dvips/svg/tm/x11/xc`，原样复制，作为 colors.cpp 私有依赖置于 `namespace moebius::data {` 块内 include，确保 `tm_colors.hpp` 的 `pastel` 引用解析）。
2. `tm_debug.hpp` 剥离：删 `colors.cpp` 里 2 处 `if (DEBUG_STD && ...)` 重复色名告警块（纯诊断日志，赋值 `ch(name)= col;` 保留）。
3. `analyze.hpp` 直接换 `lolly/Kernel/Types/analyze.hpp` 路径，零重写。
4. 新增 `moebius/tests/moebius/data/colors_test.cpp`，19 个用例（初始化、RGB 往返、命名色解析大小写/hex/短 hex/未知回退、CMYK 极值、xpm、hex 往返含 alpha、各色表查表、blend 不透明/半透明、reverse、is_color_name、xcolormap 归类）。注意 `as_hexadecimal` 用**大写** hex 字符（`hex_string = "0123456789ABCDEF"`），断言写 `#AABBCC` 而非 `#aabbcc`。
5. 跑通 moebius `colors_test`（含 `inline colorhash` 修复）。
6. 批量替换主项目 25 处 `#include "colors.hpp"` / `"true_color.hpp"` 为 `<moebius/data/...>`。
7. 删除 `src/Graphics/Colors/` 全部 10 个文件（含死代码 `named_colors.hpp`，零 include）。
8. `gui.hpp` 集中加全局 using；个别不经过 gui.hpp 的文件单独补 include + using。
9. 跑通 `xmake b stem` + `gf fmt --changed-since=main` + moebius 全测试套。

### 7.3 注意事项

1. **`analyze.hpp` 依赖**：已存在于 `lolly/Kernel/Types/analyze.hpp`，`colors.cpp` 用到的 `locase_all` / `read_int` / `starts` 均在内。迁移时直接换 include 路径即可，**无新依赖、无需重写**。
2. **`true_color` 不进命名空间**：因其重度依赖 ADL（数十个内联运算符/函数），移入 `moebius::data` 会令所有调用方的重载解析失效。仅物理迁移。
3. **本任务在迁移过程中顺手修了 2 个原代码的潜在 bug**：(a) `static colorhash` → `inline colorhash` 修跨 TU 共享；(b) `reverse_color`/`reverse_colors` 命名统一。两者均为"迁移后测试才能暴露"的问题，修复是迁移的必要组成，非额外重构。
4. **本任务与 1119 是解耦关系**：本任务先于 1119 完成，1119 实施时 font 代码即可直接 `#include <moebius/data/colors.hpp>`。
