# [0610] 修复 HTML 导出和导入时嵌套有序列表格式丢失与不匹配的问题

当 Mogan 导出包含 `<enumerate-numeric-paren>`（带有括号的数字列表）、`<enumerate-circle>`（带圈数字列表）或 `<enumerate-hanzi>`（汉字列表）等有序列表环境的文档为 HTML时，这些特殊的列表结构会被提前展开或丢失，导致生成的 HTML 不包含正确的嵌套 `<ol>` 结构，且项目样式和编号丢失。同样地，在导入包含嵌套 `<ol>` 的 HTML 文档时，应当能正确、优雅地被还原为 TeXmacs 的嵌套列表格式。

## 5 What
1. 修复了 HTML 导出时，`enumerate-numeric-paren`、`enumerate-circle`、`enumerate-hanzi` 宏因未被注册为 "identity" 宏而在预处理阶段提前展开，导致嵌套列表层级扁平化、编号丢失、样式混乱的系统缺陷。
2. 修复了 HTML 导出中 standard markup 映射表对这三种特殊有序列表环境的遗漏。
3. 随本 PR 提交了完整的 TDD Scheme 测试用例：`0610.scm`。
4. 随本 PR 提交了标准测试用例：`0610.tmu`。
5. 随本 PR 提交了可直接用于手工/自动化测试的 HTML 导入测试文件：`0610_import_test.html`。

## 6 Why
* **提前展开原因**：在 `tmhtml-expand.scm` 的 `tmhtml-env-patch` 中，虽然注册了大部分列表宏（如 `enumerate-numeric`、`enumerate-alpha` 等），但由于历史遗漏，`enumerate-numeric-paren`、`enumerate-circle` 和 `enumerate-hanzi` 未注册，使得它们在导出预处理时作为普通宏被提前展开为具体低层布局元素，从而丢失了高层的 list block tree 语义，导致 HTML 引擎无法识别并输出 `<ol>` 系列节点。
* **映射缺失原因**：在 `tmhtml.scm` 的标准逻辑表 `tmhtml-stdmarkup%` 中，也同样遗漏了这三个特殊列表宏的映射，导致即使它们在预处理阶段不被提前展开，在导出渲染阶段也因无法匹配而静默丢弃或输出不正确。

## 7 How
1. 将 `enumerate-numeric-paren`, `enumerate-circle`, `enumerate-hanzi` 补充注册到 `tmhtml-expand.scm` 的 `tmhtml-env-patch` 中作为 `tmhtml-env-macro`，确保在预处理阶段不会被提前展开。
2. 在 `tmhtml.scm` 的 `tmhtml-stdmarkup%` 的 `enumerate` 类逻辑下添加这三者，使其能正确执行 `tmhtml-enumerate` 的 HTML 渲染流程，生成嵌套的 `<h:ol>`。
