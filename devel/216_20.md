# 216_20 启动页模块预加载优化

## 如何测试
1. 编译：`xmake b stem`
2. 打开启动页，确认页面正常显示，无错误弹窗。
3. 打开调试模式（`Debug -> Debug on`），观察控制台输出：
   - 应显示 `Startup tab: modules preloaded` 表示预加载完成
   - 如有模块加载失败，会显示 `Preload warning [模块名]: 错误信息`
4. 点击 `Open a Document` 或 `File -> Open`，测试文件打开速度是否有提升。
5. 测试不同格式文件（.tmu, .tex, .md 等）的打开是否正常。

## 2026/04/17 实现说明

### What
本次改进启动页的模块预加载机制，减少用户打开文件时的等待时间：
- **后台预加载**：启动页显示后延迟 500ms 自动预加载文件操作相关模块。
- **错误隔离**：每个模块独立加载，单个模块失败不影响其他模块。
- **调试支持**：添加调试日志，便于排查预加载问题。

#### 修改文件

**TeXmacs/progs/kernel/texmacs/tm-convert.scm** (修改)
- 将 `lazy-format-force` 函数导出为公共函数 `(define-public)`，供启动页调用。

**TeXmacs/progs/startup-tab/startup-tab.scm** (修改)
  - `startup-tab-preload-modules` 负责统一调度，避免逻辑分散。
  - 增加 `startup-tab-preload-done?` / `startup-tab-preload-running?`，保证预加载仅执行一次。
  - 保留错误隔离机制：每个步骤通过 `safe-preload + catch #t` 独立保护。
  - 预加载顺序：plugins → formats → lang-minimal/lang-std-math → keyboard → font-db。
  - 调试模式下输出完成日志 `Startup tab: modules preloaded`。

**src/Plugins/Qt/qt_startup_tab_widget.cpp** (修改)
- 新增 `QTimer` 头文件包含。
- 构造函数中添加延迟预加载调用：
  - 使用 `QTimer::singleShot(500, ...)` 延迟 500ms 执行，确保 UI 先渲染完成。
  - 调用 Scheme 函数 `(startup-tab-preload-modules)` 执行预加载。

### Why
1. 原实现中，文件格式转换器、插件等模块采用懒加载策略，用户首次打开文件时才加载，导致第一次打开有卡顿。
2. 启动页显示期间系统空闲，可利用此时间提前加载这些模块，实现"无感加速"。
3. 缺乏错误处理机制，单个模块加载失败可能导致整个预加载流程中断。

### How
1. **延迟触发**：
   - 使用 `QTimer::singleShot(500ms)` 延迟执行，确保启动页 UI 完全渲染后再进行后台加载。
   - 500ms 为经验值，平衡了"尽早加载"和"不阻塞 UI"的需求。

2. **错误隔离机制**：
   ```scheme
   (define (safe-preload name thunk)
     (catch #t thunk
       (lambda (err) (debug-message ...) #f)))
   ```
   - 每个预加载步骤独立包装在 `catch #t` 中。
   - 错误信息通过 `debug-message` 输出，包含模块名称便于定位。
   - 返回 `#f` 表示该步骤失败，但不中断后续步骤。

3. **加载优先级**：
    - **Critical (关键)**：plugins、formats — 文件打开必需。
    - **Important (重要)**：languages — 语法高亮和数学支持。
    - **Nice-to-have (可选)**：keyboard — 键盘快捷键支持。
    - **Font warmup (字体预热)**：font-db — 提前加载字体数据库，降低首次排版时的字体查询延迟。
