1. 在 Windows 上打开包含嵌入式图片（PDF/PNG）的 `.tmu` 文档，文件路径中包含中文字符（如 `D:\其他\doc.tmu`）。

## 5 What
修复了 Windows 上导出 HTML/PDF 时，若目标路径包含中文字符，会报错 `open-output-file: No such file or directory` 的问题。

具体改动包括：
- 在 C++ 层新增 `binary-load` / `binary-save` 两个 Scheme glue 函数，底层复用 lolly/tbox 的文件 I/O。
- 在 `tm_file.hpp` 中新增 `tm_string_load_bytes` / `tm_string_save_bytes` 包装函数。
- 在 `glue-symbols.scm` 中注册新符号。
- 重写 `tmhtml.scm` 中的 `tmhtml-read-binary-file` 和 `tmhtml-write-binary-file`，改用新的 `binary-load` / `binary-save`。

## 6 Why
1. **路径编码问题**：原实现将 URL 转成字符串后，使用 S7 原生的 `open-output-file` / `open-input-file`，在 Windows 上最终调用 ANSI 代码页的 `fopen`，无法正确解析 UTF-8 编码的中文路径。
2. **复用 Unicode 安全 I/O**：Mogan 自己的文件操作通过 lolly/tbox，在 Windows 下使用 `CreateFileW` 宽字符 API，能正确处理中文路径。
3. **最小化修改**：仅替换 Scheme 层的二进制文件读写入口，不影响 HTML 导出的其他逻辑。

## 7 How
1. **新增 glue 函数**：在 `init_glue_l2.cpp` 中手写 `binary_load` / `binary_save`，直接操作 S7 bytevector，避免二进制数据经过 Scheme string 时可能发生的编码损坏。
2. **复用 lolly 文件层**：包装函数调用已有的 `string_load` / `string_save`，这些函数底层走 `tb_file_init` / `tb_file_writ` / `tb_file_read`。
3. **替换 Scheme 实现**：`tmhtml-read-binary-file` 简化为 `(binary-load file-url)`；`tmhtml-write-binary-file` 将 byte-vector / string 统一转成 byte-vector 后调用 `binary-save`。
4. **测试覆盖**：现有 `0623.scm` 已包含中文路径安全测试，验证读写往返后字节一致。
