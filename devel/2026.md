## 5 What

1. **按钮身份转换**：标题栏右上角原 VIP 升级按钮改造为邀请好友入口。变量名、字段、objectName、CSS 选择器、方法名全套从 `vip(B)` 系列改为 `invite(B)` 系列。
2. **文案与视觉**：按钮文字从 `Upgrade VIP`/`升级会员` 改为 `Invite Friends`/`邀请好友`；删除 `vip-lightning.svg` 闪电图标，改为纯文字按钮；颜色、渐变、尺寸（90×32）保持不变。
3. **显隐规则简化**：`updateVipButtonVisibility(bool, QString)` 改为 `updateInviteButtonVisibility(bool)`，去掉 `memberType` 参数与会员等级区分逻辑。新规则：商业版 + 已登录即显示，半屏隐藏保留。所有正式会员、体验会员、普通用户都看到邀请入口。
4. **抽公共方法 `buildAuthUrl(baseUrl)`**：`openRenewalPage` 与新增的 `openInvitationPage` 共享「load token → sha256 → 拼 `?key=<hash>&user=<id>` 后缀」逻辑，抽到私有方法 `buildAuthUrl`，两个 open*Page 各自只保留 base URL 装配和 `QDesktopServices::openUrl` 调用。
5. **新增 `openInvitationPage()`**：调 `buildAuthUrl` 拼接邀请 URL。base URL 通过 `account-oauth2-config` 的 `invitation-url` 配置项获取，与 `openRenewalPage` 走 `pricing-url` 完全对称。原 `openRenewalPage()` 也改为调 `buildAuthUrl`，对外行为不变。
6. **新增 scheme 配置项 `invitation-url`**：`TeXmacs/plugins/account/progs/liii/account.scm` 的 `account-oauth2-config` 函数新增 `invitation-url` key，基于 `current-stem-site` 返回的 base URL 拼接 `/personal-center/invitation`，按 staging（`test.liiistem.cn`）/prod（`liiistem.cn`）profile 自动切换；本地注释配置块同步加一份。
7. **遥测事件拆分**：邀请按钮点击发 `INVITE_CLICK mode=invite`；原 `VIP_CLICK` 遥测保留给登录对话框的「激活/续费」路径（mode 区分 activate/upgrade）。
8. **清理死代码**：删除点击 handler 里的 `is_community_stem()` 早返回分支——社区版 `shouldShow` 恒为 `false`、按钮不可见、点击走不到，保留只会让读者困惑。
9. **清理无读取者字段 `m_memberType`**：原 resize 回调读它、现已改为只读 `m_isLoggedIn`，字段无任何读取者。删除字段声明、初始化列表项、`updateDialogContent` 内的字段赋值。`updateDialogContent` 的 `memberType` **参数保留**（仍用于对话框标题更新）。

## 6 Why

产品决定把原 VIP 升级入口收敛为「邀请好友」功能。原按钮承担三种语义（未登录触发登录、未付费引导续费、正式会员隐藏），其中续费入口已迁移到登录对话框内的「续费」按钮（`cpp:2788`），标题栏不再需要重复入口；邀请功能对所有用户开放，是更高频的运营动作。

旧设计的三层耦合：

1. **显隐规则与会员等级耦合**：`updateVipButtonVisibility` 内部按 `memberType == "Regular User" || "Trial Member"` 区分，把产品策略（谁能看到升级入口）硬编码进 UI 层；邀请功能取消这个区分，简化为单一登录态判定。
2. **URL 拼接与按钮身份耦合**：`openRenewalPage` 同时被「VIP 升级按钮」和「对话框续费按钮」复用，但邀请 URL 与续费 URL 是不同业务端点，强行复用会污染语义——所以新增独立的 `openInvitationPage`。两个 open*Page 各自只负责 base URL 装配，共享的 token→sha256→后缀拼接逻辑抽到 `buildAuthUrl`，避免代码重复（早期版本曾克隆 `openRenewalPage` 全部 13 行逻辑，发现两份重复后改抽公共方法）。
3. **遥测事件粒度不足**：原 `VIP_CLICK` 同时承载「升级」「激活」两种 mode，邀请按钮再复用会让数据分析时无法区分「点邀请」和「点续费」——拆为 `INVITE_CLICK`（仍带 `mode=invite` 字段，方便后续若邀请场景细分）独立追踪。

死代码清理：
- `is_community_stem()` 早返回分支——曾经社区版可能显示这个按钮，但显隐规则早已改为 `if (!is_community_stem())` 外层跳过，分支变成不可达代码。
- `m_memberType` 字段——原 resize 回调读它、本任务简化后只读 `m_isLoggedIn`，字段无任何读取者。`m_isLoggedIn` 保留是因为 resize 回调仍需要它判断邀请按钮显隐；`m_memberType` 在对话框字段更新（`updateDialogContent` 内的局部变量）路径上不需要持久化，所以删除字段、保留参数。

## 7 How

整体策略：**身份重命名 + 语义简化**，把按钮从「按会员等级条件显示的升级入口」改造为「按登录态显示的邀请入口」。

### 7.1 抽 `buildAuthUrl(baseUrl)` 公共方法

`openRenewalPage` 与新增的 `openInvitationPage` 都需要「load token → sha256 → 拼 `?key=<hash>&user=<userId>` 后缀」，逻辑完全重复。抽到私有方法 `buildAuthUrl(baseUrl)`：

```cpp
QString qt_tm_widget_rep::buildAuthUrl (const QString& baseUrl) {
  eval ("(use-modules (liii account))");
  string  token  = as_string (call ("account-load-token"));
  QString q_token= to_qstring (token);

  QByteArray tokenBytes= q_token.toUtf8 ();
  QByteArray hash=
      QCryptographicHash::hash (tokenBytes, QCryptographicHash::Sha256);
  QString keyParam= hash.toHex ();

  return baseUrl + "?key=" + keyParam + "&user=" + m_userId;
}
```

两个 open*Page 各自只保留 base URL 装配与浏览器打开，base URL 都走 `account-oauth2-config` 配置：

```cpp
void qt_tm_widget_rep::openRenewalPage () {
  string pricingUrl= as_string (call ("account-oauth2-config", "pricing-url"));
  QString fullUrl = buildAuthUrl (to_qstring (pricingUrl));
  QDesktopServices::openUrl (QUrl (fullUrl));
}

void qt_tm_widget_rep::openInvitationPage () {
  string invitationUrl=
      as_string (call ("account-oauth2-config", "invitation-url"));
  QString fullUrl= buildAuthUrl (to_qstring (invitationUrl));
  QDesktopServices::openUrl (QUrl (fullUrl));
}
```

scheme 端在 `account-oauth2-config` 加 `invitation-url` 配置项，与 `pricing-url` 完全对称：

```scheme
((== key "invitation-url") (string-append base-url "/personal-center/invitation"))
```

`base-url` 由 `current-stem-site` 根据 `current-stem-profile` 决定（生产 `liiistem.cn` / staging `test.liiistem.cn`），所以邀请 URL 会按环境自动切换，不会在 staging 测试时打到生产、污染真实数据。

### 7.2 点击 handler 改造

```cpp
QObject::connect (inviteButton, &QPushButton::clicked, [this] () {
  if (is_server_started ()) {
    tm_server_rep* server=
        dynamic_cast<tm_server_rep*> (get_server ().operator->());
    if (server && server->getAccount () &&
        server->getAccount ()->isLoggedIn ()) {
#if !IS_COMMUNITY
      telemetry_track ("INVITE_CLICK", "'((\"mode\" . \"invite\"))");
#endif

    }
    else {
      checkLocalTokenAndLogin ();
    }
  }
});
```

删除原 `is_community_stem()` 早返回分支：社区版 `shouldShow=false`、按钮不可见、根本走不到这里。

### 7.3 显隐规则简化

`updateInviteButtonVisibility` 不再接收 `memberType`：

```cpp
void qt_tm_widget_rep::updateInviteButtonVisibility (bool isLoggedIn) {
  if (!inviteButton) return;

  bool shouldShow= false;
  if (!is_community_stem ()) {
    shouldShow= isLoggedIn;  // 已登录即显示，不再区分会员等级
  }

  if (shouldShow) {
    QMainWindow* mw= mainwindow ();
    if (mw) {
      int screen_w=
          QApplication::primaryScreen ()->availableGeometry ().width ();
      if (mw->width () * 2 <= screen_w) {
        shouldShow= false;
      }
    }
  }

  inviteButton->setVisible (shouldShow);
  if (tabPageContainer) {
    tabPageContainer->setVipButtonReserved (shouldShow);
  }
}
```

调用点同步：
- `updateDialogContent` 末尾 `updateVipButtonVisibility(isLoggedIn, memberType)` → `updateInviteButtonVisibility(isLoggedIn)`；
- resize 回调 `updateInviteButtonVisibility_onResize` 内部 `updateVipButtonVisibility(m_isLoggedIn, m_memberType)` → `updateInviteButtonVisibility(m_isLoggedIn)`。

`m_memberType` 字段在 resize 回调失去最后一个读取者后**整体删除**：
- `hpp:126` 字段声明删除；
- `cpp:214` 初始化列表 `m_memberType ("")` 删除；
- `cpp:3067` `updateDialogContent` 内的 `m_memberType= memberType;` 赋值删除；
- `updateDialogContent` 的 `memberType` **参数保留**（`cpp:3087` 的对话框标题 `qt_translate(memberType...)` 仍用它）。

`m_isLoggedIn` 字段保留：resize 回调仍需它判断邀请按钮显隐。
