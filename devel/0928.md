# 0928: 用 QML 重构调色板

## What
将 Qt 原生 `QColorDialog` 实现的调色板替换为项目统一 QML 弹窗体系下的 `ColorPicker.qml`，保持功能不缺失，视觉风格与现有 QML 对话框一致并更具现代感。

## Why
- 当前 `qt_color_picker_widget_rep::showDialog()` 直接调用 `QColorDialog::getColor`，风格与 Mogan 正在迁移的 QML 模态对话框体系不一致。
- QML 版本可复用 `DialogShell`、`DialogButtons`、`Theme` 等原子组件，统一暗色/亮色、DPI 缩放、圆角、按钮交互。
- 自定义调色板可在不增加依赖的情况下加入色板预设、HEX/RGB 输入、实时预览，提升可用性。

## How
1. 新增 `src/Plugins/Qt/qml/ColorPicker.qml`：基于 `DialogShell` 组装现代感调色板，含色相条、饱和度/明度面板、RGB/HEX 输入、预设色块、颜色预览与 OK/Cancel 按钮。
2. 在 `src/Plugins/Qt/QTMQmlDialog.hpp/cpp` 新增阻塞式 glue 入口 `cpp_color_picker_dialog(...)`，使用 `run_qml_dialog` exec 引擎一次性提交，返回选中的颜色 tree。
3. 修改 `src/Plugins/Qt/qt_color_picker_widget.cpp` 的 `showDialog()`，改为调用 `cpp_color_picker_dialog()`，保持 `widget-color-picker` / `interactive-color` 调用链不变。
4. 在 `src/Plugins/Qt/qml/qmldir` 与 `src/Plugins/Qt/moganqml.qrc` 登记新 QML 文件。
5. 在 `tests/Plugins/Qt/qml_load_test.cpp` 增加 `ColorPicker.qml` 加载用例。

## 测试
- `xmake b qml_load_test && xmake r qml_load_test`
- 数据契约自检：`MOGAN_TEST_COLOR_PICKER=#rrggbb|cancel`（返回形状与真实路径一致，均为 `(tuple "#rrggbb")` / 空 tuple）
- 手动 GUI 验证：菜单 Format / Color -> Palette、Document -> Color / Background color 等入口。

## 修复记录
- **点击确认后不生效（人工验证反馈）**：根因是返回值形状不匹配。旧实现回调给 scheme 的是原子颜色 tree（`"#rrggbb"`），新实现 `cpp_color_picker_dialog` 按 form 弹窗惯例返回 `(tuple "#rrggbb")`，`showDialog()` 最初把整棵 tuple 直接回调，scheme 侧 `tm->stree` 拿到的不是颜色字符串，setter 静默不生效。修复：`showDialog()` 解包 `sel[0]` 再回调；同时把 `MOGAN_TEST_COLOR_PICKER` 测试钩子的返回形状改为与真实路径一致的 `(tuple "#rrggbb")`，避免钩子与真实路径分叉。
- **底部按钮被裁剪（人工验证反馈）**：内容总高度超出窗口，QML `implicitHeight` 与 C++ `run_qml_dialog` 逻辑高度同步调高。
- **功能缺失补齐（人工验证反馈，对照旧 QColorDialog）**：
  - 补 HSV 数值输入（H 0–359，S/V 0–100），与 RGB/HEX 并列；
  - 补 Custom colors（16 格）+ Add to custom colors，OK 时经 preference `color picker custom colors`（空格分隔 hex）跨会话持久化，Cancel 不保存；
  - 补 Pick screen color：新增 `ColorPickerBridge`（抓屏快照 + 全屏十字光标 overlay 点击取色，Esc 取消；macOS 需屏幕录制权限，未授权返回空串，与 Qt 自带行为一致）。
  - 段标题/按钮文案（basic colors / custom colors / add to custom colors / pick screen color）在 cpp 侧 `qt_translate` 注入 `labelsProp`，并在 zh_CN 字典按字母序补四条中文翻译。
- **右栏输入框被截断（人工验证反馈）**：主编辑区高度 220 不足以容纳右栏（预览 + HEX + RGB 三行 + HSV 三行 ≈ 267），主编辑区调高到 280，弹窗高度同步调到 720。
- **自定义颜色增删语义（人工验证反馈）**：补删除功能——点击自定义色格即选中（选中态高亮边框），「删除自定义颜色」按钮清空该格（未选中时按钮半透明、点击无效）；添加按顺序填第一个空位，16 格全满时拒绝添加，并在色格下方显示小字提示「自定义颜色已满，请先删除一个颜色」。新增文案 delete custom color / custom colors are full, delete one first 已补 zh_CN 字典。
- **标题未翻译（人工验证反馈）**：字典缺 `choose color` / `choose background` 条目，`interactive-window` 已对标题 `(translate name)` 但查无结果原样返回。zh_CN 字典按字母序补两条。
- **添加/删除自定义颜色按钮宽窄不一（人工验证反馈）**：两个 `MiniButton` 均为 `size:"normal"`（宽度按文案自适应），中文文案长度不同导致宽度不一。改为两按钮 `width` 绑定 `Math.max(addBtn.implicitWidth, delBtn.implicitWidth)` 等宽。
- **Linux (X11 + NVIDIA) 点击 Pick screen color 段错误（人工验证反馈，栈顶 `QRhi::endOffscreenFrame`）**：根因是 `pickScreenColor()` 在 QML 事件处理器内对取色 overlay 跑嵌套 `exec()`，嵌套事件循环期间宿主弹窗的 QQuickWidget 被迫重绘，QRhi 离屏帧在 nvidia GL 驱动下崩溃。修复：取色改为异步——`pickScreenColor()` 只发起取色（overlay 用 `open()` + ApplicationModal，不再嵌套 exec），结果经新信号 `screenColorPicked(QString)` 回流，QML 侧用 `Connections` 接收。bridge 析构负责销毁未关闭的 overlay，避免遗留全屏无父浮层。
- **Wayland 点击 Pick screen color 全屏黑屏（人工验证反馈）**：Wayland 会话抓不到真实屏幕——注意 mogan 启动时强制 `QT_QPA_PLATFORM=xcb`（research.cpp），Wayland 下实际跑在 XWayland，`platformName()` 恒为 `"xcb"`，`grabWindow(0)` 只能抓到 XWayland 的黑色根窗口。修复：`canPickScreen` 改判 `WAYLAND_DISPLAY` 环境变量（platformName 判 wayland 在此恒不命中），Wayland 会话下 QML 隐藏「Pick screen color」按钮；`pickScreenColor()` 在不支持会话立即回空串兜底。
- **点取色后弹窗消失、取色界面不出现（人工验证反馈，初版异步修复引入的回归）**：初版在 `pickScreenColor()` 里 `host->hide()` 宿主弹窗，但 hide 会退出 `exec()` 中对话框的事件循环（`QDialog::setVisible` 隐藏分支 `exit()` 其 eventLoop），`run_qml_dialog` 的 exec 立即返回，bridge 析构连带销毁刚 open 的 overlay。修复：不再 hide/show 宿主——overlay 全屏置顶已足够盖住弹窗（快照含弹窗自身，与 QColorDialog 一致）；`ColorPickerBridge` 不再持有宿主指针。新增 `tests/Plugins/Qt/color_picker_bridge_test.cpp`：宿主刻意用 `exec()` 驱动复刻真实路径，以退出码 42 断言取色不打断 exec（初版测试用 `show()` 宿主，漏掉了该差异）。
- **取色时出现「双重任务栏」（人工验证反馈，KDE/KWin）**：overlay 请求整屏几何（1920×1080），KWin 会把这类窗口约束进工作区（availableGeometry 1920×1036，让出面板）；而绘制端把快照按窗口 `rect()` 拉伸，快照被垂直压缩后其面板图像与真实面板叠成两条任务栏。尝试 `showFullScreen()`/`WindowFullScreen` 均不被 KWin 采纳（对 frameless Tool 窗口强制进工作区并加 Maximized 态）。修复：放弃拉伸，改为全局屏幕坐标对齐——overlay 记录 `screenOrigin`，`paintEvent` 按 `geometry().topLeft() - screenOrigin` 偏移绘制快照，取色点击按「窗口逻辑坐标 → 全局逻辑坐标 → ×DPR」映射图像像素；未被窗口覆盖的面板区域露出真实桌面，与快照自然衔接。测试同步断言 overlay 帧几何为整屏或工作区，但左上角必须贴屏幕原点。
- **macOS CI `color_picker_bridge_test` 几何断言失败（CI 反馈）**：`test_pick_click_delivers_hex` 断言 overlay 帧几何为整屏或工作区，但 macOS WindowServer 按自身规则摆放 Tool 窗口（菜单栏/边框偏移），几何不可预期。修复：严格几何断言限定 xcb 平台（KWin 工作区约束才是该断言防的回归），其他平台只断言 overlay 非空可见——绘制/取色已按全局坐标对齐，与窗口实际摆放无关；断言失败信息附带 frame/geometry/availableGeometry 实际值便于诊断。
- **macOS 点击拾取屏幕颜色毫无反应（人工验证反馈）**：根因是 macOS 10.15+ 抓屏需「屏幕录制」TCC 权限，未授权时 `grabWindow(0)` 静默返回空图（不弹任何系统提示），QML 收到空串又不显示任何反馈，表现为点击毫无反应。修复：`pickScreenColor()` 在 macOS 先 `CGPreflightScreenCaptureAccess` 预检，未授权即 `CGRequestScreenCaptureAccess` 请求系统弹「屏幕录制」授权引导（同 WPS 取色行为，授权需在系统设置完成并重启应用生效），并经新信号 `screenPickUnavailable` 通知 QML 在主编辑区正下方显示提示文案（zh_CN 已补字典），不再静默。配套修复 overlay 生命周期：`QDialog::open()` + `WA_DeleteOnClose` 是 Qt 文档明示的未定义行为组合（overlay 弹出路径此前从未在 macOS 真实验证过），改为 `show()` + `finished -> deleteLater`。测试新增环境钩子 `MOGAN_TEST_PICK_FAKE_SNAPSHOT=#rrggbb`（合成纯色快照替代真实抓屏），`color_picker_bridge_test` 两个交互用例改走钩子后在本机 macOS 15.6 真实跑通 overlay 弹出/点击取色/Esc 取消（此前在这类无权限环境只会跳过）；三端适配复查：Linux/X11 路径不变（xcb 几何断言保留）、Wayland 仍隐藏按钮、Windows 无需权限 `grabWindow` 直接可用。
- **自定义颜色格子与按钮未对齐、格子偏小；拾取按钮位置不当（人工验证反馈）**：自定义颜色区原为「左侧竖排标签 + 中间窄格子 + 右侧按钮垂直居中」，格子宽约 29px 明显小于基础颜色格子（47.5px），且按钮列（96px 高）与两行格子（63px）互相错位。调整为：标签独占一行（同基础颜色），16 格 2 行 × 8 列、格子边长直接取 `basicGrid.cellW`（与基础颜色格子完全同尺寸），右侧「添加/删除」两按钮各占半高居中、分别对齐上下两行格子的行中心。为容纳同尺寸格子，按钮文案由「添加到自定义颜色/删除自定义颜色」缩短为「添加颜色/删除颜色」（zh_CN 字典同步增删条目；段落标题已提供语境）。「拾取屏幕颜色」按钮从底部移到最上面区域——右栏颜色预览的下一行（Wayland 下仍隐藏）。主编辑区高度 280→292（右栏字段 26→24、间距 8→6 腾出空间）。
- **确认/取消按钮下方留白过多、按钮应右对齐（人工验证反馈）**：上一轮为容纳提示行把弹窗高度固定到 750，常态底部多出约 60px 留白。改为高度随正文自适应（Version 弹窗同机制）：QML `implicitHeight` 绑 `mainCol.implicitHeight + 2×margins`，正文各项宽度绑 `contentW`（C++ 在布局宽度就位前就读 implicitHeight 定高，绑实际父宽会量出错误高度），C++ `run_qml_dialog` 开 `autofit_height` 打开时定宽读高锁定（649 仅为读取失败的回退值）；OK/Cancel 由水平居中改为右对齐；「取色不可用」「自定义颜色已满」两个提示行挪到底部与按钮同行左侧（单行省略号）——高度已在打开时锁定，运行中冒出的提示不能再占额外行高，放按钮左侧正好利用空区。
- **整体尺寸偏大、三个小按钮尺寸不一（人工验证反馈，两轮迭代）**：先统一「拾取屏幕颜色」「添加颜色」「删除颜色」为 mini 档后用户反馈仍偏小，MiniButton 原子新增 `small` 中间档（`Theme.smallBtnH` 32 / `Theme.fontSmall` 12，介于 mini 28 与 DialogButtons 主按钮 btnH 40 之间，mini/normal 两档不动、不影响其他弹窗），三按钮统一走 small 档、各自填满所在列宽；弹窗宽度 560→480→430，基础/自定义格子随之 47.5→39.5→34.5（自定义格子边长始终取 `basicGrid.cellW` 联动），主编辑区高 292→298、右栏宽 132→120；「基本颜色」「自定义颜色」段标题 fontTiny→fontBody。顺带修复无彩色（白/黑/灰）`hsvHue` 为 -1 时 H 输入框显示 -359、色相旋钮跑到面板外的问题（`safeHue` 负值按 0 处理）。
