## [7001] 协作文档 → 本地备份（Cmd+S）

### What
协作（云端）buffer（`tmfs://collab/<doc_id>`）无磁盘落点。Cmd+S（`save-buffer`）
现在静默写一份本地备份到 `$TEXMACS_HOME_PATH/system/collab-backups/<doc_id>.tmu`，
为需要从磁盘读文档的下游（如 autosave 云备份插件）提供落点。不重命名 / 不切 buffer /
不进最近文件 / 不弹窗；占位 URL（pending-…）跳过。

### Why
磁盘类下游工具读不到云端文档——先有本地落点，才能后续接入 autosave 等备份管线。

### How
- `save-buffer` 覆盖的协作分支：原弹 "use Download" 提示 → 改调 `collab-silent-backup`。
- 三段式：`collab-silent-backup`（单一同步入口，供将来 autosave 链式调用保证时序）
  → `collab-do-silent-backup`（`collab-url->doc-id` 提取 doc_id，跳过空 / `pending-`）
  → `collab-write-backup`（按需 `system-mkdir` 建 `collab-backups/`，`buffer-export "tmu"` 写盘）。
- `collab-url->doc-id` 去掉 `tmfs://collab/` 前缀；`buffer-export` 同步写盘、不改 buffer
  身份；仅失败时给一行 "Backup failed" 提示（不暴露内部路径）。

### 涉及文件
- `TeXmacs/progs/texmacs/texmacs/tm-collab.scm`
- `TeXmacs/progs/texmacs/texmacs/tests/tm-collab-test.scm`（`collab-url->doc-id` 纯逻辑）

### autosave 适配 tmfs://collab（已完成）

让 autosave 云备份管线处理协作文档：本端编辑时静默写本地备份并上传，**无星号/关闭提示**，
**只跟本端编辑**（远端 apply_remote 不 require_save）。

- **C++ `need_save` 解耦**（`edit_modify.cpp`）：collab 短路仅 `real_save=true` 生效——
  星号/关闭提示恒不脏；autosave（`real_save=false`）照常跟 archiver，故 `buffer-modified-since-autosave?`
  能感知本端编辑。
- **`save-buffer-save`（`tm-files.scm`）**：拆出私有 `save-buffer-save-file`（原文件 buffer 逻辑）；
  `save-buffer-save` 加 collab 分支 → `collab-silent-backup`（同步写本地备份 + `buffer-pretend-saved`
  清 autosave 脏）→ `auto-backup-trig`（上传）。
- **`save-buffer` 覆盖**（`tm-collab.scm`）：collab 分支改走 `save-buffer-save`（统一 Cmd+S = 备份 + 上传 + 清脏）。
- **autosave 插件（`plugin.scm`）**：`:use tm-collab`；`autosave-now` 加 buffer-list 扫描
  （`collab-buffer?` ∧ `buffer-modified-since-autosave?`，120s 周期）；`auto-backup-trig` 门控放宽
  `(or (collab-buffer? u) (eligible? u))`；`auto-backup-trig-payload` collab 分支 path=本地备份文件、
  id=tmfs URL 的 doc_id 段。
- **可见性**：`collab-url->doc-id`/`collab-backup-url`/`collab-silent-backup` 升为 `tm-define`（供插件调用）。
- **消费端 `tm-autosave.scm` 不改**：`handle-copy` 通用 path→id 复制。
- **时序保证**：`collab-silent-backup` 同步写盘后才调 `auto-backup-trig` → 子进程读到的备份即最新。

涉及文件（增量）：

- `TeXmacs/progs/texmacs/texmacs/tm-files.scm`

### 如何测试

**纯逻辑（headless，CI 可跑）**
- `xmake b stem && xmake r tm-collab-test`
  - 覆盖 `collab-url->doc-id`：与 `collab-buffer-url->tmfs` 互逆（含 UUID 连字符）、
    占位 `pending-1-2` 正确切出（是否跳过由调用方决定）。

**GUI 手动（需 loro-server）**
1. 起协作服务端：`node tools/loro-server/server.js`。
2. 客户端进协作：Collaborative 菜单 → New shared document（或 Join），等 tab 标题变成
   doc_name（即 `become_ready` 已下发真实 doc_id，buffer URL = `tmfs://collab/<doc_id>`）。
3. 按 **Cmd+S**，确认：
   - `<(get-texmacs-home-path)>/system/collab-backups/<doc_id>.tmu` 被写入
     （路径可用 `(url->system (get-texmacs-home-path))` 查；macOS 约在
     `~/Library/Application Support/<应用>/system/collab-backups/`）；
   - 内容随编辑更新（再编辑 + Cmd+S → 文件 mtime/正文变化）；
   - 当前 buffer 仍是 `tmfs://collab/<doc_id>`、tab 标题不变、协作未断；
   - 无弹窗、最近文件列表不混入该备份、无新 tab。
4. 占位阶段（create 后、`become_ready` 收到 `DOC` 前，tab 仍是 No name/pending）按
   Cmd+S → 不报错、不写文件（`collab-do-silent-backup` 跳过 `pending-`）。
5. 回归：普通本地文档按 Cmd+S → 走原 `save-buffer` 链，行为无变化。
