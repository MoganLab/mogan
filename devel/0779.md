# [0779] Collab: 远端操作不进入 Archiver

## What
让 `apply_remote` 期间应用的远端修改**不进入 undo 归档器（archiver）的 `current` 单元**。

- 新增 `archiver_rep::set_versioning(bool)`（`src/Data/History/archiver.hpp` / `.cpp`）：暴露
  `versioning` 开关，置位期间 `archive_announce` 跳过 `add()`。与 undo/redo 回放用的
  `apply()` 同一机制；但只置本对象 `versioning`，不置全局 `busy_versioning`，避免干扰
  `is_busy_versioning()` 语义。
- `edit_modify_rep::apply_remote`（`src/Edit/Modify/edit_collab.cpp`）在 `loro_applying_remote=true`
  的同时 `arch->set_versioning(true)`，覆盖 diff/apply 循环、光标恢复与 meta 回写；末尾复位。
  远端修改因此不再被 `archive_announce` 记录进本地 undo 历史。

## Why
**症状**：协作中，当一条远端编辑在两次本地按键之间到达（本地敲 `a` → 对端在别处插入 `t` →
本地敲 `b`），本地"把 `a` 长成 `ab`"的按键 coalesce 会**删掉对端的 `t`**。

**根因**：undo 归档器对每一条 announce 的修改都会记录——`archive_announce` 只由 `!versioning`
开关控制，而 `versioning` 此前**只在 undo/redo 回放时**（`archiver_rep::apply`）置位，
`apply_remote` 从头到尾没有置位。于是远端修改经 `apply → raw_apply → announce → archive_announce`
全部落进 undo 的 `current` 单元，与本地敲键的修改混在一起。

本地连续按键的 coalesce（"敲 b"被编辑器拆成 `remove 上一次输入 + insert 合并串`）会重开/重算
`current` 单元。单元里现在混着对端的 `t`，coalesce 在"撤销本单元最近插入"时把 `t` 一并撤掉，
而"重插累计串"只插本地的 `ab`——`t` 被删掉、不再插回，凭空消失。日志佐证：

```
Archive insert ([2,1,0,0], 0, t)      ← 对端 t 被记进 undo
…敲 b…
Archive remove ([2,1,0,0], 0, 1)      ← coalesce 把 t 撤掉（杀人那一刀）
Archive remove ([2,0,0,0], 0, 1)      ← 撤本地 a
Archive insert ([2,0,0,0], 0, a b)    ← 重插 ab
```

这层 bug 在 `mirror_remove` / `diff_walk` 的**上游**：镜像与 diff 只是忠实地把"不该存在的删除"
翻译/传播成 CRDT 操作。"按身份删除"的修复**挡不住这一例**——buffer 受影响槽位此刻确实坐着对端
内容，按位置删和按身份删结果一致；问题在于这条删除根本不该被发出来。

## How
在 `apply_remote` 应用远端修改期间禁用 undo 增量记录，使远端修改不进 `current`，本地按键
coalesce 便碰不到它。语义上也正确：**本地 undo 本就不该撤掉对端的编辑**。

## 涉及文件
- `src/Data/History/archiver.hpp`：新增 public `set_versioning(bool)`。
- `src/Data/History/archiver.cpp`：实现（仅置本对象 `versioning`）。
- `src/Edit/Modify/edit_collab.cpp`：`apply_remote` 用 `set_versioning(true/false)` 包裹远端应用。

## 如何测试
```
xmake f --loro=yes
xmake b stem
xmake r stem
```
A 端与 B 端在两个不同的数学环境输入。
B 端不断输入 "ab,"，触发 "a b" 的键盘绑定。
A 端输入一个 m。
检查 A 输入的 m 不被吞掉。

开 `DEBUG_LORO` / `DEBUG_HISTORY` 复现：敲 `b` 时 `Archive` / `mod:` 流里**不应**再出现指向 A
容器的 `remove`，只剩 B 自己容器上的 `remove + insert "ab"`。

## 已知限制 / 后续
本修复只封掉"文本按键 coalesce 被远端修改污染"这一颗地雷（undo 层）。协作桥接层还存在**另一族**
位置型脆弱性：`mirror_insert_node` / `mirror_split` / `mirror_assign` / `mirror_join` 仍按
`node_children(pid)[pos]` 定位目标，结构编辑（如数学环境 `^` 上标、`_` 下标、表格操作）在并发时
仍可能命中错误 TreeID。修法是"按身份定位"（pre-apply 捕获 TreeID，按身份删/插），另开任务处理。
