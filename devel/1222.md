# 1222 kernel/gui 菜单性能优化

## 目标

优化 `TeXmacs/progs/kernel/gui` 下的菜单/键盘定义代码性能，TDD 方式：
先补契约测试锁定行为，再做优化，用基准脚本量化收益。

## 基准

合成大菜单（50 section × 若干条目，约 700 项）上 `menu-expand` 耗时，
脚本见 /tmp/menu-bench.scm（20 次迭代取均值，机器负载波动约 ±10%）：

- 优化前：35.3 ms/iter
- 微优化后：~32 ms/iter（3 次：33.3 / 32.8 / 30.0）

## 已定位的热点

1. `make-menu-entry` 路径每个菜单项重复调用 `promise-source`
   （procedure-source）5+ 次（style/check/dots/shortcut/balloon 各一次）
   —— menu-widget.scm:481-621
2. `gui-make` 对同一 key 两次 `ahash-ref` —— menu-define.scm:587-588（已修）
3. `menu-expand-count` 只写不读的调试残留，每条目一次全局 set!
   —— menu-widget.scm:1389（已删）
4. `dynamic`/`former` 菜单每次打开都 eval + 宏展开；`menu-expand-link-cache`
   只覆盖少数静态菜单（static-menu-link? 白名单）
5. `make-menu-items` 分发每节点一次 `match?` 模式匹配

## 改动记录

### 2026-08-18 基线测试 + 微优化

What:
- 新增 `menu-expand-test.scm`（24 项）：menu-expand / cache-menu? /
  gui-normalize 契约，replace-procedures 经 menu-expand 间接覆盖
- 新增 `menu-define-test.scm`（17 项）：gui-make 展开结果契约
- `gui-make` 分发改为单次 `ahash-ref`（with + cond 替代双重查找）
- 删除只写不读的 `menu-expand-count`，`menu-expand-list` 简化为直接 map

Why: 菜单栏/图标栏重建是 UI 响应的关键路径，每个条目都要经过
gui-make（宏展开期）与 menu-expand（运行期），微优化积少成多。

How: TDD——先写契约测试锁定现状行为（测试全绿即行为未变），再做等价变换。

涉及文件:

### 2026-08-18 promise-source 合并调用

What:
- 新增公开函数 `menu-entry-attributes`：从动作源码一次性导出菜单项全部
  展示属性（new-style / check / dotted-label / shortcut / balloon）
- `make-menu-entry-sub` 只调一次 `promise-source`，原先 5 个子函数
  （style/check/dots/shortcut/balloon）各调一次；各子函数改为接收 source 参数
- 新增 `menu-entry-test.scm`（9 项）覆盖属性导出逻辑与 make-menu-items 冒烟

Why: 每个菜单项构建时 procedure-source 被调用 5+ 次（每次还要重复
property 哈希查找），菜单重建路径上是确定性浪费。

基准（200 条目 make-menu-items，headless）：
- 优化前：436 / 697 ms/iter
- 优化后：152 / 140 ms/iter（约 2.5-4x）

涉及文件:
- TeXmacs/progs/kernel/gui/menu-widget.scm
- TeXmacs/progs/kernel/gui/menu-entry-test.scm（新增）
