# 1186 升级内置 Goldfish 到 v18.11.21

## 2026-08-08 升级内置 Goldfish 到 v18.11.21

### What
把 `TeXmacs/plugins/goldfish` 内置的 Goldfish 从 18.11.20 升级到 18.11.21，
同步自本地 `~/git/goldfish`（tag v18.11.21，HEAD `874e8d68`）。

### Why
跟进上游 18.11.21：srfi-1 的 `fold`/`fold-right`/`find`/`any`/`every`
改用 C 实现优化性能，`string-join` 修复为 O(n) 拼接。

### How
升级前先核对 mogan 内置副本与上游 v18.11.20 逐文件一致（无本地补丁），
然后整体拷贝 6 个变更文件：
- `src/goldfish.hpp`：`GOLDFISH_VERSION` 改为 `"18.11.21"`；
- `src/s7_liii_list.{c,h}`：新增 `g_find`/`g_any`/`g_every`/`g_fold`/
  `g_fold_right` 的 C 实现；
- `src/s7.c`：注册上述 5 个 `g_*` typed function；
- `goldfish/srfi/srfi-1.scm`：单列表快路径及 `find`/`any`/`every` 转调
  C 实现，语义不变；
- `goldfish/srfi/srfi-13.scm`：`string-join-sub` 改为先交错收集再一次性
  `string-append`，消除 O(n^2) 递归拼接。

兼容性：被替换的函数行为与旧 scheme 实现一致（上游带测试），mogan 侧
无需改动；`s7_liii_list.c` 此前已在 `xmake/goldfish.lua` 编译列表中，
构建配置不变。

验证：
- `xmake b stem` / `xmake b goldfish-bin` 通过；
- `goldfish-bin --version` 输出 18.11.21；
- 针对 5 个新 C 函数与 `string-join` 的 12 项 check 全部通过
  （含 improper list 上 `find` 先命中不报错等边界行为）。

## 2026-08-08 kernel 列表基础函数接线 Goldfish C 实现

### What
`TeXmacs/progs/kernel/library/list.scm` 的 `exists?`/`forall?`/`list-find`/
`list-fold`/`list-fold-right` 改用 Goldfish v18.11.21 新增的 C 实现
（`g_any`/`g_every`/`g_find`/`g_fold`/`g_fold_right`）。

### Why
这 5 个函数是高频基础遍历器（menu、graphics、text、doc 等模块大量调用），
旧 scheme 递归实现每个元素都要走解释器；C 实现行为一致且更快。

### How
- `exists?`/`forall?` 直接定义为 `g_any`/`g_every` 的别名；
- `list-find` 转调 `g_find`（参数顺序互换）；
- `list-fold`/`list-fold-right` 的单列表路径转调 `g_fold`/`g_fold_right`，
  多列表路径保留原 scheme 实现。
- 参考 `~/git/mogan2` 的 [1185] 同名改动（那边连 goldfish C 源一起同步，
  本仓库 v18.11.21 已内置，只需改 progs 侧）。

语义差异：`forall?` 旧实现恒返回 `#t`/`#f`，`g_every` 在全真时返回最后一个
谓词值（SRFI-1 语义）；调用方均按真值使用，无影响。

### 验证
`xmake r list-test`：新增 12 项 check（basic + improper list 报错），
全套 64 correct / 0 failed。
