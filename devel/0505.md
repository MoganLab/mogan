## 3 如何测试

### 3.1 确定性测试（依赖构建）

在 Windows x64 的 MSVC 环境中强制安装 HDiffPatch：

```powershell
xmake require -f -y hdiffpatch
```

预期结果：xmake 从固定的上游 `v5.1.2` 源码归档构建静态 `hdiffpatch.lib`，并安装 `libHDiffPatch/HPatch/patch.h` 等公共头文件。

### 3.2 非确定性测试（项目配置）

```powershell
xmake f -p windows -a x64 -m releasedbg -y
```

预期结果：项目能正常解析 `updater/xmake.lua`，且不会注册已移除的 `hdiffpatch_smoke` 测试 target。

## 5 What

为未来的 Windows `MoganUpdater` 引入 HDiffPatch `v5.1.2` 静态依赖。

1. 新增仓库内 xmake package recipe，从固定版本的上游源码构建 HDiffPatch。
2. 固定源码 SHA-256，避免依赖下载内容被静默替换。
3. 新建 `updater/xmake.lua`，将 HDiffPatch、zstd 与 xxHash 的依赖声明收敛到 updater 模块。
4. 移除临时的 `hdiffpatch_smoke` 源码和 target；将来由正式的 `MoganUpdater` target 直接使用 `add_packages("hdiffpatch", "zstd", "xxhash")`。

## 6 Why

Windows 自动更新需要在 staging 目录中应用增量更新。HDiffPatch 提供核心补丁 API，适合该职责。

该依赖只会被 updater 使用。将其声明放在全局 `xmake/requires.lua`，或保留独立 smoke executable，都会扩大无关模块的构建认知范围。依赖定义与 updater 同处能明确所有权，并为后续独立 updater target 做准备。

## 7 How

本任务不依赖不存在的 xmake 官方 `hdiffpatch` 包，而是在本仓库的 package repository 中实现配方：

1. 下载 `https://github.com/sisong/HDiffPatch/archive/refs/tags/v5.1.2.tar.gz`。
2. 使用 SHA-256 `255f58b0b2b6a76c97e8fefce90097ea966a6eb40e4d2a10e530f875ef29deb1` 校验源码归档。
3. 以 xmake 构建 HDiffPatch 核心补丁源码，产出静态库 `hdiffpatch.lib`。
4. 安装上游保留目录结构的 `libHDiffPatch` 头文件，消费者以如下路径引用公共 API：

   ```cpp
   #include <libHDiffPatch/HPatch/patch.h>
   ```

5. 在 `updater/xmake.lua` 中仅为 Windows 声明 HDiffPatch、zstd 与 xxHash。未来 updater 通过 HDiffPatch 的 `decompress_plugin_demo.h` 与 `checksum_plugin_demo.h` 提供 zstd 解压和 xxh128 校验插件：

   ```lua
   add_requires("hdiffpatch v5.1.2", {system=false, configs={shared=false}})
   add_requires("zstd", {system=false})
   add_requires("xxhash", {system=false})
   ```

当前静态库包含目录 patch 与 Window Diff 解析能力，并安装了 HDiffPatch 的 zstd 解压、xxh128 校验插件头；`updater/xmake.lua` 已声明相应 zstd、xxHash 依赖。发布侧的 `dir_diff()` 和 `create_window_diff()` 不会打进 updater。插件对象的实际调用逻辑、更新包资源格式、签名校验和 UAC worker 均属于后续 updater 实现任务。
