# [1319] 解耦拆分 prog-mode.scm 并建立各语言专属 mode 模块

## 1 相关文档

## 2 任务相关的代码文件

- `TeXmacs/plugins/java/progs/java/java-edit.scm` — 加载 `(java java-mode)`

## 3 如何测试

### 3.1 确定性测试（单元测试与语法检查）
```bash
xmake b stem && xmake r 70_7
```

### 3.2 非确定性测试（交互验证）
1. 在 Windows 平台启动 Mogan STEM：`xmake r stem`；
2. 在首页（欢迎界面）的「最近的文档」列表中点击打开 `1319.tmu`（只能通过首页来测试复现）；
3. **预期结果**：
   - 包含 Python session 的文档能正常加载并显示渲染，不会发生软件卡死（stuck）或无响应错误。

## 4 What
1. 初次打开文档时会加载相应插件。如果文档本身使用了特定语言插件（如包含 Python session/code 的文档），在 `prog-mode.scm` 尚未被系统加载的情况下，加载 `python-edit.scm` 会因为 `in-prog-python?` 等符号没有定义而报错，导致软件卡死；
2. 参考 `lua-mode.scm`、`scala-mode.scm` 等独立语言模式设计，为各语言建立专属的 `*-mode.scm`；
3. 将 `prog-mode.scm` 集中定义的各个具体编程语言模式（`cpp`、`java`、`javascript`、`json`、`python`、`julia`）解耦拆分至各自插件目录下；
4. 清理已废弃无引用的 `dot` 和 `fortran` 模式定义；
5. `prog-mode.scm` 仅保留 `(in-scheme% ...)` 和 `(in-prog-scheme% ...)`；
6. 在各语言插件的 `*-edit.scm` 或 `.stem` 中按需加载对应的 `*-mode.scm` 模块。

## 5 Why
1. 修复由于符号未定义引起的卡死 Bug：在首页启动阶段，`prog-mode.scm` 尚未被加载；如果此时直接从首页最近文档打开带有 Python 等插件的文档，`python-edit.scm` 中注册的 `(:mode in-prog-python?)` 槽和快捷键便会遇到未定义符号，引发软件卡死；
2. 模块自包含与解耦：每个语言插件应该自行管理其语法模式与谓词，不应隐式依赖外部公共模式文件的加载时序；
3. 架构统一：各编程语言插件（如 `lua`、`scala`、`bash`、`fish`、`r` 等）已采用独立的 `(<lang> <lang>-mode)` 模块，将剩余语言按相同规范统一。

## 6 How
1. 创建 `python-mode.scm`、`cpp-mode.scm`、`java-mode.scm`、`javascript-mode.scm`、`json-mode.scm`、`julia-mode.scm`，通过 `texmacs-modes` 分别定义对应的 `in-<lang>%` 和 `in-prog-<lang>%`；
2. 在 `python-edit.scm`、`cpp-edit.scm`、`java-edit.scm` 的 `:use` 声明中引入各自的 mode 模块；
3. 在 `javascript.stem`、`json.stem`、`julia.stem` 中引入对应的 mode 模块；
4. 在 `prog-mode.scm` 中移除上述迁移出的语言及历史无用模式，仅保留 scheme 相关模式。
