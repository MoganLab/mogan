## 5 What
1. 采用 TDD 方式编写了自动化回归测试 `TeXmacs/tests/1312.scm`；
2. 修复了 `edit_interface_rep::key_press` 中对已包含 Cork 标签的字符串错误进行二次尖括号包裹的问题；
3. 优化了 `edit_interface_rep::handle_keypress` 中的 unwrap 条件，仅对长度为 1 的单实体标签剥去尖括号，防止多字符 Cork 字符串首尾被破坏。

## 6 Why
当用户在中文输入法下先输入字母 `A`，随后按下 `Shift+6` 输入中文省略号时：
1. 中文输入法提交 `commitString = "A……"`；
2. `utf8_to_cork` 将其转为 Cork 字符串 `"A<ldots><ldots>"`；
3. 字符串进入 `key_press` 后，原本用于检测裸符号名（如 `"alpha"`）的判断分支 `cork_to_utf8 ("<" * key * ">") != ("<" * key * ">")` 会将 `<A<ldots><ldots>>` 解码为 `<A……>`；
4. 由于 `<A……>` 与 `<A<ldots><ldots>>` 不相等，该分支误判整个字符串为一个未加括号的实体名，执行了 `call ("kbd-insert", "<" * key * ">")`，插入了 `"<A<ldots><ldots>>"`；
5. 文档排版引擎无法识别 `<A...>` 语法，导致界面上出现带有非法 `<` 和 `>` 的 `<...>` 标记。

同时，历史 PR 206_14 曾试图通过在 `handle_keypress` 中对所有标签元素进行 unwrap 绕过此问题，但在遇到前面有非标签普通字符（如 `A`）时该逻辑失效，且剥去多 token 字符串的首尾字符从原理上会破坏 Cork 字符串结构。

## 7 How
1. **在 `key_press` 中增加安全守卫**：
   在检测裸实体名的分支中加入 `!occurs ('<', key) && !occurs ('>', key)`：
   ```cpp
   else if (!occurs (" ", key) && N (key) > 1 && key[1] != '-' &&
            !occurs ('<', key) && !occurs ('>', key) &&
            cork_to_utf8 ("<" * key * ">") != ("<" * key * ">") &&
            !inside_active_graphics ()) {
     archive_state ();
     call ("kbd-insert", "<" * key * ">");
     interrupt_shortcut ();
   }
   ```
   如果 `key` 已经包含了 `<` 或 `>`，说明其本身已经是经过编码的 Cork 字符串（例如 `A<ldots><ldots>` 或 `<ldots><ldots>`），绝不可能是像 `alpha` 一样的裸实体名，因此直接跳过该分支，落入后续的 `call ("insert", key)` 分支正常插入。

2. **在 `handle_keypress` 中严格 unwrap 作用范围**：
   ```cpp
   string key= utf8_to_cork (key_u8);
   if (tm_string_length (key) == 1 && starts (key, "<") && ends (key, ">") &&
       !starts (key, "<#")) {
     key= key (1, N (key) - 1);
   }
   ```
   只有在 `key` 的 Cork 字符串长度严格为 1 且为非十六进制实体（如 `<alpha>`）时，才将其解包为 `alpha` 供后续快捷键/模式分发使用；对于长度大于 1 的多字符串（如 `<ldots><ldots>`、`<smiley><#FE0F>`、`A<ldots><ldots>`），完整保留其 Cork 格式。
