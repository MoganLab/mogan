# [1606] 修复 Go 菜单 hover 测试在 CI 高负载下的动画超时误报

## 1 任务背景

CI 失败（macOS arm64 job，C++ tests 步骤，run 35485150115，main 分支
7abdcb254）：

```
FAIL! : TestQmlLoad::test_go_menu_hover() Compared doubles are not the same
   Actual   (bg->property ("opacity").toDouble ()): 0.32
   Expected (0.0)                                 : 0
```

`GoMenu.qml` 菜单项的悬浮高亮背景 `goMenuItemBg` 通过
`Behavior on opacity { NumberAnimation { duration: 100 } }` 渐变。测试在
hover 移出后固定 `QTest::qWait (150)` 再单次断言 opacity 为 0.0，隐含
「100ms 动画在 150ms 墙钟内必定走完」的假设。

CI runner（offscreen、高负载）下 QML 动画时钟的定时器可能被饿（调度延迟/
timer 合并），150ms 时动画只走到 0.32，属测试时序脆弱而非产品 bug——本地
与常规负载下该测试一直通过。

验收标准：
- 测试不再依赖固定墙钟等待，动画时钟变慢时仍能收敛判定；
- 正常路径行为不变（hover 渐入到 1.0、移出渐出到 0.0）；
- 产品代码（GoMenu.qml 动画时长 100ms）不改。

## 2 涉及的代码文件

- `devel/1606.md` — 本任务说明文档
- `tests/Plugins/Qt/qml_load_test.cpp` — `test_go_menu_hover` 两处
  `qWait (150)` + `QCOMPARE` 改为 `QTRY_COMPARE` 轮询

## 3 改动说明

**What**：`test_go_menu_hover` 中对 `goMenuItemBg` opacity 的两处断言由
`QTest::qWait (150); QCOMPARE (...)` 改为 `QTRY_COMPARE (...)`（默认轮询
间隔 10ms、超时 5s），并在渐入断言前补一行说明原因的注释。

**Why**：QTRY 系列是本文件处理异步收敛的既有惯例（焦点到达、隐式高度
布局均用此写法；`test_version_dialog_focuses_on_open` 的注释也记录了
「CI 高负载下固定时刻单次检查会误报」的同款经验）。轮询到动画收敛既对
时钟被饿的慢环境稳健，正常环境也比固定 150ms 等待更快。

**How**：hover 移入后 `QTRY_COMPARE (bg->property ("opacity").toDouble (), 1.0)`；
移出后 `QTRY_COMPARE (bg->property ("opacity").toDouble (), 0.0)`。
`NumberAnimation` 结束时精确落在终值，QTRY 对 double 的模糊比较即可命中。
