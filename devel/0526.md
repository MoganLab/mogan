# [0526] OAuth 回调链路改造（三）：state 校验（CSRF 防护）

## 背景

`login()` 构建授权 URL 时没有发送 `state`，回调 lambda 只看 `values` 里有没有
`code`——任何带回授权码的回调都会被拿去换 token，CSRF / 重放没有防护。

同时，多实例场景（后续切 `liiistem://` 深链）需要回答"这个回调该交给哪个实例"，
`state` 是唯一能跟着授权请求往返、又不受进程重启影响的载荷，所以实例标识必须
从这一步就装进去。

本改动**不依赖** [0524]、[0525]：state 与 redirect_uri 提取、回调端口分配均无关，
分支直接基于 `origin/main`，可独立评审、独立合并。

## 改动

- `src/Plugins/Qt/QTMOAuth.cpp`
  - 新增 `generateRandomString (int)`：字母数字随机串（URL 安全），刻意不含
    `.`，使 state 的 `<实例标识>.<一次性随机数>` 拼接可无歧义拆回两段；
  - 构造函数：新增 `m_instanceId= generateRandomString (16)`，进程内唯一；
  - `login ()`：每次登录重新生成 `m_state= m_instanceId + "." +
    generateRandomString (32)`，作为 `state` 参数发出；
  - 回调 lambda 精简为一行转调 `handleCallback (values)`；
  - 新增 `handleCallback (const QVariantMap&)`：回调的唯一入口，先校验 state
    再取 code，校验通过后立即清空 `m_state`（一次性）。
- `src/Plugins/Qt/QTMOAuth.hpp`
  - 补 `#include <QtCore/qvariant.h>`（`QVariantMap` 是 typedef，无法前向声明）；
  - 新增 `generateRandomString` / `handleCallback` 声明与 `m_instanceId` /
    `m_state` 成员。

校验失败即丢弃回调并打 `OAuth callback rejected: state mismatch`，不发起 token
交换。`m_state` 一次性：同一 state 只接受一次回调，避免浏览器历史里的回调 URL
被重放（授权码本身一次性，这里不额外留口子）。

## 配套（cn.liiistem，另仓库）

state 链路上唯一的断点在官网前端：`OAuth2Login.vue` 的
`redirectToAuthorization()` 从 URL 里读得到 `state`，但拼
`/api/v1/oauth2/authorize` 时没往下传，state 在这一跳被丢掉。

**必须同批上线，且前端在先**：前端改动是纯增量（`if (params.state)` 守卫，
不带 state 的旧客户端行为逐字节不变），可立即发版；客户端若先发，回调回来的
state 为空会被本改动拒绝，登录直接失败。

后端（liii-server）**零改动**：`DirectUserAuthenticationConverter` 已把 `state`
传进 `OAuth2AuthorizationCodeRequestAuthenticationToken`，Spring Authorization
Server 在 302 回 `redirect_uri` 时原样回显。

## 验证

编译与端到端由本地执行（本任务不编译）。人工验证清单：

1. 授权页地址栏中应出现 `state=<16 位>.<32 位>`；
2. 授权后 302 的 `Location` 应带回**完全相同**的 state，回调后
   `debug_boot` 打出 `Token exchange successful`；
3. **反向验证（校验确实生效的证据）**：手工把回调 URL 里的 state 改掉一位再
   访问，应打出 `OAuth callback rejected: state mismatch` 且不发起 token 交换；
4. 双实例：两个实例各自 state 的 `.` 前缀不同；
5. 回归：登录失败/取消授权（服务端回 `error=access_denied`，带 state）时行为与
   改动前一致（静默返回，不崩）。
