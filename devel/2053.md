## 3 如何测试

### 3.1 构建（cli_frontend 模式）
```bash
xmake f --qt_frontend=n --cli_frontend=y -m release --yes
xmake b stem
# 产物：build/linux/x86_64/release/moganstem（ldd 确认无 Qt 依赖）
```

### 3.2 非确定性测试（文档验证）
```bash
bin=build/linux/x86_64/release/moganstem
TEXMACS_PATH=<TeXmacs 发行目录> "$bin" -x \
  '(load-buffer "<in.tmu>") (render-doc-to-pdf "<in.tmu>" "<out.pdf>") (quit-TeXmacs)'
pdfinfo out.pdf     # 确认 Pages / Page size（A4）
pdftotext out.pdf - # 确认文本内容完整
```
- 已知现象：`render-doc-to-png`（mupdf 光栅化路径）对无空格连续文本渲染为空白页；
  `render-doc-to-pdf`（pdf_hummus_renderer 矢量路径）正常。需要可靠的文档输出时用 PDF。

## 5 What
- 新增 scheme 函数 `render-doc-to-pdf`：在 CLI（无 UI）下把 `.tmu` 文档导出为矢量 PDF。
- 复用 `print_doc` → `printer()` 工厂的 pdf 分支（`pdf_hummus_renderer`，受 `USE_PLUGIN_PDF` 控制）。
- 修复 Linux 下 cli_frontend 构建的 harfbuzz 链接错误。

## 6 Why
- CLI 批量渲染（stem → tmu → 文档/图像）需要 PDF 输出：矢量、质量高、便于嵌入与分发。
- `render-doc-to-png` 的 mupdf 光栅化路径存在无空格文本空白页 bug，PDF 路径无此问题。

## 7 How
- 仿 `buffer_render_to_images`：用 `get_passive_view`（无窗口 view）获取 buffer，headless 可用。
- 直接调用 `print_doc (dest, false, 1, 1000000)` 而非 `print_to_file`：后者末尾的
  `set_message` 经 `get_current_editor` 在无窗 editor 下会取空指针而崩溃。
- `print_doc` 按 dest 后缀选择 renderer（`printer.cpp` 工厂），`.pdf` 后缀 → `pdf_hummus_renderer`
  （纯 C++ 实现，无 GUI 依赖）。
- `xmake/targets/stem.lua`：Linux 分支 `add_syslinks("X11", "harfbuzz")` —— mupdf 的
  `html-layout.o` 引用 `hb_*` 符号，而 libmupdf-third 未内置 harfbuzz，需链接系统 libharfbuzz。
