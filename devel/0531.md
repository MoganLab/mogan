# [0531] 更新 goldfish 到 v18.11.34

## 覆盖更新 TeXmacs/plugins/goldfish/goldfish 目录和 TeXmacs/plugins/goldfish/src 目录

## 修复 s7_liii_tree.c 未纳入构建导致的链接失败

**What**：`xmake/goldfish.lua` 的 `libgoldfish` target 在 `add_files` 中补上
`$(projectdir)/TeXmacs/plugins/goldfish/src/s7_liii_tree.c`。

**Why**：本次 s7 源码迁移把 `tree_is_cyclic`、`tree_len`、`s7_tree_memq`、
`tree_memq_*`、`tree_set_memq_*`、`tree_count`、`g_tree_*` 等 20 个函数从 `s7.c`
拆到新建的 `s7_liii_tree.c`，但构建清单没有同步登记该文件，`libgoldfish` 从不编译它。
`s7.c` / `s7_scheme_write.c` 仍在引用这些符号，于是 `goldfish-bin` 链接阶段报
20 个无法解析的外部符号（Windows `LNK2001` + `LNK1120`，macOS undefined symbols），
`stem` 因依赖 `goldfish-bin` 一并失败。

**How**：把 `s7_liii_tree.c` 加入 `add_files`。验证方式见下。

**注意**：该问题在增量构建下可能被残留的旧目标文件掩盖（旧 `s7.c.obj` 尚自带这些符号，
链接会假性通过），只有在全新构建或强制重建时才暴露——CI 是全新构建，故必然失败。

**涉及文件**：
- `xmake/goldfish.lua`
- `devel/0531.md`

## 同步 list-test 的错误类型期望

**What**：`TeXmacs/progs/kernel/library/list-test.scm` 中 8 处 `check-catch` 的期望条件
类型更新——`test-list-head-errors` 4 处、`test-list-drop-right-errors` 2 处，以及
`test-exists-errors` / `test-list-find-errors` / `test-list-fold-errors` /
`test-list-fold-right-errors` 各 1 处。

**Why**：goldfish 升级到 v18.11.34 后，`s7_liii_list.c` 的错误分类从一律
`s7_wrong_type_arg_error` 改为按语义区分：

| 场景 | 旧 | 新 |
| --- | --- | --- |
| `take` / `drop-right` 的 k 为负 | `wrong-type-arg` | `out-of-range` |
| `drop-right` 的 k 超出长度 | `wrong-type-arg` | `out-of-range` |
| 参数类型不对（k 非整数、lst 非列表） | `wrong-type-arg` | `type-error` |
| 非正规列表（点对结尾）走到尽头 | `wrong-type-arg` | `type-error` |

`check-catch` 展开为 `(check (catch <id> ...) => <id>)`，是**条件类型符号的精确匹配**：
类型不符时 `catch` 不捕获，错误直接冒泡出 `regtest-list`，被 `tests.lua` 外层
`catch #t` 打印后 `exit 1`，CI 报错：

```
Error: (out-of-range "[not-implemented]" "~A ~:D argument, ~S, is out of range (~A)" ("take" 2 -1 "it is negative"))
```

测试文件本身未被本分支修改，编码的是旧版 goldfish 的错误契约；上游分类调整后期望值需
同步。属测试期望更新，不动产品代码。

**How**：先用诊断脚本以 `(catch #t ... (lambda args (car args)))` 逐条打印实际条件类型，
再据此改写期望；随后 `xmake r list-test` 复跑确认 `64 correct, 0 failed`（用例数不变，
只改期望符号）。已逐个复跑全部 43 个 scheme 测试，确认无其他用例受升级影响。

**注意**：

- `list-head` 的 k 超出长度抛 `type-error`，而 `list-drop-right` 同场景抛 `out-of-range`。
  这是 goldfish 侧 `g_take` 与 `take_right_lead` 的既有差异，测试照实固定并在注释中标注，
  未强行统一。
- 增量构建下该失败可能被陈旧的已安装二进制掩盖（旧 goldfish 下全部期望恰好成立，报
  `64 correct, 0 failed`），须用新构建的二进制复跑才能暴露。
- 本地在 Windows 跑 `xmake r --group=scheme_tests` 时 `export-pdf-default-dir-test` 会失败：
  该用例期望 POSIX 路径 `/tmp/1268`，Windows 下 `url->system` 得到 `tmp\1268`。该用例与
  本分支无关（该文件与 `tm-print.scm` 均未被本分支修改），且 Windows CI 不跑
  `scheme_tests`（只 `xmake build stem`），Debian/Fedora/macOS CI 下 `/tmp/1268` 正常往返，
  故不构成本次 CI 失败。

**涉及文件**：
- `TeXmacs/progs/kernel/library/list-test.scm`
- `devel/0531.md`
