# [2015] 切换 tab 会把已保存的命名文件重新标脏

## 1 相关文档
- [2014.md](2014.md) - tab 切换性能修复。其 GUI 复现（`2014.scm`）暴露本问题。

## 2 现象（用户实测，已排除 doc-id）

复现步骤（用一个**已有 stem-doc-id** 的本地文件）：

1. 打开该文件。
2. 编辑内容 → 标题带 `*`（正常）。
3. 保存 → `*` 消失。
4. 新建一个 tab → 标题无 `*`（正常）。
5. 切回该文件 tab → **仍无 `*`**（说明此时 buffer 确实是干净的）。
6. **切换 tab（在两个 tab 间来回切）→ `*` 出现。**

### 关键判据

- 保存后、切回 tab 时都**不带 `*`** → 保存确实清掉了脏，buffer 此刻是干净的。
- 但**切换 tab 这个动作本身**让 buffer 重新变脏。
- 已排除 doc-id：doc-id 是打开/新建时一次性注入的，不会在切 tab 时再次写入。
  用带 doc-id 的文件仍复现，说明根因与 doc-id 无关。

### 结论

**根因在 tab 切换路径里**：`switch-to-view-index` → `window_set_view` →
`attach_view`/`detach_view_for_switch` → `editor::resume()`/`suspend()` 这条链
（或它间接调用的 scheme 代码）对当前 buffer 做了某个会标脏的操作，但这个操作
**不走 `require_save()`**（之前在 `require_save` 加日志，切 tab 时没打印）。

因此候选是：
- 切 tab 撤销了 `notify_save` 的效果（重置 `last_save`）；
- 切 tab 触发了某个 modification（`confirm`/`archive_announce`），推进了 archiver
  的 `depth` 却没同步推进 `last_save`，使 `conform_save()` 失败；
- 切 tab 重新执行了一段 init/refresh，间接 `init-env`/`init-style` 标脏。

## 3 标脏机制（背景）

- `buffer-modified?` ≡ `!conform_save()` ≡ `last_save != corrected_depth()`。
- `require_save()` → `last_save = -1`（标脏）。
- `notify_save()` → `last_save = corrected_depth()`（清脏，保存时调）。
- 任何让 `last_save != corrected_depth()` 的变化都会表现为脏。

## 4 排查计划

加更全面的 C++ 诊断日志（`LIII_DEBUG` 包裹），覆盖所有改变 `conform_save()` 的路径，
驱动「有 doc-id 文件 → 编辑 → 保存 → 切 tab」复现，定位切 tab 时究竟谁动了
archiver 的 `depth`/`last_save`。配合 `2015.scm` 在 GUI 跑。
