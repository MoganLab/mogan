## [7004] 修复 File → Recent tooltip 中文路径乱码

### What
Qt 前端下，**File → Recent**（以及 Go 菜单 buffer 列表、带 help 的工具栏按钮）
鼠标悬停时显示的 tooltip 中，若路径含中文（如 `/Users/jimzhou/文档/test.tm`），
中文部分显示为乱码。修复后 tooltip 正确显示完整中文路径。

### Why
文件路径在 Scheme 层由 `(url->system u)` 产生，是操作系统的 8-bit 编码字符串
（macOS/Linux 上为 **UTF-8**）。它作为 `(balloon 短名 长名)` 的第二个参数
（help/tooltip 文本）传到 Qt 前端 `qt_ui_element.cpp` 的 `balloon_widget` 分支时，
被**无条件**套上 `cork_to_utf8()`：

```cpp
act->setToolTip (utf8_to_qstring (cork_to_utf8 (y.x1)));
w->setToolTip   (utf8_to_qstring (cork_to_utf8 (y.x1)));
```

Cork 是单字节编码，每个 `>= 0x80` 的字节都被当作一个 Cork 字符映射成另一段 UTF-8。
而中文 UTF-8 是多字节序列（所有字节 `>= 0x80`），逐字节按 Cork 解读即乱码。

菜单项**标签**正常、只有 tooltip 乱码：同文件 `text_widget`（标签）走的是已有的
启发式 `to_qstring()`，而两处 tooltip 绕过了它，直接用 `cork_to_utf8`。

### How
- 复用同文件已有的 `to_qstring()`（定义于 `qt_utilities.cpp:448`，注释原文即指出
  「file names are internally stored using the os 8-bit encoding (UTF-8 on
  linux/Mac OS ...)」，正是为本场景设计）。逻辑：
  - 含中文的 UTF-8 路径：`looks_utf8 && !(looks_ascii||looks_universal)` 为真 →
    `utf8_to_qstring` 直通显示 → 正确。
  - 纯 ASCII 路径：`looks_ascii` 为真 → 走 `cork_to_utf8`（Cork 对 `<0x80` 与
    ASCII 兼容，无回归）。
  - 纯 Cork 西文 tooltip（带重音）：高字节单独不成合法 UTF-8，`looks_utf8` 为假 →
    走 `cork_to_utf8` → 正确。
- `balloon_widget` 在 `qt_ui_element.cpp` 有两个渲染分支，两处都改：
  - `as_qaction()` 分支（第 542 行，`act->setToolTip`）——**菜单项走这条**，
    Recent 菜单项即由此触发。
  - `as_qwidget()` 分支（第 958 行，`w->setToolTip`）——独立控件（工具栏按钮等）。
- `to_qstring` 已在本文件多处使用（第 895、977 行等），无需新增 include。
- ImGui 前端不显示 balloon tooltip（`im_gui.cpp` 的 `balloon_widget` 丢弃 help
  文本），故本 bug 仅影响 Qt，无需改动 ImGui。

### 涉及文件
- `src/Plugins/Qt/qt_ui_element.cpp`（第 542、958 行各改一处 `setToolTip`：
  `utf8_to_qstring (cork_to_utf8 (y.x1))` → `to_qstring (y.x1)`）

### 如何测试
- `xmake b stem`；打开或新建一个路径含中文的文档（如 `~/文档/test.tm`），确保它进入
  Recent 列表。
- File → Recent 悬停该项：修复前中文乱码，修复后完整正确显示中文路径。
- 回归：悬停一个纯英文路径的 Recent 项，确认 tooltip 仍正常。
- 可选：悬停 Go 菜单的 buffer 列表项，确认其中文路径 tooltip 同样修复。
- 属 Qt GUI 鼠标悬停路径，不适合 headless 单测，以手动 GUI 验证为准。
