# 1140 将编辑器 `path-exists?` 重命名为 `stem-path-exists?` 以解决与 `(liii path)` 的命名冲突

## 问题现象

执行 `Ink here`（`make-graphics-over`）时，终端出现 Scheme 类型错误：

```text
;path-exists? first argument, #f, is boolean but should be some other thing
;    (if (in? (tree-label (path->tree p))...
;    /home/da/git/mogan/TeXmacs/progs/graphics/graphics-utils.scm, line 180
```

1139 已经让编辑器 `path-exists?` 在收到非法参数时不再 abort。
进一步排查发现，编辑器 C++ 粘合函数和 `(liii path)` 库都导出了同名函数 `path-exists?`，
二者语义不同：前者操作 **stem 路径**（整数列表），后者操作 **文件路径**（字符串）。
这种重名容易导致调用歧义，也是 `#f` 等非法参数被传入编辑器版本的诱因之一。

## 根因分析

### 命名冲突

- 编辑器 glue 在 `src/Scheme/Glue/glue_editor.lua` 中注册为 `path-exists?`，
  对应 C++ 函数 `test_subtree`，参数类型为 `path`（整数列表）。
- `(liii path)` 库在 `TeXmacs/plugins/goldfish/goldfish/liii/path.scm` 中也定义了 `path-exists?`，
  参数类型为字符串路径。

`TeXmacs/progs/kernel/boot/abbrevs.scm` 的 `path->tree` 原本调用的是编辑器 `path-exists?`；
而一旦某个模块导入 `(liii path)`，同名的 `path-exists?` 就会覆盖编辑器版本，
造成语义错误。

### `make-graphics-over` 暴露的问题

0837 在 `make-graphics-over` 末尾新增 `(graphics-zoom 2.0)`。
该函数插入 `draw-over` 后使用的光标路径 `'(1 2 1)` 并没有把光标放到 `graphics` 内部，
而是放到了 `with` 的属性元组里，因此 `graphics-graphics-path` 返回 `#f`，
随后 `graphics-zoom` 内部调用 `graphics-get-property` / `graphics-eval-magnify` / `tm-upwards-path` 时，
把 `#f` 传给了 `path->tree` → `stem-path-exists?`，触发类型错误，
同时 `graphics-zoom 2.0` 也没有真正生效。

直接修改 `make-graphics-over` 光标路径的尝试（把 `(graphics)` 改成 `(graphics "")` 并动态计算路径）
不正确，已 revert。

## 修复

### 1. 重命名编辑器 glue 符号

将编辑器版本的 `path-exists?` 改名为 `stem-path-exists?`，避免与 `(liii path)` 冲突：

- `src/Scheme/Glue/glue_editor.lua`：`scm_name` 改为 `"stem-path-exists?"`。
- `TeXmacs/progs/prog/glue-symbols.scm`：符号名同步改为 `"stem-path-exists?"`。
- `src/Scheme/Glue/build-glue-editor.scm`：已移除。

### 2. 更新调用方

- `TeXmacs/progs/kernel/boot/abbrevs.scm`：
  ```scheme
  (define-public (path->tree p) (and (stem-path-exists? p) (cpp-path->tree p)))
  ```
- `TeXmacs/tests/1139.scm`：测试用例全部改为调用 `stem-path-exists?`。

### 3. 防御性检查（保留）

`TeXmacs/progs/graphics/graphics-utils.scm` 中保留以下防御性修复，
防止 `#f` 等非法参数进入 `path->tree`：

- `tm-upwards-path` 在入口检查 `p` 是否为列表，不是则返回 `#f`。
- `graphics-eval-magnify` 在 `graphics-graphics-path` 为 `#f` 时返回 `"default"`。
