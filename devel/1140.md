# 1140 修复 `path-exists?` 在图形工具中收到 `#f` 参数的问题

## 问题现象

执行 `Ink here`（`make-graphics-over`）时，终端出现 Scheme 类型错误：

```text
;path-exists? first argument, #f, is boolean but should be some other thing
;    (if (in? (tree-label (path->tree p))...
;    /home/da/git/mogan/TeXmacs/progs/graphics/graphics-utils.scm, line 180
```

1139 已经让 `path-exists?` 在收到非法参数时不再 abort，但这里的问题在于：
**上层代码把 `#f` 传给了 `path->tree`，间接导致 `path-exists?` 收到 boolean。**

## 根因分析

这是 0837 在 `make-graphics-over` 末尾新增 `(graphics-zoom 2.0)` 时暴露出来的问题。

`TeXmacs/progs/generic/generic-edit.scm` 中的 `make-graphics-over` 插入 `draw-over` 后使用：

```scheme
(insert-go-to `(draw-over ,"" ,g ,"2cm") '(1 2 1))
```

这个 `'(1 2 1)` 并没有把光标放到 `graphics` 内部，而是放到了 `with` 的属性元组里。
因此 `graphics-graphics-path` 返回 `#f`，随后 `graphics-zoom` 内部调用
`graphics-get-property` / `graphics-eval-magnify` / `tm-upwards-path` 时，
就把 `#f` 传给了 `path->tree` → `path-exists?`，触发类型错误，
同时 `graphics-zoom 2.0` 也没有真正生效。

`TeXmacs/progs/graphics/graphics-utils.scm` 里还有两处对 `#f` 缺乏防护，
会在无图形上下文时遇到同样问题：

1. `tm-upwards-path`（第 179 行）：直接对 `p` 调用 `path->tree`，
   当 `p` 为 `#f` 时进入 `path-exists?`。
2. `graphics-eval-magnify`（第 402 行）：直接写 `(path->tree (graphics-graphics-path))`，
   没有图形时同样把 `#f` 传给 `path->tree`。

> **关于直接修正 `make-graphics-over` 的尝试**
>
> 曾尝试把 `g` 里的 `(graphics)` 改成 `(graphics "")` 并动态计算 `insert-go-to` 路径，
> 让光标落到 graphics 内部，但该修改不正确，已 revert。
> 当前文档记录的是已经合并的防御性修复；`make-graphics-over` 的精确光标定位仍需
> 结合 `draw-over` 的实际树结构进一步确定。

## 修复

### 1. 给 `tm-upwards-path` 加防御性检查

在函数入口判断 `p` 是否为合法列表；如果不是，直接返回 `#f`，
避免继续调用 `path->tree` 和 `path-exists?`：

```scheme
;; Guard against invalid paths (e.g. #f returned by graphics-graphics-path)
(tm-define (tm-upwards-path p tags nottags)
  (if (not (list? p))
    #f
    (if (in? (tree-label (path->tree p)) tags)
      p
      (if (in? (tree-label (path->tree p)) nottags)
        #f
        (if (> (length p) 2) (tm-upwards-path (cDr p) tags nottags) #f)
      ) ;if
    ) ;if
  ) ;if
) ;tm-define
```

### 2. 给 `graphics-eval-magnify` 加防御性检查

先取 `graphics-graphics-path` 的结果，只有在非 `#f` 时才调用 `path->tree`；
否则返回 `"default"`：

```scheme
(tm-define (graphics-eval-magnify)
  (with p
    (graphics-graphics-path)
    (if p (graphical-get-attribute (path->tree p) "magnify") "default")
  ) ;with
) ;tm-define
```
