# [0403] 修复合并单元格后编辑线条重叠问题

## 如何测试
1. 打开 Mogan STEM，新建一个空白文档。
2. 插入一个表格（如 3x3）。
3. 选中三个或以上的单元格（横向或纵向均可）。
4. 点击菜单栏 **单元格 -> 合并单元格**，将它们合并。
5. 确认**"显示表格单元格"**偏好设置已开启（编辑 -> 首选项 -> 其他 -> 显示表格单元格）。
6. 观察合并后的单元格，确认**编辑时的辅助线条（灰色细框）没有出现重叠或错位**。
7. 对比修复前：合并 3+ 单元格后，被覆盖的单元格位置会额外绘制一层线条，导致线条加粗或重叠。
8. 再测试合并 2 个单元格，确认线条显示正常（此前已正常，应保持一致）。
9. 测试拆分单元格（**单元格 -> 拆分单元格**），确认拆分后各单元格线条恢复正常。

## 2026/05/12
### what
修复当多个单元格合并后，编辑状态下的单元格辅助线条（`env_rects`）出现重叠的问题：
- 根因：`compute_env_rects()` 按逻辑行列遍历表格时，对被合并覆盖的单元格（covered cells）调用 `find_check_selection()`。这些单元格在排版后没有独立 box，`find_check_selection()` 的行为不稳定（有时返回 `valid=false`，有时映射到主单元格返回相同的矩形，有时返回整个表格的回退矩形），导致同一区域被重复绘制边框，出现线条重叠或加粗。
- 修复：采用双重保险策略，不依赖单一判断条件：
  1. **Tree 结构解析（第一层过滤）**：在遍历前先扫描表格父节点 `TFORMAT` 中的所有 `CWITH`，提取每个单元格的 `cell-row-span` 和 `cell-col-span` 属性。根据 span 信息计算出所有被覆盖的逻辑位置，建立 `covered[i][j]` 数组。遍历时直接跳过被覆盖单元格。
  2. **矩形去重（第二层过滤）**：即使 `find_check_selection()` 返回了和已绘制单元格完全相同的矩形（如被覆盖单元格恰好映射到主单元格），通过维护 `drawn_rects` 数组跳过重复矩形。
  3. **放宽 CWITH 解析条件**：将 `is_func(with, CWITH, 6)` 放宽为 `is_func(with, CWITH) && N(with) >= 6`，兼容可能的变长格式。
- 仅影响编辑时的视觉辅助线，不影响实际排版或打印输出。

### why
合并多单元格后，被覆盖的单元格在排版底层已置为空（`cell ()`），但编辑界面的 `compute_env_rects()` 仍按逻辑行列遍历所有位置。此前多次尝试依赖 `find_check_selection()` 的返回值（`valid` 状态、矩形比较、路径比较）来判断是否跳过，但该函数行为受 box 树结构、刷新时机、合并顺序等多种因素影响，极不稳定（"一会有问题，一会没问题"）。直接从 tree 解析 `cell-row-span`/`cell-col-span` 配合几何矩形去重，是目前最可靠的双重保险方案。
