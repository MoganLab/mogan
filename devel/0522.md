# [0522] 搜索最近打开的文档：中文名称文档链接 cork 乱码

## 问题

「编辑 → 搜索最近打开的文档」的结果页中，文件名含中文的文档，其链接文本显示为 cork 乱码。

## 根因

`TeXmacs/progs/doc/docgrep.scm` 的 `build-doc-search-results` 构造结果页链接：

```scheme
(let* ((path (car x))
       (title (help-file-title path))
       (text (if (null? title) (car x) title)))
  ($link path text))
```

- `$link` 的 dest 由宏内部做 `(utf8->cork dest)`，但**链接文本不做转换**，由调用方保证编码；
- 文档有标题节点时 `text` 是 `tree-import` 解析出的内部树，编码正确；
- 文档**没有标题节点**时（普通用户文档的常态），`text` 回退为 `(car x)`，
  即 `url->system` 返回的 UTF-8 原始路径，直接插入内部文档树（cork 编码），
  中文按 UTF-8 字节被当作 cork 字符渲染 → 乱码。
- 同段代码中括号里的文件名后缀（第 63 行）已做 `utf8->cork`，唯独链接文本漏了。

## 改动

- `TeXmacs/progs/doc/docgrep.scm` — 链接文本回退分支改为 `(utf8->cork (car x))`
- `TeXmacs/progs/doc/docgrep-test.scm` — 纯逻辑测试：中文文件名、无标题节点的文档，
  生成的搜索结果树中链接文本为 cork 转义串、不含原始 UTF-8 中文

## 验证

```bash
xmake b stem && xmake r docgrep-test
```

- `xmake r docgrep-test`：2 correct, 0 failed（还原旧代码验证过测试会变红，1 failed）
- 回归：`xmake r 4157_grep`（3 correct）、`xmake r 4157`（4 correct）均通过

## 同源隐患（未改，仅记录）

`build-src-search-results` 的 `($link (car x) (src-file-short-name (car x)))`
同样把 UTF-8 路径未经 `utf8->cork` 直接作链接文本，源码搜索命中中文文件名
时会乱码。本次仅修「搜索最近打开的文档」路径，源码搜索命中中文文件名的场景
罕见，待后续单独处理。
