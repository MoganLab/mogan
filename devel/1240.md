## 3 What

新建文档的 scratch buffer 从 `no_name_N.tmu` 改为 `draft_<时间戳>.tmu`:

- 命名:精确到秒(`draft_YYYYMMDDHHMMSS`),同秒冲突追加 `-N`
- 命名与标题规则全部在 scheme 层实现(`scratch-buffer-name` / `scratch-buffer-title`)
- 标题展示规则:
  - 本周:`Draft Monday 21:27:35` / 「草稿（周一21:27:35）」(统一时分秒)
  - 今年非本周:`Draft 08/02 22:43` / 「草稿（08/02 22:43）」
  - 去年及更早:`Draft 2025/08/02` / 「草稿（2025/08/02）」(只显示日期)
- 移除 C++ `url_scratch` / `url_numbered` 及 `url-scratch` glue;新增 `get-documents-path` glue
- `QTMAction::set_text` 改用显式 `utf8_to_qstring (herk_to_utf8 (s))`,不再走 `to_qstring` 编码猜测
- 标签页最大宽度上限 150 → 190,容纳中文标题
- scratch 构建产物加入 `.gitignore`(`3rdparty/curl-*/build-*/`、`3rdparty/curl-*/CMakeLists.txt`)

## 4 Why

`no_name_N` 序号命名无时间信息,标题只能显示「No name [N]」,无法区分多份草稿;
命名与标题逻辑散落 C++(`url_scratch` + `propose_title` 字符串解析),改为 scheme 层
集中实现后规则可读、可测,并支持中文本地化展示(herk 编码链路统一)。

## 5 How

- `make_new_buffer` 调 scheme `(scratch-buffer-name)`(返回系统路径字符串,时间来自
  `(liii time)` 的 `current-date`),scheme 异常或名字被占用时以毫秒时间戳兜底
- `propose_title` 对 `draft_*.tmu` 调 scheme `(scratch-buffer-title u)`,标题在
  scheme 内按 utf8 拼接(translate 结果先 `herk->utf8`)后整体 `utf8->herk` 返回
- 周/日判断用 srfi-19 的 `date->julian-day`(跨月正确)与 `date-week-day`
- `is_scratch`(按目录判断)保持不变,存量关闭清理、另存为等逻辑不受影响

### 6.5 测试不同时间的草稿(标题分支)

无需等待,手工造不同时间戳的草稿即可。文件模板(`~/文档/LiiiSTEM/no_name/`
下按时间戳命名,正文随意替换):

```bash
cat > ~/文档/LiiiSTEM/no_name/draft_<YYYYMMDDHHMMSS>.tmu <<'EOF'
<TMU|<tuple|1.1.0|2026.2.6-rc1>>

<style|<tuple|generic|chinese>>

<\body>
  测试草稿
</body>

<\initial>
  <\collection>
    <associate|page-screen-margin|false>
  </collection>
</initial>
EOF
```

启动 `xmake r stem`,文件 → 打开,进入 no_name 目录逐个打开,预期标签页:

| 草稿时间戳 | 预期标题(中文界面) | 分支 |
|---|---|---|
| 本周任意时刻(如今天) | `草稿（周一21:27:35）` | 本周,统一时分秒 |
| 今年非本周(如 2026-08-19,今天 08-24 周一) | `草稿（08/19 15:30）` | 今年非本周,MM/DD HH:MM |
| 去年(如 2025-08-19) | `草稿（2025/08/19）` | 往年,只显示日期不带时间 |
| 新建文档 | `草稿（周一HH:MM:SS）` | 本周分支,秒级命名 |

英文界面对应 `Draft Monday 21:27:35` / `Draft 08/19 15:30` / `Draft 2025/08/19`。

边界与踩坑:
- 周一起算:昨天若是周日,应走非本周分支(不是本周);
- `date->julian-day` 返回带 .5 的有理数(历元从正午起算),不取整会使周界
  偏移一天,把上周三误判进本周(见 `day-number` 的 `floor (+ jd 0.5)`);
- 中文标题须在 scheme 内按 utf8 拼接后整体 `utf8->herk`,Qt 侧
  `QTMAction::set_text` 统一 `herk_to_utf8`。

## 9 修复打开 中文.tmu 标题乱码(2026-08-25)

- What:打开文件名为中文的 `.tmu`(如 `中文.tmu`),标签页标题乱码。
- Why:`QTMAction::set_text` 统一按 herk 解码(`herk_to_utf8`),但文件名
  进入内部 `string` 时是原始 UTF-8 字节,逐字节走 herk 单字节映射被打乱。
  `set_text` 的行为保持不变,在 scheme 侧源头修正。
- How:`tabpage-display-title` 返回前统一 `utf8->herk`:中文文件名转成
  `<#..>` 转义;已是 herk 的草稿标题经 `utf8->herk` 不变(纯 ASCII 透传,
  已用真实二进制验证幂等)。
- 涉及文件:`TeXmacs/progs/texmacs/menus/tabpage-menu.scm`(一行)

## 9 修复打开 中文.tmu 标题乱码(2026-08-25)

- What:打开文件名为中文的 `.tmu`(如 `中文.tmu`),标签页/菜单标题乱码。
- Why:`QTMAction::set_text` 改成无条件 `herk_to_utf8` 后,文件名自带的
  原始 UTF-8 字节(每个 ≥0x80 字节)被按 herk 单字节映射表重编码成拉丁
  字符;此前 `to_qstring` 的编码判别(整体是合法 UTF-8 则透传)会放行。
- How:`qt_utilities` 新增 `herk_or_utf8_to_qstring`,沿用 `to_qstring` 的
  判别(合法 UTF-8 且非纯 ASCII/universal 直接透传),非 UTF-8 分支按
  herk 解码(scheme 侧 `utf8->herk` 的 `<#..>` 标题仍正确);
  `set_text` 改调该函数。`qt_utilities_test` 增加回归用例
  (`test_herk_or_utf8_to_qstring`:中文文件名透传、herk 标题解码、ASCII)。
- 涉及文件:`src/Plugins/Qt/qt_utilities.{hpp,cpp}`、
  `src/Plugins/Qt/QTMMenuHelper.cpp`、`tests/Plugins/Qt/qt_utilities_test.cpp`

## 10 scratch url（未命名 buffer）支持自动保存（2026-08-24）

### What

scratch buffer 加入 autosave 范围，除 Ctrl+S（仍弹另存为）和标签页标题外，
其余行为与普通文档一致。

### Why

scratch buffer 在磁盘上有真实路径（`documents/LiiiSTEM/no_name/`），
autosave 插件里「无磁盘路径、保存无意义」的跳过理由已过时（devel/1120）。
不自动保存导致未命名文档的编辑在崩溃/误关后丢失。

### How

- `TeXmacs/plugins/autosave/progs/autosave/plugin.scm`：`autosave-all` /
  `autosave-now` 移除 `(not (url-scratch? name))` 守卫，scratch 走
  `save-buffer-save name (list) "auto"` 原地写 no_name 文件。autosave 不经过
  `save-buffer-check-permissions`（scratch → save-as 弹窗只在该手动保存链路）。
- `TeXmacs/progs/texmacs/texmacs/tm-files.scm` 的 `save-buffer-save-file`：
  对 scratch 保留 `buffer-notify-recent`（no_name 文件进 recent 列表，方便找回），
  仅跳过 `remember-file-dialog-directory`（不破坏 devel/0912 的 scratch 另存为默认目录约定）。

副作用说明：autosave 成功后 scratch buffer 变为未修改，关闭时不再弹确认框，
no_name 文件保留在磁盘供会话恢复；save-as 时仍按既有逻辑删除旧 scratch 文件。

### 涉及文件

- TeXmacs/plugins/autosave/progs/autosave/plugin.scm
- TeXmacs/progs/texmacs/texmacs/tm-files.scm

### 测试

纯 scheme 改动。GUI 手动验证（用户负责）：新建未命名 buffer，编辑后等
autosave 间隔，确认 no_name .tmu 内容更新、recent 列表无 no_name 条目、
Ctrl+S 仍弹另存为、关闭重开后内容可恢复。

### 追加：移除 scratch 剩余两处特殊处理

- `tm-files.scm` `save-buffer-save-file`：删除 `(when (not (url-scratch? name)))`
  守卫，`remember-file-dialog-directory` 无条件调用。scratch 原地保存后 recent
  记录本就无条件（`buffer-notify-recent`），目录记忆无需再跳过。
- `plugin.scm` `auto-backup-format`：删除 `url-scratch?` 分支，直接
  `url-format`——no_name 文件是真实 .tmu 路径，可正常探测格式。

其余 7 处 `url-scratch?`（另存为默认名、强制 save-as、save-as 后清理 no_name
文件、关闭确认文案、加载后关干净 scratch、url-autosave 放行、choose-file 回退
目录）经逐一评审均维护「no_name = 暂存区」边界，保留不动。
