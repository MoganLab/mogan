5. 更新 `init-tikz.scm` 引入 `(binary gs)` 依赖
6. 补充单元测试覆盖 PNG 尺寸解析和 EPS bounding box 检测

## 6 Why

Mogan STEM 使用 Goldfish Scheme 重写的 TikZ 插件最初发送 EPS 文件给 Mogan，由 Mogan 内部调用 Ghostscript 将 EPS 转为 PNG 显示。当用户主目录或临时路径包含空格时（如 macOS 上 `/tmp/Jack Yansong Li/.lolly/...`），Mogan 依赖的 tbox 进程启动器 `tb_process_init_cmd` 不支持 `\ `（反斜杠空格）转义，导致 Ghostscript 执行失败，图片无法显示。

此外，当 TikZ 代码生成空图形（如 `\draw (0,0);` 产生 0x0 bounding box）时，Ghostscript 拒绝处理 `0x0` 页面大小，抛出 `configurationerror`，并触发 Mogan 的 `Error: bad image size` 弹窗。

## 7 How

### 7.1 插件端 EPS 转 PNG

参考 Gnuplot 插件的模式，在 `tm-tikz.scm` 中增加 `run-gs` 函数，使用 Ghostscript 将 EPS 转为 PNG：

```
gs -dQUIET -dNOPAUSE -dBATCH -dSAFER -sDEVICE=pngalpha
   -dGraphicsAlphaBits=4 -dTextAlphaBits=4 -r144
   -sOutputFile=output.png -f input.eps
```

`init-tikz.scm` 通过 launcher 将 `gs` 二进制路径作为第六个参数传入 Goldfish 脚本。

### 7.2 空 bounding box 检测

`eps-bbox-empty?` 读取 EPS 文件的 `%%BoundingBox:` 行，解析四个坐标值。若 `x2 - x1 <= 1` 或 `y2 - y1 <= 1`，则判定为空图形，直接输出提示文本，不再调用 gs。阈值设为 1 而非 0，是因为 `\draw (0,0);` 这类仅含一个点的图形经 dvips 转换后会产生 `1x1` 的 bounding box，Ghostscript 同样会拒绝处理并抛出 `configurationerror`。

### 7.3 极小 PNG 过滤

`png-size` 读取 PNG 文件 IHDR chunk 的宽高字段（大端 32 位整数）。`flush-image` 在发送图片前检查：若 PNG 宽或高小于等于 1，则输出提示文本，避免 Mogan 处理 1x1 图片时弹窗。

### 7.4 单元测试

在 `tm-tikz-test.scm` 中补充：
- `png-dimensions-from-bv`：通过构造已知 bytevector 测试 PNG 头解析
- `eps-bbox-empty?`：通过写临时 EPS 文件测试空/非空 bounding box 检测

### 7.5 run-gs 的 sh -c 包装

`run-gs` 最初直接裸调 `os-call`，在 Mogan 会话内触发 `tb_process_run` 时偶发 `configurationerror`。与 `run-latex` 和 `run-dvips` 保持一致，为 `run-gs` 也添加 `sh -c` 包装：

```scheme
(let* ((inner-cmd (string-append (goldfish-quote gs-bin) ...))
       (cmd (string-append "sh -c " (goldfish-quote inner-cmd))))
  (os-call cmd))
```

### 7.6 eps-bbox-empty? 阈值调整

实际测试发现 `\\draw (0,0);` 经 dvips 转换后生成的 EPS 的 `%%BoundingBox:` 为 `0 0 1 1`，并非严格的 `0x0`。Ghostscript 处理 `1x1` 页面时同样会抛出 `configurationerror`。因此将 `eps-bbox-empty?` 的判定阈值从 `<= 0` 放宽到 `<= 1`，并在单元测试中补充 `0 0 1 1` 用例。
