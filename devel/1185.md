# 1185 Chat 标签页初始化性能热点定位

## What

在 `chat_init`（见 `devel/1182.md`）的 bench_start/bench_end 之间插入
`chat_init: xxx` 子阶段计时日志，定位 Chat 标签页初始化热点。

## Why

点击 Chat 标签页到渲染完成的总耗时已知（`chat_init`），需要拆分到各初始化
阶段才能定位瓶颈。

## How

子阶段日志全部由 `QTChatTabWidget::isInitBenchPending ()` 门控——只有点击
Chat 标签页触发的初始化窗口内才打印，避免新建会话、dock 模式等非点击路径
误报。命名计时器相互独立，可嵌套。

- `src/Plugins/Qt/qt_tm_widget.cpp`（`sync_chat_tab_mode`）：
  - `chat_init: sync_chat_tab_mode`：整个显示分支（隐藏编辑器、
    update_visibility、show + focus）
  - `chat_init: createView`：首次创建 chatContentWidget
- `src/Plugins/Qt/qt_chat_controller.cpp`（`createView`）：
  - `chat_init: load chat modules`：`use-modules (llm chat-loader)` +
    `chat-persist-load-all`
  - `chat_init: buildDisplayInfos`：会话显示数据构建
  - `chat_init: new QTChatTabWidget`：View 构造
  - `chat_init: activate session`：激活初始会话（`activateSession` /
    `ensureNewConversation`）
- `src/Plugins/Qt/qt_chat_tab_widget.cpp`：
  - `chat_init: setup_left_sidebar` / `chat_init: setup_right_content`：
    `QTChatTabWidget` 构造的左右两区
  - `chat_init: new ChatSidebar`：侧边栏构造（按会话数创建 item）
  - `chat_init: message widget` / `chat_init: input widget`：
    `ChatConversationPanel::setup_ui` 中两个内嵌 TeXmacs 编辑控件的创建

`chat_init` 总耗时减去各子阶段之和，即为点击后的 scheme 命令分发与 Qt
布局/绘制等未插桩部分的开销。

## 追加：update_menus 插桩

实测 chat_init 866 ms 中 `update_menus` 两次全量重建合计 327 ms，为最大
热点。对 `edit_interface_rep::update_menus (int mask)` 插桩：

- 入口无条件打印 `[update_menus] buffer=<url> mask=<int>`，确认两次调用的
  触发 buffer（怀疑是聊天页内嵌编辑器 buffer 绕过了 `is_chat_tab_buffer`
  守卫）与重建类别（mask 位定义见 `src/Edit/editor.hpp`：MENU_MAIN=1
  ICONS_MAIN=2 ICONS_MODE=4 ICONS_FOCUS=8 ICONS_EXTRA=16 TAB_PAGES=32
  NOTIFICATION=64 SIDE_TOOLS=128 MENU_ALL=255）。
- 每类重建包一层 `update_menus: xxx` 子计时：`menu_main` /
  `icons0-main` / `icons1-mode` / `icons2-focus` / `icons3-extra` /
  `icons4-tabs` / `notification` / `side-tools` / `footer+tail`
  （`set_footer` + MENU_ALL 尾部的 drd_update/cache_memorize/偏好保存）。

涉及文件：`src/Edit/Interface/edit_interface.cpp`

## 追加：chat tab 跳过模式工具栏重建

实测 `update_menus: icons1-mode` 单次 99 ms。`ICONS_MODE` 的守卫条件原本
只有 `!is_startup`，与其他几类（`MENU_MAIN`/`ICONS_MAIN`/`ICONS_FOCUS`/
`ICONS_EXTRA` 均有 `!is_chat`）不一致。chat tab 隐藏模式工具栏，重建结果
不可见，纯属浪费。

修复：`edit_interface.cpp` 中 `ICONS_MODE` 守卫补上 `!is_chat`。切回文档
buffer 时会以文档 buffer 触发 `update_menus`，模式工具栏照常重建，不受
影响。

## 优化效果总结

| 指标 | 优化前 | 优化后 | 变化 |
|---|---|---|---|
| `chat_init` 总耗时 | 866 ms | ~720 ms（预期） | 约 -140 ms |
| chat-tab buffer 触发的 `update_menus` | 118 ms | 14 ms | -104 ms |

有效修复一项：`ICONS_MODE` 守卫补 `!is_chat`——chat tab 隐藏模式工具栏，
单次 99-124 ms 的重建不可见，纯属浪费。切回文档 buffer 时以文档 buffer
触发 `update_menus`，模式工具栏照常重建。

追加修复：`TAB_PAGES`（icons4-tabs）守卫同样补 `!is_chat`——点击 Chat
标签时 tab 条选中态由 `QTMTabPage` 原生处理，scheme 侧
`(link texmacs-tab-pages)` 重建（~10 ms）多余。至此 chat-tab buffer 的
`update_menus` 整体成为 no-op。

（注：484 ms 的实测值包含了已回退的内嵌 buffer 守卫；仅保留
`ICONS_MODE` 修复后预期约 720 ms，以复测为准。）

剩余热点：`activate session` 88 ms（chat-persist 读盘 + 排版）、
`load chat modules` 47 ms（llm 插件 scheme 模块加载，可 idle 预加载）、
sync→paint 残差 ~270 ms（Qt 布局/绘制 + kbd-map 懒注册 ~50 ms）。
