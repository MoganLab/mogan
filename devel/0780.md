## Stage 2：无 UI 的 tmu→png CLI（`cli_frontend`） - #4091

### What
- 新增无 UI 前端 `src/Plugins/CLI/`（`cli_gui.cpp`/`cli_widget.hpp`/`cli_simple_widget.hpp`）：仿 `im_gui.cpp` 去掉全部 GLFW/OpenGL，实现 `gui.hpp` 契约与 widget 工厂桩；`simple_widget_rep` 仅声明 editor 重写的 `handle_*` 虚函数；`gui_start_loop` 只排空 `-x`/`exec_delayed` 命令队列（靠 `(quit-TeXmacs)`→`tm_server_rep::quit`→`exit(0)` 终结，刻意不驱动 interpose，避免对无窗 editor 跑 `apply_changes` 而段错误）。渲染复用现有 mupdf 管线（`make_raster_image`），不链任何 UI 库。
- 构建：新 xmake 选项 `cli_frontend`（`xmake/options.lua`）；`xmake/targets/libmogan.lua` 三处 `cli_frontend` 分支（依赖/包/插件文件）+ 定义 `MOGAN_CLI`；`xmake/targets/stem.lua` 在 `cli_frontend` 下不拉 glfw，macOS 显式链 `Cocoa`/`IOKit`（`Plugins/MacOS` 需要）。
- 适配核心：`editor.hpp` 与 `src/Texmacs/Window/tm_button.cpp` 把 `simple_widget_rep` 的 include 改三路（Qt/CLI/ImGui）；`src/Typeset/Concat/concat_graphics.cpp` 把 `graphics-notify-extents`（编辑器 UI 通知，经菜单链 lazy-load）在 `MOGAN_CLI` 下条件编译排除。

### 如何构建 / 测试
```bash
xmake f --qt_frontend=n --cli_frontend=y -m debug --yes
xmake b stem
bin=build/macosx/arm64/debug/MoganSTEM
TEXMACS_PATH=$PWD/TeXmacs "$bin" -x \
  '(load-buffer "<in.tmu>") (render-doc-to-png "<in.tmu>" "<out.png>" 2.0) (quit-TeXmacs)'
```
- CLI 为裸二进制，无 `.app`，无需重签；`otool -L` 确认无 Qt/ImGui/glfw。
- 回归测试：`xmake r 0780`（`TeXmacs/tests/0780.scm`）。
- 批量冒烟：`test_recursive.sh`（一次进程渲染全部 `.tmu`，逐个 `(catch ...)` 隔离失败）。

### 已知限制（后续阶段）
- 235/239 个 `.tmu` 可渲染。4 个失败：① 3 个含图像文档在 `tmimage.scm` 的 SVG 转换路径 `string-load` 收到 `#f`（无头图像转换子进程问题）；② 1 个 java 文档 `in-prog-java?` 未绑定（CLI 的 `plugin-initialize` 未加载 java）。
- CLI 不解析 `-headless`（该标志仅 QTTEXMACS；CLI 本就无 GUI，不需要）。
