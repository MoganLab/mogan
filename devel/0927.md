# 0927 帮助->版本弹窗 ESC 关闭在 Windows 下失效

## 2026/08/20 修复「帮助 -> 版本」弹窗在 Windows 下按 ESC 无法关闭

### What

0925 已在 macOS 上修复「帮助 -> 版本」弹窗按 ESC 无法关闭的问题，但合并后在
Windows 环境下仍不生效。本任务补全 Windows 路径，使 ESC 在 Windows 下也能正常
关闭该弹窗（取消语义不变），同引擎的其它 exec 型 QML 弹窗一并受益。

### Why

0925 的兜底过滤器 `QmlDialogEscFilter` 装在 `QQuickWidget` 上，依赖 ESC 按键事件
先到达 `QQuickWidget`。macOS 上 `qw->setFocus()` 后焦点确实落到 QML 视图，事件
发到 `QQuickWidget`，兜底生效。

Windows 下无边框 `Qt::Tool` 宿主窗口的焦点行为不同：`QQuickWidget` 没有真正获得
焦点，ESC 按键事件直接发到宿主 `QDialog`。由于过滤器只装在 `QQuickWidget` 上，
宿主收不到过滤逻辑，兜底失效，ESC 仍被静默吞掉。

### How

1. 把 `QmlDialogEscFilter` 从 `QQuickWidget` 移到**宿主 `QDialog`** 上安装：
   - 无论 ESC 先到达 `QQuickWidget` 还是 `QDialog`，兜底逻辑都能拦截。
   - 保持原有语义：仅在 QML 场景无 `activeFocusItem` 时 `reject()` 宿主，不抢占
     各弹窗自身的 `onCancel`。
2. `run_qml_dialog` 在 exec 前给 `QQuickWidget` 设置
   `setFocusPolicy(Qt::StrongFocus)` 并 `setFocus()`：
   - 尽量让 QML 正常链路（`DialogShell` → `Keys.onEscapePressed` →
     `closeBridge.cancel()`）继续工作；Windows 焦点落到宿主时由兜底覆盖。
3. 回归测试 `test_version_escape_fallback_without_focus` 同步改为向宿主
   `QDialog` 发送 ESC，覆盖 Windows 下焦点落在宿主的场景。
