xmake build -y qml_load_test

Manual verification:

1. Open the Select Print to file workflow.
2. Select a destination with Browse, including a path containing non-ASCII
   characters.
3. Export both PDF and PostScript, then verify the chosen file is created.
4. Verify cancellation, a page range, and invalid page bounds.
5. Open File > Print to file and verify that it still opens the native save
   dialog directly.

## 2026/08/04 QML Print-To-File Dialog

### What

Added a QML dialog for the Select Print to file interaction: PDF and
PostScript output, page selection, native destination selection, and keyboard
shortcuts. The File > Print to file menu entries keep their original direct
native save dialog.

### Why

The Select Print to file workflow did not provide a single QML surface for
output format and page selection. The QML bridge also needs to preserve native
Windows paths when sending a selected destination back to Scheme.

### How

The QML dialog returns named fields through `QmlDialogBridge`, while the
dedicated `PrintToFileBridge` owns the native save-file picker. Scheme converts
the selected system path to a Mogan `url` before calling the existing printing
glue. The C++ bridge serializes the file path as UTF-8, matching the existing
Qt file chooser, while ordinary dialog text keeps its normal text conversion.
The dialog validates page bounds, uses a clipped inner field to display long
paths without clipping its border, and reuses `TabBar` for page selection. The
matching panel in `qml-dialog.html` documents the interaction contract.
