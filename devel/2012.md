# [2012] 更新 goldfish 版本到 v18.11.13

## What

新版本 goldfish（v18.11.13）重构了 `(liii path)`，把路径解析对齐到 Python `pathlib` 语义（详见 goldfish 仓 `devel/1004.md`）。本次任务是评估这次更新是否会让 mogan 仓库内调用 goldfish path API 的代码失效，若有破坏性调用则修复，否则记录评估结论、不改代码。

**结论：mogan 仓库内不受影响，无需改动。** 详见 How。

## Why

`path.scm` 的 path 重构包含多处语义变化，其中最显著的一处是**破坏性改动**：

- 旧 `(path-root)` 是无参静态构造器，返回当前平台的根分隔符（`"/"` 或 `"\\"`）。
- 新 `(path-root p)` 变成 `pathlib.PurePath.root` 字符串访问器，接受一个 path 参数，返回其 root 字段（有根返回分隔符、无根返回 `""`）。

旧式 `(path-root)` 无参调用在新版会因缺少参数报错。因此需要确认 mogan 内没有这类调用。

其余改动（`path-absolute?` 在 Windows 下 `\foo` 改为非绝对、`path-join` 改 record 累加、`path-parts` 加 anchor 首元素、UNC/drive 解析重构等）都是内部实现变化，对外签名兼容，但行为只对 Windows UNC/盘符路径生效，需确认调用方不依赖旧行为。

## How

### 1. 定位调用方

mogan 仓库内 `(liii path)` 的消费方仅 3 个（均在 `TeXmacs/plugins/goldfish/goldfish/liii/`）：

- `logging.scm`：`path-parent` / `path-exists?` / `path->string`
- `njson.scm`：`path-read-text` / `path-write-text`
- `subprocess.scm`：`path?` / `path->string` / `path` 构造器

### 2. 逐项核对破坏性改动

- **`path-root` 语义反转**：goldfish 内部除 `path.scm` 自身定义/export 外无任何 `(path-root)` 调用。`TeXmacs/progs` 下出现的 `path-root` / `xpath-root` 是 guile 方言里不相关的局部符号——mogan 主仓用 guile，goldfish 是独立 scheme 实现，两者不共享 `(liii path)` 模块，不受影响。
- **上述 3 个消费方用到的 API**（`path-parent` / `path-exists?` / `path->string` / `path-read-text` / `path-write-text` / `path?` / `path` 构造器）签名与语义在本次重构中均保留兼容（goldfish 1004.md 标 🟢）。
- **`path-parts` 加 anchor 首元素**：若有代码把 `path-parts` 结果当纯段拼接会出问题，但 mogan 内没有调用 `path-parts`。
- **行为变化仅对 Windows UNC/盘符路径生效**，而这 3 个消费方处理的都是普通 posix 路径（日志目录、json 文件、子进程参数），不触发 Windows 分支。

### 3. 范围说明

goldfish 自带工具链（如 `tools/fmt`）若在 goldfish 仓侧调用 path API，需在 goldfish 仓内自查（参考 1004.md 提到的 `tools/fmt/liii/goldfmt-rule.scm`），不在 mogan 仓库范围内。
