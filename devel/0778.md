# [0778] 协作编辑：apply_remote 后标记可视区域重绘

## 相关 PR
- [0774.md](0774.md) - 远端操作不执行重排版和渲染（本任务在其基础上补回「可视区域重绘标记」）
- [0775.md](0775.md) - 远端执行操作时设 user_active 为 false 防止触发滚动

## What
在 `apply_remote` 末尾，对端编辑改了 body 后，把当前可视区域标脏请求重绘。

## Why
0774 为降低多人协作卡顿，删掉了 `apply_remote` 末尾的 `typeset_invalidate_all()` 与
`send_invalidate_all(this)`，只保留 `notify_change(THE_TREE)`。但 `notify_change(THE_TREE)` 只置脏标志，
真正的 `typeset(...)` 要等下一帧 `apply_changes` 才惰性执行。下一帧 `apply_changes` 中，只会 invalidate typeset 有改动的地方，而不会 invalidate 其他地方。

现在，新增了 invalidate_visible 方法，在 apply_remote 末尾 exec_delayed invalidate ，到下一帧直接 invalidate 整个可见区域，从而残留的问题。

## How
新增虚方法 `invalidate_visible()`，封装 `edit_interface_rep` 中成熟的
`update_visible()` + `invalidate(vx1,vy1,vx2,vy2)` 模式（与 `apply_changes` 内部一致），供
`edit_modify_rep::apply_remote` 跨 mixin 调用。

## 涉及文件
- `src/Edit/editor.hpp` - 新增纯虚 `invalidate_visible()`
- `src/Edit/Interface/edit_interface.hpp` - 新增 `invalidate_visible() override` 声明
- `src/Edit/Interface/edit_interface.cpp` - 实现 `invalidate_visible()`（`update_visible` 后取 vx1..vy2 标脏）
- `src/Edit/Modify/edit_collab.cpp` - `apply_remote` 末尾在 `notify_change(THE_TREE)` 后调用
  `invalidate_visible()`，并修正已过时的 debug 日志
- `glue_editor.lua` - 新增 `invalidate-visible`

## 如何测试
```
xmake f --loro=yes
xmake b stem
xmake r stem
```
打开两个客户端，进行协作编辑，检查远端编辑应用之后是不是正常渲染（更新、且没有残留）。
