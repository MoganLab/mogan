# [0778] 协作同步根治病灶：buffer 由 Loro TreeID 身份对账驱动（替换位置型 diff）

## 1 背景（Why）

协作同步把编辑器 buffer 树镜像进一个 Loro CRDT「shadow」文档。病根在于桥接层
**两个方向都拿「位置」当「身份」**，而并发 merge 后 buffer 顺序 ≠ shadow 顺序：

- **下行（shadow→buffer）**：`diff_walk` 是位置型树 diff（前缀/后缀匹配）。并发
  merge 重排子节点后，删除/插入会算到**错的下标**，把对端刚到达的内容删掉。
- **上行（buffer→shadow）**：`mirror_remove` 等用 `node_children(pid)[pos]` 把
  buffer 下标当 Loro 下标去删。错位时删掉的是**别的 TreeID**，且这条删除是合法
  CRDT op，会广播到**所有端**销毁该节点。

**实测复现**：两端并发编辑同一片公式，B 的 `remove X[2]` 经位置型镜像删掉的恰是
A 刚敲的 `<alpha>`（带 A 的 TreeID），CRDT 把它同步回 A，A 的位置型 diff 再把它
从 A 的 buffer 删掉 → 末行 `<alpha>=1` 被吞，只剩 `- `。**与时钟无关**（Loro 按
`peer:counter` 身份合并，墙钟偏差只延迟投递）。

## 2 方案（How）

**核心思想**：让 TreeID 成为整条桥的唯一身份，跨 merge 之后**绝不信任位置**。
维护不变式 **buffer ≡ shadow（内容 + 子节点顺序 + TreeID 绑定完全一致）**：

- 每次远端 import 后，用**身份对账器（reconciler）**把 buffer 精确对齐到 shadow
  的权威合并态——按 TreeID 匹配、**复用存活节点的 `tree_rep*`**（保住光标/IP 稳定）。
- 不变式一旦成立，**现有位置型 mirror 自动变安全**（位置型只在 buffer≡shadow 时
  才对；reconciler 保证每次远端 apply 后立即重建一致，本地编辑又在一致状态下做
  位置型镜像，归纳可证全程一致）。单线程事件循环保证 import 与 reconcile 之间
  不会插入本地编辑。

本任务落地 **Phase 1（对账器）**，它是根治关键，且通过维持不变式让上行位置型
mirror 也变安全。Phase 2（上行按身份镜像，防御纵深）、Phase 3（原生 Loro 事件流
FFI，纯性能）留作后续。

### 对账器算法（替换 `diff_walk`）

1. 用 `mogan_loro_doc_to_ir_with_ids` 建**带 TreeID 的 after 树**，填一张**独立的
   after_id_map**（`tree_rep* → TreeID`，不污染 shadow 的 id_map）。
2. `reconcile_node(b, a, base)` 递归：
   - 原子 vs 原子：文本按偏移 diff（单身份，安全）。
   - 复合 vs 复合且同 label：`reconcile_children` 按 TreeID keyed 对账子节点。
   - 否则（同 TreeID 但类型/label 变）：`mod_assign`（罕见）。
3. `reconcile_children(b, a, base)`：
   - **删除**：buffer 子节点 TreeID ∉ after_ids → 按**实时下标** `mod_remove`。
   - **新增**：after 子节点不在 buffer → 建子树 `mod_insert`。
   - **更新**：两边都有 → 递归 `reconcile_node`。
   - **排序**：最终顺序 = after 权威顺序，复用存活 rep（remove+insert 同 rep 移动）。
   - 顺手把 shadow 的 id_map 增量改对（存活保持/插入登记/删除摘除），取代脆弱的
     位置型 `sync_walk`。
   - mod 按顺序发射，下标始终相对实时工作副本，逐条 `raw_apply` 到活跃 buffer 合法。

### 实现要点（落地时确认）

- `to_tree_with_ids`：复用 `decode_id_node` 解出带 TreeID 的 after 树，填
  `after_id_map`（独立映射，不污染主 `id_map`/`rev_id_map`）。
- `reconcile_children`：四阶段——匹配（buffer 子按 id_map 对 after 子按
  after_id_map，同 TreeID 配对）→ 删除远端已删（倒序）→ 插入新增（after 权威
  下标处，并登记新 rep 身份）→ 排序（**按 after 下标从 cur 实际位置移动复用
  rep**，关键修正：排序必须查 `cur` 的实际下标而非近似游标，否则并发新增时
  越界）→ 对共有递归。
- `remote_diff_mods` 经 `diff_from_current` 自动走对账；`apply_remote` 不动。

### 已知限制 / 环境说明

- 多 peer 各自 `import_and_build` 同一快照时 TreeID 血统不同（各自 peer），CRDT
  对「并发 insert 与 delete」是保留语义——`to_tree_with_ids` 会同时含并发 op，
  reconcile 按身份保留并发节点（这正是修复目标：不误删）。「删除收敛」需两端
  已同步到同一棵树（真实协作即如此），属 Loro 语义，非对账缺陷。
- 本地沙箱下 `xmake b stem` 受 Qt neon 特性与 `~/.xmake` ca-certificates
  package.lock 阻塞（与改动无关；`libmoebius`/`libmogan` 编译全过，
  `reconcile_walk`/`to_tree_with_ids` 已入 `libmoebius.a`，编辑器经
  `edit_collab.cpp:129 → remote_diff_mods → reconcile` 链接）。正常环境可直接
  `xmake b stem` + `xmake r 0759` 冒烟。

### 追加修复（commit 3/4/5）：JOIN 时 buffer 结构引发的非法 mod 崩溃

JOIN 远端整文档先到时，逐项身份对账会产生应用到 et 时非法的 mod（`remove +
空/失配 insert` → `can_insert` 返回 false → `TM_FAILED`）。经 `RECONDBG` /
`apply_remote` 诊断逐层定位，分两类守卫：

1. **异构 buffer（label 不同）**：本端 buffer 可能是空 stub / 多文档容器（如
   CONCAT(空 document,...)，label 与远端 body 的 DOCUMENT 不同）。
   `diff_from_current` 仅当 `buffer` 与 `after` **同 label**（同构内容容器
   DOCUMENT/CONCAT）才走 `reconcile_walk`，否则整树 `mod_assign`。
2. **JOIN 首帧（同 label 但 buffer 根无 CRDT 血统）**：本端 buffer 是空 stub
   （`document(空 para)`），本地从未 seed，其根**不在 id_map**。逐项对账会「删
   空 stub 的 para + 插远端 para」，应用到 et 时 et[2] 先删空再插，触发崩溃。
   追加守卫：`!has_id(buffer)`（JOIN/空 stub）时直接整树 `mod_assign`（一次性
   替换，后续增量再走对账）。正常协作 buffer 根始终在 id_map（seed/同步过），
   不受影响。

新增「CONCAT 容器回退 assign」用例。26/26 用例、112/112 断言全过。
