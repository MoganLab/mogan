# 200_61 Telemetry（埋点）系统

## 如何测试

### 1. 编译与启动
```bash
xmake config --is_community=false
xmake b stem
xmake r stem
```

### 2. 事件埋点测试

#### MAGIC_PASTE 事件
打开任意文档，分别在以下场景触发魔法粘贴（`Ctrl+Shift+V` / `编辑 -> 智能粘贴`）：
- 剪贴板为图像时触发 OCR 粘贴
- 代码模式（`prog`）下粘贴代码
- 数学模式（`math`）下粘贴公式
- 文本模式下粘贴普通内容

查看终端输出，确认出现 `[telemetry] track: MAGIC_PASTE props=...` 的 `qDebug` 日志，且 `mode` 分别为 `image` / `prog` / `math` / `text`。

#### OCR_RECOGNIZE 事件
打开任意文档，插入图片后右键选择「OCR 识别」，确认终端输出 `[telemetry] track: OCR_RECOGNIZE`。

### 3. 数据落盘测试
触发若干事件后，等待约 60 秒（或重启 Mogan），检查本地 jsonl 文件：

```
$TEXMACS_HOME_PATH/system/telemetry/telemetry-pending.jsonl
```

确认文件中每行为一个 JSON 对象，包含 `event_type`、`timestamp_ms`、`distinct_id`、`session_id`、`event_id`、`app_version`、`device_id`、`platform`、`language`、`timezone`、`properties` 等字段。

### 4. 社区版兼容性
- 非社区版（`!IS_COMMUNITY`）编译时，确认日志正常输出，事件正常落盘。
- 社区版编译时，确认无日志输出、无编译错误，且 `telemetry_track` 为空操作。

## 2026/05/06 实现说明

### What

本 PR 为 Mogan 引入了一套完整的 Telemetry（埋点）系统，支持事件追踪、内存缓冲、周期性落盘，并已在魔法粘贴和 OCR 识别两个功能点完成接入。

#### 新增文件

**src/Mogan/Telemetry/telemetry.hpp**
- C++ 胶水层，提供 `telemetry_track` 两个重载。
- 非社区版：输出 `qDebug` 调试日志，并调用 Scheme 的 `track-event`。
- 社区版：空操作，避免在社区版中泄露埋点逻辑。
- **修正**：`eval_scheme` 返回 `tmscm`（指针类型），需用 `tmscm_to_object` 转换为 `object` 后再传给 `call`，否则链接器会尝试匹配未定义的 `object(void*)` 构造函数。

**TeXmacs/progs/telemetry/telemetry-utils.scm**
- 工具库：定义 telemetry 目录结构、文件路径、锁路径。
- 生成设备 ID、会话 ID、应用版本、平台、语言、时区等上下文信息。
- 提供 `telemetry-make-event` 构造标准事件结构。
- **修正**：从 R7RS `define-library` 改为 TeXmacs 模块系统 `(texmacs-module ...)`，因为 Mogan 使用 TeXmacs 自有的模块系统（基于 S7 Scheme），`define-library` 会导致模块解析失败和运行时 `unbound variable` 错误。
- **修正**：`telemetry-home-path` 改为使用 TeXmacs 内置的 `(get-texmacs-home-path)`，避免在 macOS 上回退到错误的 `~/.local/share/Mogan`（实际应为 `~/.TeXmacs`）。
- **修正**：`getenv` 改为 `system-getenv`（TeXmacs C++ glue 函数名）。

**TeXmacs/progs/telemetry/telemetry-track.scm**
- 事件追踪核心：提供 `track-event` 函数，将事件写入内存队列 `*telemetry-event-queue*`。
- 队列长度达到 `telemetry-buffer-size`（默认 10）时自动触发 `telemetry-flush`。
- 提供 `telemetry-flush-if-needed` 供外部调用。
- **修正**：同上，从 `define-library` 改为 `(texmacs-module ...)`，使用 `define-public` 仅导出需要对外暴露的符号。
- **修正**：`track-event` 内增加 `display` 输出 `[telemetry] scheme track: ...`，使 Scheme 端埋点也有可见日志，便于调试确认事件已入队。

**TeXmacs/progs/telemetry/telemetry-flush.scm**
- Flush 核心逻辑：基于目录的分布式锁（`mkdir` + `owner.json`）实现多进程安全。
- 锁超时机制（30 秒），防止死锁。
- 将队列中的事件以 JSON Lines 格式追加写入 `telemetry-pending.jsonl`。
- 提供 `telemetry-read-pending`、`telemetry-write-pending`、`telemetry-truncate-pending` 等底层 IO 函数。
- **修正**：同上，从 `define-library` 改为 `(texmacs-module ...)`，内部辅助函数使用 `define`，仅导出 API 函数。

**TeXmacs/progs/telemetry/init-telemetry.scm**
- 初始化模块：启动时根据 `autosave` 偏好设置判断是否启用 telemetry。
- 注册周期性 delayed 任务，每 60 秒自动 flush 一次内存队列。
- **修正**：同上，从 `define-library` 改为 `(texmacs-module ...)`，与 TeXmacs 启动流程兼容。

#### 修改文件

**xmake.lua**
- 在 `libmogan` 目标的 include 路径中新增 `src/Mogan/Telemetry`。

**TeXmacs/progs/init-research.scm**
- 启动流程末尾引入 `telemetry-track` 和 `init-telemetry` 模块，调用 `(init-telemetry)`。

**TeXmacs/progs/generic/generic-edit.scm**
- 模块 `:use` 中新增 `(telemetry telemetry-track)`。
- `kbd-magic-paste` 四个分支（image / prog / math / text）分别调用 `(track-event "MAGIC_PASTE" '(("mode" . "xxx")))` 上报事件。

**src/Plugins/Qt/QTMImagePopup.cpp**
- 引入 `telemetry.hpp`。
- OCR 识别成功时调用 `telemetry_track("OCR_RECOGNIZE")` 上报事件。

### Why

1. **数据需求**：魔法粘贴和 OCR 是 Mogan 的核心卖点，需要追踪用户实际使用频率和模式分布，以指导产品迭代。
2. **统一架构**：将埋点系统抽离为独立模块（`TeXmacs/progs/telemetry/`），便于后续在其他功能点快速接入，而不侵入业务代码。
3. **多进程安全**：使用目录锁（`mkdir` 原子性）而非文件锁，兼容不同操作系统的文件系统语义，防止多个 Mogan 实例同时写入导致数据损坏。
4. **社区版隔离**：通过 `IS_COMMUNITY` 宏在编译期完全剔除埋点逻辑和调试日志，确保社区版零开销、零隐私风险。
5. **统一日志入口**：C++ 的 `telemetry_track` 是所有埋点的最终入口，在此加 `qDebug` 可覆盖 Scheme 和 C++ 两端的调用，避免在每个调用点重复加日志。

### How

- **事件构造**：`telemetry-make-event` 统一生成包含时间戳、设备 ID、会话 ID、平台、语言等上下文的标准事件结构，事件属性通过 `properties` 字段扩展。
- **内存缓冲**：`track-event` 将事件写入内存队列，达到阈值后自动 flush，减少磁盘 IO 频率。
- **周期性刷新**：`init-telemetry` 注册 delayed 任务，每 60 秒检查并 flush 队列，避免事件长期驻留内存。
- **数据格式**：落盘文件采用 JSON Lines（`.jsonl`）格式，每行一个独立 JSON 对象，便于后续流式读取和上传。
- **C++ 与 Scheme 协作**：C++ 层负责编译期隔离和调试日志；Scheme 层负责事件构造、缓冲、落盘和业务侧埋点调用。
