# 200_61 Telemetry（埋点）系统

## 如何测试

### 1. 编译与启动
```bash
xmake config --is_community=false
xmake b stem
xmake r stem
```

### 2. Telemetry 开关
Telemetry 默认开启。可通过 Scheme 会话关闭：
```scheme
(set-preference "telemetry" "0")
```
或重新开启：
```scheme
(set-preference "telemetry" "1")
```

### 3. 事件埋点测试

#### MAGIC_PASTE 事件
打开任意文档，分别在以下场景触发魔法粘贴（`Ctrl+Shift+V` / `编辑 -> 智能粘贴`）：
- 剪贴板为图像时触发 OCR 粘贴
- 代码模式（`prog`）下粘贴代码
- 数学模式（`math`）下粘贴公式
- 文本模式下粘贴普通内容

查看终端输出，确认出现 `[telemetry] scheme track: MAGIC_PASTE` 的日志。

#### OCR_RECOGNIZE 事件
打开任意文档，插入图片后右键选择「OCR 识别」，确认终端输出 `[telemetry] scheme track: OCR_RECOGNIZE`。

### 4. 运行时开关测试
启动后通过 Scheme 会话关闭 telemetry：
```scheme
(set-preference "telemetry" "0")
```
触发魔法粘贴或 OCR 识别，确认终端**不再输出** `[telemetry] scheme track: ...` 日志。重新开启：
```scheme
(set-preference "telemetry" "1")
```
再次触发事件，确认日志恢复输出。

### 5. 数据落盘测试
触发 10 次以上埋点事件（或等待 60 秒周期性 flush），查看终端输出：

```
[telemetry] flushed N event(s) to /Users/.../.TeXmacs/system/telemetry/telemetry-pending.jsonl
```

也可在关闭软件前确认退出 flush：

```
[telemetry] flushed N event(s) to /Users/.../.TeXmacs/system/telemetry/telemetry-pending.jsonl
```

检查本地 jsonl 文件，确认每行为一个 JSON 对象，包含 `event_type`、`timestamp_ms`、`distinct_id`、`session_id`、`event_id`、`app_version`、`device_id`、`platform`、`language`、`timezone`、`properties` 等字段。

### 6. 配置加载测试

#### 环境变量生效
启动前设置环境变量：
```bash
export MOGAN_TELEMETRY_BUFFER_SIZE=5
export MOGAN_TELEMETRY_FLUSH_INTERVAL=30000
xmake r stem
```

启动后确认终端输出：
```
[telemetry] Loaded config: ((buffer-size . 5) (flush-interval . 30000))
Telemetry enabled
```

触发 5 次埋点事件（此前默认 10 次），确认队列提前触发 `telemetry-flush` 落盘。

#### 无效值容错
设置非法值后启动：
```bash
export MOGAN_TELEMETRY_BUFFER_SIZE=abc
export MOGAN_TELEMETRY_FLUSH_INTERVAL=-1
xmake r stem
```

确认终端输出警告，且使用默认值：
```
[telemetry] Invalid MOGAN_TELEMETRY_BUFFER_SIZE: abc
[telemetry] Invalid MOGAN_TELEMETRY_FLUSH_INTERVAL: -1
Telemetry enabled
```

埋点行为与未设置环境变量时一致（buffer-size=10, flush-interval=60000）。

#### 部分配置加载
仅设置其中一个变量：
```bash
export MOGAN_TELEMETRY_BUFFER_SIZE=3
unset MOGAN_TELEMETRY_FLUSH_INTERVAL
xmake r stem
```

确认输出仅包含已加载的配置项：
```
[telemetry] Loaded config: ((buffer-size . 3))
```

### 7. 兜底措施测试

#### 内存队列上限
连续触发超过 1000 次埋点事件，确认终端输出：
```
[telemetry] Dropped N stale event(s)
```
或队列长度始终不超过 1000（可通过 Scheme 会话检查 `(length *telemetry-event-queue*)`）。

#### 文件大小上限
制造大量事件使 jsonl 文件接近 10MB，确认终端输出：
```
[telemetry] File size limit (10MB) reached. Dropping old events, keeping N new event(s).
```
并检查 jsonl 文件大小不超过 10MB。

#### 事件老化
在 Scheme 会话中手动构造一条超期事件并触发 flush：
```scheme
(set! *telemetry-event-queue*
  (list (telemetry-make-event "OLD_EVENT" '())))
;; 修改 timestamp_ms 为 8 天前
(set-car! (cdaar *telemetry-event-queue*) (- (telemetry-now) 691200000))
(telemetry-flush)
```
确认终端输出：
```
[telemetry] Dropped 1 stale event(s)
```
且 jsonl 文件中不包含该事件。

#### 写入失败保护
在磁盘满或文件权限不足的场景下触发 flush（如将 telemetry 目录设为只读），确认：
- 终端输出 `[telemetry] write error: ...`
- 终端输出 `[telemetry] Flush failed, keeping events in memory queue`
- 内存队列中事件未被清空，下次 flush 时仍有机会写入

### 8. 社区版兼容性
- 非社区版（`!IS_COMMUNITY`）编译时，确认事件正常入队、落盘。
- 社区版编译时，确认无日志输出、无编译错误，且 `telemetry_track` 为空操作。

## 2026/05/06 实现说明

### What

本 PR 为 Mogan 引入了一套完整的 Telemetry（埋点）系统，支持事件追踪、内存缓冲、周期性落盘、退出 flush、环境变量动态配置、文件大小限制、事件老化清理等兜底措施，并已在魔法粘贴和 OCR 识别两个功能点完成接入。

#### 新增文件

**src/Mogan/Telemetry/telemetry.hpp**
- C++ 胶水层，提供 `telemetry_track` 两个重载。
- 非社区版：调用 Scheme 的 `track-event` 上报事件。
- 社区版：空操作，避免在社区版中泄露埋点逻辑。
- **修正**：`eval_scheme` 返回 `tmscm`（指针类型），需用 `tmscm_to_object` 转换为 `object` 后再传给 `call`，否则链接器会尝试匹配未定义的 `object(void*)` 构造函数。
- **优化**：使用 `null_object()` 替代 `eval_scheme("'()")`，避免无意义求值。

**TeXmacs/progs/telemetry/telemetry-utils.scm**
- 工具库：定义 telemetry 目录结构、文件路径、锁路径。
- 生成设备 ID、会话 ID、应用版本、平台、语言、时区等上下文信息。
- 提供 `telemetry-make-event` 构造标准事件结构。
- 提供 `telemetry-load-config` 从环境变量加载动态配置，支持 `MOGAN_TELEMETRY_BUFFER_SIZE` 和 `MOGAN_TELEMETRY_FLUSH_INTERVAL`，返回实际加载的 alist。对非法值（非数字、负数、零）输出警告并保持默认值。
- **修正**：从 R7RS `define-library` 改为 TeXmacs 模块系统 `(texmacs-module ...)`，因为 Mogan 使用 TeXmacs 自有的模块系统（基于 S7 Scheme），`define-library` 会导致模块解析失败和运行时 `unbound variable` 错误。
- **修正**：C 风格 `/* ... */` 注释改为 TeXmacs 标准 `;` 单行注释，避免 S7 Scheme 将注释块首行误解析为未绑定的变量。
- **修正**：`telemetry-home-path` 改为使用 TeXmacs 内置的 `(get-texmacs-home-path)`，避免在 macOS 上回退到错误的 `~/.local/share/Mogan`（实际应为 `~/.TeXmacs`）。
- **修正**：`getenv` 改为 `system-getenv`（TeXmacs C++ glue 函数名）。
- **修正**：补充导入 `(liii os)` 以使用 `mkdir`/`rmdir`。
- **修正**：`*telemetry-event-queue*` 从本模块移除，移到 `telemetry-track` 中定义，避免跨模块共享可变状态时因 S7 `use-modules` 的值复制机制导致队列读写不一致。
- **优化**：统一模块内缩进为 2 空格。
- **优化**：`telemetry-language` 清洗 `LANG` 环境变量，移除 `.UTF-8` 等编码后缀，输出标准语言代码如 `zh_CN`、`en_US`。
- **配置集中化**：`telemetry-buffer-size`（默认 10）和 `telemetry-flush-interval-ms`（默认 60000）从 `telemetry-track.scm` 和 `init-telemetry.scm` 移至本模块统一定义，解决跨模块 `set!` 导致的变量绑定失效问题。`telemetry-load-config` 通过 `set!` 修改本模块变量，确保配置对所有使用者可见。
- **运行时开关**：`telemetry-enabled?` 从 `init-telemetry.scm` 移至本模块，供 `telemetry-track` 和 `init-telemetry` 共享。用户运行时设置 `"0"` 或 `"off"` 后，后续事件不再入队，退出时也不再落盘。

**TeXmacs/progs/telemetry/telemetry-track.scm**
- 事件追踪核心：提供 `track-event` 函数，将事件写入内存队列 `*telemetry-event-queue*`。
- 队列长度达到 `telemetry-buffer-size`（默认 10）时自动触发 `telemetry-flush`。
- 提供 `telemetry-flush-if-needed` 供外部调用。
- **合并 flush**：原 `telemetry-flush.scm` 中的全部 flush 逻辑（目录锁、文件 IO、JSON Lines 写入）合并到本模块，与 `*telemetry-event-queue*` 处于同一环境，确保 `set!` 和读取操作的是同一个变量。
- **修正**：`track-event` 内增加 `display` 输出 `[telemetry] scheme track: ...`，使 Scheme 端埋点也有可见日志，便于调试确认事件已入队。
- **落盘日志**：`telemetry-write-pending` 在成功写入后输出 `[telemetry] flushed N event(s) to /path/to/telemetry-pending.jsonl`。
- **优化**：限制队列最大长度 `telemetry-max-queue-size`（默认 1000），超出时丢弃最旧事件，防止 flush 长期失败导致内存无限增长。
- **优化**：修复 JSON Lines 文件边界处理，避免空行开头和双空行问题。
- **运行时关闭**：`track-event` 入口增加 `(telemetry-enabled?)` 守卫，关闭时直接返回 `#f`，事件不入队。`telemetry-flush-if-needed` 同样增加守卫，关闭时直接返回 `#t`，不落盘（包括 `on-exit` 回调）。
- **文件大小限制**：`telemetry-write-pending` 在追加写入前计算现有文件大小 + 新内容大小。若超过 `telemetry-max-file-size-bytes`（10MB），清空旧文件仅写入新事件，防止磁盘无限增长。
- **事件老化**：`telemetry-flush` 在写入前调用 `telemetry-filter-stale-events`，丢弃 `timestamp_ms` 超过 7 天的事件，输出丢弃数量。
- **写入失败保护**：`telemetry-flush` 仅在 `telemetry-write-pending` 返回 `#t` 后才清空内存队列；写入失败（磁盘满、权限不足）时保留队列并输出警告，等待下次 flush 重试。

**TeXmacs/progs/telemetry/init-telemetry.scm**
- 初始化模块：启动时调用 `telemetry-load-config` 加载环境变量配置，打印已加载的配置项。随后根据独立的 `telemetry` 偏好设置判断是否启用 telemetry（`"0"` 或 `"off"` 关闭，默认开启）。
- 注册周期性 delayed 任务，每 60 秒自动 flush 一次内存队列。
- **退出 flush**：通过 `(on-exit (telemetry-flush-if-needed))` 注册退出钩子，确保软件关闭前将内存队列中的事件落盘，不丢失数据。
- **修正**：同上，从 `define-library` 改为 `(texmacs-module ...)`，与 TeXmacs 启动流程兼容。
- **优化**：添加 `telemetry-scheduled?` 守卫，防止 `init-telemetry` 被重复调用导致多个 delayed 任务叠加。
- **优化**：将内部调度函数重命名为 `telemetry-scheduler-step`，避免与 `telemetry-utils.scm` 中的 `telemetry-now` 时间戳函数混淆。
- **运行时开关**：移除本地 `telemetry-enabled?` 定义，改为 `:use (telemetry telemetry-utils)` 引用共享的开关函数。

**TeXmacs/progs/init-research.scm**

### Why

1. **数据需求**：魔法粘贴和 OCR 是 Mogan 的核心卖点，需要追踪用户实际使用频率和模式分布，以指导产品迭代。
2. **统一架构**：将埋点系统抽离为独立模块（`TeXmacs/progs/telemetry/`），便于后续在其他功能点快速接入，而不侵入业务代码。
3. **多进程安全**：使用目录锁（`mkdir` 原子性）而非文件锁，兼容不同操作系统的文件系统语义，防止多个 Mogan 实例同时写入导致数据损坏。
4. **社区版隔离**：通过 `IS_COMMUNITY` 宏在编译期完全剔除埋点逻辑，确保社区版零开销、零隐私风险。
5. **隐私可控**：Telemetry 默认开启，用户可通过偏好设置 `"0"` 或 `"off"` 随时关闭，符合透明可控原则。

### How

- **事件构造**：`telemetry-make-event` 统一生成包含时间戳、设备 ID、会话 ID、平台、语言等上下文的标准事件结构，事件属性通过 `properties` 字段扩展。
- **内存缓冲**：`track-event` 将事件写入内存队列，达到阈值（默认 10 条）后自动 flush，减少磁盘 IO 频率。队列有上限保护（默认 1000），防止内存泄漏。
- **周期性刷新**：`init-telemetry` 注册 delayed 任务，每 60 秒检查并 flush 队列，避免事件长期驻留内存。
- **退出 flush**：通过 `on-exit` 注册退出钩子，确保软件关闭前将剩余事件落盘，不丢失数据。
- **动态配置**：启动时 `telemetry-load-config` 读取环境变量 `MOGAN_TELEMETRY_BUFFER_SIZE` 和 `MOGAN_TELEMETRY_FLUSH_INTERVAL`，校验后实时调整 buffer 阈值和 flush 周期。
- **文件大小限制**：`telemetry-write-pending` 在追加写入前计算现有文件大小 + 新内容大小。若超过 10MB，清空旧文件仅写入新事件，防止磁盘无限增长。
- **事件老化**：`telemetry-flush` 在写入前调用 `telemetry-filter-stale-events`，丢弃 `timestamp_ms` 超过 7 天的事件。
- **写入失败保护**：`telemetry-flush` 仅在写入成功后才清空内存队列；写入失败（磁盘满、权限不足等）时保留队列并输出警告，等待下次 flush 重试。
- **数据格式**：落盘文件采用 JSON Lines（`.jsonl`）格式，每行一个独立 JSON 对象，便于后续流式读取和上传。
- **C++ 与 Scheme 协作**：C++ 层负责编译期隔离；Scheme 层负责事件构造、缓冲、落盘和业务侧埋点调用。
