## 2026/09/14 Linux 打包支持 AppImage（双产物发布）

### What（本次改动做了什么）

1. **`packages/debian/package.sh` 增加 AppImage 输出**：
   - 脚本开头设置 `export APPIMAGE_EXTRACT_AND_RUN=1`，确保无 FUSE 环境（如 Docker/CI 容器、无 libfuse2 的现代 Linux 发行版）下 `linuxdeploy` 及内嵌的 `appimagetool` 可正常自解包运行；
   - 运行 `linuxdeploy` 提取依赖时，追加 `--icon-filename "$APP_NAME" --output appimage` 参数，在复用现存 AppDir（含已收集的 Qt 库、fcitx5 输入法插件、高清图标、.desktop 文件）的基础上顺带生成 AppImage；
   - 将生成的 `Mogan_STEM-*.AppImage` 规范重命名为 `${APP_NAME}_${VERSION}_${ARCH}.AppImage`，与原有 `$OUTPUT_DEB` 同级放置于上层目录（`../`）；
   - 保留原有的 deb 打包逻辑（`AppDir/usr` 拷贝到 `/opt/mogan-stem`、控制文件写入、维护脚本、`dpkg-deb --build`）完全不变。
2. **`.github/workflows/cd-debian13.yml` CD 流程接入 AppImage**：
   - 「Generate Debian and AppImage Package」步骤在归档 deb 的同时，将 `../mogan-stem_*.AppImage` 规范重命名为 `mogan-stem-${{ env.VERSION_TAG }}-x86_64.AppImage`；
   - 「Upload Artifact」步骤增加 `mogan-stem-*-x86_64.AppImage` 路径匹配，普通分支或手动触发工作流时可在 Actions 附件中同时获取 deb 与 AppImage；
   - 「Release」步骤在打 tag 发布时，将 `mogan-stem-*-x86_64.AppImage` 一并发布至 GitHub Release 资产中。

### Why（为什么这么做）

- **扩展 Linux 分发形态**：Deb 包仅适用于 Debian / Ubuntu 系列及其衍生发行版，且需要 root / sudo 权限安装至 `/opt`；AppImage 是便携的单文件二进制镜像，免安装、支持普通用户权限直接运行，能够覆盖 Arch、Fedora、openSUSE 等各类 Linux 发行版。
- **原有 deb 保持不动**：已有用户和部署流程依赖既有的 deb 包格式与路径，新产物必须作为增量独立存在，不能侵入或改变原有 deb 的目录结构和行为。
- **为什么不走 Velopack 打包 AppImage**：
  - Linux 平台若不启用应用内自动更新与 Delta 增量更新，Velopack 方案需要额外在容器内安装 .NET 10 SDK / Runtime 及 `vpk` 全局工具，引入冗余体积与构建复杂度；
  - Velopack 打包 AppImage 底层仍然只负责归档与 runtime 包装，并不具备自动分析提取 Qt6 平台依赖和输入法插件的能力；
  - 方案复用项目在 `package.sh` 中经过长期调优的 `linuxdeploy-plugin-qt` 与 fcitx5 收集逻辑，直接在生成的 AppDir 上压制 AppImage，改动最小、稳定性最高、耗时几乎零增加。

### How（怎么做的）

1. **无 FUSE 容器安全运行**：
   在 `packages/debian/package.sh` 脚本前置环境变量声明处注入：
   ```bash
   export APPIMAGE_EXTRACT_AND_RUN=1
   ```
2. **AppImage 生成与命名规范**：
   在步骤 5 调用 `linuxdeploy` 时加入 `--icon-filename "$APP_NAME"`（确保 AppDir 根目录软链接与 desktop 中的 `Icon=mogan-stem` 匹配），并开启 `--output appimage`：
   ```bash
   rm -f "$APP_HOME"/Mogan*.AppImage
   ./"$DEPLOY_TOOL" --appdir "$APP_DIR" --plugin qt --executable "$APP_DIR/usr/bin/$BINARY_NAME" --icon-file "$ICON_SRC" --icon-filename "$APP_NAME" --output appimage

   OUTPUT_APPIMAGE="${APP_HOME}/../${APP_NAME}_${VERSION}_${ARCH}.AppImage"
   GENERATED_APPIMAGE=$(ls -t "$APP_HOME"/Mogan*.AppImage 2>/dev/null | head -n 1)
   if [ -n "$GENERATED_APPIMAGE" ] && [ -f "$GENERATED_APPIMAGE" ]; then
       mv "$GENERATED_APPIMAGE" "$OUTPUT_APPIMAGE"
       chmod 755 "$OUTPUT_APPIMAGE"
   fi
   ```
3. **CD 发布声明匹配**：
   在 `.github/workflows/cd-debian13.yml` 的 `upload-artifact` 与 `softprops/action-gh-release` 任务中追加 AppImage 路径：
   ```yaml
   files: |
     mogan-stem-*-debian13-amd64.deb
     mogan-stem-*-x86_64.AppImage
   ```

```bash

packages/debian/package.sh

# 检查产物（位于当前项目根目录的上一级）
ls -lh ../mogan-stem_*
# 预期可见：
#   ../mogan-stem_<version>_amd64.deb
#   ../mogan-stem_<version>_amd64.AppImage

# 运行验证 AppImage
../mogan-stem_*_amd64.AppImage
```

- 检查运行产物 Artifact 或 Release 页面，应同时包含 `mogan-stem-*-debian13-amd64.deb` 与 `mogan-stem-*-x86_64.AppImage`。
