# 0911: 绘图模式下线段中点绿色吸附点

## 任务需求

在绘图模式中，一旦鼠标接近线段，就在该线段的中点处显示一个绿色点，
该点是有效的吸附目标（鼠标靠近中点时，绘制点被吸附到中点上）。

## 现状分析

- 吸附候选（`gr_selection`）由 `eb->graphical_select` 收集后，在
  `edit_graphics_rep::adjust()`（`src/Edit/Interface/edit_graphics.cpp`）
  中补充网格、标尺（ghost line）候选，再经 `snap_to_guide` 选出最终吸附点。
- 鼠标贴近线段时，线段（`curve_box_rep`）产生两类命中：
  - `curve-handle`：鼠标靠近线段端点；
  - `curve-point`：鼠标靠近线段内部（最近点）。
  两者都携带完整曲线 `sel->c`，对直线段可用 `is_straight_line` 判别、
  `c->evaluate(0.5)` 取中点。此前没有针对线段中点的吸附候选。
- 绿色可视反馈已有成熟先例：标尺（ghost line，任务 0908 系列）由 C++ 侧
  `snap_ghost_line` 计算并 `call("graphics-set-ghost-lines", ...)` 注册到
  `TeXmacs/progs/graphics/graphics-ghost.scm` 的模块级状态，再由
  `graphics-extra-decorations`（`graphics-object.scm`）把状态渲染成
  `(with "color" "green" ...)` 装饰；鼠标移动时
  `move-point` → `graphics-decorations-update` 刷新，
  非绘制态 `graphics-decorations-reset` 清空。

## What（本次改动做了什么）

- `src/Edit/Interface/edit_graphics.cpp`：
  - 新增 `snap_curve_midpoint()`：扫描当前命中集合中的曲线对象
    （`curve-point` / `curve-handle` 命中），对折线/多边形**逐边**处理
    （`get_control_points` 取控制点，含闭合曲线首尾相连边，与
    `curve_box_rep::graphical_select` 的区间划分一致）；每条边先用
    `dist_to_segment` 判定鼠标确实贴近该边、再用 `is_straight_edge`
    （区间内切向一致）判定是直边，然后取区间中点
    `c->evaluate((t1+t2)/2)` 为该边中点。每次鼠标移动通过
    `graphics-set-midpoints` 向 scheme 上报当前中点集合（变更检测与
    刷新放在 scheme 侧，避免 C++ 侧缓存与 `graphics-decorations-reset`
    清空后的 scheme 状态失同步）；鼠标与中点距离小于吸附距离时，向
    候选集合追加 `curve-mid-point` 类型的吸附候选。
  - `can_snap()`：`curve-mid-point` 复用 "curve point" 吸附开关。
  - `adjust()` 中在标尺吸附之后调用 `snap_curve_midpoint()`。
- `TeXmacs/progs/graphics/graphics-ghost.scm`：新增线段中点状态与
  `graphics-set-midpoints`（含变更检测，集合变化才刷新装饰）/
  `graphics-clear-midpoints` / `graphics-get-decorations-midpoint` /
  `graphics-midpoints-active?` / `graphics-render-midpoints`；中点渲染为
  `(with "color" "green" "point-style" "disk" (point x y))` 绿色圆点，
  构造逻辑抽出为纯函数 `midpoint-decorations` 便于单测。
- `TeXmacs/progs/graphics/graphics-single.scm`：`edit_move`（'edit 模式
  非绘制态）原本每次移动都 `graphics-decorations-reset` 整体清空装饰
  层，导致未落第一个点时绿点预览永远被清掉；现改为鼠标仍贴近线段时
  仅渲染中点绿点（`graphics-render-midpoints`），其余情况照旧整体
  清空。鼠标离开绘图区时由 `graphics-reset-context` 路径兜底清空，
  无残留。
- `TeXmacs/progs/graphics/graphics-object.scm`：
  `graphics-extra-decorations` 追加中点装饰；
  `graphics-decorations-reset` 同时清空中点状态；
  `create-graphical-object` 的 group 分支（绘制完成后自动进入的
  `group-edit edit-props` 选择态走此路径）追加渲染中点绿点，空对象
  分支在中点仍激活时保留绿点预览。
- `TeXmacs/progs/graphics/tests/graphics-ghost-test.scm`：新增纯逻辑
  单元测试，覆盖 `midpoint-decorations` 的空集、单点、多点输出形状。

## Why（为什么这么做）

- 中点显示条件取「鼠标贴近线段」（存在 `curve-point`/`curve-handle`
  命中，二者已被 `graphical_select` 按吸附距离过滤），与需求「一旦鼠标
  接近线段就出现绿色点」一致；而吸附候选额外要求鼠标与中点本身的距离
  小于吸附距离，避免鼠标在线段远端时被强行拉到中点。
- 完全复用 ghost line 的注册/刷新/清空链路（模块级状态 + 变更检测 +
  装饰渲染），不引入新的刷新机制；吸附开关挂在 "curve point" 上，
  用户关闭曲线点吸附时中点同步失效，语义自然。
- 中点坐标经 `f2` 逆变换转回文档坐标系后再传给 scheme，与 ghost line
  的坐标约定一致。

## How（验证）

- `xmake b stem && xmake r graphics-ghost-test`（headless 纯逻辑单测）。
- GUI 端到端验证（X11 下 XTest 合成鼠标/键盘 + 截图像素分析，已执行）：
  测试文档含三角形 `<cline>`（3 边，含闭合边）、独立两点、独立
  `<line>`；均通过：
  1. 鼠标贴近三角形任一边，该边中点出现绿色圆点（三条边 + 独立线段
     中点逐一验证，绿点像素位置与中点理论屏幕坐标一致）；
  2. 非绘制态悬停（未落任何点）绿点同样显示；鼠标远离后绿点消失，
     鼠标移出绘图区无残留绿点；
  3. 切到 line 工具落下第一个点（绘制中）后悬停斜边中点：绿点显示，
     状态栏坐标精确读出 `(2,1.5)`（斜边中点）；
  4. 吸附落点：在底边中点附近 3px 处点击（point 工具），新插入的点
     精确落在中点 `(2,0)`（状态栏坐标与插入点像素位置双重确认）；
     偏移 6px 以上则不吸附（与既有吸附距离行为一致）；
  5. 绘制对象提交后自动进入的 `group-edit edit-props` 选择态（状态栏
     提示 "Edit groups of objects"）悬停斜边中点：绿点显示且坐标吸附
     读出 `(2,1.5)`，远离后消失。

## 2026/08/14 二次修复：折线逐边中点 + 非绘制态悬停显示

### 问题

初版只处理两个控制点的整曲线直线段，且绿点在非绘制态被装饰层整体
重建清掉。GUI 实测（用户截图场景：三角形 + 独立点，鼠标贴近三角形
边）绿点完全不出现：

1. 三角形是单条 `<cline>`（3 控制点闭合折线），整曲线 `is_straight_line`
   为假，取不到任何中点；多段折线同理。
2. 未落第一个点时 `edit_move`（'edit 非绘制态）每次移动都
   `graphics-decorations-reset`，绿点刚注册就被清掉。

### 修复

- 折线**逐边**处理（见上文 What），闭合曲线补首尾相连边，每边独立
  判定「鼠标贴近该边」与「该边是直边」。
- `edit_move` 非绘制态保留绿点预览（`graphics-midpoints-active?` 时
  改为 `graphics-render-midpoints` 仅渲染绿点）。

## 2026/08/14 三次修复：group-edit 选择态显示绿点

### 问题

用户实测反馈：绘制完成后（Mogan 自动切换到 `group-edit edit-props`
选择态，状态栏提示 "Edit groups of objects"）悬停线段仍无绿点。该模式
`edit_move` 走 `graphics-group.scm`，`graphics-decorations-update` 进入
`create-graphical-object` 的 **group 分支**，该分支拼接 `the-sketch`
轮廓时不包含 `graphics-extra-decorations`，绿点被丢弃。

### 修复

`create-graphical-object` group 分支的 concat 追加
`(graphics-get-decorations-midpoint)`（只追加中点，不追加标尺等绘制
辅助装饰）；空对象分支（o 为空）在中点仍激活时渲染绿点预览，与单一
edit 模式行为一致。已按用户截图场景 GUI 复测通过（含远离消失回归）。

## 2026/08/14 四次修复：折线绘制中的已落边中点 + CI 格式

### 问题

1. CI `clang-format-check` 失败：新增测试文件
   `graphics-ghost-test.scm` 未过 `gf fmt --check`（本地
   `--changed-since=main` 对当时尚未跟踪的新文件未生效）。
2. 折线（line/cline）绘制过程中（已落点、未提交）悬停无绿点：绘制中的
   对象只存在于绘制覆盖层（sketch/go_box），尚未进入文档树，
   `eb->graphical_select` 选不到它，选不到就没有 curve-point/curve-handle
   命中。标尺（ghost line）能工作正是因为它读的是 scheme 侧已落点。

### 修复

- `graphics-ghost.scm` 新增 `graphics-get-previous-midpoints`：绘制
  line/cline 时按 `graphics-get-all-previous-points` 同样的「固定点」
  语义，返回已落固定点连成的各线段中点（文档坐标系；spline 控制点
  连线不是线段，不在其列）。
- `edit_graphics.cpp` `snap_curve_midpoint` 消费该结果：注册绿点显示，
  并在鼠标与中点距离小于吸附距离时追加 `curve-mid-point` 候选（文档
  坐标经 `f2` 转屏幕坐标）。
- 冗余收敛仅限本功能文件：两处「去重 + 注册显示 + 追加候选」合并为
  `register_midpoint` 辅助函数；`is_straight_edge` 保持为本文件内
  静态函数，不改共享的 curve.cpp。（曾尝试改用 `graphics-mode` +
  `graphics-get-all-previous-points` 在 C++ 侧判断工具与取点，实测
  不可靠，已回退。）
- 测试文件已 `gf fmt`，全部任务文件逐一通过本地 `gf fmt` 幂等检查
  （graphics-object.scm 两处历史调用存在本地 gf 与 CI 版本分歧，
  保持上游原格式）。

### 验证

GUI（XTest 合成事件）：cline 工具连落两点后悬停第一条边中点
`(0,-0.5)`：绿点出现（圆斑 16px 宽，叠加在标尺线上），偏移 3px 悬停
状态栏精确读出 `(0,-0.5)`，吸附生效。格式化后复测通过。
