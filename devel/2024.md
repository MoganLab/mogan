### 3.2 非确定性测试（文档验证）

前置：使用**商业版**（非 community）构建，社区版不显示 VIP 按钮，无法复现。

1. **未登录态**：启动后窗口拉到半屏（约 800px 宽），观察标签页宽度。此时 VIP 按钮显示，标签页右侧应保留 VIP 按钮空间，不与按钮重叠；
2. **普通 / 体验会员**：登录普通用户或体验会员账号，VIP 按钮仍显示，行为同未登录；
3. **正式会员（关键场景）**：登录 Fruit/Sprout/Seed/Member 等正式会员账号，等待用户信息返回后 VIP 按钮隐藏。此时标签页应**向右扩展利用**原本 VIP 按钮占用的约 110px 宽度，半屏下能多容纳至少一个标签或显著加宽现有标签；
4. **半屏自动隐藏（新增）**：未登录或普通/体验会员状态下，把窗口从最大化拖拽缩小到屏幕宽度一半及以下（含等于），VIP 升级按钮应**实时跟随隐藏**，标签页向右扩展利用腾出的空间；拖回大于一半时按钮恢复显示；
5. 切换窗口在半屏 ↔ 最大化之间多次切换，标签页宽度应跟随实时重排，无残留空白、无覆盖按钮；
6. 标签数量较多时，最后一个标签后应能完整显示「新增标签」按钮，不被系统按钮/VIP 按钮挤压或覆盖。

## 5 What

1. **VIP 按钮预留宽度动态化**：`arrangeTabPages` 不再无条件为 VIP 按钮减去 90px，改为按 `m_vipButtonReserved` 标志位决定是否预留。
2. **VIP 预留宽度调整**：VIP 按钮预留宽度由 90px 调整为 110px（含按钮宽度及其与相邻系统按钮的间距），更贴合实际渲染宽度，避免标签页贴得过近。
3. **新增标签按钮补占位**：`reservedRight` 加上末尾「新增标签」按钮的宽度，避免最后一个标签贴住或越过该按钮。
4. **统一显隐驱动**：`updateVipButtonVisibility` 计算出 `shouldShow` 后同时调用 `vipButton->setVisible` 与 `tabPageContainer->setVipButtonReserved`，保证按钮显隐与标签页可用宽度计算始终一致。
5. **系统按钮宽度修正**：每个系统按钮预留宽度由 72×scale 调整为 60×scale，更贴近实际按钮宽度，让标签页可用宽度更准确。
6. **半屏自动隐藏 VIP 按钮（新增）**：未付费用户（未登录 / Regular / Trial）在窗口宽度 ≤ 屏幕可用宽度一半时，VIP 升级按钮实时跟随隐藏，让出约 110px 给标签页；拖回大窗口自动恢复显示。半屏阈值用 `<=` 包含等于一半的情况，避免临界尺寸闪烁。

## 6 Why

旧逻辑里 `arrangeTabPages` 通过 `#ifndef IS_COMMUNITY` 无条件 `reservedRight += scaled(90)` 为 VIP 按钮预留空间，但 VIP 按钮的显隐由登录态与会员类型共同决定：

- 社区版不显示 VIP 按钮（已由 `is_community_stem()` 编译期屏蔽）；
- 商业版下，**正式会员（Fruit User / Sprout User / Seed User / Member）登录后 VIP 按钮会隐藏**。

但标签页可用宽度的计算路径并不知道这一点，于是出现：**VIP 按钮已经隐藏了，标签页仍按"按钮还在"的假设预留 90px**——半屏（窗口宽度紧张）场景下，这 90px 直接吃掉了一个标签的宽度，表现为标签页被莫名压缩、右侧出现无法利用的空白。

## 7 How

### 7.1 让显隐状态传到布局计算方

VIP 按钮的显隐判定原本散落在 `updateVipButtonVisibility` 里的多个 `if` 分支中，且各自直接调 `show()/hide()` 后 `return`。重构为：

```cpp
bool shouldShow = ...;  // 集中计算
vipButton->setVisible(shouldShow);
if (tabPageContainer) {
    tabPageContainer->setVipButtonReserved(shouldShow);
}
```

把"按钮可见性"和"标签页要不要为按钮留位置"统一绑定到同一个布尔值上，二者永远不会脱节。

### 7.2 让容器按标志位重排

`QTMTabPageContainer` 增加字段与内联 setter：

```cpp
bool m_vipButtonReserved = false;

void setVipButtonReserved(bool reserved) {
    if (m_vipButtonReserved != reserved) {
        m_vipButtonReserved = reserved;
        arrangeTabPages();   // 状态变了立即重排
    }
}
```

`arrangeTabPages` 内部：

```cpp
int reservedRight = buttonCount * buttonWidth;
#ifndef IS_COMMUNITY
if (m_vipButtonReserved) {
    reservedRight += DpiUtils::scaled(110);   // VIP 按钮 + 与系统按钮的间距
}
#endif
reservedRight += getScaledAddButtonHeight();   // 末尾新增标签按钮占位
```

`m_vipButtonReserved` 在 setter 里仅在变化时才触发 `arrangeTabPages`，避免每次 `updateVipButtonVisibility` 被调用（登录态查询可能反复触发）都做无谓的全量重排。

### 7.3 补齐 add tab 按钮占位

原 `reservedRight` 只算系统按钮和 VIP 按钮，但 `arrangeTabPages` 末尾会在最后一个标签后绘制 `m_addTabButton`（尺寸为 `ADD_BUTTON_SIZE × scale`，固定 20px 缩放后）。这部分宽度从未被预留，标签数量较多时最后一个标签可能贴住甚至越过 add 按钮。补一项 `getScaledAddButtonHeight()` 让标签可用宽度计算与实际渲染一致。

### 7.4 半屏自动隐藏 VIP 按钮

`updateVipButtonVisibility` 原本只在登录态/会员信息变化时被调用一次，拖拽窗口缩放不会触发它，所以光在函数里加半屏判定没用——代码根本不被执行。

解决思路分三步：

1. **存登录态到成员变量**：`updateDialogContent` 是登录态变化的唯一入口，在此同步保存 `m_isLoggedIn` 和 `m_memberType`，让无参的 resize 回调能取到当前状态。
2. **resize 事件驱动重算**：`qt_tm_widget_rep` 不是 QObject（继承自 `widget_rep` / `abstract_struct`），无法直接重写 `eventFilter`。在构造函数里给 `mw` 装一个内联定义的 `VipBtnResizeWatcher : public QObject`（参考已有的 `ChatSidebarBtnPositioner` 模式），监听 mainwindow 的 `Resize` 事件，触发 `updateVipButtonVisibility_onResize()`。watcher 以 `mw` 为 parent，生命周期由 mainwindow 接管，无内存泄漏。
3. **半屏阈值判定**：在 `updateVipButtonVisibility` 内部，对已经判定为「应显示 VIP 按钮」的未付费用户，再检查 `mw->width() * 2 <= QApplication::primaryScreen()->availableGeometry().width()`，半屏及以下强制隐藏。用 `<=` 而非 `<` 让窗口正好等于屏幕一半时也触发隐藏，避免临界尺寸标签页右侧出现空白。

行为：未付费用户拖拽到半屏 → resize → 重算 → 按钮隐藏 + `setVipButtonReserved(false)` → 标签页腾出 110px；拖回大窗口 → resize → 按钮恢复 + 预留恢复。整个链路实时跟随，无延迟。
