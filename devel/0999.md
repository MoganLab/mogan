# 0999 释义会话按文档复用 + 会话 type 字段

## What

1. 同一文档的释义全部进同一个会话（此前释义与对话一样填进当前/新
   会话），行为对齐翻译：按 stem-doc-id 找未归档会话复用，未命中才
   新建；新建标题为「释义: 文件名（不带后缀）」——文件名取
   `chat-tab-source-doc-info` 返回的 url 末段去扩展名形式，前缀
   随界面语言本地化，与翻译标题的「翻译」同一取词方式。
2. 会话属性新增 `type` 字段（`translate` / `explain`，空串为普通
   对话），区分同一文档绑定的翻译会话与释义会话；字段随 manifest
   持久化并兼容旧 manifest（缺失回退空串）。
3. 释义动作整体改名 gloss → explain：动作名（QML model、
   `ai_action` 白名单、`qt_chat_ai_send_selection` /
   `composeAiInputBody` 分支）、词典消歧键（`explain::ai`）、
   按钮注入属性（`labelExplain`）与图标文件（`explain.svg`）。

## Why

- 释义此前每次都在当前会话里发，同一文档多次释义会散落多个会话，
  也会污染用户的普通对话；翻译已有按文档聚合的会话机制，释义应
  共享同一机制。
- 翻译与释义都绑定同一 stem-doc-id 后，仅靠 sourceDocId 无法区分
  二者（释义会复用到翻译会话里），需要类型字段各自命中。

## How

1. **会话模型（C++）**：`ChatSession` 增加 `type` 成员；
   `ChatSessionManager` 增加 `setType`，`findSessionBySourceDoc`
   增加 `type` 形参（docId + type 双条件匹配）。
2. **发送路径（C++）**：`qt_chat_ai_send_selection` 中 explain 并入
   translate 的文档绑定分支——打开侧边栏前捕获文档身份与上下文；
   复用分支按 `(docId, action)` 查找（会话类型名即动作名）；新建分支
   标题词按动作取 `qt_translate ("Translate")` /
   `qt_translate ("Explain::ai")`（"Explain::ai" 即释义按钮同一
   消歧键，裸 "explain" 词条是「解释」，随界面语言本地化），并
   `setType` 写入类型。对话分支不再承接 explain。
3. **持久化（Scheme）**：`chat-persist-make-entry` 的 rest 链末端
   追加 `type`（opts4 守卫解析，缺省空串），条目新增 `"type"` 键；
   `chat-persist-load-all` 读取 `type`（缺失回退空串），恢复时经
   新增 glue `qt-chat-tab-set-session-type` 单独设置（restore 参数
   已达 glue 10 参上限，与 stemDocId 同款旁路）。
   `ChatController::updateManifest` 透传第 11 个实参 `s->type`。

  不再加第三个旁路。

# 0999 追加：修复 test_go_menu_hover 悬浮不透明度断言在 CI 偶发失败

## What

`tests/Plugins/Qt/qml_load_test.cpp` 的 `test_go_menu_hover` 把
「`QTest::qWait (150)` 后一次性断言背景 opacity 到 1.0/0.0」改为
`QTRY_COMPARE` 轮询等待动画结束。

## Why

- PR #4619 的 macOS arm64 CI（run 35328208840）中该用例失败：
  悬停 150ms 后实测 opacity 为 0.79（期望 1.0）。
- GoMenu 悬浮高亮背景带 100ms 的 opacity 渐变动画
  （`Behavior on opacity { NumberAnimation { duration: 100 } }`），
  CI 高负载下动画帧推进滞后，固定等待 150ms 时动画尚未走完，
  属时序敏感型偶发失败，与 #4619 的业务改动无关。

## How

两处「固定 `qWait (150)` + `QCOMPARE`」替换为 `QTRY_COMPARE`
（内部以 10ms 间隔轮询、默认 5s 超时）：动画正常时几十毫秒内
通过，CI 卡顿时有充足余量等到动画收尾的精确终值（1.0/0.0）。

## 涉及文件

| 文件 | 改动 |
|------|------|
| `tests/Plugins/Qt/qml_load_test.cpp` | `test_go_menu_hover` 两处 opacity 断言改为 `QTRY_COMPARE` 轮询 |

## 测试方法

- `xmake b qml_load_test && xmake r qml_load_test`
