## 5 What
1. 新增公共模块 `utils/library/dialog-value-table.scm`：把 FontSelector 的「本地真相表 reader」骨架抽出来（`value-table-ref/set!/remove!/clean`，entry-key 由调用方自定义，模块不关心 key 形状）。
2. FontSelector 纯重构接入公共模块（行为不变，`selector-table` 改调 `value-table-*`，字体专用 fallback 抽成 `selector-fallback` 经 lambda 注入）。
3. ParagraphFormat 接入公共模块：register 时填表、`meta` 读表（不再实时读 `get-env`/`get-init`）、`set` 同步写表、reset/Cancel 把目标值写表、cleanup 清表——消除 reset 滞后。
4. 更新 `ParagraphFormat.qml` 文件头与 `resetValues` 注释。
5. 在 `ai-docs/qml/README.md`「Cancel/重置撤销」节补充「本地真相表 reader——凡带 reset 的 live 写回对话框必用」，列两个使用者；开发工作流第 4 步提一句。

## 6 Why
ParagraphFormat 本应贯彻 FormDialog 的「显示真相源 = QML `values`、改动直改 `values`、不重读文档树」思路（live 写回 `setField` 正是这么做）。但 reset 那条路破例了：`onClicked` 先 `paraBridge.reset()`（写树），紧接着 `resetValues()` 调 `basicMeta()`/`advancedMeta()`，scheme 内部 `(get-env var)`/`(get-init var)` **跨 eval 重读文档树**。而读取相对编辑命令有延迟（段落级 `make-multi-line-with` 走树编辑+typeset），于是重建的 `values` 仍是撤销前旧值，表现为「重置点一次没用，点第二次才生效」。

用户已确认：**文档里的生效值是对的，只有 QML 显示滞后一拍**——问题纯粹在 reset 路径重读树的时序。FontSelector 不重读树（有本地真相表 `selector-table`），所以它 reset 不滞后。故把该机制提取成公共模块并让 ParagraphFormat 接入，reset 走本地表（即时、零读树）。

## 7 How
核心思路：给 ParagraphFormat 的 scheme facade 配一个本地真相表（`dialog-value-table`），所有「当前值」读取经 `value-table-ref` 表优先命中、缺项才 fallback 实时树；set/reset/Cancel 把目标值写入表，后续读即时生效、不碰树。

- **entry-key**：`(key var)`，`key` 是 int 句柄（与 FontSelector 的 `(specs var buffer)` 风格不同，公共模块对 key 形状不做假设，故两种都适用）。
- **register**：打开时（live 改动前）快照 + 同步把各字段值写入 value-table。
- **meta**：`value` 取 `value-table-ref (paragraph-entry-key key var) (lambda () (getter var))`，表优先、fallback 兜底。
- **set**：`setter` 写树后 `value-table-set!` 同步写表。
- **reset（revert）**：撤销后把目标值写表——段落级经 `restore-snapshot` 内部写全部快照值；文档级 `init-default` 后用 `getter`（`get-init`，同 eval 直读 init/pre hashmap、不滞后）算全局默认写表。
- **cancel/restore-snapshot**：写树后同步把全部快照值写表。
- **cleanup**：清该 key 全字段 value-table 项，防泄漏。

难点：文档级 reset 的全局默认值如何不重读树拿到——靠 `init-default` 与 `get-init` 在**同一次 eval** 内完成（`init_default`/`get_init_value` 都直读 init/pre hashmap，无 typeset 延迟），而非「写树 → 另一次 eval 跨调用读」。段落级因 `make-multi-line-with` 必然滞后，只能用快照、不可用 reset 后读。

实施中额外踩到一处作用域 bug：文档级 revert 最初把 `for` 循环写在 `with (_ getter setter) specs` 块外，`getter` unbound，只炸「文档→段落」；修复为把循环挪进 `with` body 内。
