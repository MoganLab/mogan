4. **FontSelector Reset 语义修正**：`font-selector-restore` 按 specs 的 `global?` 分流——文档级恢复系统默认（`:default` 移除 init），段落级走 revert-to-snapshot（回打开时，不吞选区）。
5. **回归测试**：新增 `TeXmacs/tests/2036.scm`；扩充 `TeXmacs/tests/2028.scm`。
6. 更新 QML 注释与 README。

## 6 Why
- **ParagraphFormat 重置滞后**：本应贯彻 FormDialog「真相源 = QML values、不重读树」，但 reset 那条路破例跨 eval 重读 `get-env`/`get-init`——读取滞后于树写入，于是 `resetValues()` 重建的 values 仍是撤销前旧值，表现为「点两次才生效」。文档里的生效值是对的，只有 QML 显示滞后。FontSelector 不重读树（有本地真相表），故把它提取成公共模块让 ParagraphFormat 接入。
- **FontSelector Reset 语义**：原 `font-selector-restore` 与 Cancel 共用 `revert-to-snapshot`，语义被合并成「撤销本对话框改动」。但「文档→字体」的 Reset 用户预期是「恢复默认」（与老 tm-tool 字体对话框的「Restore defaults」一致）。

## 7 How
本地真相表（`dialog-value-table`）：读取经 `value-table-ref` 表优先命中、缺项才 fallback 实时树；set/reset/Cancel 把目标值写入表，后续读即时生效、不碰树。

- **entry-key**：`(key var)`（ParagraphFormat）/ `(specs var buffer)`（FontSelector）。
- **register**：打开时把各字段值写入表。
- **meta**：`value-table-ref (entry-key key var) (lambda () (getter var))`。
- **set**：`setter` 写树后 `value-table-set!` 同步写表。
- **ParagraphFormat reset**：段落级经 `restore-snapshot` 写全部快照值（**修滞后**——get-env 读排版产物 cur、滞后于树写入，是「点两次」根因，写表后 meta 读表绕开）；文档级 `init-default` 后用 `get-init` 算全局默认写表（get-init 直读 init/pre hashmap、本就不滞后，写表仅为两级统一读取路径 + 保持表与文档真相一致）。
- **FontSelector reset（按 global? 分流）**：文档级（`#t`）走 `selector-restore specs #t`——`init-multi` 对各字体 var 走 `init-default` 移除 init（回到继承的全局/pref 默认），清表后 `selector-get*` fallback 到 `initial-font-data` 得系统默认；段落级（`#f`）因 `selector-restore` 的 `:default` 未实现，走 `font-selector-revert-to-snapshot` 回到打开时（机制同 Cancel，`selector-get-changes` + 单次 setter，不吞选区）。
- **cleanup**：清该 key/specs 全字段。

**契约与前提（dialog-value-table 模块注释）**：
- 不变量：凡写文档树的路径（set/reset/cancel）都必须同步 `set!` 本表，否则表值与文档真相背离。
- 适用前提：对话框打开期间文档不被其它入口改动（read-through 缓存无外部失效钩子；当前对话框为非阻塞模态、QML 仅在打开与 reset 后重读 meta，成立）。
- falsy 前提：底层 s7 hash-table 把「存 #f」当删除（`ahash-remove!` 即 `set #f`，见 `TeXmacs/plugins/goldfish/src/s7.c` 的 `s7_hash_table_set`：value == missing_key 时走 `remove_from_hash_table`），故 `#f` 不能作缓存值。`ref` 用 `(or ...)` 正合此意。调用方只缓存非空 string，此前提天然满足。

**踩坑记录**：
- falsy 修复被推翻：原想用 `hash-table-contains?` 区分缺项与缓存 #f，实测 s7 把「存 #f」当删除、根本无此态——`(or ...)` 本就正确，回退，改为在契约里记录此前提。
- 作用域 bug：文档级 revert 最初把 `for` 循环写在 `with (_ getter setter)` 块外导致 `getter` unbound，只炸「文档→段落」。
- FontSelector 段落级选区清空（本次又引又修）：第一版让 `font-selector-restore` 一律传 `#t` 给 `selector-restore`，没读 specs 自带的 `global?`——段落级 specs（setter=`make-multi-with`）也被喂 `:default`，生成非法 `(with "font" :default <tree>)`，触发 `cpp-insert-go-to ... is a pair but should be some other thing` 错，并把选中内容吞掉。修法即按 global? 分流。
- 注：原 FontSelector Reset bug 在 main 即存在（本分支仅把 `selector-restore` 内的 `ahash-remove!` 换成等价的 `value-table-clean`，未改其语义）；段落级清空选中是本次第一版修复引入、当轮即修。
